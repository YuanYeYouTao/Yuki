# Yuki 3.9.0 配置与升级草案（未发布）

<!-- release-baseline: version=3.9.0 schema=0096 -->

本文为开发基线的未来发布准备。**目前没有 3.9.0 Release、部署包或正式镜像；不要将源码版本号当作可拉取的镜像标签。** 当前正式下载仍使用 [3.8.4 Release](https://github.com/YuanYeYouTao/Yuki/releases/tag/v3.8.4)。开发部署使用经过验证的提交镜像，核对实际迁移 head。

## 版本边界

| 来源 | 随包数据库 head | 未来升级到本源码基线 |
| --- | --- | --- |
| 正式 3.8.4 | `0072` | 顺序执行目标代码随包的 `0073`—`0096`；已完成的 `0072` 媒体会话切换不得重做 |
| 3.8.4 后的开发部署 | 以实际 Alembic revision 为准 | 从实际 revision 顺序升级至 `0096`，不按应用版本号猜测 |
| 正式 3.8.3 | `0061` | 先满足 3.8.4 的迁移和停写切换前提，再继续至 `0096` |
| 更早或过渡态 | 核对实际 revision 与 canonical 基线 | 先按对应历史升级指南演练，不承诺直接升级或使用 `stamp` 跳过 |

`0073` 增补控制请求状态与回执；`0074`—`0075` 增加有界执行诊断及发送事件关联；`0076`—`0078` 增加 Work、执行轨迹和用量查询索引；`0079` 记录后续模型物理请求与未知用量；`0080` 记录新拆分发送的计划份数；`0081` 记录后续 Claude 缓存写入及 5 分钟、1 小时分层用量。旧记录中缺失的请求、计划和计费数据保持未知，不做推断或回填。`0080` 与 `0081` 的 downgrade 刻意保留已经记录的证据字段，不能把代码回退等同于数据库回退。

`0082` 添加来源 revision 失效触发器，`0083` 添加 receipt 引用索引，`0084` 添加媒体过期、全局联网来源清理及 Work 等待扫描索引，`0085` 添加 Work 目录与近期状态查询索引；这些迁移不新增业务状态、不重建 Work、预算或发送回执。旧镜像的严格 schema 检查会拒绝新 head；需要回退至 `0081` 时，先停 Bot，使用包含 `0085` 的新镜像执行 `alembic downgrade 0081`，再切回已保留的旧镜像。该 downgrade 仅删除新增索引、触发器并回退 Alembic head，不恢复数据库备份、不删除升级后新产生的事实。SnowLuma 保持运行。

## 未来发布前要核对

当前源码迁移头继续推进到 `0096`：`0086` 投影原执行回执并关联完整工具正文，
`0087` 保留旧工作有限预算、允许新工作使用显式空累计预算，`0088` 管理私有协议对象
的 Work 引用与物理存储配额。原 Work ID、租约恢复边界和已经确认的投递不重建。
`0089` 增加作用域观察与实际选取的来源/引用边界；`0090` 仅增加两个维护候选索引；`0091` 增加普通消息接纳事实，用原内部事件去重，
不创建第二套执行恢复日志。已接纳 Work、预算、发送与工具回执保持原身份。
新语义库的参与投影存于现有快照的版本命名空间；旧 reader 可以原样保存未知命名空间。
旧 Host 严格检查迁移 head，不能直接切回 `0090` 镜像。回退须使用兼容 `0091`
且保留普通接纳去重的镜像，先在升级后数据库副本演练；不能 downgrade 删除接纳事实或恢复旧备份。
从 `0090` 回退到兼容 `0089` 的前一提交时，先停 Bot，用新代码验证并执行 downgrade `0089`，
再切回原镜像；保留升级后的数据库、文件、事件和回执。更早格式不兼容的回退须单独设计，
不能只降 head，也不能默认恢复旧备份丢失新数据。
`0092` 仅新增普通反馈会话/更新时间与 Protocol GC 游标索引，不改原 Work、预算或回执。
`0093` 仅新增 Evidence compaction 的完整 fact/count/status 候选索引。升降级均先核验
同名对象及索引完整形状；downgrade 缺索引时拒绝，只删除该索引，保留事实、证据、
原唯一约束和级联关系。启动严格检查新 head，代码回退先验证 schema 兼容；不能恢复
旧备份覆盖升级后的事实。建索引的锁与 I/O 成本须在隔离副本测量，不能假定在线零影响。
回退到兼容 `0091` 的前一镜像时，停 Bot 后使用新代码执行 `alembic downgrade 0091`，
只删除本轮两个索引并回退 head；保留升级后数据库、协议文件和普通接纳事实，不恢复旧备份。
`0094` 仅新增 pending 且尚未完成准备的 Work 输入部分索引，避免空恢复轮询扫描已消费的输入历史；
原 owner、120 秒时限、状态及 writer 条件复核不变，不重建输入、任务或预算。升降级
完整核验同名对象、谓词和索引形状，缺失或漂移时拒绝 downgrade。旧 `0093` 镜像会
拒绝 `0094` head；回退先停 Bot，以新镜像执行 `alembic downgrade 0093`，仅删除该
索引并回退 head，再切旧镜像。保留升级后数据库与文件，不恢复旧数据库备份；
启动回执不确定时先核实际状态，不盲目回退或再次启动。
`0095` 新增发送来源检查的 Person/inbound 部分索引，保持全会话来源资格与原权限语义。
形状漂移时拒绝升降级；回退至原 `0094` 镜像前停 Bot，使用新代码执行 `alembic downgrade 0094`，
只撤销该自有索引，保留现行数据、预算和回执。读取优化与检索并行的范围见
[回复准备修复记录](operations/reply-preparation-io-2026-10-05.md)。
备份校验步骤见 [Work 协议与证据完整备份](operations/work-evidence-backup.md)。

1. 重新检查从 `v3.8.4` 到最终发布提交的全部已合并 PR、迁移单一 head、发布说明与 README 基线；[3.9.0 发布说明草案](releases/v3.9.0.md)按当前开发源码持续整理，发布前须按最终发布提交核对。
2. 在数据库副本上演练完整迁移及应用启动，核对持久 Work、控制请求回执、Social 发送计划、模型用量和执行轨迹。旧的不确定发送不能因升级而重试或重发。
3. 保存数据库一致性备份和现有配置、插件、媒体及持久工作环境回执。核对实际 Compose 项目名、全部覆盖文件、镜像提交和 Alembic revision；停写范围只涉及该部署需要停的服务。
4. 检查模型连接与任务路由、密钥、Base URL、协议、搜索和工具能力，确认每个目标 Provider 的实际请求与工具调用；保存中的连接或 WebUI 显示不等于线上路由生效。还需核对原 Work 跨 Provider 接续及发送回执，不把合成测试当作真实 QQ 验收。
5. 正式发布时再构建和验证目标镜像、发行包及升级文档，并以真实镜像内的迁移 head 为准。应用版本、Plugin API 版本与可选 Genie-TTS Worker 组件版本分别核对；当前 Plugin API 为 3.1，Worker 组件为 1.9.0。

未来部署应复用原有 Compose 覆盖文件、挂载和网关，不用新模板覆盖现有目录。对已运行 3.8.4 的数据库，不再次执行 `0072` 的离线 generation 重置；若来源更早，按 [3.8.4 升级指南](upgrade-3.8.4.md)完成其特有前提。回退前先保全升级后新产生的消息、文件、模型请求和投递回执；不能通过切回旧镜像覆盖新数据。

## MCP 退出与 Plugin API 3.1

`0096` 仅删除 `mcp_server_states`、`mcp_tool_cache` 两张派生表。共享工具结果、调用证据、媒体和 Work 原回执保留；不改历史迁移、不扫描/重建业务历史。旧 MCP 配置不再生效，现有未知调用不能取得重放资格。停旧 Bot 后再升级并启动新实例；schema head 精确匹配，不能直接换旧镜像回退，优先在新 head 向前修补。离线 downgrade 只重建空缓存表，不能恢复被删缓存，也不授权生产库回退。

SDK 合同升级为 3.1，全部插件/示例须更新 manifest；原批准会失效，按现有批准流程重新批准。网易云 MCP 插件不再提供，普通插件 HTTP、自有工具及 QQ 音乐卡片发送保留。详见 [API 3.1 迁移](plugin-development/api-3.1-migration.md)。QQ 网关登录目录不受此迁移影响。
