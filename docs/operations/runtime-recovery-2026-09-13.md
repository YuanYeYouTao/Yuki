# Runtime 异常恢复与连续执行

本次修复针对工具回执直接输出、旧任务接管独立请求、到限后中断及重复交付。
实施基线为 `0da873f`；部署状态在本文末尾记录。

## 事故证据

14:38 的错误发生在收尾 Provider 请求返回 HTTP 400 后，不是第 24 次请求到限。
旧的成功工具兜底把原始 JSON 当成正文，随后又撞上旧消息额度。
15:02 与 15:03 的同一份试卷分别由旧香蕉任务和新试卷任务发送，属于两个工作归属重叠。
15:30–15:34 的数学题期间确实发生了 Python、终端与搜索调用，仍归属旧工作
`6d6fd712-7bd3-4c1d-a341-3d069ea9bc7d`；该工作累计 98 次模型请求、65 次工具、16 条消息，
最终处于 `final_delivery_incomplete`。这不能支持“没有计算”或“只是首 token 慢”的结论。

生产日志另捕获到 `UPDATE canonical_conversations` 的持锁者。
代码中确认追加事件的 Rollup 检查在写事务内读取、投影历史；现改成原子登记信号，后台只读检查，
短写事务按 revision 消费信号。不能据此断言所有 SQLite 等待都只有这一个来源。
原 HTTP 400 未留下充分的服务端拒绝详情，本次新增安全诊断，历史原因仍不可追溯。

## 运行合同

- `work_supervisor` 统一结算段结束、等待、根额度、无进展、容量及故障。回滚与租约清理不覆盖原错误。
- 主任务每段默认 24 个模型请求、32 次业务工具；根与子任务继续共享 120/160，子任务保留主任务的 8/8。
  Provider 内部重试同样先计账。段结束保留原 journal、原工具调用结果，再交给调度器。
- 新消息不自动选中同一人的任意旧工作。中性入口可以回答、登记独立任务，或通过
  `task_control.resume(work_id)` 原子追加输入并恢复原任务。没有关键词分流。
- 删除 `TaskProgress` 和 `BudgetSender`；沙箱只负责执行回执，不能再独立裁定 Agent 预算或生命周期。
- 进度、工具发送和收尾使用同一预留机制：16 条/60 秒窗口；进度保留最终消息位置，
  每段最多 4 条进度。`sent_messages` 保留累计审计值，不再作为任务终身禁发开关。
- 整组回复先持久化并预留全部分片。额度暂不可用时保留内容和下一次允许时间；恢复不再请求模型重写。
  已接受的片段跳过，结果未知的片段暂停核对，不换内容重发。文件与说明共享预留，文件成功不被说明失败抹除。
- 已登记工作的错误不会再由 Processor 另发一条笼统的 AI 不可用；暂停通知有独立意图和发送回执。
  未登记的普通请求仍保留接纳前错误提示。子任务继续向父任务回传，不能自行取得 QQ 发送权限。
- 普通续跑只追加真实历史。缺失或损坏 journal 明确暂停；合同或来源版本变化记录新旧链关联。
  主、子任务都受 4 MiB 链与 64 MiB 总检查点额度约束，接近容量才压缩。
  SQLite 触发器增量记账，检查点与执行证据同事务保存；媒体清理按引用和有界批次进行。

## 各入口的恢复所有者

| 入口 | 持续执行与回传 |
|---|---|
| 用户消息、群自主发言 | WorkScheduler 使用原内部事件和当前授权恢复；统一交付器发送 |
| 子 Agent | 独立租约，使用同一监督器；完成或问题通知父任务 |
| 自动化 | 原 `automation_run_id` 和步骤游标；pending 后继续同一步，已完成步骤不重跑 |
| 插件后台通知 | 原后台任务延期，保留工作、预算和原事件身份 |
| 插件 SDK 同步调用 | 返回工作状态和 ID，由原调用方在同一合法 invocation 中再次调用接回；不自动取得聊天发送权 |

SDK 的 `agent.run` 返回 `state/work_id/pending`。
`llm.generate` 与 `generate_with_context` 成功仍返回字符串；等待或阻塞返回 `PluginResult`，
包含同样的状态字段。插件必须检查类型，不能把 pending 当文本发送；后台工作应使用已有的通知任务 API。
相同调用恢复原链、不会重置额度；改变目标应建立新调用，不复用旧 ID 冒充续跑。

- 真实 WorkScheduler 在两种 Provider 序列化协议中分别运行 24、24、3 个请求，跨越第 25 和第 49 次请求后完成。
  对实际 `messages/input` 做逐项比较：每次续跑保留此前前缀，完整 tools 声明相等；不是只比较哈希。
- 原执行回执、未知执行禁止重跑、共享预算、父子消息、归属交接和已发送文件的定向用例保留。
- 新增整组交付窗口恢复、部分接受后下一片结果未知禁止重发、缺失已使用历史必须暂停的真实 SQLite 用例。
- 自动化真实 worker 验证同一 run 两次进入原 Agent 步骤，后续发送仅一次，累计模型使用为 2。
- 旧版本数据库升级至 0059，验证主键/外键、ORM 形状、启动校验及预算数据保留。
- 模拟 Provider 不提供真实缓存 token 命中率；前缀完整性通过不等于可以宣称 Provider 缓存命中 100%。
