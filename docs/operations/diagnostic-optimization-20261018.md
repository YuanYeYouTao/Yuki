## 已实施

- 正常物理模型请求保留 `provider_start`、`provider_response`，逻辑信息合为一条 `model_phases`；原 7 条诊断收为 3 条。错误和重试按真实发生记录。
- turn 不复制初始历史或最终正文，删除工具批次的重复参数/结果与无结果成功结束；单项实际执行诊断及原业务结果保留。Jev Snapshot 只存一次。CodeMode 子操作结果沿原 span 保存，不再额外复制结果事件。
- 删除归一化缓存代理哈希、实际 Wire Observer 的常态全量哈希、64 链 LRU、Compiler/Composer/recovery 的历史哈希、孤儿 DTO/字段/CLI 输出与恒定指标。准备阶段模型调用数直接传入原业务预算整数；旧 paid JSON 的退役字段忽略语义保留。
- 删除每条诊断独立来源 reader，条件 INSERT 仍原子核验原 ID 类型/来源/归属、隐私代次及成功投递。锁外编码与准备，单项短事务提交；FIFO、取消、关闭、缺样与未知提交语义保留。
- 修复诊断 literal INSERT 被 SQLAlchemy 编译缓存保留首份正文的问题：仅诊断语句不进该编译缓存，资源预留释放后没有旧 payload 被此缓存钉住。Provider 缓存未改变。
- 只有客户端实际读取的 chat/turn 维护 live 状态与相应唤醒，删除深层无消费者状态更新。后台元数据查询不加载 gzip 正文。
- 删除没有现行读者的工具统计与回合观测全链：不再每次工具调用另写一份统计，不再轮末 shield 等待旧观测落库；依赖注入、维护清理和孤儿哈希一并删除。真实 MemoryToolReceipt、模型用量、关联 ID、阶段计时与原投递日志保留。
- 0134 清退 `tool_invocations`、`runtime_turn_observations` 两张旧统计表，删除 roots、operation_id 两条无消费者索引。其余表事实、执行过程原行和正文及六条现行索引保留，退役数据不重建。
- Work 租约 writer 内多次往返收为一条条件 UPSERT，核当前 generation、fence 与 SQL 执行时钟；SELF 后续 checkpoint 删整行重复读，保原值 CAS；重复 Memory job 按原 event_id 只读返回原事实；重复自省周期按原 source_key 只读返回，跳过 snapshot 聚合与零行 INSERT。

Canonical 入站仍在一致快照查证 Person、别名和成员，再原子入账。该路径没有强改为提前取得 writer，避免持写锁解析身份；不新增全局锁、授权缓存、重试上限或完成门槛。

## 处理量与实际字节

合成实验使用真实 AgentRunner 外层、TaskModelExecutor、协议适配器、工具协调器和 SQLite，业务主体为固定三次调用。MockHTTP 在返回前排空诊断，以保证两侧完整覆盖；该等待人为改变墙钟，不据此报告端到端延迟或固定加速倍数。所有物理请求的字节摘要、实际工具调用与业务结果在两个版本逐项相同。线上变换只在内存处理原有记录，不保存正文副本，不重放模型、工具或消息。

该合成轮没有执行 Processor 尾部观测或完整后端工具统计，所以 34→18 不包含两张旧统计表清退的额外减少；也不包含重复自省周期快路。后者另用真实 SQLite 写锁验证：已有周期在别的 writer 持锁期间只执行 SELECT，不重新聚合或申请 writer。没有把这些不同范围数字混加成一条生产轮次测量。

## 否决合批

曾试验将原队列已经就绪的记录准备好后同事务提交。真实 SQLite 加独立业务 writer 的三轮实验表明，256条小记录的旁路业务等待从约8–44ms升到109–152ms；16条较大记录也出现等待增加。虽然诊断自己的总提交数和排空时间减少，却扩大业务被占用的时间，因此已删除合批实现及相关状态，保留单项短事务。没有另加批量阈值、定时器或优先级机制。
