# 当前模式 Harness 反馈与恢复修复

源码基线为主线 `f508f649…`；范围见[任务书](../architecture/harness-feedback-and-codemode-compatibility-taskbook-2026-10-06.md)。
本轮不迁移 Code Mode、不重构 MCP、不新增数据库表、配置或反馈状态账本。
本文先记录本地实现与验证；PR、CI、合并、生产 revision 和真实 API 验收以实际交付记录为准。

## 行为变化

- 参数拒绝保留冻结 schema 的安全字段路径、类别和期望；不放宽校验或回显参数。
- 确定未派发与已执行分开，短/长/最小回执及临绑定新输入竞态口径一致；执行次数为零
  不抹掉原已接纳尝试预算。实际发送失败或未知仍保留防重发围栏。
- 终端调用/读取成功与进程失败分别展示；退出码、pending、原 run ID 和局部修改事实
  在 artifact、摘要及原持久回执中保留。成功探测不等于测试目标完成。
- 五协议共享事实，Claude/Gemini 按各自协议表达已知失败。Responses 重复 ID，以及
  Claude/Gemini 混合原生工具的重复 ID，不派发歧义本地调用；原生状态、签名和用量保留。
- 原生请求无最终输出不按无效果空响应自动重发；合法 Claude pause、原本地空响应纠正
  与已确认未执行的 Gemini 两次纠正保持。paired 保存失败明确缺样并停止自动重排，不能
  宣称这次新返回的私有检查点已经持久；原已登记派发和预算继续保护未知效果。
- 纯工具、子任务结果可提供非阻断汇报机会；重复同一子结果不反复提醒，普通闲聊不替代
  任务报告。先失败后送达取独立成功见证，未知发送提示核对原回执。
- SQLite BUSY/LOCKED 依可信错误码分流；异常文本不授权重试。原暂停原因安全说明
  通过已有 failure/通知路径保留，不新增暂停状态或自动重试资格。

## 数据库与回归证据

参数/发送拒绝反馈在原调用内生成，测试捕获额外 SQL 为零。提醒水位并入原 dispatched
journal 提交，没有独立提醒 writer。汇报查询只投影原 Work/内部输入关联下的必要元数据，
保留 owner、来源、generation 与实际送达目标核验，不加载旧结果正文。

每输入至多三次状态见证查询；只有失败/未知首见证需要追加核对。存在性查询取消排序，
实际 SQLite plan 无 TEMP B-TREE，原 Work 索引范围仍可能因晚命中或不存在而检查全部候选，
不能宣称恒定读取。512 个同 Work 的无关大正文 fixture 验证了早/晚见证、VM 指令量及
不向调用端返回正文；没有为了该修复新增索引/迁移。原会话互斥及业务 writer 范围未扩大。

本地验证完成：

- 组合回归 175 项通过，包含新反馈、真实 MockTransport HTTP、Runner/Work、SQLite
  竞争、游标原子保存、未知/部分效果及短/长回执；XML 在私有 `.cache` 保存。
- 数据库准备/历史/来源/诊断/私聊抢占/索引与纯数据库重备相关组 206 项通过。
- 压缩 public delta、引用顺序和协议连续性组 46 项通过；原恢复/暂停原因组 23 项通过。
- 全源码 Linux 目标 Mypy：702 文件通过；全仓 Ruff check/format、release baseline 与
  diff check 通过。Windows 默认 Mypy 的旧 Linux 系统 API 缺失不伪装为通过，使用实际
  Linux 目标核对；CI 仍须独立验证。

不同组与交叉审查有重叠，不累计成唯一用例总数。已有 SQLAlchemy 表排序告警仍存在。
本地 HTTP fixture 不等于真实 API，健康不等于自然 QQ 延迟验收。

超过近期展示窗口的旧失败仍保留原持久回执与首轮压缩来源；引用校验不证明模型总结语义。
本轮未引入全量历史加载、摘要判真模型或强制逐阶段汇报来遮掩模型误判。
