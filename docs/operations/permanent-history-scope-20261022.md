# 永久历史查询与上下文重置分离

基线：`10bcae49`，迁移0147。状态：本地实现、五轮复查和定向验证完成，
已提交 [PR #492](https://github.com/YuanYeYouTao/Yuki/pull/492)；尚未合并或部署。

## 问题与行为

显式历史查询曾把 `/ai new` 的上下文起点当作读取下界，永久账本中的旧记录因此返回零命中。
Binding 查询还继承了只有本人 App/ACP 来源可用的旧门槛；同一入口换用 Conversation ID 却能读取。

现在 `/ai new` 只清理聊天上下文。显式历史查询读取当前获准的完整已入账记录，覆盖各平台：

- recent 默认浏览当前 Conversation；search 默认一次检索全部获准 Conversation。
- Person、Space、Binding 可选择多个原入口，直接合查；around 按内部事件定位原 Conversation。
- 命中保原作者、名字、事件、平台、私聊/群聊、会话名和话题来源；sources 仅列实际返回的来源。
- 复用唯一 FTS、全局整数事件 ID 和 N+1 分页；邻文始终属于各锚点的原 Conversation。
- 插件的历史查询与回复读取也可读重开上下文前的原记录；真实批准和委托仍按原范围执行。

删除显式 query/around 的下界参数、原回执跨下界特例、App/ACP 来源判断、强制挑选单入口、
重复身份预检与 view 冗余必填。自动上下文继续使用自己的窗口；原事件删除、keeper、
隐私、账号转移、人物同人关系和实际投递回执分别认原事实。无需数据库迁移或重新建立索引。

## 五轮复查

| 轮次 | 核对与结果 |
| --- | --- |
| 1 | 全消费者广查，发现 Plugin 历史和回复读取仍传 reset 限制，一并删除；Client、媒体和 Memory 证据读取无此门禁。 |
| 2 | 细查调用者后删除仓库显式查询已无用途的 floor 参数及 anchor 特权，不保兼容分支；去掉重复授权预检。 |
| 3 | 广搜旧参数、错误码、文档和测试；改正 ACP 多入口、Plugin 旧历史及 around 断言，同步开发约束和原任务书。 |
| 4 | 对抗检查人物合并、账号转移、来源覆盖、真实委托和已删除原件；修正受限来源仍应读取自己原回执缺失元数据的回归。 |
| 5 | 独立核 SQL、分页、邻文和来源链；同一只读快照，无新增写事务、深 OFFSET 或全量历史预扫描，未发现新增阻塞项。 |

sources 不覆盖事件原作者的 Person/Account/Presence；来源跟踪包含实际命中、邻文和另行显示的原回执事件，
不包含 N+1 探测行或目录中的未命中会话。读取时隐私代次沿原快照和原发布边界处理。
