## 2026-10-19 普通聊天配图误拒绝补修

前一阶段实现已由 PR #480 合并为 `878226eb`。本次补修以该 main 为基线，分支为 `codex/fix-sticker-admission`。

数字生命研究所的原内部事件 109487、109489 对应调用均有明确 emoji 参数，正文成功、配图返回 `not_accepted / emoji_source_cancelled`，没有接纳意图。普通 Coordinator 使用空 Work ID 保存工具结果，配图来源却将其当成真实任务查询；查无任务被误认为取消。纯配图另有同根错误：空 Work capture 被送进领域回执绑定，事务回滚。两处均沿普通 Social 已有的无任务语义处理，不要求普通聊天登记 Work，不删除真实取消、换代或撤权检查。

检索另修混合语言分词：`Yuki开心大笑` 保留完整 `yuki`，仅中文连续段拆字及相邻双字，删除无人传入的 `reply_text` 参数。此前把完整回复正文加入检索复算不符合实际生产调用，不能据此声称正文污染了现网查询。description、OCR、原生 emoji 与其他语言整词保持可检索；字面命中不等于所有样本的语义正确率。

Linux 隔离验证共 118 项通过：普通 Coordinator/InvocationService 图文与纯配图 2 项，分词、旧缓存重建与原图库编辑/热索引 41 项，既有 Social 配图、取消、重启、未知回执、平台发送和装配 75 项。首组先复现两层失败再转绿；Ruff 检查/格式及 Linux emoji 模块 mypy 通过。Windows 原生 mypy 不具备 Linux `fcntl.flock` 类型属性，本轮以目标 Linux 检查为准，不据此改写持久环境文件锁。
