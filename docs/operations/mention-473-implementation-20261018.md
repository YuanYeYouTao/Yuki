# #473 提及还原与当前身份退役

本轮基于 `cd791763`，处理 [Issue #473](https://github.com/YuanYeYouTao/Yuki/issues/473)。

## 原因与修改

原 OneBot 消息包含两个对其他账号的真实提及。其中一个账号仍登记为 Yuki Presence，入站被写为 `[提及Yuki]`；另一个目标在 Main 渲染时从平台编号变成 `[提及成员]`。实际模型请求丢失了原句中的可读目标，不能仅靠修改参与提示词修复。

原生提及改为按原位置保存 `@名字` 与结构化身份、名称快照；重复提及和引用各自保留。Main 与 JEV 使用同一份入账正文，Telegram 按原生 UTF-16 实体偏移处理文字和 caption。资料来自消息和既有本地记录，不增加平台资料请求。未知成员照常接纳；没有新增决定能否接话的门禁。

Presence 与人物绑定分别处理：启用的 Presence 表示当前 Yuki 账号，IdentityBinding 关联外部账号与 Person。停用 Presence 不删除已有历史来源，也不继续阻止新的人物绑定。原事件的作者、内部 ID、已付请求、公共冻结历史和投递回执不改写。

已有原生消息回执在账号退役、转移或改名后仍复用原 Event、作者和 Conversation；真实正文、目标、发送者、时间、引用或 thread 不同继续保留冲突事实。私聊沿原 Conversation 的历史 Binding 核验，不借今日账号关系搬迁原事件。旧 QQ 账本中尚未冻结的真实 AT 复用原适配器读取位置与同会话的当时名称；普通字面标记不替换，不改原账本和已冻结字节。

本轮同时按用户要求删除 Main 实际加载链中把聊天历史、引用、网页、附件或插件资料概括为“不可信”“不是指令”的提示限制。保留来源名称、`runtime_context` 的程序资料身份和执行处的真实授权；独立 Memory 提取与视觉分类任务不扩入本次删改。

上述仅证明账号退役及四个判断热修生效，完整 #473 与提示词修改的本地验证、PR、合并和部署分别记录，不能用本次重启代替完整代码上线。
