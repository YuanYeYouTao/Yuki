## 1. 改代码前列出的可能失败

### 1.1 UTC 收敛到 `yuki.time.formatting.stored_utc`

`stored_utc(v)` = naive 视为 UTC 并补时区；aware 一律 `astimezone(UTC)`。

- U1 被替换的私有实现语义不同：有的只补时区、不转换（`v if v.tzinfo else v.replace(tzinfo=UTC)`）。对 aware 非 UTC 输入，替换后返回值的偏移从原偏移变成 `+00:00`。比较、相减、`.timestamp()` 只看时刻，不受影响；`isoformat()` 输出和写回 SQLite 的值会变。
- U2 SQLite `DateTime(timezone=True)` 不做时区转换：SQLAlchemy 的 SQLite 方言按墙钟写入、忽略 `tzinfo`，读回为 naive。若把“只补时区”的值换成转换后的值再写库，aware 非 UTC 输入落盘的墙钟会改变。凡结果会写库的“只补时区”写法不替换。
- U3 序列化必须逐字节相同：回执、journal、修订摘要（`memory_revision` 的 sha256）、`occurred_at_token`、插件通知 `canonical_occurred_at` 等把时间渲染成 ISO 字符串参与比较或哈希。只有原实现本来就是“转换到 UTC 再 `isoformat()`”时才能换成 `stored_utc(...).isoformat()` / `utc_iso(...)`，否则 hash 与冲突判定会变。
- U4 无条件 `.replace(tzinfo=UTC)`（不判断是否 naive）对 aware 非 UTC 值是“改标签”而非转换，与 `stored_utc` 时刻不同；不替换。
- U5 语义完全不同的时间函数不属于 UTC 收敛：naive 视为本地时区或 UTC+8（`memory/temporal.py`、`services/history_query.py`、`persistence/event_repository.py`、`time/schedules.py`），naive 直接报错（`time/schedules.py::_as_utc`、`time/service.py`、`admin/authority/tokens.py`、`runtime/work_wait.py`），外部 HTTP 头解析（`web/tavily.py`）。
- U6 pydantic `field_validator` 的签名与 `None` 透传：模型校验器需保持 `None -> None`，`stored_utc` 不接受 `None`。
- U7 `datetime` 相等比较：dataclass 相等（如 `context_assembler` 比较触发事件是否变化）对 aware 值按时刻比较；naive 与 aware 比较会抛 `TypeError`。替换后两侧仍必须同为 aware。
- U8 公开名被外部导入：`memory/self_reflection/control.py::utc` 不是下划线名，删除前需确认无外部导入。

### 1.2 局部 import 提升

- I1 提升后成环：A 顶层导入 B、B 顶层（直接或经包 `__init__`）再导入 A，导致部分初始化模块上取名失败。判断用静态 import 图：只把顶层与 `TYPE_CHECKING` 之外的导入算作边，包 `__init__` 计入父边；逐条加入新边、每次检查目标能否回到本模块，能回到即保留局部 import。
- I2 同名绑定冲突：模块顶层已有同名但来源不同的绑定（函数、类、赋值或别的 import），或同一模块不同函数里同名局部 import 来自不同来源；提升会改写模块全局名。
- I3 函数内同名局部变量或参数：import 提升后该名在函数内若仍被赋值，变成局部变量，读取先于赋值时 `UnboundLocalError`。
- I4 `global` 声明的名字。
- I5 测试 monkeypatch：测试替换 `yuki.x.f` 时，调用方局部 `from yuki.x import f` 每次调用时取到替身；提升后调用方在导入时已绑定原对象，替身失效，测试会失败或静默不再验证。
- I6 刻意懒加载：
  - 平台专属标准库（`fcntl`、`msvcrt`、`resource`、`ctypes`）只在对应平台存在。
  - 可选依赖（`pydantic_monty`）与 `try/except ImportError` 守卫。
  - 包级 `__getattr__` 懒导出（`services/__init__.py`、`memory/self_reflection/__init__.py`、`yuki_plugin_sdk/__init__.py`）。
  - 按配置启用的平台适配器（`container.py` 中 Telegram、飞书分支，任务书 §4.5 要求保持懒加载）。
- I7 部署闭包：沙盒 Manager 在宿主上以只装 `websockets` 的 venv 运行 `yuki.sandbox.*`（`deploy/sandbox/install-manager.sh`、`sync-manager.py`），验证镜像只拷 `yuki/sandbox`、`yuki/workspace`；`emoji/media.py`、`emoji/sticker_index.py`、`sandbox/yuki_computer.py`、`sandbox/desktop_service.py`、`sandbox/environment_supervisor.py` 被单独拷进沙盒镜像。给这些模块加顶层内部 import 会把 pydantic/SQLAlchemy 等拉进只有标准库的环境。
- I8 导入期副作用与入口顺序：`main.py` 在 NoneBot 初始化后才挂载 HTTP 路由；被导入模块若在导入期调用 `nonebot.get_driver()` 会在 CLI 或测试导入时失败。每个模块需在独立进程中能单独 `import`。
- I9 提升后的 import 行落点：插入到模块最后一条顶层 import 之后，由 ruff isort 排序合并；不得落到函数或 `TYPE_CHECKING` 块中，不得产生 E402。
- I10 运行时与类型检查重复：顶层 `TYPE_CHECKING` 块已有同名导入时，提升出的运行时导入与之重复，ruff 或 mypy 可能报重定义。
- I11 与并行分支冲突：工具面切换分支（`refactor/tool-surface-cutover-20261107` 及 `tsc-*`）正在改的文件若同时被本批改动，后续 rebase 冲突；这些文件本批不动。

### 1.3 装配根别名（B6）

- C1 外部读取：`ApplicationContainer` 的属性被 `health.py`、`application/modules/admin_api.py`（`build_admin_api(self)`）、`main.py`、`cli.py`、测试与测试支撑（`app.x`、`env.app.x`、`runtime.x`、`restored.x`）读取；动态 `getattr(container, "name")` 也算。插件只经 SDK，Desktop 只经 HTTP，均不读容器属性。
- C2 方法内读取：别名若在 `__init__` 之外（生命周期注册、清理循环、插件上下文工厂）被读，删除后需改为读所属 bundle（`self.persistence.x`、`self.plugins.x`、`self.media.x`），不能改成 `__init__` 的局部变量。
- C3 赋值时序：`self.settings` 在 `__init__` 中途可能被替换（搜索模式覆写），bundle 字段在构造后不再变；改读 bundle 不改变取到的对象。
- C4 同名非别名属性：`self.x = SomeService(...)` 不是别名；只在 `__init__` 内使用的才改为局部变量。
- C5 并行分支在 `container.py` 只删了一行 `permission_catalog=...` 实参；本批不动该实参。
