# 长任务恢复校验一致性检查

本轮从真实长任务第一段完成、下一段报 `JournalUnavailable` 的样本展开，检查保存、
压缩、续跑、完成通知和父子交付的生成端与读取端。下面描述修复与回放范围；
合并、部署和真实模型持续执行须分别以对应证据确认。

## 已复现的缺口

| 路径 | 原问题 | 修复 |
| --- | --- | --- |
| 压缩锚点恢复 | 保存端追加真实公众 assistant 发言，恢复端要求最后一条为 user | 删除最后角色假设，保留真实顺序、结构与来源检查 |
| 终端结果接入 | 原模型已收到结果，同一完成通知仍 pending，阻止下一工具 | 在原确认点退役精确匹配的重复通知，保留未观察结果及真人输入 |
| 压缩任务指令 | refs 顺序改变被视为新指令，原要求被误判丢失 | 来源按集合比较，保留所有既有 ID 和真实更正边界 |
| 跨合同调用恢复 | 保存合法调用后，读取端另套 32 项、128/1024 字符常数 | 删除与生成端不一致的隐藏上限，继续执行真实配置与存储容量 |
| readonly 回执恢复 | 从右拆分效果键，误把带冒号的 Provider ID 当 Host 前缀 | 只拆 Host 的前两段，保留完整 opaque ID 和原回执核验 |
| 子任务结果交付 | 合法大笔记再次复制到更小的回执，完成后通知失败 | 删除 checkpoint 持久副本，单项结果按原 Work/通知版本读取 |
| 故障定位 | 具体 journal 原因被异常类名覆盖 | 保留有限原因码，未知文本不进入持久诊断，不扩大重试 |

真实暂停样本已只读验证全部所需协议对象可读、hash 一致、来源版本一致且无 pending
工具调用；已安装解码器明确报 `work_compaction_anchor_corrupt / invalid anchor roles`。
第一段使用 24 次模型请求、12 次工具，下一段尚未请求模型便暂停。完整内容与内部身份
仅保存在私有缓存证据中，未写入本文。

## 回放与保留边界

回归覆盖真实 SQLite 的 stage/save/load/restore、合法公众 assistant 尾部、原预算与
accepted 工具回执保持、跨合同长 ID、多调用配对、带冒号的 readonly alias、旧指令 ID
兼容、模型确认与完成转发的两种先后次序、异步结果仍唤醒、大笔记完成及按需查询。

负例保留非法结构、未知角色、工具/opaque 锚点混入、generation 变化、跨 chain/未来
sequence、错 Work/Conversation、真人与 staged 输入、未知执行、假更正及过期子任务
租约的拒绝。文件 hash、媒体存在性、隐私代次、租约、来源 CAS、回执归属及未知副作用
禁重放具有明确正确性责任，本轮没有删除。没有新增表、持久状态或配置开关。

子任务 cache_samples 对外存 manifest 的旧读取遗漏仍属于诊断缺口；本轮没有为了修它
给 SQLite writer 增加文件 hydration。它不构成本次恢复暂停的根因。
