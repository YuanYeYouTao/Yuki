# 回复准备读取与检索延迟修复

本轮处理后台重复配置读取、已冻结历史的正文重读、发送来源查询与网页正文串行提取。实现、回归、真实模型重放、合并与线上私聊验收分别记录，不能由本地通过推断生产延迟已经消失。

## 原因与变化

- RuntimeConfig 的普通快照在一个显式只读事务中解析 owner 与配置。Semantic hydration 与紧接着的本地 binding 共用这一阶段快照；外部 observer 返回后仍重新读取配置。真实 SQLite 的四个空闲 scope 一轮从 176 次 SELECT 降到 88 次，session factory 从 51 次降到 39 次。必要的时间推进、来源校验、效果同步与最新 64 条正文读取仍保留。
- 主上下文以固定内部事件上下界，在同一显式读取快照中校验原会话版本、分页读取 keeper/message 编号，再仅补读未冻结的正文。冻结 ID 只减少重复正文装配，不替代来源证明，不跳过摘要覆盖中的历史空洞。权限、隐私、代次及发布时 CAS 保持原合同；遇到版本变化沿既有重准备入口拒绝旧计划。
- 0095 新增自有 partial index `ix_chat_events_social_source_author(author_person_id,id)`，条件为原来源查询的 `direction='inbound' AND author_kind='person'`。Social 权限和查询语义不变；原事件 ID 的写入围栏不变。30,000 条合成记录上的缺失目标来源查询从约 90,000 条 SQLite VM 指令降至 23 条，不能将这个比例当作生产墙钟加速倍数。
- Gemini 网页检索保持原 Profile、请求预算与 Tavily 全局 semaphore，最多三个正文提取并行，结果按原来源顺序写回。单页失败仍返回 partial；取消和异常均取消并等待子任务结束，不在后台遗留网络请求。

## 验证与边界

实际 SQLite 回归覆盖快照并发更新、WAL writer、隐私/删除/重置、范围高水位和纯排除分页；历史准备比较完整冻结片段、messages、观察来源与 assembled context。完整 77 个工具声明保留，旧 Provider 协议和原动态快照不重建。

索引验证包含真实 ORM 查询、权限场景、形状漂移拒绝、重复迁移及 0094→0095→0094→0095 的业务表不变检查。部署前还须对独立生产副本做迁移与回退排演。

真实模型重放使用独立副本与模拟 QQ 传输；真实私聊验收沿现有 WebUI 自动化控制边界，仅创建一次有持久意图的单条发送任务。二者分别记录，不能把模拟投递、健康状态或缓存命中当作自然聊天回复速度。

本轮修复降低有证据的重复读取和串行等待，仍需区分上游模型时间、磁盘/内存压力、SQL/驱动调度与真实发送确认。阶段差额不是 SQLite 锁等待证据。

## 部署与回退

只替换 Bot，保留当前 Compose 配置、数据挂载、原镜像和完整一致备份。旧冷备 SQLite 如压缩，必须保留原 SHA256、大小、所有权、明确恢复映射与已验证的独立恢复副本；不可修改共享备份 inode 或压缩活库来腾空间。

停 Bot 后备份数据库、协议对象、工具正文、配置与全部工作区，核验引用与原 Work 预算/状态，再执行 0095。回退使用新镜像撤销自有 0095 索引至 0094，再启动原镜像；保留现行数据库与投递回执，禁止用旧数据库覆盖新事实。启动确认不明时先核对真实容器/版本/执行状态，不能盲目重启、重发或恢复数据库。
