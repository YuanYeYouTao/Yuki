## 冻结开发集的词法基线与修复

固定最大 50 条 FTS 候选、最多返回 10 条、关闭向量路径、相同授权范围，
Precision@3 以每问三个位置为固定分母；Recall@10 是每问已标直接支持事实的覆盖率再平均。
无答案候选率只说明检索有返回，**不等于 Agent 最终编造答案**。

| 指标 | 原实现 | 词项覆盖修复后 |
| --- | ---: | ---: |
| 40 个可回答问题平均 Precision@3 | 0.283 | 0.292 |
| 40 个可回答问题平均 Recall@10 | 0.754 | 0.779 |
| 40 个无直接答案问题仍有候选 | 39/40 | 39/40 |
| 80 问中标记非穷尽/截断 | 59/80 | 59/80 |
| 单问中位检索耗时，隔离本机 | 16.79 ms | 16.96 ms |

原实现从句首依次提取最多 12 个 FTS 词项。带人物和场景前缀的长问题可能在走到真正主题之前
就耗尽额度。修复把同一上限均匀分配到整句，保留句尾可检索片段；开发集中一条原本
没有直接证据进入 Top-10 的问题，修复后直接证据进入 Top-2。定向单测验证末尾词项被保留、
FTS 语法仍是安全引号词项；23 个记忆检索定向测试通过。

这只是小幅机制修复。其余漏例涉及词序/同义改述、两个汉字的关键实体不进入三字 FTS、
数字表达不一致及高频姓名造成的宽 OR 候选。将候选预算从 50 提到 100/200 后，
全组 Top-10 指标不变；对 13 个漏例单独试到 500 也没有改善，不能靠加大预算解决。
当前检索仍会把主题相关但不直接作答的事实交给 Agent；没有独立证据支持设置统一
相似度或 Rerank 分数拒绝阈值。
