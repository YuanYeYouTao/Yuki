# 搜索与压缩等待预算调整（2026-10-02）

本次针对搜索和摘要请求容易被过短等待期限或生成预算截断的问题调整策略默认值。
以下为设计与本地修改范围；CI、合并、部署及自然流量验收需分别记录，不能据此宣称已上线。

| 项目 | 原默认值 | 新默认值 / 行为 |
| --- | --- | --- |
| Tavily、网页请求等待 | 20 秒 | `WEB_TIMEOUT_SECONDS=180` |
| Gemini / DeepSeek 搜索桥等待与输出 | 额外 Web 超时及 2048 / 4096 token 上限 | 使用原所选 Profile 的超时及默认输出预算，保留显式输出限额核验 |
| 群史 Rollup 请求与整批等待 | 90 秒 | `CONVERSATION_ROLLUP_MODEL_TIMEOUT_SECONDS=600` |
| 群史、Work 摘要生成预算 | 8192 token | 32768 token，包含思考与最终 JSON |
| 两个摘要输出预算的 WebUI 上限 | 32768 token | 取消额外界面上限，保留 1024 最小值及 Profile 真实限额 |
| 群史摘要正文上限 | 16384 字符 | 仍为 16384 字符，增加生成预算不扩大默认历史摘要尺寸 |

群史 Rollup 的同一个时间配置作用于专用 HTTP 请求、整批候选和前台等待。一个候选包含
多块来源时共用期限；前台多批次也不逐批重置等待。租约依旧用 heartbeat 续期，来源批次、
输入窗口、读写 CAS 和完整覆盖校验保持原合同。失败或不完整输出不提交语义覆盖。

Work compaction 沿用原任务 Profile，不受专用 Rollup 超时配置控制。部署准备应核验原
Profile 的 `timeout_seconds` 与生成预算相容；计划将所用 Profile 请求等待配置为 600 秒，
具体保存与部署结果另记。Gemini 和 DeepSeek 搜索桥沿原所选 Profile 的超时和默认输出
预算，不另以 Web 超时压低；Tavily 和网页读取仍使用 Web 超时。

这是等待及生成策略调整，不扩大模型真实窗口。执行器仍拒绝超过 Profile 输出限额和
输入/联合窗口的完整请求；提高生成预算会减少联合窗口中的可用输入容量。摘要来源合法性、
结构校验、任务指令与回执保留规则保持不变，不从已派发历史链删除快照或工具结果。

本地聊天 96000 / Work 128000 活动窗口仍是政策，并非 Provider 真实上限；本次不调整它们。
所选连接的默认输出仍由原 Profile 声明，不修改主请求的固定工具、system 或 wire 输出设置。
不过当前 Profile revision 包含连接超时，部署改为 600 秒可能按既有合同形成一次显式新链；
原 Work、输入与回执保留。首次跨此边界不能宣称旧完整前缀连续，后续缓存须按新链实际用量观察。
桥结果缓存的 namespace 相应更新，旧低预算结果不作为新预算的首选搜索结果复用；
它与模型前缀缓存分开，不进行无意义模型保温请求。

配置键及类型保持兼容。已有 `.env`、WebUI 热配置、模型 Profile 显式值继续优先，不自动
覆盖旧值；部署必须核验并调整实际生效值。若 Profile 的 `max_output_tokens_limit` 低于
32768，应按真实模型能力调整摘要预算或显式 Profile 限额，不能靠界面无上限绕过执行检查。

本地定向验证：搜索桥实际 MockTransport 请求预算/超时、真实限额前置拒绝、65536 热预算
数据库重载、Rollup 等待/原覆盖、Work 压缩、完整请求计量及普通搜索续接，共 172 项通过。
Ruff 全量检查与格式检查、683 个源文件的 Linux 平台 mypy、`git diff --check` 通过。
这些检查不代表真实 QQ 效果或缓存改善；CI 与上线事实以对应 PR 的交付记录为准。
