# Yuki 运行时内存检查与修复

2026-09-12，在独立工作树检查 `86f406f`，修复分支为
`codex/fix-runtime-memory-retention`。本记录对应本地代码修复，未部署到服务器。

## 线上基线与判断

检查期间未重启 Bot、QQ 网关或其他服务，未清理系统页缓存、关闭 Swap。
只读取进程、容器和系统计数，不导出聊天内容、密钥或进程堆。

- 服务器物理内存约 1612 MiB，可用约 645–650 MiB；Swap 已使用约 1023 MiB。
- Bot 主进程 RSS 从约 167 MiB 到 161 MiB，另有约 167–174 MiB 换出到 Swap。
  RSS 历史峰值约 299 MiB。容器 cgroup 内存峰值约 475 MiB，包含子进程与文件缓存，
  不能与主进程 RSS 混为一谈；容器 OOM/OOM-kill 和重启计数均为零。
- QQ/SnowLuma 容器驻留工作集约 349 MiB，是另一组进程。
- Bot 主进程有 11 个线程，检查时有 10 个 socket 和 22 个数据库相关文件描述符。
  这是一份快照，不能据此证明连接泄漏或无泄漏。

短时间采样没有显示 Bot 内存持续飙升；已有的 Swap 占用也不能单独证明泄漏。
不过，下面的对象滞留和无效任务循环已经通过代码与修复前回归用例确认。

## 已修复的问题

1. **群观察事件长期滞留。** 每群一直保留 100 份消息、资料和发送器；
   发送器继续引用原始 OneBot 事件，而参与判断只使用最后一份。
   现在仅保留待处理的最新观察，任务空闲、关闭时移除状态；聊天历史仍由数据库保存。
   新观察与任务完成回调之间的交接仍受保护。
2. **无效后台任务循环。** 配置关闭主动发言或读取配置失败时，原流程没有消费
   `changed` 标记，完成回调会不断创建同一工作任务。现在在首次等待前消费当前版本，
   只有新观察才会触发后续工作。
3. **MCP 调用结果滞留。** 连接所有者协程等待下一条操作时，其局部变量仍引用
   上一次操作的参数、Future 结果或异常 traceback。现在在处理结束后立即释放该引用，
   保留连接复用、超时与取消行为。这不等同于审计或清空第三方 SDK 的全部内部缓冲。
4. **历史身份与锁无限累积。** 同会话互斥锁和发送边界锁使用弱引用索引，
   持有者与等待者仍强引用同一把锁，全部结束后回收。文字和视觉限流按窗口清扫过期身份，
   群限流拒绝的请求不再创建空用户记录；仍有效的额度不会被回收或重置。

## 验证与复现实验

新增 `test_runtime_memory_lifecycle.py`，16 个场景在旧代码上全部失败；修复后全部通过。
覆盖对象释放、配置关闭/失败、配置读取期间的新消息、完成回调交接、服务关闭、
MCP 成功/异常、等待者取消、锁超时、有效限流保留及拒绝请求。

隔离的 `tracemalloc` 对照使用同一进程中的旧版和修复版群观察器：连续输入 100 条观察，
每个模拟原始事件携带 256 KiB 数据，模型执行替换为空操作，不联网、不发消息。

| 状态 | 旧版额外 Python 内存 | 修复版额外 Python 内存 |
| --- | ---: | ---: |
| 100 条观察提交后 | 26,294,670 B | 265,070 B |
| 工作任务空闲后 | 26,299,175 B | 696 B |

这些数字证明相应引用链已解除，属于可控实验，不是生产 RSS 节省承诺。
Python 分配器、数据库和第三方库可能保留可复用内存；不要用强制 GC、定期重启或
删除历史记录掩盖增长。

相关聊天、MCP、发送边界、canonical conversation 与内存生命周期回归共 99 项通过；
6 个修改模块的 Mypy 与 Ruff 检查通过。未运行全量测试。

## 上线后的比较方法

只替换 Bot，保留 QQ 网关登录和其他服务。记录新镜像、旧镜像、进程启动时间，
同时观察主进程 RSS/Swap、容器 memory.current/memory.peak/memory.events、线程和
文件描述符计数，并与实际消息量、图片和 MCP 任务关联。
以接近的业务负载和运行时长比较，避免把重启释放、Swap 换入换出或页缓存变化算成修复收益。
目前没有修复版长期线上采样，因此尚不能断言生产环境所有内存增长都已解决。
