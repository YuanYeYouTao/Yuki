## 删除边界审查新增项

真实SQLite反例确认：原人物忘记后，事件删除只CASCADE候选证据，父候选正文仍遗留。修复复用原People删除中的真实event谓词，按关联证据清退父候选；任一擦除来源命中即清该候选。保未关联来源、同群其他候选及跨平台同号不同Person，不按旧传输标签猜归属，不新增状态/迁移或全群清理。

原探针的1 passed表示错误行为已复现，不能当作修复通过；修后正式回归覆盖四种历史status、混合来源与QQ/TG同号隔离。已失去任何出处证明的旧孤儿不能凭平台数字反推人物，本轮没有自动重写或清空历史候选表。

第四轮另用真实检查点 codec 与 SQLite 遗忘复现：群 run 的 event_map 仍留已擦事件正文。补修沿同一 People 准备快照关联真实事件、工具、旧 fact/candidate ID 与证据；旧 context 仅按程序首 envelope 的内部事件号读取其原来源，不扫描正文猜身份。短 writer 按准备 run ID 清敏感 JSON，保其他 run 字段、原请求账本、累计 token、已提交 result/fact 与同群无关原件。原 source 行已过期但副本仍有真实 canonical 作者或 trigger_event_id 时，沿原证明清退；缺出处者不猜。

新格式删除不用于恢复的 payload，避免再复制 context。迟到保存由原来源及原 JSON 比对处理；不引入全局隐私代次、恢复开关、原件重写或重新购买模型结果。旧镜像必填旧 checkpoint 字段，回退前须核对未完成已付尾部并保可读当前原件的 reader，不能盲切镜像或覆盖数据库。
