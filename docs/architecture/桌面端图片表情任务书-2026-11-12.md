# 桌面端图片表情任务书

日期：2026-11-12

状态：用户在桌面端反馈「现行表情功能没有做到，没法发图片表情」。本任务书即执行依据，基线为 `main`（d433cba6）。

## 1. 调研结论

| 事实 | 证据 |
| --- | --- |
| 桌面端的表情一次也没发出 | 本机部署 `social_emoji_intents`：`app` 平台 5 次全部以 `emoji_no_candidate` 结束；同期 QQ 519 次、Telegram 7 次成功 |
| 原因是选图只看本平台目录 | `EmojiDeliveryService` 以 `intent.source["platform"]` 调 `EmojiLibrary.select(platform=…)`，只查 `stickers/<platform>/`。本机 `stickers/qq/files` 330 张、`telegram` 4 张、`app` 0 张 |
| 桌面端能显示任何平台收藏的图片 | 桌面客户端以普通图片显示 PNG、JPEG、GIF、WebP；它没有自己的原生贴纸格式，也不会有人在 App 里「收到」原生贴纸来自动收藏 |
| ACP 不显示图片 | ACP 适配把附件交给编辑器作为文件链接，表情在那里不会以图片出现 |
| 客户端读不出「这是表情」 | 事件附件只投影 `media_id/artifact_id/version/filename/name/mime_type/size`；Social 发送时写入的 `is_sticker` 未进入客户端视图，桌面只能当作普通图片附件显示 |

## 2. 方案

- App 连接声明能力 `shared_stickers`：能把任何平台收藏的图片表情作为图片显示。ACP、QQ、Telegram、飞书不声明，继续只用本平台目录与原生格式。
- 配图来源记录路由是否具备该能力；选图时具备者在全部平台目录中检索，只取 `image/*` 资产（排除 TGS、WebM 等），按命中词数取最佳，同分按平台目录名与资产 ID 的稳定顺序。
- 索引检索结果附带命中词数，供跨目录比较；单平台检索与终端用法不变。
- 事件附件为表情时投影 `sticker: true`；普通图片不带该字段。客户端 `Attachment` 增加 `sticker`。
- 不新增图库、不复制资产、不改原生贴纸收藏与发送路径；发布与发送沿原 Social 回执。

## 3. 失败情形（先写，再写代码）

1. App 对话请求配图，`app` 目录为空而 QQ 目录有命中图片，结果仍是 `emoji_no_candidate`，或桌面事件里没有这张图。
2. 跨目录选图选中非图片格式（TGS、WebM）。
3. 多个目录都有命中时，没有取命中词最多的一张。
4. ACP 连接声明了 `shared_stickers`，或 QQ/Telegram 路由用了其他平台目录（原有用例保持）。
5. 桌面读到的表情附件没有 `sticker: true`，或普通图片附件带了它。
