# 会话 Compact

公共历史与当前执行尾部共用 `TurnExecution.compact_current`。压缩由当前 Main 模型执行，沿原 system、固定工具、Provider/Profile、输出与思考设置、会话槽位和实际请求预算派发。自动整理使用独立触发值，模型硬容量决定请求是否可容纳；没有独立摘要 Agent、Rollup 后台链、触发比例或摘要输出预算。

## 触发值与模型容量

普通聊天、已接纳 Work 与子任务共用 `context.compact_trigger_tokens`，默认 `96000`，环境变量为 `CONTEXT_COMPACT_TRIGGER_TOKENS`。Main 对完整请求的本地估值达到整理触发条件时尝试 compact；估值包含固定工具声明、媒体、工具结果和私有协议，不是 Provider 返回的精确 token 数。真实 usage 仍按原模型请求保存，不把历史用量改写成本地估值。

触发值不是可执行输入上限，也不是压缩后的目标大小。未产生有效检查点、没有合法可整理前缀，或整理后仍高于触发值时，只要请求可容纳，就继续正常工作，不为降到触发值以下反复购买摘要。实际输入超过已知硬容量时，仍须整理到可容纳，不能用软触发的继续规则绕过容量失败。

硬容量只取当前 Profile 的 `max_input_tokens` 与 `context_window_tokens`；后者扣除本次输出额度后形成输入预算，两者都设置时取较小值。`None` 表示该项未知；两项均未声明时不制造默认容量，也不将未知承诺为上游无限。旧 Host 聊天/Work 双窗口退役，不用 `262144` 或整理触发值兜底。compact 请求自身同样服从已知模型容量。

## 原件与两种覆盖范围

永久事件账本保留真实聊天、语音转写和内部事件引用。公共窗口冻结实际采用的事件呈现，检查点保存在现有 `prompt_projections.selected_summary_*`；检查点后的获准原文连续读取。当前触发、本轮 short_state/插件资料、Work 私有协议和工具结果不发布为公共历史。

- **公共段 P**：请求取当前 Main 的静态 system/工具与公共历史前缀，在公共边界追加 compact 指令。可沿真实容量选取较早的完整事件切点，产物只覆盖该前缀。新公共窗口是同一静态前缀、检查点、未覆盖原文，再接本轮私有材料与原执行尾部。
- **执行尾 E**：取原 Main 已配对的实际协议前缀，追加 compact 指令。新链保留原初始公共/运行/任务材料、私有执行检查点，以及切点后的原文和尚未观察的真实回执。工具调用与结果不拆开，opaque continuation 不转换成文本摘要输入。最近一次私有检查点保存到原 Work 的 `task_material.execution_checkpoint`，恢复时仍归该 Work。

公共检查点标明内部事件覆盖点，摘要内容作为不可信资料呈现。私有结果保留目标、纠正、限制、已确认发现、失败与未知状态、资料句柄和下一步；文本陈述不裁决工具效果或任务完成。

## 派发、发布与恢复

compact 使用原 `_PrimaryDispatch`、模型并发槽位、来源核验和请求计量。已接纳 Work 沿原 journal 保存 `dispatched → response → paired`；原协议与付费内容仍作为不可变对象保存，新链关联原件。没有业务 Work 的普通轮使用现有私有 observation 存储，按内部 execution ID、Conversation、generation 与 actor 写入不可变的三阶段回执。这些付费证据不被自动选为公共历史或 Memory。

完成响应先持久化，再准备和发布结果。P 沿现有 projection CAS 核验 generation、来源 revision 与原 epoch；E 沿 Work journal 核验原租约和来源。发布事务同时核验隐私代次，外部请求、文件准备和历史扫描不占 SQLite writer。

新消息追加保留在账本及后续原文中，不另造暂停状态。发布失败后的冷恢复复用已存 response，不重新购买模型请求。只有 dispatched、没有持久响应的情况仍是未知已付，不盲目重发。删除、隐私清退、代际变化或真实来源变化使旧产物失效。

已确认没有有效检查点的结果也保留原配对回执。自动整理再次得到相同候选时，比较实际输入内容、工具、设置和私有协议，复用该候选的已知失败，不因冷恢复更换 chain 或诊断字段而重购。比较不以 shape hash 代替原件；新内容或设置形成不同候选时仍可整理，不把一次失败变成永久停用。原请求仍超出已知硬容量时保留容量失败，不以重购同一候选替代真实容量处理。

适配器确认空响应或畸形本地工具调用且请求没有原生工具时，保存失败类别，不伪造成功响应、usage 或 Provider continuation。取消、没有持久响应的未知派发及可能涉及原生效果的失败继续沿原异常和恢复路径；已发生请求仍计入原预算。

冷恢复使用当前公共历史与本轮运行资料，并保留原任务自己的检查点和执行尾；不把旧请求中的运行资料带回当前激活。隐私清退删除普通 compact 回执的正文、actor 和读取范围，只保留所属内部执行已经派发且失效的最小事实；该事实拒绝旧来源重发，不提供已删除内容。

响应为空、未完成或包含工具调用时，不执行该工具调用。原请求仍可容纳则继续原轮；已知硬容量不足则返回容量失败。取消、来源与授权失效、已付或未知派发继续按原回执处理，不因软触发抹去。compact 不充值预算、不补发消息，也不要求额外汇报或全部子任务成功。

整理只在合法边界建立新链，不改写旧付费请求或冻结的 system/工具声明。公共检查点替换所覆盖原文，检查点后的原文继续追加；更频繁整理会改变该边界之后的缓存前缀，不承诺提高缓存命中率或降低成本，须另查上游真实 usage。

## 手动命令

`/ai compact [重点]` 进入同一 Main 入口，只压缩当前会话的公共段 P。私聊由本人使用，群聊沿 `/ai new` 的超级管理员授权。重点只影响本次整理指令；命令回复报告结果，不发送摘要正文，也不写长期记忆。

命令复用会话的既有串行槽位。有 Work 在执行时保留它的原控制和私有状态，手动 compact 不成为新的 Work 中断或压缩通道。`/ai status` 显示公共检查点覆盖点与公共窗口更新时间；后者不是最近一次 compact 的精确发生时间。

旧 journal 中的 staging/anchor 不再是运行门槛；已整理的私有任务材料仍从原 Work 读取。上线前使用生产库副本盘点旧 Rollup 来源指纹依赖，收拢单写者后整体升级，不部署半套读写链。原件、来源、隐私和已发生效果的核验不因退休派生状态而取消。
