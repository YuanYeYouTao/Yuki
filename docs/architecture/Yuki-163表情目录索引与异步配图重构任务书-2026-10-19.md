## 1. 已确定的边界

1. 表情是沙盒中的普通持久文件。按平台分 `stickers/<platform>/files/` 和 `index/`，不按账号、Person、群拆库；以后新增平台不用修改 QQ/TG 白名单。
2. 原图片和每资产 JSON 是唯一图库资料源。标签、description、OCR、资产目录和搜索索引全部退出 Yuki 主业务库。Qwen 后台和 Main 操作同一份文件，不存在两套权限或批准流程。
3. Main 用现有终端增删改、移动、复制、整理、改标签、更新索引。终端 helper 可在沙盒自行执行，不依赖 Bot 数据库、Host operator、Manager 凭据或新增模型工具。普通文件操作不强制经过 helper。
4. Qwen 沿现有明确配置的视觉能力，在首次保存后后台补一次描述和短 tag。Main 无需为打标签再跑一轮；Main 已经理解图片时也能自行编辑文件。未配置、失败或退出不阻止收藏，不隐式重试付费请求。
5. `send_message.emoji` 表达可选配图意图。文字先完成原投递并返回，后台选图、发布快照、沿同一 Social 出口发图；Main 不等选图、重建、Qwen 或图片网络投递，不为等图新增轮次。
6. 显式看图、保存附件、发布文件和已经指定的图片／文件继续原工具语义，不统统变成后台配图。
7. 允许清空旧表情库和升级数据库；清退只针对旧库，不删除原聊天、私有协议、历史 paid、artifact、执行与发送回执。

## 2. 文件资料与独立索引

```text
/workspace/stickers/
  <platform>/
    files/<sha256>.<真实扩展名>
    index/<asset-id>.json       ← 图片资料唯一源，可由 Main/Qwen 编辑
    search.sqlite3             ← 可删除重建的本地检索缓存
```

资产 ID 沿平台与实际内容 hash 保持稳定；同平台相同字节去重，跨平台分别编目。JSON 保存平台、真实路径／hash／格式、可得尺寸与动画事实、`is_sticker`、短 tags、长 description 和 OCR；不拼入原私聊、人物身份、账号凭据或权限。路径／格式等事实从真实文件取得，不能由缓存把文件“修复”为旧版本。

自动收藏进入原接收平台目录。显式保存或终端复制到另一平台是主动编目，文件目的路径照实执行，不能静默改写。非图库目录照常保存；不符合编目布局不成为普通保存失败。同平台改名／移动按相同内容ID保留当前JSON资料；重复文件优先保仍存在的canonical路径，缺失才选另一真实路径，不按遍历顺序反复换路径。移动到另一平台按该平台重新编目，不迁移或改写原事件、旧快照及已选定的发送事实。删除JSON后不从旧cache复活已经删除的标签。

`search.sqlite3` 仅加速索引，位于对应沙盒目录，不能重新成为资料权威。按 `(platform, term, asset_id)` 或等价的真实倒排查询命中项，再按内部资产 ID 点查。核实际 SQL 计划和规模样本，不能枚举平台全部资产后才过滤，也不在正常选图中全目录扫描／解码。

### 2.1 标签编辑与索引同步

- Qwen 保存原子 JSON 后调用共享增量更新函数；Main 编辑单个 JSON 后可在原终端执行同一个 helper 的 update，批量复制／移动／删除后执行 rebuild。
- helper 与 Manager 复用同一实现；不让 Main 等管理员代操作，不新增图库工具、命令审批、凭据或权限。
- 不使用 watcher／持续扫描的本版，**任意外部编辑后，新标签进入搜索的时点是 update/rebuild 完成**。不能用父目录 mtime 冒充对子文件内容变化的检测，也不能宣称自由编辑后索引天然立即同步。
- 命中的少量候选重新读取当前 JSON 和真实内容版本。删除、移动、改字节或标签已不匹配时，更新／剔除派生项后继续查询；不拿缓存里的旧标签冒充当前资料，不固定只处理首 20 个失效项。
- 新 tag 尚未 update/rebuild 时可能暂时搜不到；文件仍可显式查看、发布和发送。该边界在现行说明与 helper 使用说明里明确，不叠加自动化系统掩盖。

### 2.2 冷启动、重建和并发

索引缺失／损坏与真正无候选分开处理。启动可后台进行本地重建；配图消费者遇到缺索引可等待该平台的实际后台构建结果，不能把尚未建好直接记录为 `emoji_no_candidate`。等待不进入文字发送或工具返回。构建失败如实记配图失败，不盲目重试模型，也不要求固定次数／时间门槛。

重建读取真实文件，在原cache文件中分批增量构建，保留已可查询内容，不先清空再慢慢填；不采用未协调的影子SQLite换名覆盖，避免丢已完成update及旧inode/WAL连接继续写入。扫描、hash、解码和建库不占住 Manager 全局文件锁或长 writer，不阻塞其他平台、发布、checkout 或普通终端。同平台的增量更新与重建提交通过同一helper做本地索引写串行化；仅协调派生cache，不锁住用户编辑。扫描／解码／hash在协调段外完成，提交一批前在SQLite writer外读取当前小型JSON，不能用扫描初期的旧资料盖掉已经完成的update。索引缓存删除／损坏按实际文件结果处理；已选定图恢复与显式发送完全不依赖搜索缓存。

Main 与 Qwen 的文件修改遵循普通 Linux 最后写入语义，JSON 使用原子替换避免半份正文。不新增编辑 epoch、文件审批、强制 CAS 或写入代理；后台不得用旧 DB／旧缓存值覆盖文件。rebuild 不覆盖已有标签、描述和 OCR，只为无资料的裸文件建立最小真实资料。并发外部修改后的搜索新鲜度沿最后一次实际 update/rebuild 判断，不承诺整目录原子快照。

## 3. 原件、收藏与识别

本次入账附件的 Main、临时缓存和永久收藏共用 `PreparedAttachment` 的真实原件。内容可能在内存，也可能在共享临时路径；永久收藏复制原件，不移动、提前关闭或重复下载，不等待临时缓存发表或视觉识别。缓存满／跳过发表不阻止已经取得的表情被收藏。

原事件、附件索引和 segments 版本的核验在文件提升前完成，核验通过即本次共享复制接纳；现有 snapshot/checkout 的原 request 和回执负责真实文件效果。接纳前已经遗忘／换源不能继续提升；接纳后的共享复制不因普通 Work 完成或随后遗忘而反向删除。不为此新增 `sticker_sources`、空 writer 或“已接纳待复制”状态表。未知原执行的终端放图照常编目，不补造人物、事件或授权。

原私人附件读取继续认原内部事件、Conversation、generation、期限和原接收 Presence；相同 hash 不开放另一条私人消息。共享库不另外保存私人来源副本，Person 遗忘沿已有聊天／媒体清退，不扫描或清空共享图库。

Qwen 只给图片本身补描述、OCR 和短 tags，不做“是否可以采用”裁决。重复收藏不重复调用；重启／rebuild 只用本地资料，不因标签缺失重新付费。标签为空仍能保存、按路径查看和显式发图。静态预览仅描述可见画面，不推断未展示动画。

### 3.1 QQ、TG 与其他平台

QQ 原生表情标记在规范化时保留。小表情发送实际到 OneBot `image.data.sub_type=1`；普通图片不附该字段，普通文件仍走文件接口。只有编号的 QQ face 保留名称／编号语义，不伪造原件或另抓一套图片。

TG 静态 WEBP、动画 TGS、视频 WEBM 保存原格式，发送走实际 `sendSticker`。普通 GIF 配图可用 `sendAnimation`，明确上传的 GIF 文件仍用 `sendDocument`。不把跨平台不兼容格式暗换成预览图或虚报成功。

普通入站文件／图片准备不调用独立视觉 LLM。WebM 必须贯通当前消息、共享缓存、历史附件和工作区的实际 ffprobe/ffmpeg 采帧。TGS 原件不能交 Pillow 或普通文档 reader；Main 使用平台实际提供的静态缩略图，并明确标为预览。缺预览时保原生 emoji／格式信息和原件，不假称看过像素。预览沿同一个原附件、来源版本与期限，不造第二事件或第二套授权。

## 4. 文字先发与后台配图

```text
send_message(text, emoji)
  ├─ 原 Social 正文效果 → 原正文回执返回
  └─ 持久接纳配图输入 → 该意图独立后台执行
       → 原目标平台倒排候选 → 当前文件核验
       → 选定内容与短 tags 冻结 → 原 publish 不可变快照
       → 稳定派生 Social 调用 → 原发送回执
```

前台只保接纳需要的原来源／路由事实，不 await 图库、Manager 文件操作、索引、caption 或选图。正文真实回执成立后，完成短事务接纳／查询确认配图，再返回工具结果；持久接纳本身不能丢进fire-and-forget。文字与配图分别报告真实结果；接纳不等于图已发，纯配图也不假造正文成功。图失败不撤销确认正文。

### 4.1 发送必须补齐的缺口

1. **发布内容核验合并到原 snapshot。** 把 expected hash 传入原快照复制，在得到实际 digest 后、首次持久化前核对；删 Manager 先完整 fingerprint 再另复制的重复工作。回执 version 取实际快照 hash。文件在中途改成 B 就不能作为 A 发布，不靠终端锁或额外门禁。
2. **接纳确认丢失也唤醒原 owner。** admit 已提交但 ACK 异常时，仍通知原消费者查询原稳定键；原调用重放发现 pending 也可唤醒。只能查原事实，不能重跑正文、模型或未知网络效果。
3. **删全局图片队头等待。** 一个领域生命周期 owner 管理每个已接纳意图的独立任务；内存 active IDs 只记录本进程正在执行，不承担持久防重。选图／publish／平台发送慢不拖住其他意图，真实防重继续交原 Social CAS，不另造 worker 框架、完成表、经验配额。
4. **恢复先读原派生回执。** 已成功、失败或未知的已派发发送按原事实收拢，不重新依赖图库／索引／Manager；尚未派发才继续原图片准备。未知不等于失败，不重新选一张补发。历史正文已经完成、没有原持久配图承诺的重放，不从旧emoji参数补造新的配图。
5. **只冻结执行所需资料。** 已选版本只保存 asset/platform/hash、实际发布需要的格式／路径及发送短 tags，不把 description/OCR／整库副本存回主业务库。它是原执行证据，不是可编辑图库资料源。已发送的 tags 属原事件事实，后续改 JSON 不回写历史。

### 4.2 目标、生命周期与事实

选库认原实际接收目标的平台，不认发言者平台。配图保原 Binding、Presence 和平台，claim 复核后继续原适配器；同一 Person 的另一个账号、同 Presence 下另一 SpaceBinding 都不能悄悄替代原目标。账号变化不反造原作者。

普通 Main/Work 完成不吞已接纳图。root Work 后续失败本身也不是撤销；真实 scope／子树 cancel epoch、显式取消、generation 变化和授权撤销按原 claim 边界处理。后台不持已经结束的 ToolRuntime、Work lease 或 effect capture，不重置预算。

配图输入只保恢复所需最小事实，sent/failed/uncertain 只认原 Social receipt，不复制第二发送完成台账，不复用强制活动 Work 租约的旧 delivery intents 或插件通知 outbox。已开始的正文分段计划和 hash 不再被追加／改写。目录内容改删不影响已有不可变 artifact。

短 tags 是公共表情说明，长描述和 OCR 不进入普通公共历史／自动摘要。固定工具合同与 prompt 前缀不随图库变化，不把全部 JSON 注入每次请求。倒排词项命中只证明字面检索，不冒称模型语义理解或准确率；质量用真实误选样本复核，不加随意权重、阈值和随机兜底。
