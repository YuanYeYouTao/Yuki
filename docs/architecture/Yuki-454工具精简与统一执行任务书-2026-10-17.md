# #454 工具精简与统一执行任务书

日期：2026-10-17（UTC+8）。跟踪：[#454](https://github.com/YuanYeYouTao/Yuki/issues/454)。核查基线：main `274af3f090b485b80e6bafd4815695df53a3f59e`。**本轮只整理方案，未修改工具实现、配置或线上服务。** 下文新名称和数量均为建议合同，不是已部署清单。

本书统一承接原[工具与 Memoh 报告](Yuki-工具设计与Memoh参考报告-2026-10-16.md) §5 的候选及 §5.1 的 W01–W06。原报告保留研究基线；后续设计与实施状态集中在本书，不维护两套任务清单。共同规则仍以[开发约束](development-contract.md)、[Tool Kernel](tool-kernel.md)和[持久环境](../operations/persistent-environment.zh-CN.md)为准。

## 1. 目标与模式

尽量减少模型必须选择的入口、重复参数与重复说明；合并后删掉旧的新调用路径、重复装配和无用配置。**禁止防御性编程优先：能删、能放宽的直接处理，不把精简工具做成鉴权重构。** 不加协调器、能力注册器、经验门槛或兼容开关。保留真实能力，不把工具改成一个 `execute(method, args)` 后宣称已经精简。

**本次首先优化默认 direct，不能靠要求用户开启 Code Mode 来减少默认工具。** 两种模式的区别必须始终写清：

| 层次 | 默认 direct | 可选 Code Mode |
| --- | --- | --- |
| 完整执行合同 | 全部内置能力和批准插件，部署时冻结 | 同一领域能力，另外含代码编排及目录入口 |
| 模型直接调用 | 完整声明 | 固定直调集合；其余能力通过脚本 API |
| `execute_code`、`lookup_tools` | 不声明，不加载 Monty | 声明；查询只读固定合同，不追加工具 |
| Python/Bash 进程 | `terminal_exec` 在持久 Linux 环境执行 | 仍调用同一终端执行器 |
| 工具组合程序 | 普通直接调用 | `execute_code` 在 Monty 中组合调用；没有环境文件系统、网络或宿主 Python 包 |

`execute_code` 的 VM、snapshot 和子调用回执不是终端进程；不能与 `terminal_exec` 合成一个执行器。`run_python` 已不接收新提交，不再安排一次“删除新 Python 工具”的重复任务。沙箱是终端的现有隔离边界，不另建一个 sandbox 工具组或第二套任务表。

本次核查沿 `MainAgentContract.definitions/model_definitions`、`DIRECT_TOOL_NAMES` 和完整 ApplicationContainer 离线装配。插件关闭、自动化开启、假模型配置；没有启动生命周期、访问模型或发送消息。紧凑 JSON 仅含 `name/description/parameters`，UTF-8 字节不是 Provider token。

| 模式／入口 | 当前完整执行项 | 当前模型直调项 | 当前模型声明字节 | 建议完整执行项 | 建议模型直调项 |
| --- | ---: | ---: | ---: | ---: | ---: |
| direct／平台 | 54 | 54 | 45,237 | 33 | 33 |
| direct／App | 55 | 55 | 45,891 | 34 | 34 |
| Code／平台 | 56 | 41 | 35,058 | 35 | 29 |
| Code／App | 57 | 42 | 35,712 | 36 | 30 |

当前 Code 的 ScriptApi 为 54/55 项；15 项仅经脚本调用：11 个 `automation_*`、`recall_own_message`、`save_conversation_attachment_to_workspace`、`environment_packages`、`environment_service`。建议 ScriptApi 为 33/34 项，其中上述自动化收拢后只剩 6 项仅经脚本调用。App 始终另保留 `read_personal_entry`。批准插件增量另计，合同版本 `20` 不代表工具数量。

33/34 是下文逐项可复算的设计结果，不是完成门槛。新 schema 必须实际比较参数、字节和典型调用步骤；不能只减少名称，却让模型反复猜 action、丢参数或多走几轮。实现若发现具体能力无法以该方案保留，应修订映射及证据，不增加通用分派框架硬凑数量。

本轮另做了**非终端部分**的闭合 schema 原型：平台 54→36 项，声明 45,237→40,714 字节，减少约 10%；其中 fact/evidence 合并反而增加 45 字节。原型尚未包含终端三项，也不是最后 33 项的参数方案；只通过 JSON Schema Draft202012 语法核验，未验证 Provider wire、模型选择或真实费用/cache。减少 21 个名称不代表 token、成本或延迟也减少相同比例。

## 2. 终端统一到三项

保留 `terminal_exec`、`terminal_read`、`terminal_control`。现有终端、APT 和旧 Python 结果本来就归同一个 Manager job；收拢接口不改变原 run/request 身份。

| 现有入口 | 建议入口 | 具体改动 |
| --- | --- | --- |
| `terminal_exec` | 原名保留 | 继续提交 command/cwd/tty/timeout，返回原 run ID；pending 不重提命令 |
| `terminal_read`、`get_code_run` | `terminal_read` | 合并有限等待与字节游标；返回进程状态、退出码、next_cursor、丢失标记和终态原 completion/artifact。APT、旧 Python job 也可按原 ID 读，不能强制 terminal 类型 |
| `terminal_write`、`terminal_control`、`cancel_code_run` | `terminal_control` | 有限 action 为 `input/interrupt/cancel/close`；input 保原样文本及显式换行，cancel 沿原 Manager control，不新开命令 |
| `environment_status` | 保留 | 环境、容量、任务与服务状态 |
| `environment_packages` | 保留 | APT 的容器内 root、串行安装、repair、版本和 checkpoint 不能由普通 UID 的 shell 冒充 |
| `environment_service` | 保留 | 持久服务登记、启停、恢复和日志不能由一次后台命令冒充 |

这组 **9→6**，其中实际终端入口 **6→3**。同一个 `terminal_read` 同时提供增量日志与原终态结果，不能拿 stdout 替代 completion，也不能把空输出当完成。原最多 4.5 秒有限等待是旧能力；合并时保取消观察与取消进程的区别，不新增等待阈值或固定轮询次数。

暂不压成 `exec+session` 两项。当前 `MainAgentBackend.parallel_safe(name)` 与 CoreProvider 按工具静态风险分类；把 read、stdin 和 cancel 放同一个 session 工具，会把真正修改误标为只读，或把只读查询当修改。`_effective_descriptor` 的 target 挂钩目前没有实际 binding 实现，不是可直接复用的 action 分类通路。为少一个名称新增贯穿 Runner、CodeHost 和回执的分类机制，没有必要。三项方案直接保留现有读写边界。

机器调用者一并迁移：`SubagentExecution` 的取消、Work owned-run 查询、completion outbox、结果规范化和 Code 投影都不能只改模型名字。旧已提交调用只读原 call/effect/result；不注册一份仍接受新执行的旧工具别名，不重写旧参数 hash 或原运行 ID。

## 3. 其他领域的合并映射

### 3.1 工作区：10→5

终端与文件工具已经使用同一份 `/workspace`。本次收拢结构化接口，不把它们全部丢进 shell；文件版本、字节游标、原生图片与不可变交付仍要有明确入口。

| 现有入口 | 建议入口 | 有限操作与保留语义 |
| --- | --- | --- |
| `workspace_list`、`workspace_search` | `workspace_query` | `list/search`；保工作目录与已发布 artifact 快照目录的明确选择、分页、文本匹配及截断事实，空查询不扫描全量文件正文 |
| `workspace_read`、`workspace_inspect` | `workspace_read` | `text/media` 读取视图；path/artifact、版本和字节页完整保留，media 交原生像素或视频帧，不偷偷调用视觉摘要模型 |
| `workspace_write`、`workspace_patch` | `workspace_edit` | `write/replace`；新建与更新、expected_version、唯一匹配和冲突回执保持原义 |
| `workspace_mkdir`、`workspace_move`、`workspace_delete` | `workspace_manage` | `mkdir/move/delete`；保各自实际路径、目标、版本及空目录语义；旧 artifact 删除仍按原 artifact/revision，不误删工作文件 |
| `workspace_publish` | 原名保留 | 发布不可变快照，修改原文件不改变已发送版本；终端写文件不自动发布 |

query/read 全为读取，edit/manage/publish 全为修改；不为这些合并引入通用 action 风险路由。每个 action 使用明确字段和现有领域方法，不能用任意 JSON 或 shell 字符串包住旧工具。

现有 `workspace_list({})` 列举 artifact 快照，不是 `/workspace` 根目录；合并时保留明确视图和原调用恢复。原快照列举、读取、删除仅依赖 Bot 本地 store，Manager 不可用时继续工作；path 操作按真实环境状态返回，不能新增环境在线总闸。

`inspect_conversation_attachment`、`save_conversation_attachment_to_workspace`、`read_tool_artifact` 保留：它们分别读取原会话附件、显式提升为全局文件、读取原执行私有产物。三者来源授权不同，不能因最后都能取得文件而默认互通。

### 3.2 自动化：11→2

| 建议入口 | 接收的现有能力 | 范围 |
| --- | --- | --- |
| `automation_query` | `automation_list/list_history/get/history/diagnose` | 只读的目录、详情、终态历史、某任务执行记录、当前主体创建结果；按明确 view 走原读取 |
| `automation_manage` | `automation_create/update/pause/resume/cancel/run_now` | 创建／更新完整 TaskSpec、暂停、恢复、取消、立即调度；按明确 action 走原写入 |

TaskSpec 仍可能出现在 query 的等价检索和 manage 的创建／更新中，但同一工具内不反复展开多份相同 schema。`match_task` 是现有可选精确查询，**没有强制“先查重才能创建”的门槛**；不能误称多余限制直接删除。稳定 creation_key、payload hash、版本、创建者、Person/SELF、目标 Conversation、触发 Work 和执行回执保留。

全局目录原本只给安全摘要，当前主体终态历史和创建失败审计另有范围。合并名称不把它们扩成全局详细原文。`automation_diagnose` 是真实只读，但当前静态 READ 集遗漏它；收拢 query 时按实际读取纠正，不增权限或新审批。立即调度只确认接纳，不伪造执行成功。

### 3.3 聊天、Memory 与子任务

| 现有入口 | 建议入口 | 具体边界 |
| --- | --- | --- |
| `get_recent_chat_history/search_chat_history/get_chat_history_around` | `query_chat_history` | `recent/search/around`，默认原当前 Conversation；around 必须内部 event ID，保来源和上下文位置。#448 的检索增强接同一读取实现，不再起第二份账本 |
| `read_conversation_history` | 保留 | 显式跨 Conversation 的读取与来源授权仍与当前账本查询分开 |
| App `read_personal_entry` | 保留 | 本人其他私聊入口只读，保 Binding/Conversation/平台来源；不把历史指令当今日授权，不默认拼接共同上下文 |
| `get_memory_fact/get_memory_evidence` | `read_memory` | `fact/evidence` 视图保原内部 ID 和可见范围；不能把读取 evidence 误记成 fact 已观察，或放宽本人证据到群可见 |
| `search_memory/memory_change/update_short_state` | 各自保留 | 搜索、持久事实修改、当轮短状态不是同一数据源，不再造一个混合 memory 管理器 |
| `subagent_control/subagent_message` | `subagent_control` | 增加明确 message 操作，保原 child ID、省略 child 时联系父节点、ask/reply_to 以及运行中补充与 resume 的区别 |
| `subagent_start/task_control` | 各自保留 | 创建执行者与原 Work 生命周期分别处理，不新建通用 task 系统 |

子任务工具属于 Runtime 的特殊 host control，不能按普通业务 MUTATE 工具重新注册。合并仍走原控制顺序、特殊预算规则及父子授权；原消息已接纳、等待父回答和 Work 收尾尾部的行为不改。Memory 合并还要同步 `_OBSERVED_MEMORY_READS`、`capture_memory_tool_result` 等按旧名称识别的消费者，按实际 view 保留观察事实。

继续保留：`find_contacts/get_group_members/send_message/recall_own_message`、`get_my_capabilities`、`time_get_current`、`web_search/read_webpage`。它们的真实目标与效果不同，本轮没有证据要求再加一个泛化接口。`send_message` 仍是统一对外发送出口；不以终端、外部 Agent 或组合程序绕开它。

## 5. 共用实现与删除范围

- **不增加业务门槛。** 不要求 direct 工具先接纳 Work，不因本次合并添加先列目录、先评分、先汇报、先查重或“同一调用失败全部不能继续”的条件。现有真实来源、授权、撤销与回执按事实处理。
- **领域内合并。** 用有限 action/view 和明确参数复用现有领域服务。query/read 保静态 READ，修改保原修改协调；子任务保原 host control。不得为减少名称建设通用 action 分类器、动态注册、工具别名目录或新的任务状态机。
- **删掉重复工具名限制，不新增 action 鉴权。** `AGENT_RUN` 现已批准整组环境/工作区能力，`agent.run(allowed_capabilities=...)` 只是调用者再缩一层工具名。删除这类可选再缩名单、`source.allowed_tools` 新写入及其工具名存活检查；同一已授权工作区的 text/media 等操作不维护旧细分白名单。旧 source/hash 保原件，读旧回执和恢复不因工具改名被 `capabilities_changed` 卡住。不做旧名→action/view 权限映射、兼容授权层、权限表或新审批。
- **真实权限沿原入口执行。** 保现有 Person/Conversation/来源、插件实际批准与撤销、Memory 可见 scope、历史来源和真实运维权限；不因声明里包含某项运维能力而整体拒绝普通调用。Web 的 `WEB_SEARCH/WEB_READ` 批准目前部分通过工具名单承载，删名单时直接复用现有插件领域批准核验，不能一并删掉这两个真实权限。当前不启用工具的 PluginSession 不需要为本次合并增设任何适配或鉴权。
- **读取与缓存分开。** READ 只表示效果分类，不授予缓存资格。终端进度和工作区实时读取保持现有 `result_cacheable=False`；新 call 读取当前事实，原 call 恢复只用原回执，不增加新缓存或 epoch。
- **两种模式共用一个执行后端。** 同步普通聊天、主动触发、自动化、插件主调用、持久子 Agent、App/平台、direct/Code。Code 的 ScriptApi 仍由冻结声明确定性投影，目录只查询。不同模式可见性按 §1 明确保持，不借查询热加载 schema。
- **旧事实只读恢复。** 逐一迁移真实机器调用者和按旧名分支的授权、预算、归一化、owned-run、Memory 观察和控制处理。删除旧模型入口与新执行别名；已付请求、旧工具配对、原 call/effect、completion、artifact、预算和 unknown 原件保留。读取不到原件就保缺失事实，不重新运行或补造正文。
- **冻结前缀不改写。** 声明名称、说明、schema、顺序和模式投影在部署时一次冻结，形成新 revision；在途 paid request、公共历史和 opaque 私有状态保原件。旧 Code snapshot 是否可恢复沿真实 API/revision 判断，不伪造兼容或从头重跑剩余程序。
- **同步删冗余。** 核注册、分派、SDK/机器调用、Code 可见表、结果解释、提示、配置、文档及测试；不只套新函数后把旧分支继续留给新调用。测试不得为了维持旧工具数量、旧名称、重复预查或经验条件阻止删改。
- **说明只写必要信息。** 每项说明保目的、不同参数的语义与真实回执解释，共同约束只在权威位置说明，不复制整段操作教程。工具声明字节、Provider token、真实 cache/费用分别记录；不能从 schema 减小推算命中率提升。
