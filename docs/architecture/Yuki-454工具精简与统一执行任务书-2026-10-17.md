## 1. 目标与模式

尽量减少模型必须选择的入口、重复参数与重复说明；能用终端完成的普通文件操作直接交给终端，不再包一组 workspace facade。**禁止防御性编程优先：能删、能放宽的直接处理，不把精简工具做成鉴权重构。** 不加命令白名单、二次审批、协调器、能力注册器、经验门槛或兼容开关。终端应能完整操作 Yuki 自己的持久 Linux 环境；媒体交给模型、文件交付和原回执仍接现有业务链。

**本次首先优化默认 direct，不能靠要求用户开启 Code Mode 来减少默认工具。** 两种模式的区别必须始终写清：

| 层次 | 默认 direct | 可选 Code Mode |
| --- | --- | --- |
| 完整执行合同 | 全部内置能力和批准插件，部署时冻结 | 同一领域能力，另外含代码编排及目录入口 |
| 模型直接调用 | 完整声明 | 固定直调集合；其余能力通过脚本 API |
| `execute_code`、`lookup_tools` | 不声明，不加载 Monty | 声明；查询只读固定合同，不追加工具 |
| Python/Bash 进程 | `terminal_exec` 在持久 Linux 环境执行 | 仍调用同一终端执行器 |
| 工具组合程序 | 普通直接调用 | `execute_code` 在 Monty 中组合调用；没有环境文件系统、网络或宿主 Python 包 |

`execute_code` 的 VM、snapshot 和子调用回执不是终端进程；不能与 `terminal_exec` 合成一个执行器。`run_python` 已不接收新提交，不再安排一次“删除新 Python 工具”的重复任务。沙箱是终端的现有隔离边界，不另建一个 sandbox 工具组或第二套任务表。

本次核查沿 `MainAgentContract.definitions/model_definitions`、`DIRECT_TOOL_NAMES` 和完整 ApplicationContainer 离线装配。插件关闭、自动化开启、假模型配置；没有启动生命周期、访问模型或发送消息。紧凑 JSON 仅含 `name/description/parameters`，UTF-8 字节不是 Provider token。

| 模式／入口 | 当前完整执行项 | 当前模型直调项 | 当前模型声明字节 | 建议完整执行项 | 建议模型直调项 |
| --- | ---: | ---: | ---: | ---: | ---: |
| direct／平台 | 54 | 54 | 45,237 | 29 | 29 |
| direct／App | 55 | 55 | 45,891 | 30 | 30 |
| Code／平台 | 56 | 41 | 35,058 | 31 | 26 |
| Code／App | 57 | 42 | 35,712 | 32 | 27 |

原 Code 的 ScriptApi 为 54/55 项；15 项仅经脚本调用：11 个 `automation_*`、`recall_own_message`、`save_conversation_attachment_to_workspace`、`environment_packages`、`environment_service`。实现后的 ScriptApi 为 29/30 项，仅脚本五项为 `automation_query/manage`、`recall_own_message`、`save_conversation_attachment_to_workspace`、`environment_service`。App 始终另保留 `read_personal_entry`。批准插件增量另计，Main 合同版本由 `20` 升至 `21`，版本号不代表工具数量。

29/30 是下文逐项可复算的设计结果，不是完成门槛。新 schema 必须实际比较参数、字节和典型调用步骤；不能只减少名称，却让模型反复猜 action、丢参数或多走几轮。实现若发现具体能力无法以该方案保留，应修订映射及证据，不增加通用分派框架硬凑数量。

上版五项工作区方案的非终端 schema 原型已不适用于本版，不沿用其 40,714 字节或收益估算。当前工作树实际离线装配：direct 平台/App 为 29/30 项、33,510/34,164 字节；Code 完整31/32项、直调26/27项、28,440/29,094字节。协议与行为验证见实施审查记录；没有调用付费模型，真实选择质量、费用/cache保持未知。减少名称不代表 token、成本或延迟也减少相同比例。

## 2. 终端统一到三项

保留 `terminal_exec`、`terminal_read`、`terminal_control`。现有终端、APT 和旧 Python 结果本来就归同一个 Manager job；收拢接口不改变原 run/request 身份。

| 现有入口 | 建议入口 | 具体改动 |
| --- | --- | --- |
| `terminal_exec` | 原名保留 | command/cwd/tty 和原 run ID 保留；补足环境内统一管理员终端，默认不强制终止；pending 不重提命令 |
| `terminal_read`、`get_code_run` | `terminal_read` | 合并有限等待与字节游标；返回进程状态、退出码、next_cursor、丢失标记和终态原 completion/artifact。APT、旧 Python job 也可按原 ID 读，不能强制 terminal 类型 |
| `terminal_write`、`terminal_control`、`cancel_code_run` | `terminal_control` | 有限 action 为 `input/interrupt/cancel/close`；input 保原样文本及显式换行，cancel 沿原 Manager control，不新开命令 |
| `environment_status` | 保留 | 环境、容量、任务与服务状态 |
| `environment_packages` | 退役新调用 | 管理员终端可直接 apt；删除安装专属包装、软预算、dpkg 版本记账和自动镜像 checkpoint 新链。旧 job/结果/checkpoint 保原件，环境持久化与备份在部署生命周期处理 |
| `environment_service` | 保留 | 持久服务登记、启停、恢复和日志不能由一次后台命令冒充 |

这组 **9→5**，其中实际终端入口 **6→3**。同一个 `terminal_read` 同时提供增量日志与原终态结果，不能拿 stdout 替代 completion，也不能把空输出当完成。原最多 4.5 秒有限等待是旧能力；合并时保取消观察与取消进程的区别，不新增等待阈值或固定轮询次数。

暂不压成 `exec+session` 两项。当前 `MainAgentBackend.parallel_safe(name)` 与 CoreProvider 按工具静态风险分类；把 read、stdin 和 cancel 放同一个 session 工具，会把真正修改误标为只读，或把只读查询当修改。`_effective_descriptor` 的 target 挂钩目前没有实际 binding 实现，不是可直接复用的 action 分类通路。为少一个名称新增贯穿 Runner、CodeHost 和回执的分类机制，没有必要。三项方案直接保留现有读写边界。

机器调用者一并迁移：`SubagentExecution` 的取消、Work owned-run 查询、completion outbox、结果规范化和 Code 投影都不能只改模型名字。旧已提交调用只读原 call/effect/result；不注册一份仍接受新执行的旧工具别名，不重写旧参数 hash 或原运行 ID。

### 2.1 当前够做什么，还缺什么

源码的终端最终执行 `/bin/bash -lc`，没有 rm/git/python 等命令关键词白名单；支持真实 PTY、stdin、字节输出、信号、原 run 状态和重连接管。Python、Node/npm、Git、curl、jq、rg、编译工具已装。读写、搜索、重命名、删除和二进制处理均可交给 shell，因此八项普通文件工具有替代入口。

实施前基线尚不能称为完整自由终端：普通执行固定 UID 10001，只有 APT 专用路径用 root；存在下表的软件门槛，公网联网也仅限代理 HTTP/HTTPS 80/443。实施前测试只覆盖部分真实 Supervisor/Manager，execd 使用替身；旧 runtime 探针仅测普通 Python、查询和发布，未证明管理员 PTY、独立后台进程和完整网络。实现需补齐再验，不能拿“shell 理论上能做”当已上线能力。

| 项目 | 本次明确改法 |
| --- | --- |
| 环境内管理员操作 | 同一 execd/PTY/Supervisor 链统一为环境内管理员执行，直接运行 apt 和普通 Linux 管理命令；不增加 user 参数、sudo 审批或第二执行器。不能复制当前无交互的 APT docker-exec 路径冒充完整终端 |
| 默认 1800 秒杀进程／最长 86400 秒 | 默认不强制结束；仅显式指定的执行期限生效，删除人为最长天数。工具约五秒返回 pending 是观察窗口，不是进程寿命 |
| 固定一个普通执行／四个 PTY／两个服务 | 删除软件数量封顶，不换成另一个配置门槛；保原执行 ID、真实进程状态和现有资源结果 |
| 低于 256MiB 内存提前拒绝／APT 空间预判和1GiB软预算 | 删除经验预判及中途取消；磁盘满、OOM、dpkg 实际互斥等沿真实 OS 结果处理，不把固定安全余量当授权 |
| 未 ack completion 数量阻新执行／固定小队列拒绝 | 删除512条回执准入检查及既有job派发队列的maxsize=4/queue.full拒绝，保该队列、持久outbox、分页和原确认；不清空历史或假ack解限，不另建队列。execd WebSocket的同名max_queue是传输流控，不按数字相同误删 |
| command 64KiB／stdin 8KiB／cwd 与次数等硬校验 | 一并核 schema、Manager、Supervisor；删无实际语义的长度、天数、路径形式或次数拒绝。真实类型、协议容量与系统调用错误照实返回，不加命令内容过滤 |
| 服务五次失败后永久停恢复／固定进程树深度32 | 移除经验次数与深度封口，按真实树和原服务 restart 选择处理；不另造守护或重试系统 |
| 正常联网 | 为该环境提供实际公网路由，同步专属bridge/NAT、原INPUT/DOCKER-USER规则和代理接线，允许正常公网SSH/TCP/UDP出站；只放宽Squid端口无效。不增加域名/命令审批，保现有宿主/其他私网隔离及环境内localhost服务，Bot数据和凭据不挂入环境 |

CPU、内存、磁盘和进程数的容器配额是部署分配，并非物理机天然上限；按实际部署配置和资源失败处理，不再叠加上述计数/余量门禁，也不声称有限机器能无限运行。输出分页、完整日志的实际保留范围与丢失标记继续如实展示，展示预算不杀进程、不限制正常文件操作。

### 2.2 环境身份与持久化

管理员终端涉及环境镜像和现有容器，不能只改工具文字。同步 Dockerfile 的 USER、容器启动身份、execd、Supervisor、状态目录 owner 及 HOME/Python/npm 路径；继续使用原 `/home/yuki` 与 `/workspace`，不悄悄切成 `/root`。Host Manager 的组和 UMask 仍应保证 Bot 能读取其发布文件，不为环境 root 改掉 Host 权限或增加逐文件鉴权。

保原家目录、安装文件、在途进程和 run/receipt。Bot、Manager 或宿主重启复用原容器时保 rootFS；确需重建容器时先保原 rootFS 和家目录，按实际结果接管或记录中断/未知，不拿旧镜像覆盖已安装软件，不重跑旧命令。删除 APT 自动 checkpoint 不等于已有 checkpoint 被清空；它们仍按原运维证据处理，不再让安装动作隐式建立一套新状态链。环境部署和迁移验收单列，不能只有 Bot healthy 就宣称完成。

## 3. 其他领域的合并映射

### 3.1 工作区：十项只留两条桥

终端与文件工具已经使用同一份 `/workspace`。本版直接删掉普通文件接口，不再建设 `workspace_query/edit/manage` 外壳，也不把普通文件覆盖限制或 CAS 再搬到终端。

| 当前入口 | 处理 | 实际替代能力 |
| --- | --- | --- |
| `workspace_list/read/write/search/patch/mkdir/move/delete` | 八项全链删除 | 用终端 ls/find、cat/sed、rg、Python、mkdir/mv/rm 等直接操作；允许重定向、管道、符号链接及普通 Linux 文件语义，真实权限/磁盘错误照实返回 |
| `workspace_inspect` | 保留 | 把选定文件的图片/视频帧交给原模型；这不是终端文本输出，可读取已发布 artifact，不增视觉摘要模型 |
| `workspace_publish` | 保留 | 把选定文件固化为不可变可交付版本；继续用 send_message 发送，保原 artifact/version 和投递回执 |

旧 artifact 的公开目录、分页文本读取和删除兼容入口也随八项一起退出；不为了旧工具参数保留一套新 CRUD。原 artifact 数据、下载、发送、隐私和引用回收仍由现有链处理，已经发出的版本不因终端修改原文件而改变。

`inspect_conversation_attachment`、`save_conversation_attachment_to_workspace`、`read_tool_artifact` 保留：会话临时媒体没有挂载进终端，仍需明确读取／提升桥；私有执行 artifact 也不是普通全局工作文件。保这些实际能力，不让 shell 直接读 Bot 数据库、临时缓存或私有索引。

### 3.3 自动化：11→2

| 建议入口 | 接收的现有能力 | 范围 |
| --- | --- | --- |
| `automation_query` | `automation_list/list_history/get/history/diagnose` | 只读的目录、详情、终态历史、某任务执行记录、当前主体创建结果；按明确 view 走原读取 |

全局目录原本只给安全摘要，当前主体终态历史和创建失败审计另有范围。合并名称不把它们扩成全局详细原文。`automation_diagnose` 是真实只读，但当前静态 READ 集遗漏它；收拢 query 时按实际读取纠正，不增权限或新审批。立即调度只确认接纳，不伪造执行成功。

## 5. 共用实现与删除范围

- **不增加业务门槛。** 不要求 direct 工具先接纳 Work，不因本次合并添加先列目录、先评分、先汇报、先查重或“同一调用失败全部不能继续”的条件。现有真实来源、授权、撤销与回执按事实处理。
- **能删不包。** 普通文件和包安装直接走终端，删除其专用新执行链；剩余自动化/历史等领域用有限 action/view 和明确参数收拢。query/read 保静态 READ，修改保原修改协调；子任务保原 host control。不得为减少名称建设通用 action 分类器、动态注册、工具别名目录或新的任务状态机。
- **删掉重复工具名限制，不新增 action 鉴权。** `AGENT_RUN` 现已批准整组环境/工作区能力，`agent.run(allowed_capabilities=...)` 只是调用者再缩一层工具名。删除这类可选再缩名单、`source.allowed_tools` 新写入及其工具名存活检查；退役工具不维护旧细分白名单。旧 source/hash 保原件，读旧回执和恢复不因工具改名被 `capabilities_changed` 卡住。不做旧名→action/view 权限映射、兼容授权层、权限表或新审批。
- **真实权限沿原入口执行。** 保现有 Person/Conversation/来源、插件实际批准与撤销、Memory 可见 scope、历史来源和真实运维权限；不因声明里包含某项运维能力而整体拒绝普通调用。Web 的 `WEB_SEARCH/WEB_READ` 批准目前部分通过工具名单承载，删名单时直接复用现有插件领域批准核验，不能一并删掉这两个真实权限。当前不启用工具的 PluginSession 不需要为本次合并增设任何适配或鉴权。
- **读取与缓存分开。** READ 只表示效果分类，不授予缓存资格。终端进度与保留的媒体实时读取不因精简变为可缓存；新 call 读取当前事实，原 call 恢复只用原回执，不增加新缓存或 epoch。
- **两种模式共用一个执行后端。** 同步普通聊天、主动触发、自动化、插件主调用、持久子 Agent、App/平台、direct/Code。Code 的 ScriptApi 仍由冻结声明确定性投影，目录只查询。不同模式可见性按 §1 明确保持，不借查询热加载 schema。
- **旧事实只读恢复。** 逐一迁移真实机器调用者和按旧名分支的授权、预算、归一化、owned-run、Memory 观察和控制处理。删除旧模型入口与新执行别名；已付请求、旧工具配对、原 call/effect、completion、artifact、预算和 unknown 原件保留。读取不到原件就保缺失事实，不重新运行或补造正文。
- **冻结前缀不改写。** 声明名称、说明、schema、顺序和模式投影在部署时一次冻结，形成新 revision；在途 paid request、公共历史和 opaque 私有状态保原件。旧 Code snapshot 是否可恢复沿真实 API/revision 判断，不伪造兼容或从头重跑剩余程序。
- **同步删冗余。** 核注册、分派、SDK/机器调用、Code 可见表、结果解释、提示、配置、文档及测试；不只套新函数后把旧分支继续留给新调用。测试不得为了维持旧工具数量、旧名称、重复预查或经验条件阻止删改。
- **说明只写必要信息。** 每项说明保目的、不同参数的语义与真实回执解释，共同约束只在权威位置说明，不复制整段操作教程。工具声明字节、Provider token、真实 cache/费用分别记录；不能从 schema 减小推算命中率提升。
