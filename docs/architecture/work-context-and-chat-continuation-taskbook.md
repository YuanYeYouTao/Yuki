# Work 上下文与普通聊天续接修复任务书

状态：2026-10-03，PR #228 已实施、合并并完成 Bot-only 部署。本文保留实施前证据与设计规格；测试、部署及真实模型实验见[交付记录](../operations/work-context-delivery-2026-10-03.md)，自然 QQ 能力验收仍由用户完成。

本次修复让 Yuki 在当前聊天时间线上继续工作。聊天和必要观察保持连续；研究原文保存为可回查资料，按需读取，用完可以退出工具工作区。Work 保留目标、进度、原始要求、预算和执行回执，恢复时不再把主 Agent 的聊天倒回任务刚创建时。普通聊天工具续接的容量整理纳入同一修复。

设计核查基线为 `7d26e2212c690d85e90cba436b2c498603602558`，当时已有未提交的软水位分离修改。文中的事故和热配置保留其 2026-10-02 证据范围；当前整理与事务规则以现行合同及 PR #229 为准。

## 一 设计决定和实施范围

用户确认的设计决定如下。

1. 聊天记录保持真实时间关系。模型首次观察后冻结旧表示，新聊天和更正追加；迟到事件记录发生时间与观察时间，不插回已提交前缀。
2. 多个 Work 使用当前获准的聊天前缀；选择 W1、W2、再回 W1，只改变必要执行内容，不轮流换回各自的旧群史。
3. 完整研究资料持久保存，不自动常驻提示词。保留有用结论、未决事项及资料入口；原文可以临时读取，读完退出。
4. 接受工具工作区退出和必要压缩的缓存损失。优先保证长聊天前缀稳定、资料相关、恢复准确，不以命中率换取无关上下文。
5. 模型决定哪些发现值得留下。harness 保证原件、来源、读取范围、执行状态和恢复身份正确；不强制每个工具结果额外调用 LLM 总结。
6. 普通聊天仍是普通聊天，不为获得压缩能力自动创建 Work。真实模型、磁盘和显式资源预算保留，软水位和经验长度不得成为小而写死的业务停止门槛。
7. 不符合上述方向的旧实施要求直接删除或改写。保留独立事故证据和正确性约束，不保留两套活跃上下文实现或相互矛盾的任务书。

本次包含 root Work 恢复、期间聊天补齐、观察线索、正文外存与回读、普通同轮整理、动态快照的 scope 摘要来源、来源核验和真实缓存观测。复用已有开工说明、阶段汇报和 steer，不重做沟通状态机。

本次不改 Provider 路由，不建立全量知识库、通用记忆管理器、定时汇报器或新的审批系统。子 Agent 仍有独立任务上下文和权限；只把获准采用的结果交回主 Agent，不合并全部 worker 思考与原文。普通轮跨重启精确续跑不在本次承诺内。

多会话调度延迟作为实施时的关注项，不预设固定并发数、延迟阈值或必须更换调度策略；本次保持既有会话隔离与租约正确性。Work 迁移仅为未来可能研究的方向，不纳入本次设计或实施。

## 四 提示词和持久事实的分工

主 Agent 的模型输入分为稳定历史和当前工作区：

```text
固定系统合同与完整工具声明
历史摘要
已冻结的获准聊天和必要观察线索
尚未观察的新聊天与新线索
当前输入及本次必要的 Work 状态和要求
当前工具往返、临时读取的资料和私有协议状态
```

当前事件只呈现一次。Work 目标仍有效而原请求已退出近期聊天时，必要目标与用户约束在当前工作区明确给出；这不意味着重新注入原群史或全部最初 envelope。同一激活内没有变化的状态不反复追加，选 Work 时只提供当前需要的状态，不在每轮附整个任务目录。

`state_scope=current_activation` 的运行状态与本次 Work 材料属于临时工作区，不冻结进公共聊天投影。短状态等确实选中的动态资料仍按观察快照保存；跨激活验证公共聊天与观察前缀，不要求旧激活的运行状态或私有协议尾部继续常驻。

公共聊天前缀按实际 actor/read-scope 选择。不同权限、私人材料或不同合同不承诺完整前缀相同；可共用的公开聊天有相同表示。主 Agent 观察条目不是平台发言，不写成虚假的 user/assistant 聊天，不自动发到 QQ，不自动晋升为 Memory。

| 持久内容 | 唯一用途和拥有者 | 自动进入主提示词 |
| --- | --- | --- |
| 原始聊天账本 | canonical Conversation 的聊天事实 | 获准历史按连续覆盖进入 |
| 新增观察来源 | 带来源和读取范围的快照或线索 | 选择后冻结进入；不等于公开消息 |
| 研究原文 | 现有 ToolArtifactRepository，必要时工作区文件 | 否，目录或引用进入，正文按需读取 |
| Work checkpoint 和输入 | 原任务目标、备注、约束及恢复状态 | 当前需要的轻量材料 |
| effect 和 Social/dispatch 回执 | 原调用与真实副作用状态 | 必要状态摘要；原件不常驻 |
| work-protocol 不可变对象 | 原签名、完整序列和恢复证据 | 精确协议恢复需要时；不作为公共资料全文注入 |
| projection 与 Rollup | 可重建模型视图 | 是，但不是聊天、线索或执行事实的唯一存档 |

## 五 线索的最小数据和写入方式

### 持久观察来源

`model_context_observations` 保存轻量观察来源，`model_context_selections` 保存实际请求选取的有序表示；它们不把投影缓存升级为事实库，也不伪造平台聊天事件。原 Work observation 只归原 Work，普通 projection 可清空，不能替代跨正常聊天的线索来源。

记录只包含：内部观察 ID、Conversation/generation、原可信来源、actor/read-scope、首次观察顺序与时间、可选资料发生时间、版本化线索或快照片段、真实引用和可选更正关联。原研究正文不复制到这张表。按会话/generation/观察 ID 做增量索引；同一发布意图使用原 execution/call/input 身份和备注版本幂等，不按文字相似度跨任务去重。

聊天与观察的首次呈现顺序由 selections 持久保存，不能只存两组集合或最大 ID。聊天条目绑定原内部 event，payload 冻结实际所选表示；线索条目绑定 observation 的版本和来源。它是模型表示，不是第二份聊天事实账本。projection 由这些有序来源构建，淘汰后仍能恢复交错顺序。未派发的准备不推进已提交顺序，迟到条目追加，不重新按发生时间排序。

观察与资料拥有引用一同发布，沿现有 Artifact 仓库扩展引用登记和 GC 复核，不另建资料管理服务。模型不能填写 Conversation、授权范围、执行状态或隐私代次；这些由可信入口盖入。观察被选择进入实际请求时，保存其与原 event 的选取关系，沿既有投影派发边界提交。

引用拥有者明确为原 Work、观察条目或已选历史摘要。现有 Artifact 的单 work_id 不能表达这些多拥有者关系，扩展原仓库的小型引用关联，键为 owner 类型、真实内部 owner ID 和 artifact handle，并按 handle 建索引；不复制执行状态。新观察发布时同事务取得引用；摘要接替覆盖时先在同一提交中取得必要引用，再解除旧观察的活动保护。最后有效拥有者解除后才按保留期 GC，隐私删除、撤权和 generation 失效优先核验。旧对象保留原 Work 关联，不能迁移成全群可读。

需要持久关联的信息不得仅放可丢 trace。内容删除、scope 撤销和隐私清理撤销相应观察可见性及其引用；诊断队列不能重建已删除内容。线索永久存档、所有原文永久保护均不在本次目标内。

scope 指纹只标识视图，不授予读取权。发布和回读核原来源、当前 principal/委托及实际读取合同，不能凭一个 artifact handle 自动公开原 Work 的私有材料。Artifact 读取边界使用可信 actor/read-scope；模型只传原 handle 和查询，不传自选权限。note 保存不等于观察发布：失败保留原版本，恢复沿原发布意图幂等重试纯发布，不重做模型或业务工具。

### 模型提供的语义备注

固定 `task_control.update` 已支持可选、版本化 `context_note`，复用 SourcedFact 和来源引用校验。字段表达已知发现、待核问题、下一步和依据，不能表达预算充值或自证成功。

仅更新 note 不修改 goal、state、reporting 或 wait，不解除 unknown 围栏；wait/fail 等 checkpoint 替换也必须保留它。原输入和约束继续来自 Work goal、输入日志和有来源的 task_material，note 不能自由删改用户要求。正常停跑可使用最后有效 note；不要求每个工具或每次 quantum 调用 update。

Worker 的已验收结果可作为带 child/结果引用的线索。本次普通无 Work 聊天只发布真实 outbound、结果 manifest 和可信入口提供的必要动态快照，不增加通用私有语义笔记工具，也不为写 note 自动 accept。没有有效 note 的 Work 仍保留原 goal、输入和回执，不能因为“没写笔记”卡住合法工作。

线索建议几句话，100 至 300 个中文字仅是普通案例的写作示例，不进入代码常量或验收门槛。复杂比较可以保留小表；确实无用的结果可以不留长期线索。典型线索如下：

```text
W1 已核对 A、B 的导出能力。
A 支持 PDF；B 免费版不支持，付费版尚未核实。
C 的中文支持还未检查。
依据 R17/export 和 R25/套餐说明；下一步核对 B 付费版及 C。
```

摘要、模型推断和尚未读取的原文范围明确标注。引用存在不证明结论正确，harness 不增加裁判模型来评估每条语义。

## 六 大资料保存和回读

短状态、ID、错误和执行 envelope 留原效果事实即可，不强制每个结果生成新文件。需要以后回查的研究正文先存完整原件，再向主 Agent 给短回执、目录、必要节选和引用。选择性回读使用现有 `read_tool_artifact` 的 inspect/get/search/text 和分页游标。

结构化资料优先确定性提取相关字段；长文交 worker 按需阅读。首尾截取只作为显式节选，不能称为语义摘要。摘要失败可退回目录和原文引用，不重复业务调用，不把尚未归档的内容宣传为可回查。

归档应保存原返回数据的不可变版本、来源与取得时间；之后的网页 URL 内容变化不能冒充原快照。二进制和附件继续使用已有媒体/产物能力，不能声称 JSON 文本引用保存了全部附件。Provider 原生工具返回不支持完整外存时，准确标明能力范围，不拼造签名或原生来源。

资料从提示词退出不释放执行证据。活动 Work 的结果、当前未覆盖观察及仍被选用摘要引用的资料按真实拥有者保护；旧观察归档或退出可回查承诺后，按明确保留政策解除保护。清理按索引分页准备，提交时核引用和文件身份，文件 I/O 在 writer 外。

资料已过期、隐私删除或损坏时，读取返回明确 missing/deleted/expired 状态，线索不能继续承诺原件可用；不得重新执行旧工具补造原文。必要新搜索由模型作新的读取决定并留下新观察。

沙箱只用于需要 shell 分析的获准资料。复用持久 workspace、发布与安全路径机制提供文件；不挂载 Bot 私有 DB、索引和签名目录，不把私人资料自动复制进全局共享环境。通用跨结果知识目录和复杂检索系统暂不增加。

## 七 恢复和工具正文退出

先核对原 Work 身份、checkpoint 阶段、待配对调用和 Provider 状态，再决定请求编排。无需的最新完整上下文不提前准备，旧 Work 记录也不能先覆盖实际读取版本后再声称使用新群史。

| 原执行状态 | 恢复动作 |
| --- | --- |
| 已配对，可进入正常业务续跑 | 在当前合法历史视图追加未观察聊天，使用原目标、输入约束和有效 note。旧大正文及执行尾部可退出；发生改变时显式结束旧 continuation，公共历史 epoch 保持 |
| response 已保存，工具结果尚未全部配对 | 按原 call/effect/run 查询真实状态，先补齐原回执；不重新发起原工具。保持原签名和顺序，在合法安全点再采用当前聊天 |
| dispatched 后上游结果未知，或原生效果未知 | 沿已有未知结果处理，不假定失败或可重试；新资料整理不创造重跑资格 |
| 真正 Provider pause_turn 等中间态 | 按该协议要求精确恢复；不能把一般业务暂停全部归为这种状态。恢复到安全边界后再退出旧尾部 |
| reset、实际来源失效、权限或合同变化 | 当前授权核验后显式处理，保留原预算和已发生效果。禁止旧内容借“历史稳定”绕过删除 |

同一激活内仍有效的当前工具往返保持有序追加。退出已经派发的正文时，构造一个完整合法的新请求，不在旧 opaque checkpoint 中删字段、改签名或只删工具结果。新输入不得撕裂 call/result；pending 长操作已有合法回执时可以外置正文，但 pending/unknown 状态及回查入口仍在执行事实中。

新请求编排和公共历史重建是不同边界。因退出旧私有尾部停止 continuation，不要求清空聊天投影；切换 Work 本身不构成重排聊天的理由。也不让 W2 接管 W1 的签名、预算或效果身份来维持缓存。

旧版本 Work 的转换按原 goal、trigger/input/effect 和真实引用进行，不从第一条 user 或最终自由正文猜任务。缺少 note 时使用确定性必要材料，允许随后补 note；不能新建替代 Work、清预算或补发开工。无法安全转换的具体记录保留原证据并报告缺失，不设置全局“旧记录一律禁止继续”的门槛。完成转换后删除旧写路径，兼容读取只服务真实未转换记录。

## 八 中途聊天和多任务

未触发 Yuki 的群消息只落账，不请求模型、不生成摘要、不自动恢复等待任务。原本即将请求模型的安全点，按当前读取范围补齐未观察消息；当前 event 与已作为 steer 的同一 event 合并展示身份，输入消费仍归原 Work 输入日志。

不能用单个最大 event ID 推断全部内容已经观察。选择后的内部 event/观察集合、原输入批次与连续覆盖一起确定去重；迟到消息、之前不可见而现在获准的来源追加到首次观察尾部。准备失败或未派发候选不推进已提交视图，重启恢复使用持久选取事实。

普通聊天查进度只读原 Work，不自动 resume。已有 wait、显式 resume、取消、暂停、source 和 unknown 效果围栏不因群聊补齐而解除。多候选保持既有明确定位，不新加按语义猜“最近任务”的分类器。

新独立 Work 仍按已有 handoff/yield 和来源所有权接纳。W1、W2 的公开进度进入真实群聊；获准私有观察只进入对应读取视图。任务补充作为原 input 进入 W1，独立目标进入 W2；本次不改其已有登记原子性和完成判断。

## 九 各个关键节点的提示词和 runtime

例子是远野请求比较 A、B、C 并制作 HTML。H 表示当前视图已冻结聊天和必要线索，T 表示本次私有工具工作区；以下是拟议行为。

| 节点 | 主 Agent 本次看到什么 | runtime 做什么 |
| --- | --- | --- |
| 普通聊天 | 固定合同 + H + 当前消息 | 记录真实消息与发送回执，不创建 Work |
| 创建 W1 | 固定合同 + H + 比较请求一次 | 接纳原来源、保存目标预算；先交代再做，沿原 interactive 合同 |
| 搜索 A | 同一激活前缀 + A 的短结果、依据 R17 + T | 保存原件和真实 effect，正文不自动进入长期历史 |
| 临时细读 R17 | 稳定历史 + 当前需要的段落 + T | 用原 reader 分页；读完可退出临时正文，留下必要线索 |
| 被迫暂停 | 没有虚构的“暂停模型请求” | 保存最后有效状态与配对证据，核对未知效果，释放名额 |
| 群友讨论 B 和 C，Yuki 未触发 | 没有模型请求 | 只落账，W1 不被任意闲聊唤醒 |
| Yuki 被 @ 问进度 | 固定合同 + 最新连续 H + 当前询问 | 必要时读 W1；准确发送进度，不暗自恢复 |
| 恢复 W1 | 固定合同 + 当前 H + 尚未观察消息 + 必要 W1 状态和约束 | 先处理原未决协议；安全时采用当前聊天，不恢复整份 H0 |
| 继续查 B、C | 上述内容 + 新短结果与引用 + T | A 原文不重复注入；确实需要再按 R17 读取 |
| 创建 W2 做海报 | 当前 H + 新请求 + 必要 W2 状态和 T | 按原 handoff 接纳，W1 身份预算留原记录 |
| 再回 W1 | 同一当前 H + 此后新聊天 + 必要 W1 材料 | 不换回 W1 旧群史，不复制 W2 原资料 |
| 完成 W1 | 当前 H + 本次交付结果 | 产物和附言按原真实回执核对，线索可留产物入口 |
| 普通轮连续工具增长超软水位 | 稳定聊天 + 必要当前要求 + 整理后的 T | 复用纯整理能力，仍无 Work；能 fit 的请求不因软目标失败停止 |
| 历史需要 Rollup | 固定合同 + 新摘要 + 未覆盖聊天与观察 + 当前工作区 | 明确提交新历史边界，原事实和必要引用保留 |

多任务请求的长期部分应当这样增长：

```text
请求一：固定合同 + H + 远野请求 + W1 本次工作区
请求二：固定合同 + H + 远野请求及实际进度 + 新聊天 + W2 本次工作区
请求三：固定合同 + H + 前述聊天及进度 + 更新聊天 + W1 本次工作区
```

例子不承诺整个请求二以整个请求一为前缀：旧临时工作区可以退出。验收稳定的部分是其前面的聊天和观察；不得为维持尾部命中把无关研究正文一直带着。

## 十 普通聊天同轮容量整理

保留现有完整请求预检，在无 Work 分支补同轮整理。优先外置大正文、保留短回执和必要引用；还不足时复用已有纯摘要分页、引用校验、配对分组和候选 fit，不复用 Work 接纳或生命周期来伪造恢复拥有者。

整理保留当前用户要求、内部身份、已发生计量、真实发送与未知效果；不要求永久携带最初完整 compiled envelope。完成配对的大正文可退出，原件保留；未决协议内容按第七节处理。

候选在实际固定 tools/native tools、Profile、输出预留、媒体和协议负担下检查完整请求。软整理失败而原请求仍 fit 时保留原请求继续；真正超限且整理仍不能 fit 时准确停止，保留已送达事实，不补发、强制完成或更换 Provider。

辅助调用计入原普通执行的预算。普通执行没有已接纳 Work 的持久摘要游标，因此本次只承诺当前拥有者内的同轮整理；重启后不自动重放原入站、业务工具或发送。现有 Work 的已付摘要页和游标仍按原持久事实恢复，不能因抽取纯函数丢掉这项能力。

## 十一 Rollup 和来源核验

canonical Rollup 整理共享聊天事件；必要动态快照与 Work 线索在原 actor/read-scope 的观察摘要中处理，不混入全群语义摘要。两者在模型视图中按真实覆盖组合，公共聊天覆盖不能替代私人观察覆盖。

覆盖记录至少能区分聊天 event 范围和观察来源集合或连续观察水位。未覆盖的观察保留在尾部；聊天 coverage 前进不能顺带宣称工具线索已整理。超大原聊天仍按完整来源分页，工具原文可按引用保留，不强制每次 Rollup 再读完所有外存资料。

已有冻结视图在后台纯 Rollup 追赶或 housekeeping 更新后继续使用；真正需要整理该视图时才采用新摘要。摘要发布、覆盖与观察引用同步短事务核验，不能因为新摘要存在就每轮前置替换旧摘要。

来源 guard 必须绑定实际提交的聊天、观察、任务要求和读取范围。真实事件删除/修改、generation、隐私、权限和有效来源变化继续失效；不把全局派生 revision 当唯一证明，也不能直接删掉所有 revision 检查。冻结迁移文件不改；需要改变触发器时新增实施时 head 后的迁移，并验证旧触发器形状和新行为。

缓存报告按实际 Provider/Profile/协议和自然流量窗口分组，分别记录总 input、cached input、已知样本数、未知样本数及已知输入加权命中率。未知值保留 NULL，不能当作零；规范化 input 已包含 cache 时不再把 cache 加一次。主调用、worker、搜索和摘要计量分开，压缩/合同变化与临时正文退出单列原因。

同时报告公共历史最长相同前缀、首差异位置、原文重复注入量和请求容量，避免只看命中率掩盖提示词膨胀。无授权不发送 QQ 探针或启动第二个生产 Bot；不以保温调用制造改善。上游最终请求报文无法核对时明确证据止于 Bot serializer，不能宣称中转也完全稳定。

技术验证后由用户验收真实能力和线索质量。目标是历史连续、恢复准确、输入更相关，不承诺固定命中率、永久缓存或摘要无损。

### 参考 OpenClaw 的真实缓存回归实验

OpenClaw 有 [真实缓存回归入口](https://docs.openclaw.ai/reference/prompt-caching#live-regression-tests)，覆盖重复前缀、工具、图片、MCP 风格回合及 Anthropic 无缓存对照。本次核查的源码固定在 `3c5010ebfacd96e6b4836c9080e58ab42c1ac7ab`，避免把不断变化的 main 当成固定实验协议。

其 [runner](https://github.com/openclaw/openclaw/blob/3c5010ebfacd96e6b4836c9080e58ab42c1ac7ab/src/agents/test-helpers/live-cache-regression-runner.ts#L354) 先预热、再测两次并选择 cacheRead 较高者；[比例函数](https://github.com/openclaw/openclaw/blob/3c5010ebfacd96e6b4836c9080e58ab42c1ac7ab/src/agents/live-cache-test-support.ts#L167) 使用其自身归一化的 `cacheRead / (input + cacheRead + cacheWrite)`。工具场景还有生成调用的请求与可能重试，样本数不等于物理 API 请求数；实验必须另报总调用。当前官方文档对 Anthropic 和 OpenAI 使用不同回归处理。它是受控热缓存实验，不是自然群聊命中率。

Yuki 借鉴实验结构，自行实现适配本仓库的手动核查脚本，不复制整套 harness，不照搬数字门槛或 token 分母。用户已授权使用 Gemini API，并在 2026-10-03 授权使用 DeepSeek 作同场景对比；各次使用显式选择的 Profile，其他 Provider 不自动追加。真实缓存实验不得加入常驻测试集合、CI、定时任务、启动检查或每次提交的必跑清单，也不由普通测试自动发现或触发。脚本放 tools 等手动入口，当前修复完成时按需核查；后续仅人工启动。常规 CI 只运行离线请求前缀验证，不产生 API 用量。

实验流程如下。

1. 使用隔离数据库、合成群史及 fake QQ 网关，所有外部业务效果接测试执行器。模型传输经过真实 TaskModelExecutor 和 Provider serializer；不启动第二个生产 Bot，不读取私人群资料，不向 QQ 投递。
2. 每次实验使用新的固定命名空间，放在本轮实验一致的位置，避免前次实验污染；后续请求沿同一实验身份。固定 Profile、路由、完整 tools/native_tools、reasoning、输出预算和其他缓存相关设置，尾部只作场景要求的变化。
3. 各场景记录第一次冷请求，再记录全部后续热请求。默认可用一次预热和三次后续采样，次数与输入长度作为实验参数；前缀长度须满足选定 Provider 的有效缓存条件且 fit，不能用一个很短的问题判定“不支持缓存”。有短延迟的补测时另记，不丢掉先前零命中样本。
4. 保存每个样本的真实 input、cached input、可得的 cache write、output、耗时、请求阶段、首差异位置及路由证据；缺失保持未知。逐样本表、冷样本和热样本的各自输入加权比例都给出，可以另列最佳值，但不能只报最佳一次。
5. 比较改动前后的同构场景时，分别使用独立命名空间，多组交替顺序采样。环境、间隔、模型或路由不一致时标明不可直接归因，不能仅凭单轮波动证明代码改善。

| 场景 | 改变什么 | 验证什么 |
| --- | --- | --- |
| C01 重复前缀 | 同一长聊天，只改末尾问题 | 基础缓存可得性；完整固定合同与历史实际相同 |
| C02 工具续接 | 合法读取 call/result，继续追加 | 配对和签名合法；工具加入不改聊天前部 |
| C03 Work 切换 | W1→W2→W1，期间增加聊天与线索 | 公共前缀沿当前时间线增长，私有尾部退出损失单列 |
| C04 大结果回读 | 外存目录、读取节选、退出原文、随后再次聊天 | 原文不反复注入；报告缓存与总输入，避免只提高比例却扩大上下文 |
| C05 重启恢复 | 第一段后重启隔离 runtime，复用原持久数据 | 固定设置和公共历史保持；预算、回执及资料引用未丢 |
| C06 必要整理 | 主历史压缩或普通执行尾部整理后继续 | 整理后的首次变化准确记录，后续新前缀可再次复用 |
| C07 输入形态 | 已支持的图片和 MCP 风格回合 | 与 OpenClaw 类似的形态覆盖；不把模拟原生块当实际功能验收 |

基础重复场景需有“不共享同一前缀”的独立对照，使用另一命名空间替换前部历史。只有明确支持关闭缓存的路由才做真正 no-cache 对照；不把 `cacheRetention=none`、换缓存 key 或未命中自动称为缓存已关闭。

缓存用量沿 Yuki 现有口径核对原字段：如果总 input 已包含 cached tokens，分母直接使用总 input；若某 Provider 分别报告未缓存输入、读和写，先归一化且记录公式。未报告 cache write 不补造写入量，未知 cache 不转零。缺 telemetry 的路由标记“无法计量”，仍做结构验证，不将其结果判为缓存失败。

结构不变和没有重复副作用是确定性验收。真实命中比例先形成同路由基线，必要回归阈值再按实际稳定性决定；不把 OpenClaw 的另一 Provider 最佳热样本百分比设成 Yuki 的统一失败门槛。Gemini 经上游代理的实验只能证明该路由的实际计量；没有最终 upstream 请求证据时，不能将异常唯一归因给 Bot 或宣称反代透明。

这项实验会产生真实 API 用量。Gemini 授权持续有效，无需为本次范围内的手动核查重复请求批准；不因此建立常驻或自动执行机制。当前任务书编制没有运行实验，也没有新增付费请求；实施报告必须给实际执行次数和用量。受控实验结果与上线后自然流量的缓存报告分别呈现。

## 十六 Pi Durable 对照后的实施补充

2026-10-03 按用户要求核查 Pi Durable 官方源码，固定修订为 `9fba660cf1caca0ade5bea72269352416e595a19`。逐项证据、采用与不采用的理由见 [Pi Durable 对照](pi-durable-work-context-comparison-2026-10-03.md)。这是源码核查，不表示已独立运行 Pi demo。

1. 采用历史与任务归属分离、应用原件与模型选取分离、输入持久去重和安全边界接入的设计；通过现有 Conversation/Work/input/effect/projection 实现，不另建通用 TaskEngine 或引入 Pi 运行依赖。
2. 第八节的安全点包括当前激活在工具往返完成后原本即将发送下一模型请求的位置，不能缩窄为下一次业务恢复装配。该位置补齐当前可读取的一般群聊增量，与同一内部 event 的 steer 去重，原输入消费不变；不唤醒等待工作、不创造新请求。真实未决协议及 child 的独立上下文保留原恢复合同。
3. 新增多人混合输入组合验收：多个 steer、一般群聊和后续独立输入，核 call/result 配对、实际观察顺序、首次真实派发选取、重开后恰好一次及原预算/回执。未派发候选不推进观察；只追加真正新事件，不为读增量重编整份历史或重新认证旧来源。
4. 保留本任务书的原文外存与线索策略。Pi 默认仍把工具结果作为模型贡献，omit/replace 或 compaction 才使内容退出；不能把通用持久 transcript 当作已具备本应用的资料整理与引用生命周期。
5. 不照搬动态 system/tool 策略。Pi 的 Gemini 适配将系统增量折叠到开头，动态变化仍可能改前缀；Yuki 的固定系统与完整工具合同继续有效。真实缓存数据仍区分 NULL 和 0，不能搬 Pi 归一化分母或宣称其 E2E 是群聊命中率基准。
6. 借用摘要候选提交、过期判定和工具配对的验收思想；本轮复用现有 CAS、paid 游标与 ProtocolStore，不增加完整后台压缩调度。任务中断时按原 effect/run/发送回执核对，不能把 Pi interrupted 文本解释为外部效果确定未发生。
