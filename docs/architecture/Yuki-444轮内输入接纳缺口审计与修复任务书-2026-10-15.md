## 3. 缺口与最小收敛方向

原缺口链接固定到首轮审计基线；10-16 节奏补查固定到 `9e6f6147`。实施时按符号重读，不拿旧行号代替当前实现。

### F01 · P1 · 准备期间二次读取扩收新事件，接纳候选没有同步扩收

**确定的实现缺口；尚未证明本次 C 恰好落在这个微小时序。**

`observation_boundary()` 首次读到 `[B]`，只对 B 调用 `ordinary_inputs()`。准备可能等待 ASR、附件或数据库读取；此时 C 到达。第二次 `read_scope_delta()` 重新取得 `[B,C]`，用它重算 `fresh`、渲染请求，却只筛选第一次准备出的候选，最后按第二批 rows 推进观察水位。

结果是：C 即使已经完成原资格判断和材料准备，也能进入当前业务请求而不进入本次 admission。二次读取本身是合法新版本，CAS 不会识别“渲染集合大于准备集合”这一语义错误。

定位：[首次读取和候选准备](https://github.com/YuanYeYouTao/Yuki/blob/af0770fcd54a5fad78771ae02004f1f483d8eaad/src/qq_ai_bot/services/main_agent_turns.py#L280)、[二次读取及重算 fresh](https://github.com/YuanYeYouTao/Yuki/blob/af0770fcd54a5fad78771ae02004f1f483d8eaad/src/qq_ai_bot/services/main_agent_turns.py#L310)、[候选提交](https://github.com/YuanYeYouTao/Yuki/blob/af0770fcd54a5fad78771ae02004f1f483d8eaad/src/qq_ai_bot/services/main_agent_turns.py#L440)、[水位推进](https://github.com/YuanYeYouTao/Yuki/blob/af0770fcd54a5fad78771ae02004f1f483d8eaad/src/qq_ai_bot/services/main_agent_turns.py#L484)。

最小方向：固定本次最初选中的事件集合，二次读取仅刷新这些内部 ID 的真实内容、来源版本和准备结果；后来到达的事件留给下一个合法边界，不越过它推进水位。保留同一事件 ASR/附件准备后的来源重读，不靠多加一轮读、循环重试或等待群聊安静收敛。

### 历史曝光的范围

线上 C 被两轮真实回答已经证实，但不能据此断言它一定落在 F01。入账、observed 注册、continuation 分类和媒体准备存在异步间隔；公共观察可以先看到尚非普通候选的事件。原任务书 F02、§4.2 明确保留初始历史、晚分类和历史工具曝光后的独立合法机会，这本身不是新增故障。

F01 只修准备集合、请求材料与接纳集合的错位。这里不另建 ready 标记、旧水位追领或“回答识别”，也不要求遮掉公共群史。模型看过、提到或回答过，不是 admission 依据；不能为绝对不重复吞掉合法新入口。若后续证据表明 C 属于有意保留的历史边界，应据实归类，不再扩建机制。

### F03 · P1 · Compact 先提交公共投影后，业务接纳跳过 writer 内来源核验

**确定存在跳过路径；撤回/隐私变化撞中该窗口的后果尚未执行验证。**

同一 boundary 可先以 `business_inputs=False` 服务 Compact，提交公共 projection 并令 `committed=True`。之后真实业务请求准备了新的 `projection_publication`，但 `publish()` 因已 committed 跳过它，只执行新增 ordinary admission。

被跳过的 projection publication 原本在 writer 内复核 conversation generation、starts-after、prompt source revision、privacy generation 及 projection 版本。`selected_guard.check()` 在 writer 前读取，不能替代同一短写事务的条件核验；`commit_to_activation()` 只核当前候选，并将其 conversation/generation 与冻结的原 activation 字段比较，没有重新核验原 A 及公共上下文的完整来源。

定位：[跳过 publication](https://github.com/YuanYeYouTao/Yuki/blob/af0770fcd54a5fad78771ae02004f1f483d8eaad/src/qq_ai_bot/services/main_agent_turns.py#L435)、[原 writer 核验](https://github.com/YuanYeYouTao/Yuki/blob/af0770fcd54a5fad78771ae02004f1f483d8eaad/src/qq_ai_bot/conversation/projections.py#L287)、`conversation/ordinary_admission.py::commit_to_activation`。

最小方向：已发布只跳过重复写入，不能连同必要核验一起跳过。复用原 publication 的来源、隐私与版本条件，在原 admission writer 内核对；不重复发布、不增加第二份状态或通用 publication 框架，不在 writer 扫历史。原 A 撤回、隐私删除或公共 projection 变化发生在最后读取与 writer 之间时，旧请求不得借新 C 接纳继续派发。

### F04 · P2 · 最终请求的整批匹配门槛会同时丢掉仍完整的候选

**确定存在整批判断；真实容量规划造成的具体混合形态仍待核对。**

`_PrimaryDispatch.__post_init__()` 要求 boundary 的全部公共 fragments 和全部 `current_inputs` 都在最终冻结请求中，任意一个缺失就把整个 `selected_boundary` 置空。候选 C、D 的材料不是按事件分别匹配；`ContextBoundary.current_inputs` 也只保存一整个 tuple。

静态可达的最小形态是：C/D 的新公共片段都进入 Compact 前缀，C 的私有输入被摘要覆盖，D 的私有输入保留在后缀；公共原文经 `retained_public` 保留。此时 D 的实际材料完整，整批门槛仍可能因 C 缺失而把 D 一起排除。摘要提到 C 也不表示原完整 C 材料被业务请求采用。该形态尚未端到端执行验证。

定位：[整批门槛](https://github.com/YuanYeYouTao/Yuki/blob/af0770fcd54a5fad78771ae02004f1f483d8eaad/src/qq_ai_bot/services/turn_execution.py#L131)、`services/context_boundary.py::ContextBoundary`、`context_compaction.py::execution_compact_plan`。

本项并入 F03 的 Compact 核对，不单列必修实现。真实混合保留成立时，只沿现有 `OrdinaryContextInput.prepared.event.id` 和 `message` 做局部选择；不预建事件映射层、材料清单或完整性框架。若该形态被真实调用链排除，记录依据并结束本项。不能直接删掉全部选中检查，使已被替换的输入也获得 admission；摘要不代替原件。

### F05 · P1 · 接纳提交后的派生参与反馈仍能阻断实际请求

**确定存在可抛错路径；不是本次双回复的已证明原因。**

`commit_boundary()` 已提交 admission、finalize 后，仍在模型 HTTP 前逐个 await `on_committed()`。回调进入 `_record_ordinary_participation()`；其中 admission 查询在 try 外，衍生服务保存也仅捕获三类异常，数据库错误仍可向上退出。结果可能是 C 已归 A、worker 因已有 admission 退出，A 却被派生反馈错误挡在真正请求之前。#445 没有删掉这层阻断。

定位：[提交后回调](https://github.com/YuanYeYouTao/Yuki/blob/af0770fcd54a5fad78771ae02004f1f483d8eaad/src/qq_ai_bot/services/main_agent_turns.py#L489)、[参与反馈](https://github.com/YuanYeYouTao/Yuki/blob/af0770fcd54a5fad78771ae02004f1f483d8eaad/src/qq_ai_bot/services/processor.py#L1846)。

最小方向：取消派生反馈保存失败对业务派发的否决，沿现有错误记录保留失败，真实取消、来源撤销和接纳 writer 失败继续传播。持久 admission 仍是输入事实源；不另建异步反馈队列、补偿重放或模型重试。现有 admission 查询可保留，不为少一次读取改回调接口；若实际修改确需删除查询，必须使用 writer 确认的最终 admission，保留 A 的 activation/coordinator 和 C 的 reason、binding、来源，不能拿未移交的 `candidate.prepared.admission` 代替。

### F06 · P2 · 固定 256 条 envelope 淘汰可能丢失仍有调用者的输入

**继承的经验阈值风险；并非 #444 新增，尚无本次生产丢失证据。**

Processor 按条数从 `_observed_human_turns` 淘汰最旧 envelope。pending attempt 只捕获 event ID/binding，最后仍回 map 查原 envelope；查不到就返回 `ordinary_envelope_unavailable`。A 长时间运行、C 仍为 pending latest、后续大量纯观察又不替换其 ordinary slot 时，C 可以因第 257 条记录而失去原输入。

定位：[经验淘汰](https://github.com/YuanYeYouTao/Yuki/blob/af0770fcd54a5fad78771ae02004f1f483d8eaad/src/qq_ai_bot/services/processor.py#L1021)、`processor.py::promote_committed_event`、`_defer_ordinary`。

最小方向：删除有效 attempt 必须仍能从 256 条缓存找回原输入的前提，优先沿已有 ordinary 调用直接传递原输入。不调高阈值，不新增 TTL、owner、保留表、引用计数或清理器，也不简单取消淘汰后永久保存全部观察。进程退出不自动重跑普通轮，平台消息号不用于重建原输入。

### F07 · P2 · 纯观察可将已排 ordinary attempt 覆盖为 legacy

**覆盖赋值已确认；是否造成永久漏答取决于策略和其他入口，尚未证明。**

新事件 D 没有 ordinary 资格时，仍可能沿 autonomous-enabled 分支调用 `observe(D)`，不传 attempt。`AutonomousGroupService.observe()` 无条件替换 message 并把 `ordinary_attempt` 写成 `None`，原 C 的待尝试闭包随之退出 latest slot。后续若 `legacy_allowed()` 拒绝，worker 结束。

定位：[纯观察调用](https://github.com/YuanYeYouTao/Yuki/blob/af0770fcd54a5fad78771ae02004f1f483d8eaad/src/qq_ai_bot/services/processor.py#L1049)、[覆盖赋值](https://github.com/YuanYeYouTao/Yuki/blob/af0770fcd54a5fad78771ae02004f1f483d8eaad/src/qq_ai_bot/services/autonomous_groups.py#L116)。

最小方向：删除纯观察用 `None` 覆盖原 ordinary attempt 的赋值路径，沿原 latest slot 处理。合法较新 ordinary D 仍可取代 C；不改 FIFO，不拆 ordinary/legacy 双队列，也不新增 pending、owner 或 coordinator。

保留 F06/F07 的原输入不等于冻结尚未选择的机会；它仍在 promotion 复核当前资格。已被同一 Main 选择的补充沿 #446 保留选择时的参与资格，后到 quiet、跨度或语义纠正不再否决其发布；来源、身份、授权和唯一归属继续核验。不恢复已经失效的待尝试快接，也不新增资格门槛。

### F09 · 10-16 已同意调整 · 无 @ 的语义邀请绕过普通防抖
