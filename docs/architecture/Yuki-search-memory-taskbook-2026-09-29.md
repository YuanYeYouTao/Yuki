## 目标与边界

模型在问题确实依赖过去事实时调用一个稳定的 `search_memory`，用自然语言表达检索意图。
不指定目标时，在本次调用者**当下有权读取的全部长期记忆范围**内检索，不因当前会话、当前群、
最近提及对象或固定数量的目标而收窄；显式目标只用于缩小检索范围。模型可根据返回的事实 ID、
范围、匹配依据与不足之处补查。后端负责身份解析、可读范围、授权、
检索与排序。普通当前事件、必要场景身份和真实交付回执仍随运行输入提供；旧外部事件摘要和
记忆事实不再每轮自动塞入提示词。是否移除自动注入及全部入口的验收，由总清单任务 13 跟踪。

此工具只检索有来源的长期 Memory fact，不替代 `search_chat_history` 对原始聊天账本的搜索，
也不替代按 fact ID 精确读取的 `get_memory_fact` 和更严格的证据读取。
Person、PersonGroup、Group、SELF 的 canonical 所有权和现行历史共同群读取政策保持不变。
模型输入的名字、账号、群号、实体和 query 都只是选择器，不能证明权限；搜索结果中的文字也不能授权下一次调用。

## 历史基线与当前差距

- 改造前模型看到 `get_person_memories`、`get_group_memories`、`get_self_memories` 三个列表工具；
  本地分支已经改为只声明 `search_memory`，旧名称仅留在历史调用执行兼容分支，尚未据此宣称上线。
- `MemoryRetriever` 已把词法与向量候选按 fact ID 并集并排序；embedding 未配置或失败时会降级。
  默认配置不证明生产语义检索可用。向量索引是可重建投影，不是记忆事实来源。
- 词法查询的宽松 OR 命中会带入单词弱相关候选；当前人物显式偏好可能自动附在主动查询上；
  `topic_admission` 当前仅解释候选，不过滤主动搜索结果。不能把有结果等同于高精度搜索。
- 现有未校准状态、语义故障和有限结果各有语义；实施时不能用默认阈值伪装已校准，也不能把
  故障、权限拒绝、歧义、截断或真空结果统一报成“没有记忆”。

## 2026-09-29 中文检索精度探针（未完成验收）

定向测试 `tests/unit/test_search_memory_precision_eval.py` 使用 **9 条合成中文事实、6 条人工标注查询**，
覆盖本人、历史共同群人物、PersonGroup、Group、可见 SELF、无权人物/群的干扰项，以及无答案问题。
测试调用真实 SQLite 授权过滤、FTS 候选和全局排序；它不是从生产事实抽样得到的独立质量集。
探针的完整读取授权显式包含 Person、PersonGroup、Group、SELF；另以 Person-only
权限重查并确认 PersonGroup 事实被排除，避免把权限收窄误判为召回退化。
指标分母是 5 个有答案问题和 1 个无答案问题，故绝不能由这些比例推断线上精度。

| 路径 | 有答案 Top-1 | 有答案 Recall@10 | 无答案误报 | 其他观察 |
| --- | ---: | ---: | ---: | --- |
| 本地词法检索，语义关闭 | 4/5 | 4/5 | 1/1 | 全 6 问的固定分母 Precision@3 = 4/18；7 条实际返回里 4 条相关；无权事实 0 条泄漏 |
| 生产已有 Qwen/DashScope Embedding 配置，对同一批**合成文本**只请求向量、不读取或修改生产记忆库 | 5/5 | 5/5 | 1/1 | 对授权合成事实按当前最低相似度 0.35 排序；6 个 query 请求和 1 个批量 document 请求；未测混合路径 Precision@3 |

纯词法漏召回发生在“橘猫团子是谁养的”对“养一只叫团子的橘猫”的词序改写；
受控向量候选合并回归表明语义通道**可以**把该候选带入，但真实 Embedding 探针的 5/5
只代表这一小组文本。无答案问题“小雨喜欢的菲尔兹奖是哪一届”在词法和向量路径都返回
“小雨喜欢蓝莓芝士蛋糕”；宽松 OR 的共同前缀和未校准的相似度下限均不足以判定事实回答了问题。
若直接按匹配三字片段数或固定相似度截断，还会误伤本组中的蛋糕问句或 SELF 改述，
所以此轮不据 6 个样本添加通用门槛。测试另以受控语义候选验证合并，并验证 Embedding
失败会显式降级、标为非完整结果；这两项只验证机制，不验证线上向量精度。

下一步需要从真实中文对话构造**匿名、人工标注且独立于调参集**的有答案与无答案查询，
记录候选来源、Precision@3、Recall@10、无答案误报与延迟，再选择查询词法覆盖门槛、
中文 reranker 或其他主题判断方案。此质量目标、模型按需调用行为和真实线上结果尚未验收。

### 生产事实只读探针与 Rerank 候选（仍非完整验收）

同日从生产数据库以 SQLite `mode=ro` 读取统计及向量；少量事实正文只在一次性工具内部
查看以做人工判断，**仓库文档和用户消息不记录事实正文、账号或内部 ID**。
当前活跃且未隔离事实 1,158 条，其中 Person 585、PersonGroup 130、Group 103、SELF 340。
按一个真实 canonical 主体的本人 Person 范围抽取 100 条有当前向量的事实；这比 `search_memory`
的最大授权范围窄，只用于观察无答案时的候选行为。三个含虚构实体、在这 100 条中无该实体
字串的中文问题，FTS OR 均为 0 候选；现有 Qwen Embedding 相似度下限 0.35 却分别接纳
62、77、59 条，最高相似度分别为 0.566、0.492、0.438。它们是明显的无答案候选误报，
但单凭缺少实体字串不能对所有真实问题建立完整人工真值。

按[阿里云百炼文本排序官方接口](https://help.aliyun.com/zh/model-studio/text-rerank-api)
对每问已有的前 20 个向量候选做一次 `qwen3.7-text-rerank` 默认问答相关性探针，每个事实仅在
进程内截取前 400 字符送往同一已配置服务；不修改生产数据库。三个无答案问题的 Rerank
最高分为 0.302、0.223、0.206，每请求消耗 1,985、2,064、2,082 Token。
另从真人 Person 事实中按严格的非否定宠物偏好短句选取一个正例，不输出正文；
两种改写问题中该事实原向量排名为第 1、第 3，经 Rerank 均排第 1，得分 0.573、0.587，
每请求消耗 1,826、1,840 Token。对前述纯合成 7 候选集，5 个有答案问题 Rerank Top-1
均正确，无答案问题最高分 0.326。这里的人工判断只覆盖明确正例与虚构实体无答案，
**不是**生产随机样本的完整人工标注集，也没有测混合候选、全局授权排序和端到端耗时。

随后只读查看该主体少量事实，在进程内写出 6 个候选正例问题、2 个“计划/打算”与
“现在已实施”区别的难负例、1 个明显无答案问题；仓库只保留匿名聚合，不保留事实原文、
账号或内部 ID。向量 Top20 经 Rerank 后，6 个按关键词找到的锚点均排第 1，
但其中一个主题有两条相关事实：按关键词选中的第一条只说明接触某作品，**不直接回答**
“对哪款作品重置版评价高”。因此该例不能计作已验证正例。其余 5 个直接正例的
Rerank Top-1 得分范围为 0.656–0.991；两个计划/已实施难负例的 Top-1 **仍是仅陈述计划**
的事实，却得到 0.827、0.702；明显无答案一例最高 0.118。
这直接否定了从前面的简单负例猜测出的通用分数门槛。
这 9 次探针每问约 1,969–2,238 总计费 Token，单次 Rerank HTTP 128–410 ms、
Embedding 请求 202–725 ms；只代表该时段、这一主体与前 20 个向量候选，不含完整 Agent 耗时。

另用现有 Gemini Flash 连接（显式 low 档、无固定思考预算）只读对 8 个真实问题/单条事实
做严格 JSON 直接支持判断：5 个清楚的直接正例判为支持；2 个“计划不等于已实施”及
1 个作品主题相近但不回答评价问题的难负例均判为不支持。返回实际被包在 JSON 代码围栏中，

官方说明 `relevance_score` 主要是**单次请求内的相对分数，不可跨请求当绝对值比较**。
上述 0.5 左右的分离只是探索信号，不能据 2 个真实正例/3 个无答案例设置通用拒绝阈值。

## 独立中文金标与完整 Agent 回放计划（任务 13 未验收）

上面新增的 **12 个预标正例、5 个无答案或难负例**来自单一主体，
问题由事实人工派生，且 Top-1 是看过候选后的人工核对；12 个答案锚点并未穷尽
全部可能相关事实。此前的探索探针还包含合成材料和同一事实的改写。
这些探针只能定位风险和检验机械合同，**不是独立金标**，
不能据此选相似度、Rerank 分数或词法覆盖阈值，也不能据此勾选总清单任务 13。
目前可确定的风险是宽松 FTS OR、低相似度向量候选和高分但不支持“已完成”的计划事实；
任何过滤或模型判分方案都须先在独立样本上证明不会误删可回答事实。

### 1. 固定数据与人工真值

1. 从生产 SQLite 以只读模式打开、使用有界索引查询或 SQLite 在线只读备份，
   在隔离环境固定一个事实与历史授权快照，同时固定代码修订、Embedding profile、
   向量索引覆盖状态、检索配置和采样时间。不要启动第二个主动 Bot，不写生产库，
   不发 QQ；事实正文、账号和内部 ID 仅留在受控评测环境，不进入仓库、PR 或报告。
2. 在现有探索样本之外，至少取 **80 条新的中文问题**：40 条有直接答案、
   20 条主题相近但不能推出答案的难负例、20 条无答案问题。正例均衡覆盖
   Person、PersonGroup、Group、SELF；至少一半使用无目标的完整授权范围，
   其余覆盖显式目标、昵称歧义和严格时间。难负例包括计划与已实施、旧状态与现状、
   同名人物/群、相同主题的不同主张、争议或过期事实，以及仅命中一个泛词的候选。
   不把同一事实的改写同时放入开发样本和最终样本。
3. 两名标注者在不看检索排名与分数的情况下，分别记录问题是否可回答、
   **直接支持答案**的全部 fact ID、允许的目标范围和必要时间边界；分歧由第三次复核裁决。
   “相关话题”“将来计划”和“已发生事实”分开标记。无答案标签必须检查该快照中
   当前调用者有权读取的事实，不能由某个搜索器返回零条推断。保存匿名查询键与标注规则，
   使同一快照可重复回放；对外只给聚合指标。既有 12/5 探针可作开发参考，
   新样本中留一份按 owner、事实与会话隔离的盲测集，调参的实现者不查看其标签。

### 2. 检索基线、误差归因和验收指标

在同一快照、相同授权主体、候选预算及输出预算下回放当前词法、向量和混合路径，
逐问保存候选来源、Top-10 fact ID、语义状态、截断、穷尽状态、
延迟和实际 Embedding/Rerank 用量。先固定当前版本基线，再根据错误归因决定是否试验
词法覆盖、重排或直接支持核验；候选召回不足与候选虽靠前却不能回答要分别统计。
开发集上选择方案，盲测集只用于最终比较；在看到盲测结果前登记目标与允许的召回损失，
不从这 12/5 个探索案例反推出“通用安全阈值”。

- **Precision@3**：有答案查询的前三条中可直接支持答案的事实数，以三个位置为固定分母；
  同时报实际返回条数，避免少返回制造虚高精度。
- **Recall@10**：有答案查询的前十条覆盖其全部金标 fact ID 的比例，按查询汇总；
  另报词法独有、向量独有和两路共有的金标召回，防止只保留向量候选。
- **无答案误报**：分别报告无答案/难负例返回至少一条候选的比例、Top-3 中
  主题相近但不能直接支持答案的候选比例，以及最终 Agent 给出无证据肯定回答的比例；
  返回弱相关候选本身不等于最终编造答案。
- **边界与成本**：无权 fact 泄漏必须为零；按 Person/PersonGroup/Group/SELF、
  无目标/显式目标、正常/故障降级分层报告截断、索引覆盖、延迟、HTTP 用量和费用。
  非穷尽结果不得当作“全范围没有答案”的证据。

### 3. 完整 Agent 回放

从独立样本中至少挑 20 条（正例、难负例、无答案及歧义均有），把当时的真实
History/Rollup、可信 actor、场景和工具合同作为固定输入，分别覆盖正常聊天、SELF、
外部唤醒与原 Work 续接。用隔离数据库快照和假网关拦截发送、写入及其他外部副作用；
保留原内部事件/Work/执行 ID、预算与已完成回执的语义，不真的重发 QQ 或已确认效果。
记录模型是否在需要旧事实时主动调用 search_memory、不需回忆时是否避免无谓搜索、
首轮不足时是否改变查询或目标补查、遇到歧义/权限拒绝/截断时是否正确处理，
以及最终答复是否逐条得到**实际进入模型请求**的事实支持。冻结模型、Provider、
思考配置与请求日志结构；若换 Provider，另列一次回放，不能与检索算法改动混算。

只有独立盲测集显示预登记的精度改善、召回与费用可接受、权限零泄漏，
并且上述 Agent 回放没有无证据肯定回答或重复副作用，才能继续勾选质量验收；
小样本仍须注明置信范围和未覆盖场景。上线后的真实调用、管理页和长期漂移另行验收。
