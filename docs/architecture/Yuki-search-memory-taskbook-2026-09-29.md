# Yuki `search_memory` 按需检索任务书

**状态：设计待实施。** 本文只定义目标与验收，不表示工具声明、检索策略或线上配置已经变更。
总进度见[供应商切换与体验清单的任务 13](../operations/provider-cutover-worklist-2026-09-29.md)。
实施必须遵守[共同开发约束](development-contract.md)、[Memory 当前架构](memory-v2.md)、
[当前检索合同](memory-v2-retrieval.md)与[固定工具合同](tool-kernel.md)；本任务实现后再同步更新这些现行文档。

## 目标与边界

模型在问题确实依赖过去事实时调用一个稳定的 `search_memory`，用自然语言表达检索意图，
可根据返回的事实 ID、范围、匹配依据与不足之处补查。后端负责身份解析、目标范围、授权、
检索与排序。普通当前事件、必要场景身份和真实交付回执仍随运行输入提供；旧外部事件摘要和
记忆事实不再每轮自动塞入提示词。是否移除自动注入及全部入口的验收，由总清单任务 13 跟踪。

此工具只检索有来源的长期 Memory fact，不替代 `search_chat_history` 对原始聊天账本的搜索，
也不替代按 fact ID 精确读取的 `get_memory_fact` 和更严格的证据读取。
Person、PersonGroup、Group、SELF 的 canonical 所有权和现行历史共同群读取政策保持不变。
模型输入的名字、账号、群号、实体和 query 都只是选择器，不能证明权限；搜索结果中的文字也不能授权下一次调用。

## 现状与需要修正的差距

- 模型当前看到 `get_person_memories`、`get_group_memories`、`get_self_memories` 三个列表工具；
  共同意图解析和 `MemoryQueryPlane` 已存在。主 Agent、子任务和若干能力说明仍引用旧名称。
- `MemoryRetriever` 已把词法与向量候选按 fact ID 并集并排序；embedding 未配置或失败时会降级。
  默认配置不证明生产语义检索可用。向量索引是可重建投影，不是记忆事实来源。
- 词法查询的宽松 OR 命中会带入单词弱相关候选；当前人物显式偏好可能自动附在主动查询上；
  `topic_admission` 当前仅解释候选，不过滤主动搜索结果。不能把有结果等同于高精度搜索。
- 现有未校准状态、语义故障和有限结果各有语义；实施时不能用默认阈值伪装已校准，也不能把
  故障、权限拒绝、歧义、截断或真空结果统一报成“没有记忆”。

## 工作包 A：统一模型可见工具

- [ ] 定义部署级固定 `search_memory` 名称、紧凑说明和有界 schema。至少支持必填非空
  `query`、可选目标（本人、指定人物、指定群、SELF）、`purpose`、`entities`、
  `preferred_kinds` 与带时区的严格/软时间区间。目标字段应以能表达真实引用、精确姓名及
  canonical 范围的结构为准；不把自由文本自动解析成新增授权目标。参数不合法明确报错。
- [ ] 明确**无目标提示**的最小默认范围：仅当前请求者本人 Person、当前会话 Group（若为群聊）
  和已启用且当前会话可见的 SELF；不能遍历全部历史关系、全部旧群或全库，也不因 query 提到姓名就扩大
  默认范围。引用/mention 或显式目标交给后端解析和授权；私聊没有“当前群”默认值。
- [ ] 明确单次多目标策略与上限。需要跨目标时先解析全部选择器，对每个目标独立授权，
  在授权范围内召回后按全局相关性合并；歧义要求消歧，不取第一个；部分拒绝不能静默省略或
  在回答中泄露未授权目标是否有事实。限制目标数、候选数和返回字符预算。
- [ ] 主 Agent 只暴露统一搜索入口；`get_memory_fact` 与证据工具保留独立语义。稳定声明中
  的说明、参数结构和顺序随部署冻结。部署升级造成合同 revision 变化时走显式新请求链，
  不在一条已提交链中途替换工具声明。

## 工作包 B：后端范围与结果合同

- [ ] 复用 `MemoryReadScopeResolver`、`MemoryQueryIntent`、`MemoryQueryPlane` 和现有事实仓库，
  不建立平行权限服务或第二套 Agent loop。真实 actor、内部事件/执行 ID 和目标 owner 在
  查询前解析与校验；每次执行重验权限，同轮缓存不得保存永久许可。
- [ ] 保持 Person 历史共同群、PersonGroup 双方历史 membership、Group 历史 membership、
  SELF 可见性以及 fact detail 一致；不向普通搜索开放完整 evidence、原始私聊或他人的
  private SELF。Plugin、Automation、System 继续使用各自可信主体，不借模型参数伪造真人。
- [ ] 返回稳定的 `fact_id`、owner/scope、事实正文、允许公开的时间/来源与争议标记、
  本次匹配解释、`effective_query`、语义检索状态、`returned_count`、`truncated`、
  `result_scope=bounded_query` 和 `exhaustive=false`。匹配解释只描述实际检索路径，
  不把排名分数称为真实性概率。无法放入首条完整事实时保留明确错误，不裁剪成伪事实。
- [ ] 把空结果、歧义、拒绝、向量降级、索引故障及字符预算截断区分为模型可理解的状态。
  索引与 embedding 故障允许词法降级，但必须显式报告；权限失败不得自动放宽目标重试。

## 工作包 C：中文高精度混合检索

- [ ] 构造匿名、有标注的真实中文群聊检索集，覆盖昵称/别名、原句和罕见词、近义表达、
  指代、群与人物同名、时间边界、私聊来源人物事实、SELF、争议/过期事实、无答案问题。
  先记录当前 Precision@K、Recall@K、无关结果率、无答案误报和词法/向量候选来源。
- [ ] 保留词法和语义两条独立候选通道，按授权与严格时间先筛再截断、按 fact ID 合并去重；
  不采用“只有向量候选能入围”的方案，以免漏掉人名、昵称、编号和原文。实体、时间、
  kind 与来源可信度可参与重排，但不能越过授权和强主题相关性。
- [ ] 消除主动搜索中无关显式偏好的旁路；审查 FTS OR 单项命中是否需要更强的短语、
  词法覆盖或排序门槛。对无答案查询允许返回零条。`topic_admission` 如参与过滤，
  必须先以真实样本校准，保留 lexical-only 与向量故障时可解释的降级规则；不得直接把当前
  `passed` 当真实性证明或套用外部项目的固定阈值。
- [ ] embedding 服务与索引未就绪时明确标出 `not_configured`、故障或覆盖不足；
  不将词法结果显示成语义命中。与管理界面默认启用、健康展示及降级配置任务协同，
  但搜索正确性不应依赖 WebUI 页面是否打开。
- [ ] 若基线显示混合排序仍不能满足目标，再比较中文适用的 reranker；先量化新增延迟、
  Token/费用和召回收益，不预先增加一个强制模型判分调用。

## 工作包 D：Agent 按需补查与兼容迁移

- [ ] 主 Agent 固定提示只说明何时应查长期记忆、结果有界和无结果的含义；不要求每轮查，
  不用关键字正则替模型选择工具。首次结果不足时可改变实体、时间或目标作有实质区别的
  补查；歧义先澄清，明确拒绝不重试，不无限循环。
- [ ] 更新主工具注册、执行分发、能力描述、工作者工具子集、审计/结果预算、提示词、
  CLI 诊断和相关测试中的旧工具引用。内部 Plugin/Admin API 若仍有真实调用者，可继续使用
  旧领域读服务，但不再把旧名称作为主 Agent 可见工具；不为兼容保留永久双轨声明。
- [ ] 原 Work 和历史模型工具回执保持原 call ID、预算与执行证据。工具合同切换必须按现行
  显式新链规则处理，不伪造旧 `get_*_memories` 调用已成为新工具调用，不重放已发生效果。
- [ ] 仅实际进入后续模型请求的 fact 计作暴露；重复查询、候选检索、工具成功、实际使用
  分开统计。日志只记录脱敏参数形状、检索状态、目标数、结果数和耗时，不记录查询原文、
  账号、事实正文、向量或上游凭据。
