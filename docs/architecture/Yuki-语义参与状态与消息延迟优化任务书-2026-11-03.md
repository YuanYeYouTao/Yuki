## 1. 目标与排查依据

## 2. 理论最低延迟的工作量要求

`Δ`是本次真实新增或变更的输入量，`D`是当前确需核验的依赖及实际变更影响，`V`是实际输出量，`B`是本次必须读写的编码字节量，`T`是完整参与checkpoint规模，`U`是单元数，`Kᵢ/Rᵢ`是单元i本次需检查的引用/保留退休引用数；`A`是本次需处理的输入数，`Q₁/Q₂`是两阶段各自需处理的表达数。不同单元、人物或授权关系对同一来源的判断可有不同上下文；可以批读共同原件，但不能据此删除这些不同关系的实际判断。

| 路径 | 最低必要工作与优化要求 |
| --- | --- |
| 冷恢复/真实外部输入 | 至少读入并解释实际数据，具有Ω(B)或Ω(Δ)成本。外部格式在必要加载/输入边界解释，同一未变化同步阶段复用结果；运行中直接消费唯一类型化事实，跨await或依赖变化按实际重新核验，不固定调用次数。 |
| 已加载单元点查、重复输入/回执 | 利用原内部ID和已有关系直接定位，只处理实际需核的依赖与变化；不为一次点查重建完整T大小checkpoint或扫描其他单元历史。哈希点查按期望常数时间讨论。 |
| 退休来源成员判定 | 已有合适运行态表示时直接查成员；为R条无索引数据首次建索引可付O(R)，处理K条必要引用应接近O(K)，不能每条再建集合或线性扫R，也不能无变化时每tick重新支付历史全量转换。 |
| 时间推进和实际失效 | 处理当前数学模型确需更新/评分的项、实际到期项与相关影响。必要输出V或fan-out D至少需Ω(V)/Ω(D)；旧关系总量不应成为无变化重复重建的理由。 |
| 纯控制命令 | 未消费的前台语义binding、水合与checkpoint解析的额外成本目标为零。保留该命令真实需要的入账、身份/授权、generation、effect gate和实际发送/确认。 |
| 持久化 | 确需提交B字节时至少Ω(B)。同一安全提交边界内只编码实际需要的表示；无冷体变化不导出冷体，不为经验容量统计再导出完整State。 |
| 当前来源/授权 | 实际执行处核真实依赖。能在同一读快照/无await阶段共享的原件和计算共享；跨await旧准备不成为许可。缺少能证明局部变化的真实信息时，保留必要核验并说明代价。 |
| 数值评分 | 共享相同输入的计算，删除重复扫描；再评估现行公式的解析或分段求值。保持数学、浮点/精度与抽样合同，不能静默放宽精度或延后应发生的判断来制造低耗时。 |

“最低”需要从事实依赖和输出证明，不能用人为阈值、隐藏等待、减少观察机会、清空仍需状态或关闭功能达成。对仍不能证明最优的部分，明确剩余工作、上下界、精度条件和测量差距，继续推进必要的算法工作；最终结论按实际已证明范围写。

## 3. 设计裁决

### 3.1 唯一类型化运行态

已知参与关系由一个权威类型化状态持有，加载后直接读取和更新。删除日常调用中的`dict → model_validate → 修改 → model_dump → dict`循环；序列化DTO只在真实输入、加载和持久化边界存在。同一个事实不保留两份需要双写同步的可变权威对象。

Host通过明确的只读领域接口读取，修改仍由真实owner进入既有变更/提交边界；不能暴露可绕过dirty、顺序与身份事实的可写容器。权威对象可以有为实际查询服务的派生索引：索引不授予资格、不作为独立事实源，由同一owner按真实变更维护或从不可变事实重建，不另建持久账本/全局版本。优先选合适的原数据组织，必要时说明索引的生命周期、内存、更新与冷恢复成本；不因“唯一权威”拒绝有必要的加速结构。

未知version/扩展保留唯一opaque原件，按现行读取合同处理，不当空状态覆盖。现有单unit窄读特例只适用于已知version=1带未知额外字段，继续核scope、actor、revision、retired/invalidated与原顺序；未知version=2等格式不能借此取得资格。

当前协议“typed读取只在单次同步调用内复用”“原容量不变”等条款要随实现直接改写：权威运行态与可丢局部计算是不同职责。删除或替换旧说法和对应测试，保留原已提交请求与历史验收原件，不并列两套矛盾合同。

### 3.2 变化与真实消费者决定处理范围

输入、表达、晚到锚点、hint/review、来源修订/撤回、到期和generation变化分别定位实际影响。用已有事件、admission、effect/run、operation和来源版本维护幂等；同一批中后项看到前项修改后的状态。对账前后的真实边界继续发挥作用，共同部分直接复用，重复已确认部分局部返回。

辅助状态按实际消费者清退。当前关系、在途观察、原已接纳输入/工作和迟到回执仍需要的来源按原事实可查；无消费者的重复投影、完整祖先链和短期调节记录直接删除。身份、授权、已付计量、永久事件与真实回执留在所属账本，短期控制器不复制成第二套持久事实源。

### 3.3 删除优先

禁止防御性编程。优先删除无用条件、重复数据和转换，不用新增缓存许可、全局revision、影子水位、独立计数表、第二套调度或新的次数/TTL/字节帽替代。现有64单元、1024 seen、原文窗口及1/16 MiB等数字各有不同职责，不能据其声称计算量恒小，也不固定为新设计合同；核实际用途后清退无必要部分。

先消除工作，再评估真实剩余计算的调度。扩大并发、搬线程或增加让步不能替代算法删减；任何执行位置调整仍须核共享状态、GIL、顺序和取消行为。所有性能验证属于改动验收，不加入产品的工作接纳、授权或完成流程。

## 4. 施工任务

### D01 基线与失败场景

在两个隔离工作树固定Host和库修订、lock、解释器与Pydantic版本，记录现行消费者和调用链。先写§6失败场景的预期并尝试E2E基线复现，再改对应产品代码。环境或依赖使某场景暂未复现时，记录原因与缺证，继续不依赖它的工作，不伪造失败或把未验证判成完成。旧报告数据作为对照，不重复购买模型或向真实群发消息来重做已有证据。后续源码、库pin与合流由主Agent统一安排。

### D02 替换全量checkpoint往返转换

由参与库实现唯一权威类型化运行态及加载/保存DTO边界，Host改用领域接口。覆盖`observe_unit_input/expression/hint`、参与视图、人物收集、source refs、Session/observer、Host普通接纳与反馈、诊断、测试fixture和所有直接namespace reader。重复查询与重复回执不先全量validate、dump或深比较；按真正变化维护既有dirty语义。已知/缺失/旧格式/未知扩展分别沿现行合法行为处理。

明确类型化对象的原地变更规则：现有`_same_fact`遇到同一对象会直接返回相同，不能先改`checkpoint.units/expressions`，再把同一对象交给`_set`来判断是否变更。由原owner在实际变更处正确发布dirty/提交事实，或采用不会丢失旧新差异的更新方式；只读与真正幂等调用不误标冷体变化。不得为规避漏标而每次强制dirty、导出完整JSON或深复制全状态。冻结捕获前后的修改分别归属真实保存批次，既有保存完成/失败/取消不清掉后来新增变更。

### D03 消除退休引用与关联的乘积扫描

同时去掉`_unit_ref_valid`重复构造退休set、`_retire_participation`的tuple线性包含，以及同一次同步计算中重复的表达映射/所属关系推导。优先以权威运行态的数据组织直接支持成员与关联查找；需要顺序或重复项时保其真实语义。原序列确有不可删用途时，允许由它派生必要成员索引，按§3.1维护；索引重建/更新本身不改变领域事实，也不触发无用冷体保存。防止可写事实镜像与永久资格缓存，不把正常的派生索引一概禁止。

真实撤销、revision与原关系证据仍决定有效性，任意`seen`命中不能复活旧关系。无实际影响时省掉对全部历史的重新推导；有到期、纠正或同源fan-out时处理实际影响，继续消除可以删除的全量工作。

### D04 Host输入与表达对账按实际变化应用

处理[`sync_scope_effects`](https://github.com/YuanYeYouTao/Yuki/blob/b81c20a55d3a714168e7d8306ccfbf74dddb3eb4/src/yuki/services/participation_feedback.py#L252)与hydrate/普通接纳：前阶段确认表达，水合后按真实SELF SourceRef补锚点。删除无用重复遍历与逐行全状态解析，不要求保留固定两遍，也不机械删掉第二阶段。

同一读快照和同步阶段批读、归组并共享admission、人物、source、输出event及原回执。消除相同材料重复hash/复制的前提必须来自真实不可变材料或本阶段事实，不能凭对象ID、updated_at或dirty标记代替来源有效性。跨await后按本次执行需要复核；批内前后项顺序、caption父发送、原Presence与逻辑分片、失败/未知/迟到回执都保原事实。

同步处理普通接纳的写时热点：当前[`continuation_matches`](https://github.com/YuanYeYouTao/Yuki/blob/b81c20a55d3a714168e7d8306ccfbf74dddb3eb4/src/yuki/services/participation_ordinary.py#L333)可在[`ordinary_admission.commit`](https://github.com/YuanYeYouTao/Yuki/blob/b81c20a55d3a714168e7d8306ccfbf74dddb3eb4/src/yuki/conversation/ordinary_admission.py#L420)的writer内调用全参与视图/`continuation_current`。除去Pydantic重解析，还要把全量关系推导、历史/身份准备移到首次写入前；writer只核本次真实相关source、actor/root、授权、场景、generation及领域依赖，并作必要局部判定。依赖变化时沿原请求退出未写入事务并重备，保原ID，不以全局revision或准备时allowed值代替当前资格。

写前准备必须包含当前资格的正、负依赖：原来源版本不变期间，quiet、review、关闭边界、更新邀请或另一匹配单元仍可能改变资格与唯一性。定位并复核这些相关关系及必要的不存在/唯一匹配条件，复用已有锁或领域原子边界，不能只检查准备时basis的revision。准备与写时判断之间发现变化时重备原请求；已接纳Main/Work和已发生效果仍沿原合同处理，不因后来短期纠正倒退。

### D05 删除控制命令未消费的参与准备

沿原命令解析和Processor分流，让确定性内建命令跳过没有消费者的前台语义binding、hydrate与Social同步，优先覆盖`/ai ping`；逐命令核实实际需要，不增命令白名单框架或另一调度器。`/ai new/stop/compact/forgetme`保各自generation、取消、准备与隐私边界；插件命令和普通`@`/引用/前缀Main按实际效果、admission与权限处理。

保留原内部事件、canonical去重/必要入账、执行时原Person/root有效性、原限流、generation与effect gate和真实发送回执。群聊且已装配autonomous服务时，现有入账后`observe_context(..., direct=True)`背景提示继续沿原事件处理；私聊不由此获得群scope队列。当前`hydrated_scope/event_scope`的前台hydrate可能未带direct字典、与后台tick抢先排观察，删除未消费准备会改变该时序。按直接输入合同覆盖前台、tick、dirty合并/溢出和未加载scope的交错；保真实账本、已在途观察与原已付回执，不把旧无消费者准备的全部副作用冻结成必须保留。

### D06 缩减关系辅助历史

对continuation、review/hint basis、retired refs、anchors、expressions、seen/source_order、边界释放证明及observer队列逐项记录事实源、消费者、必要寿命和删除后行为。优先利用原admission、已冻结在途Snapshot和原effect/receipt，去掉重复祖先与已无用途证明；必要历史按原内部ID在reader批量准备，writer不扫描历史。

保持quiet、真实stop/转题、更新邀请、unknown、同时间顺序和已接纳Main的不同作用。迟到事实能按原ID结算，已退役短期关系不靠旧回执重建；原工作和已发生效果不被辅助清理回滚。核查现有经验容量/计数限制的实际用途，连同无必要限制及其冻结测试一起删除，不新增补偿上限。

### D07 快照只支付必要编码与提交

唯一运行态仅在实际提交边界转为不可变编码，复用既有head/body、dirty、layout、单owner store、revision CAS及取消/提交确认对账。无冷体变化不构造冷体；删重复完整State导出、无用拷贝和仅为准入统计的第二遍JSON。

删除每scope 1 MiB、全局16 MiB的经验字节拒绝及每次保存的全库`SUM(logical_bytes)`，连带清理仅服务这些限制的派生长度计算、配置与测试；有真实其他消费者的字段按实际用途处理。SQLite/文件系统真实错误、CAS、短事务和未知提交继续按原事实结算，不增加替代额度或总量影子表。

优先复用现有wire与存储布局，类型化运行态不要求同时重写持久化协议。删除长度字段时同步处理`SnapshotWrite`、现存head/body的NOT NULL列`logical_bytes/logical_size_delta`、旧单表`SnapshotStore._migrate`及`LegacyState → freeze`路径。原长度字段还参与body/进度配对检查，需用真实格式结构继续识别缺半对/损坏，不能仅删条件后放行不完整状态。确需schema变更时采用最小一次性原子迁移，明确reader衔接及中断/回退行为；保留字段有真实消费者时仍保其真实含义，不填占位值冒充实际长度。迁移不调用advance、模型或发送来补状态，不另建计数影子。

旧代快照保留与回收另核真实reader、pin、在途/未知接纳及原已接受执行恢复。确认不再服务实际消费者后复用原scope/revision删除派生快照或省掉无用旧代保存；`is_current=false`、年龄或体积本身不替代事实判断。先在隔离副本验证，不因本任务书直接清生产库。格式确需升级时提供原子转换与兼容回退边界，原数据库不覆盖新消息和回执。

### D08 评分与候选处理达到最少必要计算

删除全human同组的两次相同积分、概率唯一最大值的重复`max`，将新事件options去重和相关事实按真实键/顺序处理。保event与boundary各自去重口径、SELF锚点优先顺序、全部合法候选、并列/unknown和冻结材料。

继续评估`aggregate_attention`的分段积分及候选/边界/观测失效的交叉扫描，依据现行数学与数值合同选择最少必要求值；真实同源失效的fan-out保留。评分不能靠少观察、降低精度或延后决策提速。正常Host常见同时有效结果约不超过8的估算不作为库接口硬帽；64/256合成形状用于压力与扩展性，不冒充生产负载。

### D09 SQL与scope调度

捕获真实ORM语句、参数形状、SQLite版本、计划及行数，优化`list_active`和批量run事实归组，使发现/对账成本随实际活动与相关数据增长，消掉无关终态扫描/排序和页内反复过滤。按需要选择现有查询与最少索引，核读写成本；不建立平行active账本。

人物、Social、caption父回执、事件来源、历史页和必要活动聚合按其真实依赖批读，来源hash所需作者、正文、提及、suppression及因果字段完整。保持reader准备、writer相关复核、FIFO与短事务。scope生命周期沿既有owner，处理热点scope的实际事件循环影响与其他scope延迟，避免无业务依据的新并发配额或协调器。

### D10 诊断与服务器等待

删除诊断关闭或现有准入信息已能确定会丢弃时仍发生的昂贵payload构造，以及Snapshot/trace的重复dump、冻结和编码。实际收录时在真实来源和隐私代次边界捕获不可变原Snapshot/材料，不能把可变Controller或嵌套payload交线程后再读；确定丢弃时按原coverage语义记录缺样。可丢诊断不拖住确认业务；真实账本、权限、已付协议和效果回执不降格为可丢诊断。

核公开健康的实际字段消费者及DTO/API合同，删除无实际用途的Memory全量hash扫描；精确embedding状态沿现有受权按需查询执行。字段删减同步服务端、SDK/客户端、文档和受权命令的真实消费者，保留必要的status/database/连接故障含义，不以旧缓存或伪造覆盖率冒充精确值。`/livez`、`/healthz`和ping分别计量。

性能回放及有后续上线授权时，按相同时段采CPU、RSS、swap、major fault、PSI、磁盘吞吐/等待和SQLite诊断差分；把算法CPU、事件循环、主库排队、实际I/O、网络/模型分别归因。采样不与大量日志/数据库导出重叠，不仅根据累计BlockIO、已用swap或GIL频数判断事故原因。服务器配置改动沿实际授权单独记录。

### D11 E2E与复杂度验收

先定义并按D01尝试复现§6的失败场景，再随D02–D10同步实现真实Host/Controller/SQLite主链E2E；暂未复现的部分保留缺证，不阻塞不依赖它的工作，也不计为通过。确定性假Provider/网关用于可控输入和回执，真实边界由合法合成事件、admission和效果经过原服务创建，不直接灌不可能通过Host的ID或绕过Processor。必要隔离算法实验作性能分解，不能代替主链。

在同数据、同配置、同到达负载的旧/新版本比较原始墙钟/CPU、吞吐、延迟分布与工作量，并与§2最小必要链比较。先定位仍可删除的成本，修正后复测受影响部分；不因达到某个经验毫秒数提前结束。产出可验证的脱敏artifact，真实模型/QQ、生产自然流量与模拟分别说明。

### D12 两仓合流与现行文档

主Agent统筹库接口/格式、Host消费及lock更新，执行子Agent完成各自写集。参与库与Host分别验证，再用实际pin安装做联合E2E；更新现行协议、模块文档、迁移/兼容说明及陈旧测试。旧任务书只保历史基线，不恢复已删除终态重放或旧入口。

使用与改动风险相符的静态检查和CI，避免重复无关全量测试。实施记录列出每项代码、验证artifact、残留必要成本和未证明部分；提交/推送、合并、上线与真实流量按实际发生记录，不由本任务书推定已获生产操作范围。[Issue #560](https://github.com/YuanYeYouTao/Yuki/issues/560)的预算/执行持久恢复另案，不与本期性能修复混作同一验收。

## 7. 性能计量与完成证据

### 7.1 计时边界

保留同一合法请求的单调时钟时间点：接收 → canonical pre-admit/入账 → 当前身份/配置 → 必需参与准备 → coordinator/effect gate → 命令或Main → 发送派发 → ACK/未知 → 确认入账。按真实调用嵌套与并行关系记录独占区间，包含式子阶段不能相加；CPU、事件循环调度、数据库排队与物理执行分别标注。

参与子阶段分别标首次效果sync、hydrate、外部await、真实来源/授权重核、后续sync与提议/接纳；保存分别标full/progress freeze、writer准入/连接取得、SQL、真实commit/rollback和取消清理。各span给出起止、嵌套与并发关系，用互斥自耗时/关键路径计量。无await同步段可测线程CPU与墙钟；跨await的进程CPU包含其他任务时不归给单请求。

同时报告现有ping文本计时与完整入口/送达观察。前者开始晚于pre-admit，结束早于发送ACK，不能通过移动计时起终点来宣称整体改善。模型等待、观察去抖与最短间隔、网络往返和实际gate等待各有独立含义。

### 7.2 工作量与负载

以原报告真实快照作隔离重状态对照，并新增合法Host合成夹具。规模轴至少包含单关系引用增长、当前活跃/无关历史规模、实际依赖fan-out、scope数、表达回执数、观察/候选及冷/热持久化；范围从轻态经过现有资源边界，覆盖其两侧，不把1024或64固定为未来准入合同。

优先在与生产运行时/依赖/配置一致的隔离Linux环境，同机、同数据、同配置与相同到达负载交错运行旧/新版本，记录预热、冷/热缓存、GC、解释器/依赖、试验次数及机器资源。到达负载包含按既定时刻输入的场景，避免服务慢时自动降低输入率而隐藏排队。测主链墙钟、吞吐、事件循环lag、CPU，样本充分时给p50/p95/p99及样本数/不确定性，并保留原始样本；少量微基准只给样本统计。Windows回放说明规模形态，各历史代末态/当前代、机器与窗口不混作生产因果证据。
