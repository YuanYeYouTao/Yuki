## C1 观测语义

新增 agent_evidence 内容无关日志，以每次 AgentRunner 调用生成的 UUID 关联，包含 origin，
并携带已有 ambient runtime_turn_id（无真实关联时为 null），可与现有调用/回执表连接。
request_prepared 记录实际函数/native schema 指纹、已暴露的已知读取工具、Web route 与最终收尾状态。
tool_result_staged 区分执行/缓存复用，仅表示结果待交给模型；没有后续响应不能算确认暴露。
response_received 单独报告已接收后续响应的前批结果数，以及本次 native 完成/失败事件和 citation 数。
确认是保守口径：网络失败或取消后模型可能已接收的输入仍不标为已确认；不能当作模型未见。
prepared 不是网络发送计数，不能代替真实验证 transport 预算；native 事件数也不是去重后的调用次数。
不记录工具参数、查询词、账号、引用 URL、结果正文或 provider 原始错误。

已通过 49 项 Web/聊天目标测试；其余 C1 人工机会标注和后续 C2–C5 尚未完成。

## 固定查证合同及结果状态

人工初筛 11 条真实查证机会（原文/索引仅在仓库外），发现明确要求搜索却仅口头应答的案例，
也有明确要求搜索后确实产生 native 运行的案例。人物身份查询仍有无 Person 补查便断言不存在的案例。
其中若干连续追问可能复用前一轮材料，历史 prompt 暴露不完整，标为 context_dependent，
不强算漏查率；没有逐项核验外部来源支持度，不能把成功搜索判成回答正确。
这 11 条是机会分析试点，不是 60/30 相关性验收集；180 条原始候选也不等于 180 个合格标注样本。

Main Agent 的 core.contract 固定声明历史/人物补查、时效/明确联网、普通闲聊不强制查证。
不修改人格，不引入分类模型、强制工具调用或每轮审查；原完整 History/Rollup 结构保留。
普通记忆和受控 Web 工具结果增加 evidence_state：来源、查询状态、数量、截断、partial_failure、
后端真实 source_refs。delivery=staged 只说明待送给模型；后续响应确认仍独立记录，不能自报已注入。
native 来源仍走原有事件/citation/来源持久化，不伪造函数结果或普通记忆回执。
此状态不意味着每句事实已被语义验证；未知/弱候选必须结合正文判断。
结果预算包含新元数据，Web 被缩短时明确 truncated；记忆仍不截事实正文。
Memory 暴露确认从并发槽等待前移到模型响应收到后，避免取消/发送前预算拒绝被记成注入。
这是保守确认：已发送但未收到响应的输入仍属未确认，不能据此说模型一定没看到。
