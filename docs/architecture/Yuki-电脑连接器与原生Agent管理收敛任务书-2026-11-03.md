| 用户动作 | 必须产生的效果 | 不隐含的效果 |

## 4. 原生配置删除和运行态差量应用

### 4.1 一个配置更新入口

收拢add/configure/remove、full-access和server改址的配置更新，复用原私有文件原子发布。安装发现、命令能力和路径准备放在短写入序列之外；进入该配置的更新序列后重读当前值，只修改本次实际字段。文件原子替换不等于并发读改写已经串行化。

允许使用必要的同配置短写互斥，其owner、目录和寿命由原Config写入入口持有，覆盖实际支持的Desktop及独立CLI调用者；不拿整个运行期installation锁阻止正常配置，不持锁等网络/进程，不增加全局revision、影子副本或自动重试。无关字段、明确false、原env/profile/socket、凭据与原ID保留。

新增实例沿调用方已经分配的稳定ID一次保存，明确create/edit；编辑不存在的原实例仍报告原事实，不能默默重建。重复删除只确认已无该条配置，不创造新ID。部分保存或确认丢失时查原文件/原请求，不能统一写“设置未保存”。

### 4.2 不用重启整条电脑连接

在现有Connector中读取同一配置并按目标实例差量应用：标签变化不重启原生进程；真正连接参数变化只作用于后续使用该参数的原生连接；删除A不影响B、Shell与文件传输。Desktop保存后在线触发原device已有的status/资源命令及catalog通路，不能靠之后恰好收到另一条用户命令才生效；断线重连在hello前主动刷新。独立CLI若无法即时通知，如实保留待原服务加载状态。不新增本地常驻监听端口、轮询器或第二个执行器。

从配置删除或修改连接参数，与原生owner退出必须分开。Codex stop只应关闭Yuki持有的proxy；Claude/ACP的SDK退出可能结束它们持有的进程，不能承诺通用driver.stop完全无影响。删除立即清掉本机待发选择，不等待所有操作结束；运行态和云端候选以实际应用/接纳为准。原已派发操作仍由其原owner和journal结算，必要时让原owner沿现有持有关系收尾；新参数供后续操作，不凭同一local ID把原请求转交新owner重派，无法查证时保unknown。运行态确认删除后的新任务不可因drivers仍持有旧owner而进入；同一已提交operation的查询/迟到结果保持原事实。

配置写入、运行态应用和云端同步分别反馈。在线时应用目标差量；WSS重连发送hello前也先读取实际原配置，不能再次上传已删实例。旧版或独立服务若不支持即时应用，可以如实显示“本机配置已删除，运行态/云端待原服务重新加载”，不得宣称已同步，也不得擅自接管服务或重启无关执行。目录ACK不能成为本机删除配置成功的额外门槛。

### 4.3 当前目录与历史保留

以当前设备连接上报的**完整catalog快照**确定现在仍配置哪些原生实例。复用现有实例行和catalog元数据表达是否仍在最近有效完整快照中，不新增影子目录。缺席项退出当前候选，保留原稳定行、旧label/driver及全部原回执；unavailable实例仍属于配置，断网本身绝不能推断删除。

旧catalog缺少新的登记事实时沿既有记录解释，收到真实完整快照再纠正。内部标记须由投影显式消费，不借extra=allow无意暴露成公共字段。旧连接被替换后不得用旧catalog恢复已删候选；沿现有连接ID/当前owner判断，目录事务不等待网络。实际收到的合法迟到response仍沿原device、instance、operation核对并保存，不能因原pending已经结束而丢弃；合法迟到event沿原归属提交后ACK。未收到或无法确认的结果保unknown，并在授权允许时按原journal查证，不给response新增ACK协议或承诺断连后必达。

Desktop设置页以所选安装的本机配置为准，尚未上报、离线或旧版独立服务中的条目仍能编辑和删除。本机任务候选不继续保留已在本机删除的目标；服务器接纳与同步状态另行呈现，其他客户端按服务器最近有效完整快照列出当前候选。复用原配置与目录，不再造第三份列表。删除当前选中的A后清掉未提交的A/session/cursor选择，不自动改指B；已经提交的请求保原目标和UUID。

## 5. 电脑记录移除与本机连接移除

### 5.1 服务端同一设备行保存移除意图

现有revoked_at只表示撤销，无法区分“保留已撤销记录”与“用户明确移出当前列表”。在原client_devices行增加一个nullable移除事实（建议removed_at），只保存这项真实意图，不建立回收站、影子设备表、经验保留期或自动清扫服务。历史device UUID不改、不复用为另一人，不物理DELETE级联会话/操作/事件。

提供独立的类型化移除操作。保留现有DELETE /client/v1/devices/{id}的撤销合同，不能仅因HTTP方法名就改成物理删除。移除仍有效设备时，在同一短事务中复用撤销领域行为并保存一个原移除命令回执；不要用同request_id写两份相互冲突的client.revoke与remove回执。已撤销项直接移除，重复请求查原结果，非本人按现有Person/device来源拒绝；不额外引入superuser作为操作本人电脑的条件。

默认/me及当前任务目录排除明确移除项；未移除的已撤销项仍按真实状态呈现。操作记录保留原设备来源。设备撤销不等于远端执行已经中止，不显示虚假的“任务全部停止/数据已删除”。迁移从实施时最新单head继续，不重写冻结旧迁移。

设备安全页为有效与已撤销的电脑连接器提供“移除…”；撤销与移除说明各自效果。当前聊天设备若涉及登出，沿已有LogoutFlow，不绕过原凭据撤销和本地资料选择；本期重点是电脑连接器记录。

### 5.2 取消本机关联的范围

在“这台电脑”设置提供“取消本机关联”，明确它只停止当前managed进程并取消Desktop选择，不冒充删除Connector配置或撤销服务器授权。保留原config/token、journal和原生登录；仍有效的服务器记录需沿第5.1节的撤销/移除操作处理。说明停止managed进程会影响其持有的本机Shell等实际执行，原文件/原生服务不随之删除；若以后重新配对，不能把新device直接写进旧journal namespace。

独立安装仅取消Desktop关联或保存用户明确要求的配置，不自动卸载OS服务、删其目录或接管启停。断开关联后，已有独立安装可以作为“可关联的原安装”被发现，但不能恢复为已选中的活动连接。远端移除设备条目没有权限删除那台电脑的文件；本机配置与服务端记录的结果分别显示。

不增加一键删除所有资料或通用递归清理接口。用户本期要求的是能删除配置、移除不用的记录；物理清空原执行资料不属于完成这些动作的前置或默认效果。

## 6. 删除后仍能读取原事实

沿现有Person族和原instance→device归属校验读原operation/session/execution，不把是否仍在当前配置或凭据是否可派新任务当作所有历史读取前置。另一人物仍不能读原私有资料。服务器已持久的原终端/原生回执应有可达的Work/原操作或历史入口，不能把设备加回新任务选择器才能查询。

原Connector journal按operation_id查询可复用，但只能在当前来源仍获准通信时发只读查证；撤销凭据不重新授予通信权限。已删driver不能把旧running/pending证明为实时状态：有真实终态则返回原终态，无进一步事实时保last_confirmed和unknown/uncertain，不重发原命令。只有离线电脑保存而服务器从未取得的输出字节不能凭空恢复。

原在飞响应、事件和终态按原ID、归属、顺序及授权边界继续归并；目录删除不能让同一次已经发生的效果变成另一实例的请求。迟到终态不能被较旧的未知投影覆盖。

## 7. Codex启动、状态与错误收口

### 7.1 只准备用户已选的服务

原生安装不等于服务已运行。本期把用户已配置的默认Codex服务准备接到新增配置保存后及重新开启Connector时的现有启动流程：复用当前运行owner，必要时调用该安装所支持的官方daemon start，再完成原proxy/initialize。保持原CODEX_HOME、安装来源、socket/endpoint、账号及会话。显式socket/endpoint优先，只连接用户指定目标，不启动默认daemon冒充成功。

以本机实际能力为准，不写死旧版本目录、品牌推断或仅凭文件存在宣布就绪。缺完整安装包、不能启动或目标不支持时，说明实际原因，Shell/文件和其他实例继续可用；不额外下载安装器、替换已有选定包、运行bootstrap/restart/update、启用远程控制、替用户登录或改原生权限。允许所选完整CLI的官方start按其合同准备该profile缺失的本地daemon包，不增加“daemon包必须预先存在”的门槛；准备失败如实报告，不自动换另一安装或owner。

参考[与现场匹配的官方0.166合同](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/app-server-daemon/README.md)：start是幂等启动，实际采用原profile选定包；缺包时可用发起命令所属完整CLI包作本地准备来源。其正常流程还可能处理上游判定过期的恢复文件、调整feature overrides或按用户原偏好启动updater。这不等于已证明现场丢失原transcript，也不是完全只读操作。必须用隔离profile核实真实包来源、运行版本和附带效果，不承诺“必定是调用exe/绝无副作用”；Yuki不额外直接修改恢复文件、原更新偏好或配置来假装启动成功。版本差异按当前上游和实际可执行文件验证。

关闭Yuki只结束自己持有的Connector及Codex proxy，不顺手停止用户Codex daemon、其他会话或原生更新器。不得把启动服务与创建模型任务混成一次操作；启动/就绪E2E不发turn/start或付费模型请求。

### 7.2 状态从真实阶段得出

分开表示配置已保存、Connector进程启动、服务器接纳、Codex服务可达、原生握手/登录、实际任务结果。spawn事件不能代表网络已连接；原生不可用不把整台电脑说成离线。后台子进程立即非零退出、锁冲突或配置损坏应沿实际退出事实更新页面，不等用户再点一次刷新才纠正成功提示。

合并doctor/diagnose的公共诊断事实和错误处理，保留必要的“仅就绪”与“目录查询”用途差别，不再维护两份启动/异常语义。InvalidMessage不是固定的“daemon未运行”同义词：只有原proxy/socket证据支持时这样报告，其他握手失败保阶段与可公开的实际原因。原生完整输出、密钥和账户资料仍留在原私有边界，不能把原stderr原样回传UI。

诊断和页面busy状态必须可取消；断开、取消后清理本次自有proxy、relay和pending请求，不停用户daemon或操作会话。官方start可能已拉起后台服务却尚未返回确认；此时取消只说明观察结束，页面保留未确认并可重查原目标，不反向声称服务未启动，也不restart/stop。对端完成HTTP握手却不答initialize/account/read等情况分别验证，不新增固定重试次数、延长timeout或固定sleep作为就绪判据。

## 8. 旧服务迁移与可删除逻辑

Windows的真实Scheduled Task和本地service.xml不是同一事实。查询实际登记，分别处理任务缺失、权限拒绝与其他失败；不因XML存在就必须卸载，也不因XML缺失就忽略仍存在的旧任务。macOS plist本身的登记语义单独处理，不照抄Windows规则。

stop/uninstall只等待它实际成功停止且确属该服务的进程。/End失败或任务不存在时，不无限等待同目录锁上任何owner，更不能强杀手动run/其他安装。真正的旧服务按原安装迁移、确认退出；保配置/journal/native身份。现代Desktop不注册新的OS登录任务。

明确清理：配置add/configure重复写和重复发现；重复诊断准备；实际为子进程却仍叫service的桌面内部命名；无消费者ConnectorRunner类型；旧“背景連接”定位和“只保存/保存即能交代任务”等失真文案。同步主仓与桌面当前合同/README/测试，不在旧说法后叠矛盾补丁。删除文件时一并追调用方、配置、提示、测试和CI，不新建兼容别名替换垃圾。

明确保留：冻结LocalExecutor历史表和原回执、当前仍被任务目录选择使用的chooseProject、独立CLI服务、真实profile/socket/endpoint消费者、不可变运行包及平台/架构/来源校验。不能按旧文件名或GUI没暴露就判死代码。

## 10. 编码前固定的失败场景与验收

采用隔离profile、临时数据库和真实桌面IPC/CLI/Connector/测试服务器，构造两台设备、两个原生实例及一条运行中Shell。下面是必须覆盖的已知失败条件，不把假原生owner称作真人账户或付费验收。

| 验收 | 场景与必须观察的事实 |
| --- | --- |
| V01 | 已选daemon包存在但服务停止；仅有所选完整CLI包而原profile尚无daemon包：分别验证官方启动/本地准备的真实来源、profile、版本及设置/恢复文件/updater效果，握手后才显示就绪；缺完整包按原失败，不隐式下载或换owner，无新thread/turn |
| V02 | 选定服务已在运行且有原会话：复用同owner，不restart/update，不重发原执行 |
| V03 | 自定义socket/endpoint、不同CODEX_HOME、多安装：不连接其他默认owner，缺失/不支持按实际报错 |
| V04 | 原proxy立即退出、socket拒绝、错误HTTP：报告真实失败阶段；不把全部InvalidMessage映射同一原因 |
| V05 | HTTP成功但initialize不答；initialize成功但account/read不答；官方start已拉起后台服务但确认前取消：退出busy并保真实未确认，可重查原目标，不假成功、不restart/stop原daemon |
| V06 | 只改A标签、空改动或无关配置：B、Shell和文件传输不停止，原native owner不重建 |
| V07 | A正在执行时修改真实连接参数并切换owner，尤其覆盖Claude/ACP：只应用A后续连接；B和Shell保活，原A工作不因保存被主动中止，沿原owner继续/结算；不能只以查到unknown当作保护成功，不转给新owner重派 |
| V08 | 删除空闲A且没有其他外部命令触发：本机配置、运行态及云端当前候选按保存后的显式刷新移除A，B仍可用，原device/instance/凭据/journal保留 |
| V09 | 删除有原执行的Codex/Claude/ACP：删除不被历史活动阻止，不发自动cancel，也不因删除主动中止原owner持有的执行；验证原工作真实继续/结算，不能仅以unknown代替保护成功，不虚报任务完成 |
| V10 | 删除生效后新命令/旧待发选择到达：新任务不进入已删除目标；同operation重放只读原记录 |
| V11 | 原任务结果丢失、迟到终态、事件延迟/ACK丢失：原ID/来源保持，event提交后ACK；已实际收到的response按原操作保存，未确认保unknown与last_confirmed，不重派 |
| V12 | 本机文件写失败、写成后运行态未应用、云端离线或同步未确认：无其他命令辅助时仍分阶段如实显示，可查原配置，不撒谎整体成功/整体未保存 |
