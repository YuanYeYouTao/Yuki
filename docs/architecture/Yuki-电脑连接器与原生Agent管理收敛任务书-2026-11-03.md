## 4. 原生配置删除和运行态差量应用

### 4.1 一个配置更新入口

沿现有保存路径去掉add/configure重复写和重复发现，只保存本次真正修改的字段，保无关配置及明确false。安装发现、命令能力和路径准备不占文件写入。文件原子替换不等于并发读改写已经串行化。

若实际多写者竞争确需串行，在原配置写入入口做必要的短处理，不预建通用锁框架，不拿整个运行期installation锁阻止正常配置，不持锁等网络/进程，不增加全局revision、影子副本或自动重试。原env/profile/socket、凭据与原ID保留；不为改保存入口顺便重写所有无关配置模块。

新增实例沿调用方已经分配的稳定ID一次保存，明确create/edit；编辑不存在的原实例仍报告原事实，不能默默重建。重复删除只确认已无该条配置，不创造新ID。部分保存或确认丢失时查原文件/原请求，不能统一写“设置未保存”。

### 4.2 不用重启整条电脑连接

在现有Connector中按目标实例应用变化：标签变化不重启原生进程；真正连接参数变化用于后续连接；删除A不影响B、Shell与文件传输。Desktop保存后沿已有最短通路让运行态反映配置，可复用device-status和catalog通路，不锁死具体调用顺序；不能靠之后恰好收到另一条用户命令才生效。重连hello前读取实际配置。独立CLI若无法即时通知，如实保留待原服务加载状态。不新增本地常驻监听端口、轮询器或第二个执行器。

从配置删除或修改连接参数，与原生owner退出必须分开。Codex stop只应关闭Yuki持有的proxy；Claude/ACP的SDK退出可能结束它们持有的进程，不能承诺通用driver.stop完全无影响。删除立即清掉本机待发选择，不等待所有操作结束；运行态和云端候选以实际应用/接纳为准。原已派发操作仍由其原owner和journal结算，必要时让原owner沿现有持有关系收尾；新参数供后续操作，不凭同一local ID把原请求转交新owner重派，无法查证时保unknown。运行态确认删除后的新任务不可因drivers仍持有旧owner而进入；同一已提交operation的查询/迟到结果保持原事实。

优先复用原操作已有的持有关系自然收尾，不另建retire manager、双owner注册表或等待历史任务清空的删除门槛；实际断连保未知，不为辅助收尾状态无限延长后台生命周期。

配置写入、运行态应用和云端同步按真实结果反馈，不把内部每个阶段都做成新的持久状态或界面步骤。旧版或独立服务若不支持即时应用，可以说明“本机配置已删除，运行态/云端待原服务重新加载”，不得宣称已同步，也不得擅自接管服务。云端确认不作为本机保存成功的前置。

### 4.3 当前目录与历史保留

以当前设备连接的完整catalog确定现在仍配置哪些原生实例。先复用已有连接和目录事实；只有现有持久目录确实无法区分在册与历史项时，才保存最小登记事实，不预定JSON标记或另建影子目录。缺席项退出当前候选，保留原稳定行和原回执；unavailable仍属于配置，断网本身不能推断删除。

沿现有连接归属避免旧catalog覆盖替换后的新目录，目录事务不等待网络；新增内部事实不经extra=allow意外暴露。目录删除不否定已存的合法原回执，原event仍沿既有提交后ACK路径；未确认的结果按原operation/journal查证并保unknown。不为此另造迟到response接管、ACK或重投协议，不承诺断连结果必达。

Desktop设置页以所选安装的本机配置为准，尚未上报、离线或旧版独立服务中的条目仍能编辑和删除。本机任务候选不继续保留已在本机删除的目标；服务器接纳与同步状态另行呈现，其他客户端按服务器最近有效完整快照列出当前候选。复用原配置与目录，不再造第三份列表。删除当前选中的A后清掉未提交的A/session/cursor选择，不自动改指B；已经提交的请求保原目标和UUID。

## 5. 电脑移除复用现有撤销

### 5.1 不新增第二个移除状态

本期需求是让不用的电脑退出当前列表，没有要求保留“撤权但继续显示”和“另行移除”两个可见阶段。将电脑连接器的现有撤销入口明确为“移除…”，复用原DELETE /client/v1/devices/{id}撤销合同和revoked_at；当前电脑列表及任务候选过滤已撤销连接器，旧的已撤销连接器也退出默认列表。

沿原Person/device来源授权、原request_id和原撤销回执处理，响应丢失仍用现有原请求查证；不额外引入superuser条件、第二种命令回执或恢复机制。只改变当前展示和选择，不物理DELETE原device/instance，不级联原会话、执行、事件和回执。

本方案不需要removed_at、独立移除接口、数据库迁移、回收站或经验保留期。操作记录保留原设备来源。撤销不等于远端执行已中止，不显示“任务全部停止/数据已删除”。如果未来确实需要两种独立可见意图，再按新需求讨论，本期不预留机制。

当前聊天设备若涉及登出，仍沿已有LogoutFlow；本期不把聊天设备退出流程改成电脑删除，也不扩大超管对他人设备的权限。

### 5.2 本机操作与远端移除的范围

沿现有开关停止Desktop自有Connector，不另添解除关联按钮。原安装选择、config/token、journal和原生登录保留，不宣称已清除；服务器移除沿原撤销操作。停止managed进程会影响其持有的本机Shell等执行。若以后重新配对，不能把新device直接写进旧journal namespace。

独立安装仅沿现有选择/更换安装或明确保存配置的入口处理，不自动卸载OS服务、删其目录或接管启停。没有执行取消选择动作就不宣称已解除关联。远端移除设备条目没有权限删除那台电脑的文件；本机配置与服务端记录的结果分别显示。

不增加一键删除所有资料或通用递归清理接口。用户本期要求的是能删除配置、移除不用的记录；物理清空原执行资料不属于完成这些动作的前置或默认效果。

## 6. 删除后仍能读取原事实

沿现有Person族和原instance→device归属校验读原operation/session/execution，不把是否仍在当前配置或凭据是否可派新任务当作所有历史读取前置。另一人物仍不能读原私有资料。服务器已持久的原终端/原生回执应有可达的Work/原操作或历史入口，不能把设备加回新任务选择器才能查询。

复用现有Work/原回执入口，不新建通用历史中心；已有覆盖直接保留，不为删除功能复制一套查询和授权链。

原Connector journal按operation_id查询可复用，但只能在当前来源仍获准通信时发只读查证；撤销凭据不重新授予通信权限。已删driver不能把旧running/pending证明为实时状态：有真实终态则返回原终态，无进一步事实时保last_confirmed和unknown/uncertain，不重发原命令。只有离线电脑保存而服务器从未取得的输出字节不能凭空恢复。

原在飞响应、事件和终态按原ID、归属、顺序及授权边界继续归并；目录删除不能让同一次已经发生的效果变成另一实例的请求。迟到终态不能被较旧的未知投影覆盖。

## 7. 三类原生Agent的准备、状态与错误

### 7.1 共用用户要求，保留真实接入差异

Codex和Claude Code是具体工具，通用ACP是协议入口，可连接实现该协议的其他程序。三者共用电脑Connector，但不用同一种原生协议，也不承诺相同的历史、恢复或接管能力。

用户启用所选Agent时，沿原安装、环境、profile和工作目录，在该驱动实际需要的时机准备或启动进程；已有原生服务则按其合同复用。程序已找到、电脑已连上、原生登录和实际任务成功各认事实。只检查就绪不创建会话、发送prompt或付费请求，不把“用户必须先打开窗口”作为通用前置。

| 入口 | 当前真实方式与边界 | 本期处理 |
| --- | --- | --- |
| Codex | `drivers/codex.py:37–99` 显式endpoint直连指定app-server；否则所选程序经`app-server proxy`连指定或默认控制socket。默认目标可由原daemon提供，显式目标不一定由daemon管理；当前不负责启动daemon | 对默认目标补该安装实际支持的服务启动/复用；显式socket/endpoint仍只连指定目标，不启动其他默认owner冒充成功 |
| Claude（Claude Code CLI） | `drivers/claude.py:67–74` 只核程序；诊断单独执行原CLI的`auth status`。提交新任务或显式resume时，`:178–225` 经官方SDK启动所选CLI子进程并用stdio通信；无需预开Claude桌面/TUI | 保按需SDK连接，不套Codex daemon。诊断、历史和实际执行沿所选同一profile/原cwd；文件、认证检查与实际SDK连接分别报告，不把找到程序写成任务已可用 |
| 通用ACP | `drivers/acp.py:83–113` 直接启动所选程序，使用分开的args、cwd和env，经stdio做ACP v1 initialize；能力由对端声明。普通交互CLI不自动等于ACP | 根据该程序文档配置真正的ACP入口及参数，沿现有握手报告结果，不硬编码某品牌旗标。列表/恢复仅用对端支持能力；initialize成功不证明认证或模型调用成功 |

上述方式与[Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/python)、[ACP stdio传输](https://agentclientprotocol.com/protocol/v1/transports)及[初始化合同](https://agentclientprotocol.com/protocol/v1/initialization)核对；本轮只读调查，未把SDK/规范核查称作用户三类真实账户的运行验收。

Codex仅在其专属分支使用[现场版本0.166的daemon合同](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/app-server-daemon/README.md)：官方start可复用原profile选定包，或从所选完整CLI准备缺失本地包。官方自身可能有配置、恢复文件或updater附带效果；Yuki不额外下载安装器、换profile/owner、改更新偏好或主动执行update/restart。不能把0.166机制外推所有Codex版本，更不能推广到Claude/ACP。

Claude的原历史可沿原profile查询，显式resume不等于接管另一个手动终端正在执行的任务。ACP的历史/恢复取决于实际声明及当前适配支持，不为统一界面伪造能力。Windows当前ACP入口要求实际可执行文件，不能将一整串shell命令或任意cmd/bat当作已支持；参数分别传入，不经shell拼接。

### 7.2 按驱动诊断，不另造统一服务平台

复用各驱动现有检查和必要的公共错误处理：Claude的auth status只证明原命令报告的认证状态；ACP当前无专用UI检查按钮，可复用既有doctor握手事实，不假称已有通用登录能力。不为诊断新建会话或发prompt，缺安装、登录、依赖、启动参数或协议问题按真实原因反馈，不因此让Shell/其他Agent不可用。

本轮源码还发现静态线索：Claude相对CLAUDE_CONFIG_DIR在诊断、历史与执行处可能按不同cwd解析；ACP当前未消费authMethods，也未核对返回的协议版本，session/new明确auth_required且尚未发prompt时也可能被普通异常压成unknown。这些未做真人账户复现；涉及对应分支时保同一profile、相容协议和原生明确错误，不把认证方式列表非空猜成未登录。拒绝按其发生阶段报告，已派发效果无法确认时仍保unknown，不推断此前无效果。不扩成登录平台、会话恢复重构或独立测试矩阵。

页面只显示用户需要的保存、电脑连接、Agent状态及可处理的错误；不另造协议状态灯或持久状态。原生完整输出、密钥、账户资料留在原私有边界，只提取必要原因。InvalidMessage不是固定的daemon缺失同义词，也不作为Claude/ACP的通用失败原因。

### 7.3 生命周期按实际持有对象处理

Codex关闭Yuki所持proxy不会主动停止用户daemon；Claude退出SDK会关闭它持有的CLI会话；ACP退出会关闭它启动的子进程和相关终端，可能影响本来由它们执行的任务。关闭任意Agent窗口、WSS断线、detach、删除配置和真正退出Connector不是同一动作，不统一套成“只关proxy”或“关闭所有原生程序”。

编辑/删除仍按第4节保护原工作与无关实例，不用整Connector重启生效；不自动接管或停止独立用户终端。沿原owner和operation查证，失联保unknown而不重派。新增前台等待沿现有调用方取消/退出清理自有资源，不加跨IPC取消状态机；启动确认丢失查原目标，不推断无效果，也不加重试、扩大timeout或固定sleep。

## 8. 旧服务迁移与可删除逻辑

Windows的真实Scheduled Task和本地service.xml不是同一事实。查询实际登记，分别处理任务缺失、权限拒绝与其他失败；不因XML存在就必须卸载，也不因XML缺失就忽略仍存在的旧任务。macOS plist本身的登记语义单独处理，不照抄Windows规则。

stop/uninstall只等待它实际成功停止且确属该服务的进程。/End失败或任务不存在时，不无限等待同目录锁上任何owner，更不能强杀手动run/其他安装。真正的旧服务按原安装迁移、确认退出；保配置/journal/native身份。现代Desktop不注册新的OS登录任务。

明确清理：配置add/configure重复写和重复发现；重复诊断准备；实际为子进程却仍叫service的桌面内部命名；无消费者ConnectorRunner类型；旧“背景連接”定位和“只保存/保存即能交代任务”等失真文案。同步主仓与桌面当前合同/README/测试，不在旧说法后叠矛盾补丁。删除文件时一并追调用方、配置、提示、测试和CI，不新建兼容别名替换垃圾。

明确保留：冻结LocalExecutor历史表和原回执、当前仍被任务目录选择使用的chooseProject、独立CLI服务、真实profile/socket/endpoint消费者、不可变运行包及平台/架构/来源校验。不能按旧文件名或GUI没暴露就判死代码。
