# Yuki 开发架构约束

本文规定跨模块边界；模块细节见[架构索引](README.md)。现行合同描述真实实现与必要约束，任务书和日期报告保留当时的设计与证据，不覆盖现行合同。实现、验证、合并与上线分别记录。

## 0. 设计原则

注重可扩展性和可维护性，不把当前流程、实现方式和经验规则写死，为未来变化留出必要空间。允许真实的部分成果和未决状态，有清楚的继续或退出方式。

**能通过删除或放宽现有条件解决的问题，不新增替代代码或机制；非必要不增加代码。** 先删重复状态、判断、经验上限和无人使用的分支，不给旧限制换一个开关或另建协调器。身份、授权、真实来源和已发生效果仍须正确；旧代码、旧测试和“以前为了安全”不能独立证明限制必要。

以去掉限制后能否完成真实工作判断其价值。正常部分成果、待处理、来源更新或普通失败不按固定次数、长度、标签和整齐程度封死；同时核对入口、下游执行、存储和测试，避免只放宽一层。

测试验证真实错误和行为，不冻结文件布局、固定调用数量或经验规则。陈旧说明直接删改，不叠加矛盾补丁。

- **绝不要在写完代码之后再去补单元测试。**
- **强烈倾向于把端到端（E2E）测试作为唯一的测试机制。** 用它来验证复杂功能是否正常工作；在 E2E 测试结束时，必须产出一个可验证且可重复复现的产物（artifact）。
- **如果确实需要对系统做隔离测试，必须【先】把所有可能失败的情况全部写出来，【然后】再去写代码。**

**刹车信号不重要，刹车的行为才重要。** 短期调节信号允许过期、合并和丢弃，以及时生效和实时处理速度为先，不为逐条持久化、完整恢复或历史重放增加负担；真实身份、授权、执行回执和累计预算仍按原事实处理。

## 1. 主体、事件与来源

一个数据库对应一个长期 Yuki。Person、Account、Space、Conversation 与 GatewayConnection 各认自身事实；平台账号、Provider 与连接不是人物或业务所有者。Account 唯一保存原生平台账号与账号资料，AccountAssignment 是唯一归属关系；Binding／Presence 只是其中 person／yuki 的类型投影，不另存两套当前归属。换账号或网关不复制人物、记忆或重置 generation；有多个真实候选时消歧。

事件入账后传递可信内部账本主键，canonical 关联 ID 不等于 `chat_events` 主键。平台消息号只用于接入去重、引用、撤回和投递关联，不重建已有业务身份。无用户事件的工作使用可信执行身份，不伪造入站消息。

**Person ID 与内部事件 ID 同为业务身份硬条件。** Person ID 建立后不复用为另一个人；人物资料与原历史归属直接使用内部人物身份，不由今日平台账号、昵称、Binding、Presence 或发送路由反向重建。一个 Person 可有多个账号，也允许没有账号；账号变化不抹去人物、历史或已发生事实。同一人的显式 Person 合并统一当前人物归属，保留原 Person ID、事件、Conversation、执行、已提交请求与回执的来源和身份；不同入口的上下文不拼接。账号真正转给另一人只改变今后的绑定归属，原历史仍归原人。

当前人物资料按同人族查询，真实 actor／source 保原 Person ID，并在实际执行处核资格；资料读取不要求原 owner 启用或有账号。Assignment 只存 active／disabled／ended：暂停保归属，结束才释放；换人、解绑后再绑和人↔Yuki 都建立新阶段。同人重复关联不换阶段、不顺手启用。历史阶段 ID、当时作者、提及快照、原设备 namespace 和执行回执不随当前资料归一而改写。账号昵称认 Account，群名片认 Account＋SpaceBinding，不用人物主名或同人的另一账号名片覆盖。

超级管理员资格直接持久化于 Person，不由平台账号、有效 Binding 或环境名单反推；账号转移不携带资格，解绑与换平台不删除资格。当前授权保原 actor Person，核原人物与当前 root 的有效性和当前资格；显式撤销不从历史合并成员复活。角色不改变固定工具声明或原已付请求，operator 与个人设备凭据分别按真实入口授权。

有效配对的个人客户端共用角色资料、头像、SOUL、角色电脑与 SELF 安排目录，不再叠加 character owner 或管理员资格。设备与 Person 有效性、个人私有数据、安排创建者、Work、Native 设备及电脑租约的真实归属仍在执行处核验；不改原管理员资格、历史授权行或原请求回执。

人物资料认 Person，聊天上下文认 Conversation，平台收发认 Binding、Presence 和适配器，已经发生的事情认原事件与回执。新效果沿实际当前授权执行；媒体寿命、今日账号可用性、会话新起点和辅助状态不能代替原回执否定已经发生的事实。

原生提及按原句位置保存目标和当时展示名，Main、JEV 与历史读取共用这份正文。名称不是身份；普通文字中的 `@` 不反造平台提及，后来的账号关联、退役或改名不改写原事件与已冻结请求。停用 Presence 保留 Yuki 归属但暂停新效果；结束阶段才释放账号，原 Presence 及历史来源继续保留。

取消或 generation 失效保留已发生事实，停止旧来源的新效果；隐私删除按实际授权清退相关资料。恢复按当前合法来源与原回执判断，不能把失效历史当作成功或重放依据。

见[Canonical runtime](canonical-runtime.md)。

## 2. 执行入口与工具合同

依赖方向为传输适配 → 应用运行时 → 领域服务/执行器 → 仓库或外部适配器。入口不复制身份、权限、任务与记忆规则；插件经 SDK 使用能力，不直访 ORM、数据库或私有 Host。

代表 Yuki 思考和发言的入口复用主 Agent loop、提示词与工具实现。共享 Runtime 管生命周期；会话、actor、Memory session、目标和预算按原执行隔离。普通聊天不强制登记 Work，关闭时先停止新激活并保留恢复事实。

本机原生 Agent 沿 Person 的显式设备授权和固定 `external_agent` 服务接入，设备、实例、原生会话、执行与原操作各认自己的内部 ID。电脑连接不创建聊天 Conversation，也不继承服务器沙盒所有权。原生执行、Work 委托／监督关系与平台送达分别结算；detach 结束所属关系，不代表原生成功、取消或关闭用户会话。确认丢失查原操作，原生 transcript 留在原 owner，重要进度和问题进入原 Work 私有输入，汇报沿统一 send。配置与真实能力变化不改工具声明，不新增本机 Harness、Work 或隐式服务器后备链。

部署冻结完整执行工具清单和模型直调清单。默认 direct 声明完整工具，执行处核验来源、委托、权限与预算；Code Mode 为可选调用语法，复用同一清单和执行器，不增加第二套调度。目录查询不修改已提交声明，声明可见不等于授权。原生工具缺少本地逐次拦截，按可信授权、配置和协议能力决定是否声明。

Person 自动化使用创建者在目标会话的当前权限；SELF 使用稳定自身主体和原场景，不借最近真人或超管身份。工作者使用 Main 的完整能力合同，执行时核验自己的真实来源、目标、授权和原回执。实际插件批准继续单独核验。

见[主 Agent](main-agent-runtime.md)、[Tool Kernel](tool-kernel.md)、[工作者](persistent-subagents.md)和[插件架构](../plugin-development/architecture.md)。

## 3. Provider 与模型任务

协议和任务路由沿显式配置，不按日期、关键词、品牌或回答内容暗中分流。结构化模式与思考按 Profile/请求的真实选择，不强制开启、设最低档位或自动抬档；协议方言转换不增加产品策略。配置声明不能证明端点实际可用。

搜索沿明确的原生/独立连接配置执行；真实失败、无效协议或无真实来源保原失败事实，不隐式切换 Tavily 或另一次付费调用。适配器不从普通正文制造工具调用，也不隐式建立付费续跑循环。私有协议状态、原工具配对、usage 和执行身份保留在原链。

Memory 提取、SELF、Dream 可分别配置；事实仍归原 Person/Space/SELF，不随模型复制。检索按事实 ID 和授权范围返回独立事实，key 是标签而非唯一槽位。允许部分整理、未决冲突与未处理事实，不以遗漏冒充已检查。

见[Provider](model-providers.md)和[Memory](memory-v2.md)。

## 4. 上下文与历史

账本、公共 compact 检查点、Memory、short_state、工作区、任务日志与执行回执职责分开。本轮运行资料只属于当前激活，每次准备当前有效值，不进入公共 FrozenFragments、自动观察或公共摘要；为空不展示，不保存首份、差量或最后展示值。首次请求的资料位于当前触发正文前，文字边界使用明确换行，不能无缝贴到用户正文后。

一个真实 Conversation 只有一份共同公共历史，冻结实际采用的原事件渲染。当前说话人、个人偏好、入口、插件或工具清单不另建历史视图，也不重建过去。群历史窗口沿真实 Space 配置，当前时间与历史显示统一默认 UTC+8，不保存或读取个人、SELF 时区偏好。context_note 使用原 Work 私有资料入口，不自动发布到公共聊天或公共观察摘要。

显式聊天记录查询读取 Yuki 实际参与并已入账、当前真实来源获准读取的跨平台原账本。`/ai new` 只清理当前 Conversation 的聊天上下文，不删除永久账本或截断显式检索；App/ACP、QQ 或其他入口平台不决定能否读取重置前历史。目标 ID 只定位真实范围，执行处继续核当前 actor、委托范围、插件批准和隐私；结果保留每条原 Conversation、平台和作者来源，不合并公共历史或重写已冻结请求。自动上下文、FrozenFragments 与 generation 继续沿原上下文和原执行合同管理。

Work 业务续跑使用当前获准聊天和必要任务线索，不恢复整份过时群史。真实私有协议检查点、原工具配对、签名、任务日志与回执沿原合同保留；新状态在既有有序输入尾部接入，不插回旧私有轨迹前面。原已付请求中的运行资料是该请求的证据，不抽取为下一次激活的公共知识。

工具结果配对不等于模型已观察。段末尚未交给模型的调用和详细回执，在当前来源有效时作为工作证据接续；保留原执行键，不搬运旧 opaque、签名或思考内容，不重发原调用。必要中间结果使用有来源的 context_note。

已提交协议不暗改。来源退出或上下文整理在合法边界建立新输入，保留原件、预算和回执；发布时复核来源版本、generation 与隐私代次，失败不推进共享历史前缀。压缩不要求虚假的全集分类，也不强制候选必须更短。

自动 compact 的整理触发值与模型硬容量分开。触发值只安排当前 Main 提前整理，不要求请求必须压到该值以下；原请求仍可容纳时，不能因没有可整理前缀或未得到有效检查点而拒绝正常工作。硬容量只沿当前 Profile 的明确输入上限、联合窗口与输出设置计算，未声明的容量保持未知，不用 Host 窗口或隐含默认值代替。手动 compact 只处理公共历史。容量计量包含完整输入、工具及私有协议；缓存使用上游真实 usage 核对，哈希或本地估值不独立证明命中或节省。

见[会话 Compact](conversation-compact.md)与[主 Agent](main-agent-runtime.md)。

## 5. Work、恢复与效果

任务、激活、模型请求和终端执行分开。启动外部执行前登记原意图及稳定 ID；等待时保存事实并释放名额。获准输入、时间、插件和完成信号在安全边界接入原 Work，不伪造用户请求或新授权。

完成、等待、取消和交接沿一次接纳的控制结果，由原 settlement writer 收尾。已接纳结束不再要求全部历史效果成功、额外通报或产出分类；只收拢真正所属的活动执行，等待期间保留决定。真实新授权输入可在原边界接续，辅助通知不撤销决定或复活终态。普通工具成功不等于目标完成，模型陈述不裁决真实效果；文件交付与附言分别核对，已交付不重传。独立新任务和交接按原控制合同登记，旧任务让出。

超时、断连或确认丢失先查原 ID，未知不等于失败。重启、分段和压缩不重置累计预算；父子按真实祖先共用根预算，默认无限，不扣固定收尾预留。重复、迟到回执不重复产生效果，相同读取结果不自动判定“无进展”。

业务父子关系在 Work.parent_work_id 保存，工作者表仅保存执行者资料；派生沿原来源、持久调用键和上下文冻结入口。指定节点取消复用原子树撤权，子节点继续不重开已结束祖先。

调度器负责扫描、容量和生命周期，领域服务提供授权及类型化效果结论，不扫描其他领域内部表猜成功。撤回绑定原发送 Presence，主动路由不证明成员可达。备份和回收同时考虑数据库与文件引用。

## 6. SQLite 与诊断

主库由应用装配的同一个 `Database` 持有写入入口。writer 在连接 checkout / `BEGIN IMMEDIATE`
之前按 FIFO 等待，业务仍在原调用协程执行；`read_session()` 并行读取，不自动 flush 或提交。
供给 session 的组合操作继续复用该 session，不在内部另开 reader、另抢 writer。应用只关闭自己
创建的 Database；外部注入的资源由原 owner 关闭。独立文件和进程保留各自 owner。

写事务短。历史扫描、身份与证据解析、聚合、正文转换、hash 和外部准备先在 reader 完成；
写时只核实际相关来源、成员和缺席条件，再作原子变更。新生成 ID / 时间参与的小型回执编码，
及罕见的整次隐私清退、人物合并和显式 FTS 重建，依各自原子单位处理。持锁不等模型、网络、
终端或文件 I/O，不靠全库修订、无效 UPDATE、经验次数和影子账本替代真实依赖。

准备不等于授权。写时按实际 owner、来源、权限、generation、领域 CAS 和租约判断；行数、
hash 或 updated_at 不能单独代替真实依赖。变化后重备同一个领域请求，保原 ID、预算和回执。
租约时间以取得 writer / 执行 SQL 时为准，过期资格不能因排队延长。

公共入口负责提交、回滚和取消收尾。取消后等实际 driver 操作或物理关闭退出，才释放 owner；
关闭未能确认时停止接纳 writer。保原异常和原生错误码，分别说明 begin / execute / flush /
commit，以及已提交、已回滚或未知。没有通用快照升级重试；未知不授予重放资格，不重调模型、
重发消息或重做外部效果。健康分别报告读连通和 writer 是否接纳，不能用 SELECT 1 证明写健康。

根提交确认成功且 owner 释放后同步发布 CommitHint，取消不能丢掉成功提交的最后通知。
reader、savepoint release、外层回滚不发布提交提示。TraceRecorder 的 live 提示仍按实际用途发布。
诊断只保 SQL 和准入、连接取得、事务、commit / rollback、清理的内存计时；不恢复 holder / 首写
物理 ID 追踪或观察用 dialect 包装。

无变化只读返回，维护按索引候选分页并释放 writer；不以分页遗漏来源或破坏原子变更。
删除文件前核实际引用。冻结迁移管理自身对象，不依赖可变 ORM。普通启动核版本和结构合同，
不扫描全部业务数据，也不因缺加速索引拒绝启动；全库外键完整性由冻结迁移或离线审核校验，
正常连接仍启用真实外键写约束。

可丢诊断不阻塞模型成功响应、名额释放或已确认效果，失败报告缺样；账本、请求检查点、Work
journal、授权、预算和效果回执不是可丢诊断。派生收尾失败不能推翻确认结果。性能同时核同数据、
同到达负载的端到端耗时、吞吐与等待 / 持有；BUSY 减少和健康检查不冒充真实延迟验收。

## 7. 持久环境

Yuki共用一个持久Linux环境，普通文件与包操作由同一管理员终端完成，不叠加命令审批、重复文件接口、经验次数或余量门槛。终端写入按正常Linux语义，不宣称自动防冲突。交付发布不可变 artifact，任务清理不隐式删除产物。Manager 管生命周期，环境不获得宿主 Docker 控制、Bot 数据库或 QQ 凭据。

入站媒体原件统一在共享环境可读的临时目录保存 24 小时，所有会话中的 Agent 可按需读取或自行收藏；原件缓存由 Bot 写入与清理，共享挂载只读，普通持久文件由终端自由修改。首次 Main 输入只提供内部事件、附件索引和文件资料，不自动展开图片、视频、贴纸或文件内容；入站 ASR 沿自己的显式配置处理。共享原文件不合并不同 Conversation 的历史，也不改写原事件、已付请求和执行回执。24 小时是实际文件寿命，不另设会话、generation、floor 或终端到期读取门禁；已被清理的原件不重新下载来重置期限。

见[持久环境](../operations/persistent-environment.zh-CN.md)。

## 8. 修改与交付

新增状态或抽象说明事实源、owner、生命周期和真实调用者，优先复用已有领域语义，不为假想未来或文件行数制造包装层。产品配置与经验策略不能冒充身份、授权或事实不变量，参数可调也不等于已生效预算或租约可忽略。

默认值、协议特例和实现细节放模块文档，技术合同不写入人格提示词。删除功能时连带核消费者、装配、配置、提示、文档、测试和 CI；历史事实、回执与真实升级 reader 不按死代码清空。
