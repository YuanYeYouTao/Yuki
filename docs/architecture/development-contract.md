# Yuki 开发架构约束

本文规定跨模块核心边界；模块细节见[架构索引](README.md)。历史任务书和验收报告不覆盖现行合同，源码符合程度、验证与上线状态分别说明。先检查能否删除状态、缩短生命周期或复用现有语义，再增加机制。

## 1. 主体、事件与来源

一个数据库对应一个长期 Yuki。Person、Space、Conversation、Presence、Binding、GatewayConnection 各有归属；平台账号、Provider 和连接不是业务所有者。换账号或网关不复制人物、记忆或重置会话 generation。多个候选必须消歧。

事件入账后沿链传递可信账本主键；canonical 关联 ID 不等于 chat_events 主键。读取仍核验 Conversation 与来源；禁止用平台消息号、正文或“最新消息”重建已有身份。平台凭据仅用于接入去重、引用、撤回和投递关联。无用户事件的工作使用可信执行身份，不伪造入站事件。

见 [Canonical runtime](canonical-runtime.md)。

## 2. 依赖与执行入口

依赖方向：传输适配 → 应用运行时 → 领域服务/工具执行器 → 仓库或外部适配器。入口不复制身份、权限、任务和记忆规则；插件经 SDK 使用能力，不直访 ORM、数据库或私有 Host。

代表 Yuki 生成或发言的入口共用主执行语义、Runner、提示词编译与工具实现，不建第二套人格或恢复循环。共享 Runtime 管理生命周期；会话、actor、Memory session、Work 目标、预算与调用上下文隔离。普通聊天不强制登记 Work。关闭时先停止新激活、保存恢复事实，再释放依赖。

调度器只负责有界扫描、容量和维护；执行服务负责授权与恢复。领域效果由所属服务提供类型化结论，不跨域扫描内部表猜成功。

见[主 Agent](main-agent-runtime.md)、[插件架构](../plugin-development/architecture.md)。

## 3. 工具、授权与 Provider

当前部署策略为本地函数工具提供稳定完整清单；目录查询、消息内容和任务阶段不修改已提交声明。声明不是授权，每次执行核验真实来源、委托、当前权限、预算和效果围栏。

原生工具没有本地逐次拦截，须在请求前按可信授权、配置与协议能力决定是否声明；必要的协议同名排除不是内容路由。实际链内合同稳定，授权或 Provider 边界改变时明确停止旧授权或开启合法新链，不以缓存绕过权限。

Person 自动化使用创建者在目标会话的当前权限；SELF 使用稳定自身主体与原场景，不借用最近真人或超管权限。插件批准单独核验。工作者复用工具实现，但不继承主 Yuki 的发送、长期记忆写入和自动化权限，也不额外增设工作区审批。

后端选择遵循显式配置；适配器不按日期、关键词或回答内容暗中分流。搜索适配仅在真实失败、无效协议或无真实来源时使用已配置兜底，不将兜底固化为后续绕过策略。能力不足须如实报告。

见 [Tool Kernel](tool-kernel.md)、[Provider](model-providers.md)、[工作者](persistent-subagents.md)。

## 4. 上下文与事实

账本、Rollup、Memory、short_state、工作区、任务日志与执行回执职责分开，不能互相替代或全量塞入提示词。Work 业务续跑接当前获准聊天和必要任务线索，不恢复整份过时群史。

已提交协议不暗改；未决调用先核对原检查点，保留配对、签名与 opaque。资料退出或压缩须在合法边界建立新输入，保留原件、来源、预算与回执，不取得重跑资格。观察顺序以实际请求选取为准；Work 选取与 dispatched journal 原子发布，失败不推进共享前缀。发布压缩结果须复核来源版本、generation 与隐私删除代次。

真实请求容量与整理软水位分离；能装入完整请求时不因经验目标暂停。容量、缓存验证使用实际 messages/input、tools/native_tools 与设置，哈希和命中率不能独立证明正确；不保温或注入无关资料。

见 [Rollup](conversation-rollup.md)、[主 Agent](main-agent-runtime.md)。

## 5. 工作、恢复与效果

任务、激活、模型请求与终端执行分开。启动外部执行前登记意图和稳定 ID；等待时持久保存并释放名额。新输入在安全边界接入；时间、获准插件和执行完成信号可按可信来源触发或续接原 Work，不伪造用户请求。新任务接纳与旧任务恢复分开，模型假设不构成用户授权。

超时、断连或提交确认丢失先查原 ID；未知不等于失败，不盲重跑、重发。重启、分段、压缩不重置累计预算；父子共用根预算并保留主任务收尾额度。重复或迟到回执不得重复产生效果。

普通工具回执按原 call_id 配对保存、供原循环继续，业务成功不等于目标完成。显式完成、等待、取消和交接按控制合同处理；完成须满足原目标和交付证据。文件与附言分别核对，已交付不重传或重复收尾。独立新任务与交接标记原子登记，旧任务立即让出，不代做代发。

取消或 generation 失效保留已发生事实并禁止旧链新增效果。撤回绑定原发送 Presence，主动路由不证明成员可达。模型陈述、展示摘要和诊断缺样不裁决效果。恢复快照的文件与数据库引用共同备份、回收。

## 6. SQLite 与诊断

写事务必须短。历史扫描、证据聚合、大正文转换和外部准备在首次 DML/BEGIN IMMEDIATE 前完成，注意 autoflush。持锁不等待模型、网络、终端或文件 I/O；仅保留必要当前状态复核与原子变更。必要的小型 JSON/DTO 转换须有数据量、次数与持锁成本依据，不能为机械外移另建状态协议。同步 I/O 不阻塞事件循环；线程隔离覆盖连接、事务与取消清理的完整生命周期。

准备不是授权。使用一致读快照或完整依赖版本复核，核对 owner、来源、权限、generation、revision 与租约；不能用行数、哈希或 updated_at 冒充全部依赖。租约时间以取得 writer/SQL 执行时为准，条件写入及受影响行数决定成功。

无变化只读返回；维护按索引取有界候选，写时复核，每页释放 writer，不以分页破坏原子性、遗漏对象或截断精确证据。文件提交后回收，删除前重核引用与身份。冻结迁移不依赖可变 ORM，仅管理自身对象。

可丢诊断从准备、编码到提交均与业务结果隔离，有界异步写入；模型成功响应、名额释放和已确认效果不等待诊断 writer，诊断失败不丢弃成功业务结果。冻结来源与隐私代次，不重解析当前 owner 或回填已删除内容；失败报告缺样，取消和进程终止照常处理。账本、Work journal/请求检查点、权限核验、预算、强制审计和效果回执不得按可丢诊断处理。派生收尾失败不能推翻已确认效果。

竞争时完整回滚、有界重备纯数据库计划，保留原 ID，不重做模型判断或外部效果。按失败阶段和可核验错误码区分 BUSY、LOCKED 与内部故障；续租仅在仍有效时有界重试 BUSY，租约失效停止受保护执行。不无限重试或加长 timeout 掩盖长事务。分别测排队、SQL 与真实 commit/rollback；锁与性能诊断日志不保存正文、SQL 参数或凭据；并发修改使用相关 SQLite 竞争回归，健康检查不冒充自然延迟验收，不启动第二个主动 Bot 写生产库。

## 7. 持久环境

工作区全局共享、不按人群分区；结构化写入检查内容版本，终端任意写入不宣称自动防冲突。交付发布不可变 artifact。Manager 管生命周期，环境不得获得宿主 Docker 控制、Bot 数据库或 QQ 凭据。任务清理不隐式删除产物。

见[持久环境](../operations/persistent-environment.zh-CN.md)。

## 8. 最小充分设计

按违反后果分类：身份、授权、事实、承诺与副作用正确性是不变量；产品范围、审批和资源配置是政策；排序、软水位等是经验策略。参数可调不等于已生效的权限、预算或租约可忽略。分类不清先说明风险，未证明等价安全前不降低保护，也不因不确定增加永久机制。

持久化真实长期事实、承诺和可能发生的效果；派生数据可重建，未形成承诺的内部判断默认可丢。只恢复必要承诺，不恢复全部思考。

新增状态或抽象须说明事实源、owner、生命周期、真实调用者、替代了什么及净收益。优先复用领域语义，不复制平行链；不为假想未来建模，不为文件行数制造包装层。同样正确时选更易读、测试、恢复和删除的方案。

## 9. 修改与交付

默认值、协议特例和实施细节放对应模块；兼容分支说明真实调用者及退出条件。技术合同不写入用户人格提示词。过时规则直接删改，不叠加矛盾补丁。

验证匹配改动风险，不重复未变的无关全量检查；遵守用户对测试、提交、上传与部署的范围。分别报告修改、验证、提交、推送、合并和上线，不把未验证写成完成。回退不覆盖上线后的新消息、文件和回执；恢复旧数据库不是默认代码回退步骤。
