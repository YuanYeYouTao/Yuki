## 3 推荐的完整行为

### 3.1 搜索只返回搜索服务已经提供的内容

所有后端统一，包括独立 Gemini、Messages、Responses 与显式 Tavily。`web_search` 和 `ctx.web.search` 不再下载搜索来源页面；也不偷偷开启搜索供应商的额外正文提取选项。

保留真实 URL、标题、日期、Provider 摘录、已有结构化正文、来源配对、总结和实际用量。Gemini 当前通常只有来源 URL、标题和模型总结，逐来源正文为空应如实展示。Anthropic 原有 `content/cited_text`、Tavily 原有 `content` 不因改为纯搜索而丢弃；`provider_summary` 继续与网页原文分开，正文中的虚构 URL 不升级为来源。

读取失败不改变已确认搜索的成功事实，不使它成为需要重新购买搜索的理由。`partial_failure` 仍表达原生响应不完整、真实来源动作失败或未满足的过滤条件，不再由额外抓页失败产生。

### 3.2 按需读取明确 URL

保留 Main 的 `read_webpage(url, question)` 和插件 `ctx.web.read(url, question)`，不新增工具。模型可选择用户给出的、历史中已有的或搜索实际返回的 URL。删除 Main 对“当前输入必须含该 URL”及 `used_url_for_trigger` 的硬性检查，不新增会话白名单、URL 登记状态或跨轮配额。

执行处继续核验当前真实来源、联网批准与插件 `WEB_READ` 权限。各读取入口保留现有公共 URL 静态校验，包括拒绝 URL 用户凭据。本机 DirectPageExtractor 继续执行 DNS 公网校验与固定 IP、逐跳重定向、TLS 和下载容量校验；显式 Tavily 读取仍调用供应商 `/extract`，不把本机检查描述成对供应商内部下载过程的保证。工具提示说明何时读取与资料可信度，不把“必须先搜索一次”写成执行条件。

`WEB_SEARCH` 不自动获得 `WEB_READ`。仅有搜索权限的插件以后得到搜索服务原有结果，不能为保留旧自动正文而暗中补读或扩权。公开 SDK 签名和响应结构可保留，发布说明要明确内容语义的变化。

### 3.3 默认复用标准代理，复用现有超时

线上网页下载器 `trust_env=False`，绕过已有 HTTP 代理；原生桥默认又沿用了搜索模型的 600 秒超时。已有 `WEB_TIMEOUT_SECONDS` 足以负责网页下载，不新增超时字段。

2026-10-17 的有界网络探测确认：

| 路径 | 观察结果 | 结论 |
| --- | --- | --- |
| Bot 网络直接访问来源域名、固定公网 IP 加原 SNI | 各约 6 秒达到本次诊断截止时间 | 不能依赖当前直连出口 |
| 现有 HTTP 代理按原域名连接 | 约 0.83 秒收到 302 | 出口可以连接该站点 |
| 同代理加现行固定 IP URL，HTTPX 0.28.1 / HTTPCore 1.0.9 | TLS 校验失败；HTTP CONNECT 实现未使用请求的 `sni_hostname` | 仅打开环境代理不足以修复 |
| 当前混合代理的 SOCKS5，固定 IP、原 Host/SNI、正常证书校验 | 同 Bot 网络下 curl 约 1.04 秒收到 302；隔离 Python HTTPX 客户端约 1.19 秒收到 302，TLS trace 的 server_hostname 为原域名 | 标准 SOCKS5 能保留当前 DNS 固定和 TLS 合同 |

探测仅访问站点根路径，未使用 Bot 凭据或模型接口。这证明连接与 TLS 路径，不等于事故中的引用路径、真实正文及自然流量已验收。诊断使用的短截止时间不是生产超时建议。

不新增 `WEB_PROXY_URL`、代理模式或专属热配置。网页读取默认复用 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY` 及其小写拼写；按请求协议选择专用项，再使用 `ALL_PROXY`，没有代理则直连。沿 Python 标准代理发现处理大小写优先级，以及无环境代理时 Windows/macOS 的系统代理；不扫描 Mihomo 端口、不改写用户给定的代理协议。

选路按原始网站域名和端口处理 `NO_PROXY`，然后再连接已校验的 IP；每次重定向重新判断，不能按改写后的 IP 选路，也不能由 `NO_PROXY` 绕过公网检查。HTTP、HTTPS 和 SOCKS 代理按各自声明工作；`HTTPS_PROXY=http://…` 是普通 HTTP 代理承载 HTTPS 目标的合法配置。SOCKS 依赖随镜像和安装依赖提供，部署者不再手工安装。

仅本机 DirectPageExtractor 新增传输适配。启动加载会让标准 `.env` 代理与 CA 对现有自行读取环境的客户端统一生效，包括模型和 Tavily；不逐个替换这些客户端。其余显式 `trust_env=False` 的调用链保持原行为，包括普通 MediaResolver、ASR、Telegram 和插件通用 HTTP。持久沙箱的独立 Squid 出口仍按隔离合同执行，不向它透传 Bot 的 `NO_PROXY` 或另建直通路径。代理认证与标准 CA 设置属于启动环境，不进入 Admin 覆盖、RuntimeConfigSnapshot、Work 合同、模型资料、日志或工具回执。

NativeSearchBridge 的 reader 由 WebModule 显式注入并独占，使用 `WEB_TIMEOUT_SECONDS`；删除 constructor 内按模型 Profile 超时创建默认 reader 的退路，搜索请求继续使用 Profile 超时。保留已有 `search/extract` 公共合同、Hot provider、TaskRouted provider 和 Runner pin，不为分工增加另一层业务路由器或共享资源协调器。沿现有资源所有权关闭 client，不能将新 client 注入后留给不拥有它的 MediaResolver 关闭。

### 3.4 用公开传输接口兼容普通 HTTP 代理

首选保留 HTTPX/HTTPCore，在专用网页 client 注入一个传输适配模块，使用公开的 `AsyncBaseTransport`、`AsyncNetworkBackend/AsyncNetworkStream`、连接池与字节流接口。按原 URL 选路后，代理仍收到已校验的字面 IP；请求级 backend 显式持有原域名。HTTPS 代理自己的 TLS 使用代理域名，隧道内 TLS 使用目标原域名；用两个独立 SSLContext 区分，不能把同一个 `sni_hostname` 错用到两层 TLS。两套 context 沿 `httpx.create_ssl_context(trust_env=True)` 读取正常 CA 配置。

不 patch 私有隧道类，不复制 HTTP CONNECT 或 SOCKS 协议，不用全局域名映射或 ContextVar 拼接请求归属。直连和 SOCKS5/SOCKS5h 继续使用已有标准能力；HTTP/HTTPS 代理使用公开连接池和上述 TLS 适配。通过 `httpx.Proxy` 正常解析代理认证；代理凭据仅用于代理，不能作为站点 Authorization。为明文 HTTP 也传递原 URL/Host，不能只依赖 HTTPS 才有的 `sni_hostname`。

响应流拥有其连接池并在关闭、异常和取消时释放；请求前失败也关闭所拥有资源。保现有下载器的物理并发容量和禁止跨虚拟域名复用 IP 连接的行为，不能因为请求级建池而放大总连接数；不另加业务并发门槛或协调器。只给专用公共网页 client 使用标准库拒收 Cookie 的策略，不保留/自动发送站点 Cookie。现有 IP URL 会使默认 CookieJar 把两个不同 Host 当成同一站点，已用 MockTransport 复现；删除这份隐式登录态即可，不新增人物或会话身份域、Cookie 缓存键及每次清空的竞态。

| 候选 | 已完成研究验证 | 取舍 |
| --- | --- | --- |
| 原样 HTTPX 开环境代理 | 普通域名代理能连；固定 IP 加 HTTP CONNECT 时目标 SNI 不正确 | 不能只改 `trust_env` |
| HTTPX 公开接口适配 | 本地两层真实 TLS：HTTP/HTTPS 代理成功、两项代理 URL 认证不泄露给目标站、三种错误证书拒绝、两项明文 HTTP、两项提前关流及四项取消，最后无遗留转发任务，共 15 项 | 首选；保持现有响应、异常、流读取和依赖体系，仍须补标准环境、IPv6及真实集成验收 |
| aiohttp 3.14.5 公共参数 | `server_hostname` 加 IP URL 在本地直连、HTTP CONNECT 成功，错误主机名拒绝 | 可行，但需引入另一套 client/响应及 SOCKS 接入；本期不选 |
| curl_cffi 0.16.3 / libcurl | 固定 IP、原 Host/SNI、环境代理可实现；真实 MediaResolver 注入也验证了 DNS、重定向、声明长度超限与单次取消 | 该版本 CONNECT_TO 需 FFI slist；默认 stream 取消及关闭等待有反例，独立会话还需额外适配；本期不选 |

以上 HTTPX 15 项完整实验在 Windows Selector 的本地 fake server 夹具中通过；默认 Proactor 夹具在坏证书/取消后有服务端连接关闭警告，不能据此宣称 Windows 默认循环、Linux 或生产 HTTP 代理已完整验收。此前真实 Mihomo SOCKS 根路径探测证明出口存在，但不代替新 HTTP 适配的生产验收。

### 3.5 本地与 Docker 使用同一份标准配置

当前 Compose `env_file: .env` 会把标准代理交给 Bot 进程；本地 `Settings(env_file='.env')` 只读取已声明设置，不会把被忽略的代理项导出到 HTTP 客户端。实施时在启动入口补一处共用加载函数：按实际使用的 `.env` 路径，仅读取标准代理与 CA 项，现有进程环境优先；同一代理项的大小写作为一组处理，不能让文件里的小写项覆盖进程已设的大写项，显式空值也保留。`SSL_CERT_FILE/SSL_CERT_DIR` 沿标准 CA 语义处理，不把整份 Bot 密钥导出到进程环境。

该函数由 Bot `main.bootstrap`、普通管理 CLI 和使用实际 `--deployment-root` 的 setup 入口在 HTTP client 创建前调用。不要放进 Settings 初始化、容器重建 Settings、热刷新或每个 HTTP 构造函数；隔离 sandbox manager 与显式 `trust_env=False` 的个人客户端不被隐式改变。

| 部署方式 | 用户操作与默认行为 |
| --- | --- |
| 本机原生启动 | 已启用的系统 HTTP 代理或标准进程环境可直接复用；也可在既有 `.env` 写一次标准代理，不加 Yuki 专属开关 |
| Docker Compose | 在既有 `.env` 写标准代理；补 Bot 的宿主标准变量传递及 `host.docker.internal:host-gateway`。每组大小写先选定同一有效值再写入双别名，例如均用 `${http_proxy-${HTTP_PROXY-}}`，保显式空值，避免空小写意外清除非空大写。Compose 合并后的环境按小写优先，不承诺宿主大写覆盖文件小写 |
| 宿主机 Mihomo | 容器中使用可达的宿主地址，原生进程使用本机地址；示例说明代理须监听容器可达接口，容器的 `127.0.0.1` 指向容器自己，不自动猜测或替换 |
| 透明代理或无代理 | 系统网络路由照常工作；无显式代理时正常直连，不要求安装 Mihomo |

实施后的本地 `.env` 示例（7890 是示例，替换为用户实际代理端口）：

```dotenv
ALL_PROXY=http://127.0.0.1:7890
NO_PROXY=localhost,127.0.0.1,::1
```

实施后的容器 `.env` 示例（宿主代理须可从容器连接）：

```dotenv
ALL_PROXY=http://host.docker.internal:7890
NO_PROXY=localhost,127.0.0.1,::1,bot,snowluma
```

实际私有模型入口按用户环境加入 `NO_PROXY`。已设置的协议专用代理仍优先于 ALL_PROXY；本地系统代理可直接复用，无须重复填文件。这些是实施后使用示例，不代表当前原生启动已加载 `.env` 代理；不在程序中固定端口。不支持的代理、不可达地址或错误证书照实失败，不自动改协议、退回直连、重搜或关闭证书校验。

### 3.6 删除无读取消费者的第二份来源索引

当前 `web_search_runs/web_search_sources` 的唯一生产查询用途是本轮 URL 门槛。`for_trigger/latest` 仅由测试调用；工具实际返回值中的 source ID 不依赖这份数据库插入结果。

删掉门槛后，一起停止新结果的 `_persist_web_response/save_response` 写入，删除相应预读、查询方法和 AgentToolService、ChatService 的无用注入。成功付费搜索不再因这份无消费者的二次写入而不能交回结果。

已持久化的工具结果、artifact、原调用配对、Work journal 和使用量仍沿既有权威链保留。`model_invocations` 只有调用元数据，不能据此补出辅助模型整包响应；artifact 缺失、禁用或结果合法截断时保留原先实际接受的结果与缺失事实，不另造全包日志，也不重发未知或已付请求。旧来源表及原内部事件、执行、Conversation 关联继续保留，既有保留清理和人物隐私删除仍消费历史记录；不清库、不 DROP 历史表、不修改冻结旧迁移。

## 5 升级与缓存

删除字段后，旧环境变量按现有 `Settings.extra=ignore` 自然退役。现有热配置 reader 会忽略已无 spec 的旧行；下个冻结迁移只删除 `web.extract_max_results` 与 `web.source_max_runs_per_conversation` 的现行覆盖，覆盖所有 scope，保管理操作历史。旧 key 的管理写入、查询和历史回滚按已有未知配置语义处理，不改名映射为新功能。迁移编号在实施时取得，不提前占用。

不要建议将提取数量临时设零：现行 Settings 和热配置要求正数，这既不是合法域配置，也无法删除旧 scope 覆盖的行为。

BridgeState 只保存 `WebSearchResponse`，删请求字段不破坏旧响应。沿既有 namespace 版本区分新搜索语义，旧检索缓存自然过期；不清空其他 cache、历史或模型上下文。公开页面的读取语义未变，保留 `direct-page-v2` 及现有 URL/问题缓存键、过期规则；代理和超时属于传输配置，不另分 namespace，代理凭据也不进入缓存内容。失败仍不写页面缓存，不用切换出口触发额外重搜。

检索结果缓存与 Provider 前缀缓存分开。删除额外抓页后，网页失败不再把一次成功搜索排除在检索缓存之外；这不等于已经证明线上 Token 命中率提升。原 Provider usage/cache 字段保真，缺失保持未知。

Runtime Web 字段属于 `AgentRunner.work_contract`。删除字段及更新工具说明按既有合法新链机制应用，保同 Work ID、累计预算、已接受输入、原工具回执和已付协议原件；恢复先查原执行结果，不因新缓存未命中而再次调用搜索。部署重启按现有固定声明合同执行，不热改已提交请求的工具或前缀。
