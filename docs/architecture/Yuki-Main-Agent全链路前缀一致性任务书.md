## 1. 目标、边界与验收口径

同一部署合同、同一模型配置与协议内，所有以 Yuki 身份对外发言的模型请求必须使用相同的固定指令、完整工具声明及顺序。来源、目标、权限、附件、当前时间、短期状态、执行结果只能进入约定的动态位置；后端独立执行授权。不同会话的正文和历史本来就不同，不要求整份请求相等。

必须区分三层合同：

1. **跨入口固定部分相同**：普通私聊、群聊、自主回复、插件唤醒、自动化和 Yuki 发言用插件接口一致。
2. **同轮序列只追加**：后续请求保留此前提交的输入项和协议要求的模型输出，再追加工具结果与控制提示。
3. **跨轮投影稳定**：同一上下文版本中，已提交的历史投影不可重新分组、改名、重渲染；无法保留时建立有原因的新版本。

DeepSeek 当前官方说明要求完整匹配已持久化的前缀单元，并提供请求边界、公共前缀和固定间隔等持久化机制；缓存仍是 best-effort。验收目标是消除应用自身的非预期前缀变化，不能承诺每次命中或承诺某个命中比例。[官方缓存说明，2026-09-11 核对](https://api-docs.deepseek.com/guides/kv_cache/)

不改写文件中转、QQ 网关、沙箱、工作区或社交路由。本次不能回退已修好的原 Presence 撤回、群可达性、Binding 歧义拒绝、委托戳人、结构化 @、旧账号路由恢复。维护 Memory、视觉、摘要、Embedding 等内部模型任务的独立职责，不能机械地给所有模型调用塞入 Main Agent 工具。

## 3. 入口清单与最终归属

| 入口 | 最终归属 | 约束 |
|---|---|---|
| 普通私聊、群聊、自主群回复 | 统一 Yuki 生成入口 | 保留真实触发来源、会话协调、取消与快照检查。 |
| 当前 Agent 主动联系、群发、文件/图片/语音及说明 | 当前轮工具执行 | 不新建生成上下文；实际发送各自记账，失败和部分成功进入原轮结果。 |
| 插件 external_event → ask_agent | 统一 Yuki 生成入口 | actorless 唤醒，真实 event/target/causality，不伪造用户指令。 |
| 自动化 generate / agent 后对外发送 | 统一 Yuki 生成入口 | 复用上下文构造，但权限和读取范围不因统一而扩大；generate 保持无外部副作用。 |
| 插件 SDK 为 Yuki 生成对外文字 | 统一 Yuki 生成入口 | 旧接口迁移策略见待决项 D1。 |
| 插件独立 AI Session、内部分析 | 独立计算合同 | 不冒称已走 Yuki 主入口；对外表达时提交资料、唤醒主入口。 |
| 固定通知、转发、命令回复、纯媒体投递 | 直接投递 | 不额外调用模型；统一发送回执和历史投影。 |
| Memory、Rollup、视觉等内部模型任务 | 原有内部合同 | 不扩大到 Main Agent 发言重构。 |

盘点包括定义、实际调用方、动态注册/别名以及生产安装插件；仓库搜索没有发现调用方，不等于不存在外部插件。普通字符串一旦离开生成接口，无法可靠推断它是模型文本还是固定通知，不能设计“自动识别任意字符串来源”的虚假保障。

## 4. P1：请求序列单一真源

### 实施

引入一个轮内请求记录对象（名称可采用 `TurnTranscript`），由 AgentRunner 唯一持有。它记录固定前缀引用、初始上下文、触发输入、协议输出、调用、结果、控制提示的顺序和已提交边界。Provider 负责协议编码和解码，不能再独立维护业务历史。

- 沿用现有 tail 修复作为基线，逐步替换四份状态；最终删除生产主路径的重复拼接规则，不保留两套长期分叉。
- 保留 Provider 返回的 continuation 项、调用 ID、必要的推理/原生工具项；不将隐藏推理改成可见文字，不将不同协议项目互相硬拷贝。
- 工具结果按真实 call_id 关联，一次成功提交只追加一次；同一 ID 的冲突结果必须报错，不能默默去重掩盖矛盾。
- 并行执行允许完成顺序不同，但提交结果采用预先固定的调用顺序。重复工具请求、网络重试、取消后的副作用仍服从既有幂等账本。
- 收尾、空输出恢复、incomplete、无进展、结构化 @ 修正全部作为序列尾部控制项。第一请求即预算收尾也不能增加顶层固定 instructions。
- 原模型配置/协议保持不变时重试同一序列；Provider 切换不得复用不兼容 continuation，应显式建立新请求版本并记录原因。
- 保留已有预算和终止机制，不通过增加最大轮数解决重复工具调用。

### 完成标准

后续 HTTP input 的前 N 项与上次提交 input 完全一致；新增模型输出、匹配结果和控制项有可解释顺序。Chat Completions 使用其协议 messages 做等价检查。异常、取消及已提交写入后的恢复均不重复外部副作用。

## 5. P2：完整声明固定，执行权限独立

### 实施

扩展现有 MainAgentContract 为明确的版本合同，保存静态指令版本、函数 manifest、名称映射、协议配置及序列化版本。

- 从同一注册真源产生核心、已批准插件/MCP、自动化工具名称和 Schema；禁止运行时“描述相同则认作同一工具”的隐式推断。
- 冻结名称、说明、参数、排序及最终 Provider 字段；向调用方返回不可变值或防御性副本，测试不得可变地污染后续请求。
- 启动阶段等待已批准工具就绪再冻结；失败时明确启动失败或选择明确标记的新合同，不能静默缺少工具后仍宣称同一部署版本。
- 新工具、Schema、模型协议或静态提示词更新只在显式合同切换后生效；已开始轮次继续使用旧合同。运行时禁用某能力立即影响执行授权，不能等重启才撤销权限。
- request_tools 仅查询固定目录和当前可用性；移除其动态追加 Schema、触发续链重建等过时副作用和误导说明。
- tools_closed、Memory 独占、附件有无、管理员、委托、只读、权限撤销只影响执行。模型看见工具并不授予执行权。
- 将 A4 的条件规则写成固定通用合同，将本轮是否命中、能否执行等事实放进结构化动态资料。不得在无历史时额外合并 system。

### 原生工具必须专门处理

原生联网由 Provider 执行，不经过本地工具 execute。**不能直接对所有人固定暴露原生工具再声称后端会拦截。**

建议本任务的统一 Main Agent 合同采用可由宿主授权的函数联网路径。若要保留 native/mixed，须证明目标 Provider 能在不改变声明的条件下可靠限制当轮执行，且有真实请求及拒绝证据；无法证明时不能纳入“统一且授权安全”的完成声明。仅仅传一个被适配器省略的 tool_choice 不算完成。

DeepSeek 适配器当前省略 tool_choice，任务需按实际版本核验兼容性；不能在本任务中凭印象添加 Provider 不支持的字段。终止时函数调用必须由 Runner 拒绝执行，且不得伪造工具已成功的回复。

### 完成标准

同一合同下实际非空 tools 字段逐项相等，覆盖权限来源与收尾分支；对每种执行后端有负向授权样例。模型配置差异显式标为新合同，不用多个隐蔽入口配置掩盖差异。

## 6. P3：收拢 Yuki 生成入口

建立唯一的应用级入口（可称 `MainAgentTurnService`），接收真实触发对象、canonical Conversation、目标、执行授权、预算和上下文读取约束，内部统一调用：

```text
触发/授权校验 → Conversation 快照与协调
→ ContextAssembler → PromptComposer（包括 short_state 快照）
→ 固定合同 + TurnTranscript → AgentRunner
→ 已授权投递/回执 → 账本与历史投影
```

- 迁移自动化自建 system/history JSON；允许不同上下文读取约束作为输入，但不可把“统一上下文”当成读取更多私聊/记忆的授权。
- 迁移以 Yuki 身份表达的插件 SDK 调用方，保留独立计算用途。主入口不得递归调用同名自动化生成能力形成无限嵌套。
- `generate` 的外部副作用限制保持；主入口提供统一声明，并由执行策略区分纯生成与可执行委托。
- 避免沿用插件随机 conversation_key 作为 Yuki 正常会话；目标不明确时拒绝，不挑第一个人物或绑定。
- 检查自动化 ModelTask 与主聊天的 profile/protocol 配置；相同 Yuki 合同不能在入口处暗中选择另一套模型。用户显式配置的不同模型需独立版本和可观测边界。
- 已完成的插件唤醒沿用原协调链；并发任务必须尊重 generation、/ai new、Rollup 及 before_model_request 检查。
- 删除已迁移的独立 Prompt 拼接；独立 AI Session 使用明确独立 runner/合同，不能因 DI 共享意外获得 Main Agent 状态写入能力。

### short_state 保留约束

用户已确定它是全局短期区域，与人物、群、权限分区无关；该约定不变。现实现为 3 槽、24 小时、完整 envelope 最大 512 UTF-8 字节（不是 512 tokens），用 revision CAS 更新。

把它纳入统一 Prompt 编译和预算，每轮只取一次快照，放在当轮动态尾部、时间项之前；同轮工具写入以工具回执告知，下一轮再取新快照，不能回改已经发出的旧输入。全局状态不是权限凭证，也不是历史记录的替代品。FIFO/自动淘汰旧槽尚未实现，本任务不顺带改变其写入语义；若另立状态生命周期改动，应检查过期清空与 revision 的并发语义。

## 7. P4：统一并冻结历史投影

### 数据合同

ledger 继续是事实真源；投影快照是可重建、有版本的模型输入视图，不另造一份事实账本。建议以 canonical Conversation + generation + context epoch + contract revision 标识上下文，以事件覆盖范围、投影序号和 fingerprint 标识片段。

- 首次投影确定作者身份、引用、@、媒体表示、时间及因果说明。昵称改变、后来出现引用目标、同作者新消息到来都不能重写旧片段。
- A9 的相邻分组只能在尚未提交的批内进行；不能扩写已提交的最后一条 message。
- 区分“模型原始输出”“平台实际投递内容”“工具执行回执”。分段发送、文件成功而说明失败，只投影真实事件；不能补造用户说过的话或成功结果。
- 跨会话主动发送：源会话保留真实工具结果/因果关联，目标会话只记录实际输出及其来源；不能把源会话的完整动态资料搬到目标会话。
- 插件原因引用使用已冻结的事件因果资料，不能因为旧 external_event 离开可见窗口而悄悄改写主动消息标签。
- 直接通知、命令、语音、表情、上传文件等逐一核对入账路径；无入站消息并不等于可以免记账，但修复前需确认该投递有独立合法目标与权限。
- 投影提交必须与 turn/ledger 边界协调；取消、发送失败或进程重启后不将未投递文字伪装成已发消息。发送状态 unknown 时保留不确定性与对账线索，不自动重发。

### 持久化与跨轮边界（受 D2 影响）

建议保存有界的实际投影片段，含当时已提交的动态资料与选定的工具结果。不是无限留存全部响应，更不把隐藏推理写入普通历史。若协议必需 continuation 内容不能安全/完整保留，需明确一次重建边界，不伪称严格追加。

必须先决定哪些项首次提交前即裁剪，哪些跨轮保留。工具大结果先做稳定有界表示；不能本轮发送长原文、下一轮悄悄替换成摘要而仍标注相同 epoch。

允许新建上下文版本的原因至少包括：Rollup、/ai new、窗口容量边界、旧数据引导、新静态合同、模型/协议切换、法定或用户要求的数据删除。事件撤回/删除不得为了缓存保留应删除的正文，应使相应快照失效并重新建立上下文。

旧数据首次用新 renderer 生成一个明确的初始 epoch；不改写旧账本。快照容量沿用现有上下文预算派生，并有单会话/总量上限与清理策略；实施前测量尺寸，不任意放大数据库。short_state 过期或替换不要求改写旧轮事实，但当前有效状态只来自新快照。

### 完成标准

同一 epoch 里新事件只添加新片段；已提交片段和引用表保持相同。任何删除、压缩、协议转换、选择性遗忘都产生可解释边界。对账能从投影定位真实事件及投递回执，不混淆模型生成与平台发送。

## 8. P5：最终请求的全链路对照

验收必须使用真实生产构造代码，将网络边界替换为 MockTransport/捕获传输，检查序列化后的 HTTP JSON；不以自造等价 ChatRequest 替代入口调用。

| 维度 | 必须覆盖 |
|---|---|
| 入口 | 私聊、群聊、自主、插件唤醒、自动化 generate/agent、迁移后的 SDK、直接投递后的下一轮 |
| 权限 | 普通用户、管理员、actorless、有效/失效委托、只读、工具关闭、Memory 独占 |
| 内容 | 文字、结构化 @、图片、文件+说明、语音、无历史、已有历史、跨会话发送 |
| 恢复 | 空输出、incomplete、无进展、部分成功、预算收尾、HTTP 重试、取消、写入后恢复、协议切换 |
| 历史 | 连续同作者、改名、引用目标可见性变化、插件原因出窗、Rollup、/ai new、重启恢复、快照清理 |
| 工具 | 非空完整 manifest、request_tools、插件启动延迟/失败、运行时禁用、Schema 版本更新、并行结果 |
