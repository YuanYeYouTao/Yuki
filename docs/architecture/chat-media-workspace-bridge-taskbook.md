# 聊天媒体索引与工作区交换任务书（讨论稿）

> 状态：设计稿，尚未实施、测试或上线。对应 [Issue #142](https://github.com/YuanYeYouTao/Yuki/issues/142)。本文以现行 [开发合同](development-contract.md)、[Conversation Rollup](conversation-rollup.md)、[Tool Kernel](tool-kernel.md)、[持久环境](../operations/persistent-environment.zh-CN.md) 为约束；历史任务书不覆盖这些合同。

## 1. 目标与边界

1. 用户先发图片、视频或文件，随后不引用地自然提问时，Yuki 能从同一 canonical Conversation 的真实事件中找到候选，并按需读取实际内容。多人交错、多附件和跨若干条消息由主 Agent 结合语义决定；不设“总选最新附件”或单一时间窗。
2. 历史聊天里出现稳定、可操作的媒体标识，而不是每轮注入一份随缓存状态变化的动态媒体清单。标识只说明“这条事件有第几个什么类型的附件”，不声称已经读过。
3. 原件以受限媒体缓存保存；需要长期编辑时才显式导入 Yuki 的持久工作区。工作区与 Memory、表情库日后的交流走类型化导入/导出服务，不挂载其数据库或内部目录。
4. 本任务不整理工具结果 Artifact，也不重构其存储。
5. 启用时不批量改写 `chat_events`、Rollup、冻结的历史片段或所有会话的 Prompt；不自动重跑历史模型任务，不预热全部旧媒体。

## 2. 现状与已经确认的缺口

- `normalizer._extract_segments` 把媒体列为 `attachments`，文字投影主要保留普通文本和卡片文本；`event_prompt.event_content` 对历史图片只附加已有的 `visual_summary`。历史摘要明确不是本轮原件读取。
- `AttachmentInputService.prepare` 选择本轮或回复附件；`VisionService.select_references` 也只选本轮或回复图片。无引用后续消息不会进入这条链。
- `get_recent_chat_history` 的网关路径返回文字消息，`_store_history_item` 将网关历史媒体 URL、文件标识等去定位信息剥离；仅返回 `newly_recorded` 数量，不给模型一个可直接使用的内部附件引用。账本路径的 `_event_json` 已列出内部事件 ID 与附件序号。
- `workspace_import_attachment(event_id, attachment_index)` 可从同一 canonical Conversation 的入站事件导入，但它会写持久文件，不能代替一般的按需查看；`workspace_inspect` 又要求已发布图片快照。
- 现行模型序列化只允许在 `user` 消息中携带原生图片；普通工具回执不能直接声称把像素交给了主模型。第一阶段的按需工具可由既有视觉 Provider 读取原件，向主模型返回带来源的结构化观察；之后如改造传输合同，须单独验收原生多模态回执。
- 自动化 DSL **目前仍有可达的旧发送出口**：`automation/compiler.py` 生成 `onebot.send_private_message` / `onebot.send_group_message`；`registry.py`、`validator.py`、`handlers.py`、`executor.py`、`model_delivery.py` 仍识别它们。这是本任务必须审计与收口的现存事实，不能以主 Agent 已有 `send_message` 推断自动化也完成统一。
- 插件主调用使用统一 Main Agent Backend；直接通知和独立插件会话另有边界，仍需按入口逐一核验媒体可见性、授权和发送回执。

## 3. 稳定媒体引用如何进入上下文

### 3.1 入账与显示

新增入站事件在同一事件提交中登记附件元数据，按原始 segment 顺序赋予从 0 开始的 `attachment_index`；同时保存真实 `segment_index`。唯一业务引用是 `(source_event_id, attachment_index)`。新增的文字投影在媒体原来的位置插入稳定标识，例如：

`[发送者:小明|...|消息:...] “看看这个” [图片附件0] [文件附件1：报告.pdf]`

主 Agent 的历史事件封装已经带 `#内部事件ID`；工具参数明确使用该 ID 与附件序号。展示名只允许经净化、有界的 basename；不展示本地路径、下载 URL、Base64、网关文件 ID、缓存键或未经验证的内容判断。“可缓存/已失效/已查看”是动态状态，不写进稳定历史文本。视觉摘要若存在，仍单独标为旧观察，绝不拼成“已读取”。

**不覆盖旧事件正文。** 只让启用后新增事件使用新标识。旧事件保留原文字投影；查询历史或媒体目录时从已有可信事件 `segments` 有界地派生同样的 `event_id + attachment_index` 引用。旧网关回填记录若没有可恢复原件定位，明确标记只能看到元数据。

### 3.2 候选选择与索引

建立 Host 管理的 `conversation_media_items` 索引：`source_event_id`、`canonical_conversation_id`、`generation`、`attachment_index`、`segment_index`、类型、净化展示名、声明大小、入账时间与缓存状态。`(source_event_id, attachment_index)` 唯一；按会话和事件顺序索引。真实来源仍是 `chat_events`，索引可校验、可重建；缓存状态不改变历史投影。

- 新事件：账本提交时写索引元数据；下载、抽帧、模型调用一律在提交后进行，不持 SQLite 写锁等待外部工作。
- 旧事件：在已获授权的有界历史查询中按需派生/补充索引；不执行全库扫描或全会话 backfill。
- 历史工具网关补查时，先在传输边界关联/落账并取得内部 ID，再返回事件与附件索引。网关若提供一次性媒体定位，只在传输边界按安全下载策略尝试缓存原件，然后剥离定位信息；没有成功缓存的旧记录保持“原件未证实可用”。平台消息 ID 只用于网关取回或去重，不能成为模型工具参数或业务所有权。
- 主 Agent 用原消息文本、发送者、顺序、回复关系和现有已标注的观察来消歧。可分别检查几个合理候选；仍不明确时澄清。候选搜索不因跨过固定分钟数而突然无效，实际能否获取原件由缓存与网关状态决定。

### 3.3 读取时的授权

`inspect_conversation_attachment(event_id, attachment_index, question?)` 在执行处按内部 ID 读取事件，复核当前 canonical Conversation、可见 generation/历史范围、入站消息、keeper 状态、附件序号和当前工作来源。不能接受模型提供的任意 URL、路径、平台消息 ID 或另一个会话的附件。独立插件 AI 会话无主聊天历史权限，不能继承这个工具。

事件消失、索引损坏、权限变化或原件不可达时返回具体类别；旧 `visual_summary` 或文件名可作为已注明来源的线索，但不能冒充新的原件观察。所有实际读取回执记录内部事件 ID、附件序号、内容 hash、读取方式、截断/抽帧范围和观察模型版本，避免把文件名当正文。

## 4. 原件缓存与工作区

Bot/Host 管理专用磁盘缓存，不直接占用 `/workspace` 的长期项目目录，也不使用仅 128 MiB 的 `/tmp` 保存大视频。入站后在大小、并发和全局容量预算内异步缓存原件字节；缓存不会自动调用视觉模型。高流量或超大附件可保持“仅有元数据/未缓存”，在首次查看时按既有安全下载策略尝试读取。缓存失败不阻止事件入账或普通聊天。

缓存写入使用临时文件、完整校验与原子发布；索引记录 digest、实际类型、大小、访问/过期时间。正在下载或正被 Work 读取的对象持租约；清理器按有效期与配额回收无租约对象，重启后恢复或清理失效租约。Linux `systemd-tmpfiles` 只作孤儿文件兜底，不作为决定活跃对象是否可删的唯一机制。需要从生产流量测定保留期和配额；这些资源参数不参与语义选哪张图。

`save_conversation_attachment_to_workspace(event_id, attachment_index, destination)` 是显式提升：复用同一来源校验与读取实现，写入持久工作区并返回真实路径/版本。`inspect_conversation_attachment` 依赖会话读取授权和媒体服务，不要求持久工作环境已连接；只有提升操作需要工作区能力。缓存过期不会删除已提升的工作文件。原有 `workspace_import_attachment` 的重复选择、下载和写入路径要并入同一后端；对尚未结束的旧 Work，仅保留受控的执行兼容适配，不在新主工具目录同时暴露两套可选入口。

## 5. 图片、视频、文件的统一读取实现

重写相关工具时，将本轮、显式回复、历史事件和工作区已保存文件的读取收敛到同一媒体服务，选择来源与实际解码分开：

| 来源 | 选择依据 | 内容处理 |
| --- | --- | --- |
| 本轮/显式回复 | 已认证的当前或回复事件 | 保留现有即时输入体验；共用安全下载、校验、限额 |
| 历史无引用 | 主 Agent 基于事件索引与语境选择 `event_id + attachment_index` | 按需读取并返回有来源的观察 |
| 工作区文件 | 已验证的路径/版本或已发布快照 | 共用图片/视频/文档处理，不反查聊天来源 |

图片先验真实字节、按现有预处理和视觉预算分析；视频仍只按允许地址下载、验证容器、时长/大小/帧数并抽帧，音轨未处理时明确说明；文件按真实类型与现有文档读取器解析，明确截断、加密或不支持状态。模型观察按内容 hash、问题/模式、Provider 与提示版本复用现有分析缓存；原件缓存与观察缓存各自清理。任何路径都不把 QQ 网关容器本地路径当作 Bot 文件读取。

新主工具合同在部署时冻结。旧 `workspace_inspect` 若保留名称，内部必须复用统一读者；旧历史/媒体工具不能仍走平行的 URL、抽帧或鉴权实现。`request_tools` 只查已冻结工具用法，不临时加入 schema。

## 6. 前缀缓存、历史与上线切换

目标是 **懒切换、只追加**：

1. 先部署索引/缓存能力，不改已有事件正文、Rollup checkpoint、`FrozenFragments` 或所有会话的投影。
2. 新文字标识只由切换水位之后新入账的事件生成；旧事件按原格式显示，缺少索引则在有界查询中按需派生。发布时记录全局切换水位/格式版本，重启后稳定，不以当前时间重新决定同一事件的文本。
3. 新工具 schema/说明形成新的固定主 Agent 合同 revision。现行 `prepare_history` 在 `contract_revision` 变化时会丢弃该会话的旧 `FrozenFragments` 并重新渲染选中的历史；因此仅靠“懒激活”不能声称完全保住旧前缀。实施时应将“历史文本投影格式版本”与“工具/模型合同版本”分开：新 Provider 链在安全边界开启，若 generation、读范围、Rollup 和原历史格式未变，则复用已提交的历史片段；新媒体标识只追加到新事件。必须证明该复用不携带旧工具调用、过期权限或旧图片字节。若无法安全复用，退为每个自然激活会话至多一次有界重建，并先测量成本；不主动唤醒全部会话，不跑“上线后重看所有媒体”。
4. Rollup 继续使用原事件账本和既有 checkpoint；不因新增展示标识重跑已覆盖段。正在执行的 Work 保留原执行 ID、预算、回执和已提交输入；在安全链边界切换，不能重发工具或消息。
5. 用完整 Provider `messages/input`、`tools`、`native_tools` 和 continuation 对照证明：旧历史在新链中按既定兼容策略复用或只发生有界重建，新事件只产生预期尾部增量。工具合同更新本身仍可能导致活跃会话首次新链的**一次性**缓存失配，须测量并如实报告，后续前缀应重新稳定；不把“零失配”作为不实目标。

本方案不需要对所有会话执行 `/ai new`。如果实现中发现必须替换旧历史状态才能保证正确性，则停止该上线方案，先给出受影响会话、Work、Rollup 和缓存成本的 dry-run；另行按真实 `/ai new` 语义做一次受控切换，并处理执行中任务与回执。禁止通过 SQL 直接伪造 generation 重置，禁止悄悄对全库清投影后重跑。

## 7. 插件与自动化全入口检查

媒体能力和新工具应覆盖普通聊天、自主 SELF、定时/用户自动化主 Agent、插件唤醒的主 Agent、持久续跑；每个入口都用真实 ToolRuntime 权限在执行处核验。插件独立 AI 会话、直接通知、DSL 明文发送不是同一主发言场景，分别核对其合法能力与可见来源，不能“统一”成越权读取。

自动化旧发送链目前可达，本任务书要求实际收口：

- `AutomationTaskCompiler` 不再生成 `onebot.send_private_message` / `onebot.send_group_message`；新 DSL 明文投递也进入与 `send_message` 共用的 SocialService/路由、幂等和持久回执实现。
- 检查 `registry`、`validator`、`executor`、`handlers`、`model_delivery`、权限目录、SDK/Facade、历史脚本以及测试夹具。新增脚本拒绝旧名称；已有脚本保留原 step ID、工作 ID 和已送达回执，通过版本化迁移或明确的旧 Work 适配完成未完成步骤，不能重复发送。
- 适配期结束后，旧名称不可从新创建、模型声明、插件 facade、自动化编译或执行分派到达；历史审计 action 可保留只读解释。用运行时可达性测试证明，不只依赖 `rg` 零匹配。
- 插件主调用验证新媒体工具与 `send_message` 权限；插件直接通知核对真实媒体 handle、过期和发送回执；独立插件会话不能借工作区路径或事件 ID 窃取主会话媒体。
- SELF 自动化使用 SELF 主体和原群场景，不能因媒体工具或旧发送别名继承创建者/超管权限。

如旧 DSL 明文发送收口需要独立迁移或扩大 PR，仍是本任务的必过依赖；媒体改动不能以“主 Agent 已统一”为由跳过它。历史审计记录可以继续保留旧 action 名称，但运行中的新发送只应有一个真实效果出口。

## 8. 验收矩阵

### 功能与隔离

- 图片、视频、受支持文档：先发媒体后无引用自然提问；间隔多条消息；多人交错；一条消息多个附件；当前媒体与显式回复保持原效果。
- 模型能从历史拿到可验证 `event_id + attachment_index`，没有来源时不猜平台 ID；候选歧义时不悄悄选错。
- 另一群、私聊、另一 canonical 会话、不可见 generation、被删除或非 keeper 事件都拒绝；插件独立会话与低权限自动化不能越界。
- URL 失效、网关回填只有元数据、缓存损坏、格式不支持、视频超限、文件截断均返回准确状态；旧摘要不冒充本次读取。
- 多次查看同一原件命中字节/分析缓存，问不同问题按真实语义重新分析；缓存清理不删除运行中的 Work 或已提升文件。

### 稳定性与成本

- 升级前后取现有长会话、压缩会话、活动 Work 和静默会话的 Provider 请求对照；检查冻结历史、工具顺序、native tools、Rollup coverage、generation 与 continuation。
- 部署本身不产生针对全部旧会话的模型调用；下一次自然激活只发生合同切换所需的请求。记录首次新链缓存失配和后续回稳，不只报告 hash。
- 后台下载/清理受并发、磁盘、大小和 IO 预算限制，故障时不阻断聊天入账；清理后索引能准确反映原件是否可用。
- 自动化 DSL 明文、模型生成、SELF、插件主调用和直接通知分别跑成功/失败/未知回执及重启恢复；确认旧名称不可新建/不可达、既有已送达消息不重发。

### 上线与回退

- 在测试副本完成迁移与流量回放，再按既有 Bot-only 部署规程备份并上线。不给真实 QQ 群发送测试消息；线上验收用只读状态与既有安全探针。
- 回退保留事件、媒体索引、缓存和所有新消息；旧代码忽略新增索引，不能用旧数据库覆盖上线后事件。若工具合同或迁移不能兼容回退，先列出具体阻断点。
- 交付报告分别说明代码、测试、PR、合并和生产镜像状态，以及真实 QQ 无引用媒体效果是否完成验收。

## 9. 工作区与 Memory、表情库的后续交换合同

本次不实现这两条链，但媒体服务与工作区导入要为它们留下相同的来源/版本接口：

- `Memory → 工作区`：按现有 Person、Group、SELF 读取权限导出选定事实、版本、证据引用和可见范围，供 Yuki 分析或写报告；导出文件是快照，不是新的 Memory 真源。
- `工作区 → Memory`：Yuki 可从文件提出带文件版本、摘要与事件证据的变更提案，执行仍走现有 `memory_change` 的主体解析、证据、冲突与权限校验。目录变化不能自动写 Memory；文件里的指令只作不可信资料。
- `表情库 → 工作区`：选择性导出已授权素材/预览及资产 ID、版本与使用状态；不挂载整个资产库。
- `工作区 → 表情库`：提交指定文件版本，经现有格式、大小、来源和资产生命周期规则入库；使用或发送仍走表情服务和 `send_message` 的授权/回执边界。
- 每次交换都保存来源对象 ID、目标 ID、内容 hash、版本和操作回执；插件只能通过获准 Facade 使用这些交换能力，不能拿到工作区目录或 Memory/表情库数据库句柄。

媒体缓存的`提升到工作区`先验证这组接口模式；后续 Memory/表情库分别写任务书和验收，不在本次上线时隐式开启双向同步。

## 10. 实施顺序

1. 建立稳定媒体引用、索引、缓存与有界旧事件派生；先验证无批量历史改写。
2. 统一图片/视频/文档读者，接入“查找、按需查看、提升到工作区”新工具；旧工具收成单实现兼容层。
3. 覆盖主聊天、SELF、自动化、插件主调用与持久续跑的权限和完整 Provider 请求。
4. 处理已经确认的自动化旧发送 DSL 与插件残留审计，完成持久脚本/回执迁移测试。
5. 对照缓存与成本后灰度上线，再验证真实无引用对话。Memory/表情库与工作区的类型化交换另立后续任务，不占用本次聊天媒体验收。
