## 1. 约束、依据与证据状态

### 1.1 最新要求优先

用户已明确否决“每日自主启动上限”。本任务书将它落实为：**自然日不是自主行为的控制周期；一天内已经发生的次数不能成为继续参与的独立否决条件。**

因此当前规范同时取消旧实验中会间接造成同类停机的日请求、日发送、独立回忆日配额。旧的自然小时请求计数上限也不迁入自主模型，避免将同一配额换一个时间单位重新引入。这一扩大清理范围是本任务书为保持规则一致性作出的实施决定。

| 旧字段或行为 | 当前处理 |
|---|---|
| `wake_cap`：每日自主启动上限 | 删除控制用途，不改成一个更大的整数 |
| `req_cap`：每日自主模型请求上限 | 删除控制用途；保留逐请求统计 |
| `send_cap`：每日自主发送上限 | 删除控制用途；保留实际交付统计 |
| `recall_wake_cap` / `recall_send_cap` | 删除独立回忆与自由分享的日配额 |
| `hour_req_cap`：自然小时请求配额 | 不迁入当前自主策略 |
| 午夜重置额度、午夜恢复主动性 | 删除；状态按经过时间连续演化 |
| 日均发言目标、最低发言数、补足发言占比 | 不设置 |
| 以很大的数、无穷值或日志数组容量代替删除配额 | 不接受，必须删除相关控制分支 |

保留的是**局部、可解释的运行约束**：本群单个主动执行租约、单个 Work 的有限执行、短时间防重入、来源幂等、过期检查、平台真实限流和运行故障处理。它们不能被解释为日行为配额。

日统计仍然可以存在，用于报告消耗和观察行为；禁止让它反向影响唤醒门。

## 2. 系统目标与设计决定

### 2.1 产品目标

Yuki 是长期存在于群聊中的数字角色。它应能参与陈述、感想、补充和来回讨论，不将“没有 @ 或明确任务”理解为“不得说话”。明确请求仍走原有直接响应路径；已接受的 Work 和必要交付不受自主意愿控制。[S1；S5 §1、§7]

数学系统仅决定**是否值得启动一次理解与行动过程**，不负责写回复、判定人物事实、授予权限或重新实现长期记忆。唤醒不保证发送，沉默也是正常终态。

### 2.2 唯一设计决定

| 决定 | 当前规范 | 来源或理由 |
|---|---|---|
| 自主环境 | 每个 canonical Conversation 独立状态，并受 generation 隔离 | S1、S2 |
| 执行方式 | 便宜状态持续存在，LLM 按需运行有限回合 | S1、S2 |
| 自主判定 | 一套门，区分首次加入、持续接话、独立主动发起 | S5 |
| 真人请求 | 保留原路径，不经过自主意愿阈值 | S1、S2 |
| 注意模型 | 带泄漏的拉普拉斯图扩散；不再使用使孤立输入缩水的旧式 | S3、S5 |
| 语义输入 | 当前主 Agent 可选的 `engage` / `mood`，不每轮必填 | U1、S2 |
| 关联图 | 保留数学接口；无合法边时取零，不制造相似关系 | S2；图的额外收益尚未证实 |
| 发起者 | 自主轮为 Yuki，观察来源与发起者分离 | S1、S2 |
| 权限 | 由后端本群自主授权决定，不继承最后发言者 | S1、S2 |
| Prompt | 保持真实历史与原有编排，新增明确的自主触发上下文 | S1、S2 |
| 资源策略 | 无日配额，使用实际消耗痕迹、有限单轮与即时运行状态 | U1；本版修订 |
| 评估目标 | 参与是否合适、接话是否连贯、调用是否有效 | 不以发言总量最大化替代质量 |

### 2.3 不进入本期范围

不新增逐消息 Planner，不训练触发模型，不常驻另一套语义编码器，不建立跨群全局聊天流，不重复建设 Memory、Relationship、Work；也不承诺“纯时间统计能理解所有群聊含义”。已有底层模型当然属于语言模型，准确表述是**无额外训练的数学触发器**，不能把整个 Yuki 称为没有机器学习模型的系统。

## 3. 文本架构与责任边界

```text
真实消息 / 已有合法记忆 / 工具结果 / 既有反馈
                        │
                        ▼
        canonical 记录、读取范围、来源去重与版本
                        │
                        ▼
       本群状态：活动、参与倾向、情感、证据痕迹
                        │
                        ▼
             耗散注意场与候选竞争
                        │
                        ▼
          逐候选积累、迟滞、当前机会复查
                        │
                        ▼
     唯一自主执行门：授权、来源、租约、局部节奏
                  不读日配额计数
                        │
                        ▼
       GroupInitiativeRun / 正式自主 Trigger
                        │
                        ▼
        现有 PromptCompiler / ContextAssembler
                        │
                        ▼
          有限 Main Agent / 已有 Work 与工具
                  │                   │
           表达或显式沉默       可选状态尾段
                  │                   │
                  ▼                   ▼
       执行与平台发送回执     后端分离、校验、去重
                  │                   │
                  └─────────┬─────────┘
                            ▼
                   更新实际状态与记录
```

共享调度器只计算下一次本地检查，不在心跳时请求模型“看看要不要说话”。明确请求独立进入现有 Main Agent，但其真实请求消耗、发言回执可更新本群痕迹。

同一条消息的持久化、历史可见性与唤醒价值是不同概念。候选只引用证据，不能再把历史消息重新合成“当前用户消息”。

## 4. 统一数学对象

### 4.1 范围与状态

本群范围写为：

\[
g=(c,\nu),
\]

其中 \(c\) 是 canonical Conversation，\(\nu\) 是 generation。若 canonical ID 未全局区分机器人实例，持久键再加入 bot ID；这由实际主键语义决定。

每群至多 \(K\) 个活跃候选。连续状态为：

\[
X_g=(q,p,f,d,e,m,s,x,h,\eta).
\]

| 符号 | 范围 | 含义 |
|---|---|---|
| \(q\) | \([0,1]\) | 最近真人活动强度 |
| \(p\) | \([0,1]\) | 最近已确认的 Yuki 发言存在度 |
| \(f\) | \([0,1]\) | 最近实际模型计算形成的占用痕迹 |
| \(d\) | \([-1,1]\) | 本群参与倾向 |
| \(e,m\) | \(\mathcal A=[-1,1]\times[0,1]\) | 即时情感、缓慢心境 |
| \(s_i\) | \([0,1]\) | 候选的短期来源痕迹 |
| \(x_i\) | \([0,1]\) | 持续注意 |
| \(h_i\) | \([0,1]\) | 近期考虑或暴露形成的熟悉度 |
| \(\eta_i\) | \([0,1]\) | 候选唤醒积累 |

固定 \(K\) 的基础连续维数为 \(8+4K\)。近期参与状态由确认参与时间推导；新证据质量、发言占比由事件记录推导，不能为了沿用维数而隐瞒这些辅助状态。

离散状态 \(D_g\) 包括来源、版本、已考虑快照、有效期、迟滞开关、执行租约、图版本、回忆游标和自报接收序号。**不包含用于控制行为的日剩余次数。**

### 4.2 混合系统形式

\[
\dot X_g=F(X_g;\widehat b,\widehat z,W,\widehat\tau_\eta),
\qquad
(X_g^+,D_g^+)=J_\xi(X_g^-,D_g^-).
\]

\(\xi\) 表示后端可观察事件。连续段采用采样保持，事件引起离散更新。外部事件序列假设在有限区间内有限；真实大量消息可批量读取，但每条来源仍保持身份。

引用 P1、P2 是为使用混合流与动态触发的表达框架。本任务书的方程、资格规则与结论需要单独证明，不能直接继承被引用控制系统的稳定性结论。

### 4.3 时间语义

运行内使用单调时钟计算间隔，持久化记录 UTC 与逻辑顺序。状态按经过时间变化，不在午夜归零。重启后恢复当前状态与当前仍有效的检查，不补跑所有错过的心跳。

`generation` 只随现有会话生命周期变化，不能每天增加。日历时间仅用于显示、分析窗口和用户明确设置的场景时段，不能隐含地成为行为配额重置点。

## 5. 候选、来源版本与新证据

### 5.1 候选类型

| 类型 | 合法来源 | 说明 |
|---|---|---|
| `conversation` | 真实本群消息、实际引用链、因果构造的有限片段 | 表示有材料值得理解，不预先断言它在求助或邀请 |
| `recall` | 已有、获准在本群使用的 Memory / SELF 经历 | 允许主动想起，不把旧经历当成刚发生的新事实 |
| `result` | 有真实执行证据的可选结果分享 | 已承诺或用户要求的必要交付不属于可自由忽略的候选 |

新的创意可在主 Agent 已经运行时形成，并通过原有合法记录成为以后材料。数学层不能凭空创造未经记录的新想法。

候选最小结构：

```text
candidate_id / root_identity / kind
conversation_id / generation
source_refs / evidence_revision
considered_snapshot / consumed_evidence_refs
created_at / latest_content_at / expires_at
last_considered_at / last_confirmed_participation_at
s / x / h / eta / latch
status
```

### 5.2 先有真实身份，后有聚合

优先使用实际回复链或已存在的结构关系；没有关系时，可用仅依赖过去信息的有界时间片。不能直接拿仿真器预先知道的整段话题 ID、结束时间或未来消息簇边界作为生产输入。

同根来源可以持续产生新内容。禁止将“整个话题曾回复一次”解释为这个话题永久不可再参与；也禁止仅更换候选 ID 就重新获得资格。

### 5.3 新证据资格

设 \(U_i\) 为尚未纳入已读快照的合法新内容引用，定义辅助量：

\[
M_i=\min\left\{1,\sum_{j\in U_i}w_j\right\}.
\]

它是内容质量代理，不是语义概率。当前阈值小于 1，因此截断不改变“是否超过阈值”的判断，同时避免将无界计数误称为有界状态。

\[
\mathrm{eligible}_i=
\mathrm{valid}_i
\land(\mathrm{revision}_i>\mathrm{considered}_i)
\land(M_i\geq M_{\min})
\land\mathrm{root\_cooldown\_ready}_i.
\]

`valid` 包含当前群可读、generation 正确、来源未撤回、候选未过期。版本只由新的合格内容、已有记录的实质变更、或此前未考虑的合法回忆来源推进。

时间过去、情绪变化、图传播、重复检索、相同文本重放不能独立产生新证据版本。活动消息照常进入历史，哪怕其内容刺激为零。

**本版规范化要求：** 精确重复和零内容刺激不刷新机会新鲜度或内容 TTL。V3 仿真代码对部分这类事件仍可能增加版本或刷新时间，不能宣称这项要求已经由旧测试完整覆盖。

### 5.4 “已考虑”必须对应实际阅读快照

启动时冻结候选及来源快照，原子保留执行权。最终记录的是本轮实际提交给主 Agent 的证据，而不是运行结束时群里所有最新消息。

运行中到达、但未进入主 Agent 任一次真实输入的新消息必须保留。不得在回合完成时把整个候选清空，从而吞掉这些新消息。多次工具调用期间纳入的新输入，按已有 Work steering 和输入记录合并。

允许一次正常 `noop` 消耗本次已考虑资格，但不删除历史。请求未发出时只能恢复同一 run 的有限技术尝试，不能重新建候选规避幂等。

### 5.5 激活槽与持久记忆分离

只对 \(K\) 个活跃槽运行数值计算；来源幂等与已考虑记录持久保存。淘汰活跃槽不能丢失已考虑版本，也不能使另一候选继承 \(x_i\) 或 \(\eta_i\)。长期来源记录可随正式数据保留策略归档，不能按午夜清空。

## 6. 多时间尺度状态与稀疏语义跃迁

本节主体继承 S2；数值采用 V3 最终参数。它们是工程状态，不是对真实心理过程的测量。

### 6.1 活动、发言与计算

\[
\dot q=-q/\tau_q,\qquad
\dot p=-p/\tau_p,\qquad
\dot f=-f/\tau_f.
\]

对 \(u\in[0,1]\)，定义饱和跃迁：

\[
\mathcal S_w(u)=u+w(1-u),\qquad 0\leq w\leq1.
\]

真人活动更新 \(q\)，平台确认的逻辑发言更新 \(p\)，实际模型请求更新 \(f\)。一次回复拆成若干消息气泡，不机械地多计完整发言。生成文字、排队发送和平台确认发送必须分开。

同一用户 4 秒内分条可在活动统计中按一次 burst 处理；真实消息仍逐条记录。不能用群体密集聊天本身制造强内容价值。

### 6.2 参与倾向

\[
\tau_d\dot d=d_0-d,
\qquad
D(d)=D_{\min}+(1-D_{\min})\frac{d+1}{2}.
\]

有效自报映射：

| `engage` | 跃迁值 |
|---|---:|
| `quiet` | -0.7 |
| `neutral` | 0 |
| `join` | 0.7 |

缺失或接收失败等于“没有这次跃迁”，原状态仍按时间恢复。`quiet` 不取消真实请求，不影响已经接受的任务责任。

### 6.3 即时情感与缓慢心境

\[
\begin{aligned}
\tau_e\dot e&=m-e,\\
\tau_m\dot m&=m_0-m+\rho(e-m),
\end{aligned}
\qquad \rho>0.
\]

合法 `mood` 只改变即时情感 \(e\)，不直接跳变慢心境 \(m\)。

| `mood` | 正负方向 | 激活程度 |
|---|---:|---:|
| `calm` | 0.05 | 0.15 |
| `pleased` | 0.55 | 0.35 |
| `curious` | 0.20 | 0.65 |
| `tense` | -0.45 | 0.70 |
| `tired` | -0.10 | 0.10 |

映射只是冻结的实验基线，不是心理量表；本期不在线学习它。工具失败、没人回复或群友继续说话，都不自动映射为某种心情。

设 \(u=e-m_0,w=m-m_0\)，

\[
V_a=\frac{\rho\tau_e}{2}\lVert u\rVert^2+
\frac{\tau_m}{2}\lVert w\rVert^2.
\]

在基线固定、无新跃迁的连续段：

\[
\dot V_a=-\rho\lVert u-w\rVert^2-\lVert w\rVert^2.
\]

因此快慢耦合本身不会无限放大。矩形边界向内，合法映射和回忆的凸组合保持 \(e,m\in\mathcal A\)。这不是“包括语言模型与群友在内的整个系统全局稳定”的证明。

### 6.4 证据痕迹与熟悉度

\[
\tau_{s_i}\dot s_i=-s_i,
\qquad s_i^+=\mathcal S_{w_i}(s_i^-),
\]

\[
\tau_{h_i}\dot h_i=-h_i,
\qquad h_i^+=\mathcal S_{w_h}(h_i^-).
\]

熟悉度由真实考虑或暴露事件更新，在同一机会内使用统一接触标识去重。会话熟悉度恢复较快，回忆较慢；不修改原 Memory 的长期强度、可信度与关系值。

## 7. 证据驱动的耗散注意场

### 7.1 关联只连接已有材料

由合法的已有实体、实际引用或已有记忆关联构造：

\[
A=A^\top\geq0,\quad A_{ii}=0,
\qquad
W=\frac{A}{\max\{1,\max_i\sum_j A_{ij}\}}.
\]

没有关系就取 \(W=0\)。图不创建新事实，不提高读取权限，也不自动代表语义理解。原长期关系服务只提供合法投影，不新增第二份关系真值。

### 7.2 情感对已有输入的有界调制

已有合法的 Yuki 侧情感标签 \(a_i\) 时，取

\[
T(v,a)=(v,2a-1),\qquad
\chi_i(e)=\frac12+\frac14\langle T(e),T(a_i)\rangle\in[0,1].
\]

没有标签时 \(\chi_i=1/2\)。

\[
b_i=s_i[(1-\varepsilon)+\varepsilon\chi_i(e)].
\]

因此 \(s_i=0\Rightarrow b_i=0\)。情绪只调制已有刺激，不能独立制造来源或发言任务。

### 7.3 当前采用的注意方程

\[
\boxed{
\tau_x\dot x=-x-\kappa Lx+\widehat b,
\qquad L=\operatorname{diag}(W\mathbf1)-W.
}
\]

旧式 \(-(I-\kappa W)x+(1-\kappa)b\) 不再采用。S3 已指出：孤立候选在旧式中会额外损失直接输入幅度。

令 \(H=I+\kappa L\)。对合法对称非负图和 \(\kappa\geq0\)，有 \(H\succeq I\)。当前参数仍取 0.35；不要因旧代码校验的限制而声称新方程在数学上必须 \(\kappa<1\)。

固定图与保持输入时：

\[
x^*=H^{-1}\widehat b,
\qquad
\mathcal E(x)=\frac12x^\top Hx-\widehat b^\top x,
\]

\[
\dot{\mathcal E}=-\tau_x\lVert\dot x\rVert^2\leq0.
\]

### 7.4 可检查的性质

在 \(x_i=0\) 时，导数非负；在 \(x_i=1\) 时，\(-1+b_i+\kappa\sum_jW_{ij}(x_j-1)\leq0\)。因此合法初值和输入保持 \([0,1]^K\)。

每个连通分量满足：

\[
\tau_x\frac{d}{dt}\mathbf1^\top x
=-\mathbf1^\top x+\mathbf1^\top\widehat b.
\]

图项只扩散，不创造注意总质量。无输入连续段有

\[
\lVert x(t)\rVert_2\leq e^{-(t-t_0)/\tau_x}\lVert x(t_0)\rVert_2.
\]

图切换仍保持逐时正定与边界性质，但不同输入、候选加入和状态重置会改变能量函数；不能将固定输入的能量下降直接推广为全程单调。

**研究约束：** V3 去掉关联边并未降低模拟发言数。图是待检验模块，不能先写成已证实的性能贡献。[S5 §3、§9]

## 8. 参与情境、竞争与唤醒

### 8.1 时间空档与机会新鲜度

设 \(\Delta_{\mathrm{gap}}\) 为距最近真人消息或 Yuki 确认发言的时间：

\[
O=1-e^{-\Delta_{\mathrm{gap}}/\tau_{\mathrm{gap}}}.
\]

会话候选还使用：

\[
F_i(t)=e^{-(t-t_{i,\mathrm{content}})/\tau_{\mathrm{fresh}}},
\]

回忆与结果取 \(F_i=1\)。新内容更新时间只来自符合第 5 节的证据；不存在可靠输入状态时，不推测对方是否正在打字或是否已经结束讨论。

长期无人活动的附加代价：

\[
C_d=c_d(1-e^{-\Delta_{\mathrm{human}}/\tau_{\mathrm{dormant}}}).
\]

空档和休眠改变时机，不创造内容。

### 8.2 近期参与状态

同根来源有可确认的参与绑定、并出现未处理的新真人证据时：

\[
E_i(t)=
\begin{cases}
 e^{-(t-t_i^Y)/\tau_E},&0\leq t-t_i^Y<\tau_E,\\
 0,&\text{otherwise}.
\end{cases}
\]

\(t_i^Y\) 必须源于确认发送。不能仅因请求发出、模型生成正文或其他群活跃就更新。

**实现细化：** 现有真实引用回复目标能够确定来源时，更新对应来源；没有可靠来源绑定时只更新群级 \(p\)，不猜测主 Agent 在回复哪段历史。不能每轮额外要求模型填写话题或记忆 ID。V3 模拟借用了模拟 Agent 的已选机会标签确定目标根，真实实现不天然拥有这项信息，必须作为迁移差异测试。

### 8.3 近期占比仅增加超额代价

\[
R_w=\frac{N_Y(t-w,t]}{N_H(t-w,t]+N_Y(t-w,t]},
\]

分母为零取零。\(N_Y\) 按已确认的自主逻辑发言统计，\(N_H\) 按真人消息统计，继承 V3 定义。消息气泡拆分敏感性须单独测试。

\[
C_{\mathrm{share}}=c_R[R_w-r_0]_+.
\]

低于 \(r_0\) 没有奖励，不要求达到某个占比。\(r_0=0.20\) 不是目标发言率。

### 8.4 统一净机会

\[
\begin{aligned}
v_i={}&OD(d)\frac{x_iF_i}{1+\beta h_i}
-\theta_{k_i}-c_pp-c_ff-c_qq-C_d-C_{\mathrm{call},i}\\
&+\mathbf1_{k_i=\mathrm{conversation}}
  (c_EE_i-C_{\mathrm{share}})
-\mathbf1_{k_i\ne\mathrm{conversation}}c_{\mathrm{ind}}.
\end{aligned}
\]

`conversation` 包含首次加入和持续接话。独立回忆、自由分享使用更高类型门槛与额外代价，但不再检查日配额。

\(c_{\mathrm{ind}}=0.05\) 在 S6 的 `engine.py` 中作为独立主动候选额外代价存在，S5 参数表未单列。本任务书将其命名列出，避免复制参数时遗漏。

所有分数无量纲，不是概率。\(f\) 是过去的实际计算痕迹，\(C_{\mathrm{call}}\) 是本次调用成本代理；本期不把货币费用直接与它们相加。

### 8.5 严格凸竞争，允许全不选

令 \(B\) 的列表示非负、规范化的根来源特征：

\[
Q=I+\gamma B^\top B,
\qquad
\mathcal Z=\{z\geq0:\mathbf1^\top z\leq1,\ z_i=0\text{ if ineligible}\}.
\]

\[
\boxed{
z=\arg\min_{z\in\mathcal Z}
\left(\frac12z^\top Qz-v^\top z\right).
}
\]

\(Q\succeq I\)，因此解存在且唯一。所有合格 \(v_i\leq0\) 时唯一解为零。固定 \(Q\) 和资格集合时，最优性条件给出

\[
\lVert z(v)-z(v')\rVert_2\leq\lVert v-v'\rVert_2.
\]

V3 日仿真只使用 \(B=I\)，于是 \(Q=(1+\gamma)I\)。一般重叠来源必须使用正确的二次规划求解器，不能无条件沿用单纯形投影特例。求解失败时记录数学错误、保留来源并安排本地重试，不能因此额外调用 LLM 判断。

### 8.6 逐候选积累与迟滞

\[
\tau_{\eta,i}\dot\eta_i=-\eta_i+\widehat z_i.
\]

一般加入使用 \(\tau_\eta=3\) 秒；近期参与且有新真人证据时使用 \(1.95\) 秒。这个时间尺度在保持段内冻结，情境到期是显式调度边界。

\[
\ell_i^+=
\begin{cases}
1,&\eta_i\geq\vartheta_{\mathrm{on}},\\
0,&\eta_i\leq\vartheta_{\mathrm{off}},\\
\ell_i^-,&\text{otherwise}.
\end{cases}
\]

申请执行需要 \(\ell_i=1\)、当前重新计算的 \(z_i\geq z_{\min}\)、来源仍合格，以及第 9 节的运行条件。多个候选按积累值与稳定 ID 选择一个主机会；不能为同一唤醒并行开启多个主 Agent。

同一候选的新版本不能继承另一候选的积累。已考虑快照的数值机会可以清除，但须保护第 5.4 节所述的运行中新输入。

## 9. 无日配额的调度与资源处理

### 9.1 唯一执行门

申请一次自主回合时，只检查：

```text
当前群启用了自主能力
来源和 generation 仍然有效
当前存在正的、已经积累的机会
本群执行租约可取得，不与实际直接请求冲突
本群及同根短间隔已满足
后端自主授权允许本次工作
必要的本地资源和服务实际可用
```

明确排除：今天已经启动几次、今天发了多少、今天回忆过几次、离次日还有多久。保留这些数值作统计时，也不得传入判定函数。

已有平台限流或实际服务故障会影响能否执行，但必须返回具体运行原因，如 `provider_rate_limited`、`authorization_revoked`、`group_busy`，不能伪装成“Yuki 不想说话”。

### 9.2 成本处理方式

当前使用 \(f\)、\(C_{\mathrm{call}}\)、短时并发与实际服务状态调节计算。一次成功 `noop` 消耗实际资源，但不自动产生负面情感。后台不为了记录状态再调用模型。

单个 Main Agent / Work 继续沿用部署中已有的累计模型请求、工具执行和运行时间上限。限的是**这项工作本身**，不是一整天的行为。到限后按真实状态结束或暂停，不通过自动新建相同 run 无限续接。

本任务书不凭旧仿真每轮 1–3 次请求的生成假设，擅自将生产 Work 限成三次。任务 T13 要从既有运行合同读取实际限额，分别记录每次请求和工具的消耗。

全局只共享调度和真实资源容量，不共享人物上下文。多个群竞争容量时须具备公平排队、取消和过期重查，不让最活跃群长期占满；排队等待不能被当作更高语义价值。

### 9.3 保留的短时约束

本版继承 V3 的本群自主启动最小间隔 15 秒、同根来源间隔与滚动 60 秒最多 3 次自主逻辑发送。后者属于短时发送保护，不是发言目标，也不会让 Yuki 停到次日。

保护层是否必要、是否造成等待与浪费，须通过有/无保护的配对实验评估。它必须独立记日志；正式论文不能将它造成的有限频率完全归功于数学门。

如发送槽暂时不可用，发送前按现有交付规则短暂等待或明确结束，并重查来源与授权。不能立即重新调用模型生成同一条内容，也不能因为几秒内出现其他普通消息就无条件丢弃已生成回复。真正冲突或新直接请求按现有 turn/Work 规则处理。

### 9.4 有限性不依赖日配额

若同一 canonical 群的自主启动时间满足

\[
t_{n+1}-t_n\geq\delta_{\min}>0,
\]

则任意长度 \(T\) 的有限区间内

\[
N_g([a,a+T])\leq1+\lfloor T/\delta_{\min}\rfloor.
\]

这是最小间隔导出的数学上界，不是在一天用完后停机的计数规则。调度时间戳须跨普通进程重启保留；generation 更换不能用于绕过运行层防重入。

若每个自主工作的实际模型请求数还受已有有限值 \(B_{\mathrm{run}}\) 约束，则该区间中新启动工作对应的请求总数至多为 \(B_{\mathrm{run}}N_g\)；跨区间开始的未完工作须另外计入。无配额不代表固定账单，也不保证无限时间内总成本有限。

此证明不保证候选一定被执行。是否发生饥饿、是否错过时机是另一组实验与调度性质，不能混为“稳定所以好用”。

### 9.5 精确的保持段推进

在本地检查 \(t_n\) 时计算并保持 \(b_n,z_n,W_n,\tau_{\eta,n}\)。

标量恢复项：

\[
y(t+\Delta)=\bar y+e^{-\Delta/\tau_y}(y(t)-\bar y).
\]

情感状态：

\[
\begin{pmatrix}e(t+\Delta)-m_0\\m(t+\Delta)-m_0\end{pmatrix}
=e^{M\Delta}
\begin{pmatrix}e(t)-m_0\\m(t)-m_0\end{pmatrix},
\quad
M=\begin{pmatrix}
-1/\tau_e&1/\tau_e\\
\rho/\tau_m&-(1+\rho)/\tau_m
\end{pmatrix}.
\]

注意状态，令 \(H=I+\kappa L\)：

\[
\Phi=e^{-H\Delta/\tau_x},\qquad
x(t+\Delta)=\Phi x(t)+H^{-1}(I-\Phi)\widehat b.
\]

积累状态：

\[
\eta_i(t+\Delta)=\widehat z_i+
(\eta_i(t)-\widehat z_i)e^{-\Delta/\widehat\tau_{\eta,i}}.
\]

固定图时可缓存矩阵分解；不为每群设置持续数据库写入。浮点实现只允许容差内修正区间误差，禁止用无日志的大幅裁剪隐藏错误。

### 9.6 预测检查与边界

当 \(\eta_i<\vartheta_{\mathrm{on}}<\widehat z_i\) 时，预计越阈时间：

\[
\Delta_i=\widehat\tau_{\eta,i}
\log\frac{\widehat z_i-\eta_i}{\widehat z_i-\vartheta_{\mathrm{on}}}.
\]

预计时刻仅触发本地复查，不授予发送权限。下次检查取预计越阈、候选到期、同根间隔到期、近期参与状态到期、短时发送保护解除、回忆检查、授权变更与最大保持间隔中的最早者。新真实事件可提前打断。

一般与持续参与两种 \(\tau_\eta\) 必须在实际积分和越阈预测中一致使用。旧 V3 代码的积分使用情境缩短值，预测表达式仍使用一般值；本版修正这项实现不一致，并要求单独回归测试。

没有候选、没有待处理来源时停止高频检查，只保留合法的低频回忆检查或等待真实事件。不可用 \(\Delta=0\) 反复安排内部检查；共享调度器应合并同刻事件，并设置有限正的本地重试间隔。

## 10. 回忆、执行与真实反馈

### 10.1 主动回忆不靠日配额，也不凭沉默制造内容

共享调度器可以每 30 分钟对获准群做一次有限本地回忆检查。检查来源是已存在的记忆，不是新事实生成器；未发现合格材料时不调用模型。

本地排序可沿用：

\[
R_i=\overline A_i r_i(1-h_i),\qquad \overline A_i,r_i\in[0,1].
\]

\(\overline A_i\) 来自已有 Memory 的合法投影，\(r_i\) 来自已有本群关联。没有关联信息不填造高分。查询如会触发 embedding 或辅助 LLM，须另做真正的本地读取路径；在它完成前不能称后台回忆为零模型。

删除旧的“每天最多考虑 4 次、发 2 次”。同一记忆版本、同一机会不能因冷却或午夜而重新获得资格；新的相关线索、实质修正或新的合法结果可以形成新机会。未曾考虑的旧记忆可以在本地检查时首次进入候选，不要求每次一定先有新真人消息。

每次只检查和激活有限条记录，使用持久游标与来源去重。有限单次扫描用于控制本地查询规模，不是限制一天最多能出现多少合法回忆。

### 10.2 五类记忆事件

| 事件 | 只证明什么 | 可更新什么 |
|---|---|---|
| `recall.activated` | 本地选到已有合法材料 | \(s_i\)、候选引用 |
| `memory.retrieved` | 查询返回结果 | 查询记录，不等于模型接收 |
| `memory.exposed` | 实际发出的模型输入含该记忆 | 去重后的 \(h_i\) 与合格情感刺激 |
| `memory.attributed` | 现有归因过程认为输出使用该记忆 | 后验使用记录，不等于用户认可 |
| `memory.changed` | 正式修正、撤回或删除 | 资格、版本、候选和待执行状态 |

已有 `MemoryExposureRegistry` / `MemoryAttributionWorker` 的定位来自 S2 的固定提交审计。要验证其实际接入位置，而非假定注册到内存表就已经向模型发送。

### 10.3 回忆对情感的影响

只有记忆原来存在合法的 Yuki 侧情感标签 \(a_i\) 时，首次有效暴露允许：

\[
\alpha_i=\alpha_{\mathrm{recall}}(1-h_i^-),
\qquad e^+=(1-\alpha_i)e^-+\alpha_i a_i.
\]

随后更新熟悉度。没有标签不猜测；人的情绪标签不直接当成 Yuki 的情绪。主 Agent 可以在实际阅读后偶尔报告新感受，但不能把这次感受永久回写给同轮所有记忆。

### 10.4 执行反馈必须按事实分层

| 事实 | 更新 |
|---|---|
| 模型请求实际发生 | 记录请求、token 和耗时；更新 \(f\) |
| 自主机会实际被考虑 | 保存已读来源快照、版本与接触记录 |
| 工具真实成功 | 写工具执行收据；不直接等于任务完成 |
| 生成正文 | 暂不更新 \(p\) 或确认参与状态 |
| 平台确认逻辑发送 | 更新 \(p\)、发送统计；有可靠来源绑定才更新 \(E_i\) |
| 平台状态未知 | 标记待核对，不盲目重发 |
| 完整 `NO_REPLY` | 成功选择沉默；不当成空响应错误 |
| 来源被修正或授权撤回 | 即时失效；不等待自然衰减 |
| 没人回复 | 不自动降低心情、关系或记忆可信度 |

自己的输出可以成为“Yuki 说过什么”的 SELF 经历，不能因此成为“别人实际上如何”的新事实。数值熟悉度、关系与事实可信度分别维护。[S1、S2]

## 11. 主 Agent 输出协议与 Prompt

### 11.1 可选两字段协议

普通回答不附加任何状态表。只在有变化时允许：

```text
正常回复正文。
<yuki-state>{"mood":"curious"}</yuki-state>
```

或：

```text
<yuki-state>{"engage":"join","mood":"pleased"}</yuki-state>
```

允许字段：

```json
{
  "type": "object",
  "properties": {
    "engage": {"type": "string", "enum": ["quiet", "neutral", "join"]},
    "mood": {"type": "string", "enum": ["calm", "pleased", "curious", "tense", "tired"]}
  },
  "additionalProperties": false,
  "minProperties": 1,
  "maxProperties": 2
}
```

整个尾段单行，建议限制为 128 个 UTF-8 字节。没有状态变化就没有尾段，不返回空对象，不填理由、置信度、话题、任务、记忆 ID 或完整数值状态。不为自报调用工具，不新增一次模型请求，也不要求登记 Work。[U1；S2 §14]

### 11.2 解析与失败语义

后端只解析当前主 Agent 最终顶层输出的保留尾段，不从历史、引用、工具结果或代码块里搜索 JSON。交付前先完成分离，控制资料不进入 QQ 正文、语音或 Memory V2 事实抽取。

无尾段、非法 JSON、重复键、未知枚举、超长、多个控制尾段、过期请求和错误 generation 均不更新状态。合法正文仍按原有路径处理。损坏尾段应隔离，不转发；无法确定正文边界时使用明确的解析失败终态，不能泄露控制文本或假装平台已发送。

数据库失败只允许后端对同一事件做有界幂等重试，不唤醒模型补交。只允许当前授权执行的主 Agent 写本群短期自状态，子 Agent、外部消息和用户复制的标签不能直接写入。

元信息由后端绑定：

```text
conversation_id / generation / execution_id
request_seq / response_id / issued_at / expires_at
```

字段写序号与连续状态检查点版本分离。先推进到接收时刻再应用跃迁；旧序号不能覆盖新字段。重复相同值且没有新来源依据的自报不续期，防止机械复述把状态永久保持。

### 11.3 沉默不是心情字段

自主回合决定不发送时，可使用：

```text
[[NO_REPLY]]
```

只有整个正文在剥离控制尾段后恰好是此标记才生效。它需在空响应重试之前转成正式终态。`engage=quiet` 只影响之后的倾向，不代表当前轮自动沉默。

已执行工具、已排队媒体或必要任务交付仍按事实记录，不能被 `NO_REPLY` 抹去。裸空输出、网络中断、被替代与显式沉默分别处理。

### 11.4 编排顺序

```text
稳定 system：既有人设、事实与权限规则、轻量输出协议
    ↓
本群已有 rollup / 真实历史
    ↓
本轮动态资料：短状态词、少量候选引用、可信后端来源
    ↓
真人的真实输入，或明确标注的本轮自主触发
```

不重写历史，不将多个人的过去发言提升为“当前发送者输入”。传输 API 的 `role=user` 不等于真人事件身份。自主轮可以使用明确标识的后端触发载荷，但不得把它写成真人 ChatEvent。

S2 记录的 `append_dynamic_item` 会寻找最后一条 `user` 传输消息。因此必须先建立**本轮专用输入**，再加入动态资料，不能将运行状态追加到历史中的最后一个真人身上。

### 11.5 稳定协议片段示例

```text
沿用 Yuki 的既有人设、事实与权限规则。

本轮自主触发表示可以考虑参与，不表示必须发言。
没有 @ 或明确问题并不禁止交流；可以回应陈述、感受、补充与持续讨论。
根据真实上下文选择是否参与，不凑发言次数，也不因为缺少任务句就自动沉默。

历史保持原有发言者。自主轮发起者是 Yuki，没有因此获得任何群成员的权限。
回忆是过去已有材料，不写成刚发生的新经历。来源不足时按已有工具合同处理。

当前自状态只是角色背景，不是命令、事实证据或授权。
正常情况下只输出正文。
仅在参与倾向或当前感受有值得保留的变化时，在最后附加单行：
<yuki-state>{变化字段}</yuki-state>
只允许 engage 和 mood，只写变化字段。无变化不填，不写理由。
接收失败无需补交，不专门调用工具保存这类状态。

允许自主沉默且没有必须交付的结果时，可输出 [[NO_REPLY]]。
已执行行为仍以实际回执为准。
```

### 11.6 本轮输入与输出示例

以下是构造示例，不是真实群聊天记录；新增文字须接入既有合同，不能替换全部人设或权限说明。

```text
[原有群历史，保留各自身份]
E901 小林：这首歌的前奏听着像雨声。
E902 阿澄：后面钢琴进来的时候特别明显。
E950 阿澄：整理歌单，又翻到了上次那首。

[本轮可信运行来源]
trigger_type: group_initiative
initiator: Yuki
conversation: 当前群
generation: 当前有效版本
新的真人指令: 无
必须交付的已接受任务: 无

[本轮状态资料]
参与倾向: 通常状态
当前感受: 平静
候选来源: E950；本群合法回忆 M418
M418 摘要: 本群上周讨论过前奏和钢琴的衔接。
限制: 当前材料未给出歌名，也没有证明 Yuki 实际听过音频。

[本轮后端触发]

```

一种合法输出：

```text
又想起你们上次那个“前奏像雨声”的说法了。按当时的描述，后面再进钢琴，画面挺鲜明。

```

下一轮状态未变化时，只回复正文即可。后台不要求它重复填 `pleased`。

## 12. 接口、权限、数据库和恢复

以下接口名均为拟实现合同。不能把它们直接称为 Yuki 当前已经提供的 API。

### 12.1 按既有模块接出事件

| 合同 | 输入或输出 | 现有接入方向 | 验收要点 |
|---|---|---|---|
| `observe_group_event` | 已持久化真实事件 | canonical 入站后、`autonomous_groups.py` | 不重复入库，不伪造当前用户 |
| `read_recall_projection` | 获准的有限本地记忆投影 | Memory query plane / eligibility | 不偷偷调用模型或 embedding |
| `memory.exposed` | 实际模型请求中的记忆引用 | 请求发出位置、ExposureRegistry | 未发出不记已暴露 |
| `memory.attributed` | 原有归因结果 | `memory/attribution.py` | 只复用已有结果，不新增必跑语义模型 |
| `memory.changed` | 正式变更事件 | Memory 提交后 | 删除、撤回先于执行 |
| `model.request_accounted` | 请求与使用量 | model executor / receipts | 逐请求，不按回合估算 |
| `delivery.confirmed` | 平台逻辑交付确认 | 现有发送层 | 幂等更新 \(p\) 与真实绑定 |
| `semantic_delta.accept` | 解析后两字段与后端票据 | 最终输出正规化 | 不要求 Work，不影响正文成功条件 |
| `prepare_initiative` | 正式自主来源与租约 | trigger / main_agent_turns | 发起者 Yuki，授权独立 |
| `initiative.finished` | 真实终态与已读快照 | AgentRunResult / Work | 保留未读新事件，不重复同机会 |

### 12.2 事件信封

```text
DynamicsEvent
  event_id
  canonical_conversation_id
  generation
  occurred_at
  received_at
  event_kind
  typed_source_ref
  execution_id?
  payload
```

引用必须来自可验证后端对象；模型不能填写任意数据库 ID 授予自己读取能力。处理乱序时先检查 generation、来源有效性和字段序号；`occurred_at` 与 `received_at` 分开，不把迟到回执写回过去重演整个群。

### 12.3 自主身份的四个分量

| 分量 | 自主轮含义 |
|---|---|
| 观察来源 | 若干真人消息、记忆或工具结果 |
| 发起者 | Yuki 自主主体 |
| 交谈对象 | 当前群或明确选择的本群成员 |
| 授权来源 | 当前有效的本群自主 grant |

S1、S2 记录的旧路径把自主插话挂在最后一条真人入站上。必须扩展正式 Trigger 类型，而不是把 `actor_user_id` 随便改成机器人账号或授予机器人超级管理员身份。

有效权限由后端自主主体能力、本群范围、有效 grant 和工具限制共同决定。声明工具、查询工具列表和 Prompt 中的文字均不授予权限。工具真正执行、恢复 Work 与发送前均重新检查。

自主轮 `current_person` 可以为空。依赖 `current_speaker` 的工具在没有真实当前人物时须要求明确目标；不能悄悄退回最后发言者。成员隐私上下文也不能因候选引用而被继承。

### 12.4 持久对象

| 拟新增或扩展对象 | 必要内容 |
|---|---|
| `GroupDynamicsCheckpoint` | 群、generation、状态、保持输入、图版本、检查时间、参数哈希 |
| `InitiativeCandidate` | 来源、版本、TTL、数值槽、已考虑快照和状态 |
| `InitiativeSourceLedger` | 根来源身份、已考虑版本、接触去重、归档位置 |
| `GroupInitiativeRun` | 自主主体、授权快照、来源快照、执行 ID、终态和实际消耗 |
| `InitiativeExecutionReceipt` | 模型请求、工具、平台效果与 source/run 关联 |
| `SemanticDeltaReceipt` | 字段、序号、接收/拒绝原因、幂等标识 |

数据库采用现有存储体系。不能仅因增加自主状态就迁移数据库；长事务、锁竞争和事件一致性分别处理。外部模型与网络调用不在数据库写事务中执行。

### 12.5 原子申请、调用和确认

```text
短事务 A
  读取当前来源、generation 与授权
  比较并取得本群执行租约
  创建 initiative_run_id，冻结已考虑快照
  保存防重复标识与必要检查点
提交

事务外
  构造本轮上下文
  运行现有有限 Main Agent / Work
  每次请求、工具和发送各自记录实际回执

短事务 B
  记录真实终态、实际暴露/已读快照、字段更新
  只消费本次确实处理的证据
  保留执行期间未被读取的新消息
  释放租约，重新评估当前状态
提交
```

若实际模型请求未发出，使用同一 run 的有限技术恢复；若发送结果未知，先核对，不重建同一发送。数据库可以实现一次状态跃迁的幂等，但不能无条件承诺跨外部平台的严格 exactly-once 发送。

### 12.6 主动轮工具收据与自省

消息回合可关联真实 `ChatEvent`，自主回合关联 `GroupInitiativeRun`。对这两类来源可以用二选一约束表达；已有定时、插件、系统任务来源仍须被正确表示，不能强行塞进二选一。

Self Reflection 的查询要覆盖无公开发言但有实际工具活动的自主轮。仅将 `trigger_event_id` 改成可空不够：查询、归因、权限、撤回与来源解释均要支持新类型。

已有 Work 的恢复、steering、租约、工具回执继续复用。全局三槽 `update_short_state` 仍是原有短期记录，不能当作本群情感状态数据库。[S1；S2 §13]

## 16. 无配额版实验计划

### 16.1 第一阶段：只取消配额的因果对照

同一输入必须完整回放至相同结束时刻。不能某个模型“额度用完”后停止采样，又将少量输出解释为更低成本而忽略错失机会。

### 16.2 时间与规模

保留原 30 个验证种子作回归，但它们已经被看过，不能再称为 V4 未见测试集。

**拟采用的新协议：** 校准 `81001..81004`；冻结完整配置后，以 `82001..82030` 做独立单日测试；`83001..83010` 用于连续 7 日序列；另做至少一条连续 30 日的耐久运行。种子为实验标识，不是现实日期。执行前固定协议，不根据结果临时挑选有利子集。

规模覆盖 0、1,000、2,000、4,000、8,000 条/日，包含多日总量超过旧的 10,000 条数组，以及自主运行数超过旧的 1,000 行日志容量的场景。规模测试应观察真实数组扩展与状态保留，不仅统计是否崩溃。

跨午夜的专门测试：

```text
23:59 有效讨论持续
00:00 日期切换

```

在关闭明确时段规则、控制实际时间差和输入后，日期切换不改变状态、来源资格或执行条件。达到旧的 48、240、360 等计数也不应独立改变决策。

### 16.3 输入场景

| 场景 | 要观察的问题 |
|---|---|
| 普通陈述、观点、感想，无 @ | 是否正常获得参与机会，而非只认问号 |
| 同一话题中多次真实补充 | 是否在确认参与后自然接话；不永久封闭整个根来源 |
| 多话题交叠、引用链不完整 | 因果分组的误并、误拆和参与绑定错误 |
| 短时密集、长时稀疏、午间/晚间变化 | 时间尺度是否匹配，而非硬等讨论结束 |
| 纯短附和、精确重复、编号变化的重复句 | 内容价值是否被数量或表面变化制造 |
| 同义改写、长垃圾文本、表情/图片占主导 | 弱规则的边界；不能称短附和测试覆盖全部噪声 |
| 未处理问题被真人解决、明确结束 | 能观察到什么；不能依赖隐藏截止标签 |
| 回忆缺少标签、重复检索、来源撤回 | 只影响合法候选，不制造情绪或新事实 |
| 没有真人消息但存在未考虑合法回忆 | 可本地激活；不能因取消回忆配额而不断重复旧材料 |
| 自报缺失、损坏、乱序、相同值重放 | 不新增模型请求，状态恢复正确 |
| 正常回复刚生成又有普通消息 | 不无条件取消；保留必要安全校验 |
| 授权撤回、模型超时、发送结果未知、进程重启 | 来源、租约、外部效果和重复尝试可追溯 |
| 多群同时活跃 | 公平调度、资源争用、范围隔离 |

### 16.4 控制器与模拟 Agent 的隔离

严格接口如下：

```text
ControllerInput = 截至当前的真实可见事件 + 已发生反馈 + 当前数值状态
MockAgentInput  = 本轮真实可见上下文 + 测试机会标签（仅模拟器内部）
EvaluatorInput = 完整运行结果与评估标签
```

控制器进程不直接接收机会数组、未来消息或真实语义截止时间。模拟 Agent 的输出需转换成与生产一致的事件合同再反馈。无法在生产中获得的目标根 ID 或语义判断不得直接写入控制状态。

不仅测试“首个唤醒不变”，还应固定可见反馈进行全轨迹隔离测试。允许模拟 Agent 根据隐藏标签选择不同行动，但须明确：这是输入反馈差异，不是触发器已理解隐藏语义。

生成器应至少包含多个独立的内容模板族和强度参数族。使用一套生成规则时，即使随机种子独立，也只能证明对该生成分布的稳定性，不能自动推广到真实群聊。

### 16.5 对照与消融

同一实验中的所有控制器使用相同原始历史、来源 adapter、主 Agent/模拟 Agent、权限、单轮执行合同和短时发送保护。只改变所研究的部分。

| 编号 | 对照或消融 | 检验内容 |
|---|---|---|
| B0 | 现有事件评分器重放 | 新系统相对当前能力的实际差异 |
| B1 | 便宜的事件评分 + 同样冷却 | 复杂状态是否真正必要 |
| B2 | 固定空档/防抖式判定 | 积累和持续状态的增益 |
| A1 | 无持续参与调节 | 已加入讨论的情境是否有价值 |
| A2 | 无关联边 \(W=0\) | 图是否值得计算与维护 |
| A3 | 无逐候选积累 | 是否只是额外延迟；瞬时读出的效果 |
| A4 | 无情感调制，保留其记录 | 情感是否实际影响合理选择 |
| A5 | 无自报 / 全部失败 / 稀疏合法自报 | 是否依赖强制语义输入；失败是否增加费用 |
| A6 | 无新鲜度或不清已考虑机会 | 旧证据重复与过时参与 |
| A7 | 有/无短时发送保护 | 有限发送中有多少来自保护层而非门函数 |
| A8 | 无配额与历史有配额 | 明确识别配额造成的删失，不作为当前产品规则 |

以独立校准集调整阈值建立质量与成本曲线。**成本匹配通过冻结阈值和参数比较实现，不在每一天达到相同调用数时把模型硬停。** 同时保留原始非匹配点，避免隐藏实际资源差异。

### 16.6 指标定义

| 类别 | 指标 | 解释限制 |
|---|---|---|
| 行为量 | 唤醒、模型请求、工具请求、生成、确认发送、noop | 不用发言数单独代表质量 |
| 时机 | 首次合理参与延迟、持续接话延迟、过时发送 | 真实合理时机需人工或独立评价 |
| 质量 | 相关、自然、连贯、重复、打断、臆造来源 | 不用“有人后来发言”当自动认可 |
| 效率 | 每 1,000 条真人消息的请求/token；每次被评为合适表达的成本 | 完整计算包括取消与失败请求 |
| 稳健 | 日/小时内与跨日漂移、极端密度、低可参与性 | 不只展示一个容易的日样本 |
| 数学 | 区间、QP 残差、解析推进误差、积累/预测一致 | 数值稳定不等于社交质量 |
| 工程 | 本地 CPU、内存、数据库提交、查询次数、队列时延 | 不用仿真运行时替代 2C2G 部署性能 |
| 来源 | 重复考虑、未读新消息丢失、非法来源访问 | 以可回查原始标识核对 |
| 协议 | 尾段缺失/损坏/重放、正文泄露、额外请求 | 所有失败场景要明确是否确实执行过 |

成本统计记录实际模型名称、版本、输入/输出 token、缓存、工具费用、延迟与失败。不把模型请求数直接换算成价格；价格计算属于后续按实际服务账单进行的独立工作。

### 16.7 统计与冻结

以独立日/独立群作为主要统计单元，配对同一输入比较。报告均值、分位数、分组差值和预先指定的置信区间方法；不要把几千条同群消息当成几千个独立样本。

在校准前写明目标和不能接受的错误。避免沿用以发送数为主要正收益的旧校准目标来证明真实交流质量。正式主评价以盲评的合适参与、过时/重复/打断与真实成本构成明确的多维结果，展示取舍，不随结果重新定义“成功”。

失败、崩溃、超长延迟、超出可运行规模的样本必须保留。不同评估器的结果单独分表，不能混成同一指标。

### 16.8 真实接入路径

先离线回放，再运行固定真实 Main Agent 的不发送测试，随后经授权进行真实事件影子运行。得到足够来源、权限、输出和时机证据之后，才执行受控群内验证。

群体体验需要参与者知情同意、可退出与数据最小化。公开复现包优先发布合成数据和脱敏统计，不直接公开群聊天、人物记忆或隐私关系。论文的人类评价、退出情况与采样范围须如实记录，不能把用户没有投诉当作认可。

## 17. 论文问题、命题和写作准备

### 17.1 建议的论文主题

**中文工作标题：证据约束与稀疏语义反馈驱动的群聊自主参与混合动力系统。**
**英文工作标题：Evidence-Constrained Hybrid Dynamics for Autonomous Group-Chat Participation with Sparse Semantic Feedback.**

研究对象是“何时值得运行一次语言智能，以及如何保持交流连续性”，不是发明一种能独立理解自然语言的微分方程。

不将“没有日配额”本身包装成数学创新。可能形成的方法贡献是：明确的来源资格、事件驱动连续状态、有限的参与延续机制、可为空的决策，以及不依赖每轮语义观察器的反馈接口。这些是候选贡献，仍需相关工作对照和实验建立。

### 17.2 研究问题

| RQ | 可检验问题 | 对应证据 |
|---|---|---|
| RQ1 | 无 @ 条件下，持续参与情境能否减少遗漏的自然接话，而不显著增加重复和打断？ | 同一主 Agent 的参与情境消融与独立质量评价 |
| RQ2 | 相比事件评分/防抖，持续状态能否改善质量与计算量之间的取舍？ | 无日配额的质量-成本曲线、简化基线 |
| RQ3 | 稀疏可选自报能否影响有意义的状态延续，并在缺失、失败时保持功能？ | 无自报、损坏、频率变化与状态响应测试 |
| RQ4 | 来源版本、真实回执与上下文分离能否减少重复执行和身份/证据错误？ | 可复核不变量、故障注入和真实集成 |
| RQ5 | 图扩散、情感与逐候选积累各自是否值得保留？ | 模块消融；允许得到无收益或有害结果 |

不要求每个模块都带来正结果。如果无图版本更简单且相当，论文应如实报告，系统也可以据此减少复杂度；不得为维护先前设计而删除负面消融。

### 17.3 拟写入的方法命题

| 命题 | 条件 | 可主张的结论 | 不可越界的结论 |
|---|---|---|---|
| P-A 范围不变 | 合法初值、非负图、有限合法跃迁 | 数值状态保留在定义域 | 情绪“真实”或行为“合理” |
| P-B 注意耗散 | 图与输入在连续段内固定 | 能量不增、无输入时衰减 | 整个含 LLM 系统全局渐近稳定 |
| P-C 竞争唯一与鲁棒 | \(Q\succeq I\)，固定资格集 | 唯一解、全负时零解、1-Lipschitz | 全局语义最优决策 |
| P-D 空来源不唤醒 | 没有合法候选，也没有新合法回忆输入 | 心情与时间不能独立获得执行资格 | 所有安静群永远不允许主动回忆 |
| P-E 非 Zeno | 每次自主启动间隔至少 \(\delta_{\min}>0\) | 任意有限区间自主启动有限 | 无限时间账单有限或无候选饥饿 |
| P-F 来源至多一次 | 原子 run 申请、根来源版本唯一、技术重试不造新 run | 同一可执行来源版本不重复新建自主轮 | 外部平台严格 exactly-once |
| P-G 自报缺失等价 | 相同可见事件、参数与接受结果，失败无跃迁 | 未自报与全拒绝轨迹相同 | 任意真实 LLM 输出均不受 Prompt 改动影响 |

P-F 还可给出一个条件性计数上界：若一次新自主 run 至少消费一个此前未消费的有效来源版本，且版本不能由内部时钟伪造，则新 run 数不超过该区间可用的独立来源版本数加初始待处理量。这来自证据规则，不是人为配额。多源合并、别名、重试与回忆来源如何计数需要在 T21 中严格定义。

这些命题多数是模型和实现应满足的基础性质，不应逐个宣称为独立新数学发现。真正的研究价值需结合方法组合、可验证接口和实证结果论证。

### 17.4 需要保留的反例与局限

原注意式可能让孤立候选永远达不到积累阈值；多重抑制可能让已经加入的 Yuki 无法持续接话；只加预算无法修复候选和时机；只增加唤醒在限制型 Agent 下会大量增加 noop。以上均应保留在分析或附录。[S3、S5]

统计特征相同的两段话可以有相反的社交意义。没有相应输入的数学触发器不能恢复这些含义；稀疏自报只是有限的语义接口，不是完整语义模型。

现有仿真由规则生成机会、没有人的互动反馈，来源归并与表达新颖性也比真实情况简单。论文应把“数学门的行为”“模拟 Agent 的假设”“真实 Main Agent 的表达”和“群友体验”四层结果分开。

### 17.6 研究计划摘要草稿

> 本研究面向无需显式提及即可参与讨论的群聊智能体，设计一种由证据约束、连续状态与稀疏语义反馈组成的混合动力框架。系统在群内维护活动、参与倾向、情感和候选注意，通过可为空的竞争读出与逐候选积累决定是否启动有限语言模型回合。直接请求、自主发起、观察来源和授权在执行层明确分离；主 Agent 仅在状态变化时可选提供少量语义字段。该框架不使用日行为配额，依赖来源幂等、局部时间条件与实际执行反馈控制重复和瞬时消耗。计划通过无 @ 合成场景、多日回放、固定主 Agent 实验和受控群内评价，检验参与连续性、表达质量与计算消耗之间的关系。

这是研究计划摘要，不是完成实验后的论文摘要。最终摘要的结果句只能由无配额版及真实接入实验产生。

每个实验绑定代码 commit、配置哈希、adapter 版本、Prompt 完整版本、模型版本、数据/生成器版本、随机种子、实际请求和回执日志、分析脚本。用户原始文件和历史结果只读保存，不能覆盖为新版本。

历史 V1/V3 可作为设计演进与反例，但正式主结果必须来自同一已冻结实验协议。不得从多轮已看过的测试中选择最好数值，再称为独立验证。

### 20.2 判定过程伪代码

```text
on_backend_event(event):
    verify_origin_scope_and_deduplicate(event)
    advance_old_held_flow_to(event.received_at)
    apply_event_without_fabricating_semantics(event)
    invalidate_revoked_or_expired_sources()
    update_only_qualified_content_versions()
    refresh_graph_and_current_opportunities()
    solve_competition_and_update_latches()
    try_admit_or_schedule_next_local_check()

try_admit():
    candidate = select_current_eligible_positive_opportunity()
    if candidate is absent:
        return
    if not backend_authorized(candidate):
        return with explicit denial record
    if group_lease_busy_or_local_spacing_not_ready():
        schedule_recheck_without_llm()
        return
    if actual_service_unavailable():
        retain_valid_source_and_schedule_bounded_technical_retry()
        return
    atomically_create_run_and_freeze_source_snapshot()
    dispatch_existing_finite_main_agent()

on_run_finished(result):
    normalize_final_output_and_optional_delta()
    persist_actual_requests_tools_and_delivery_receipts()
    consume_only_evidence_in_actual_read_snapshots()
    preserve_new_unread_events()
    apply_accepted_sparse_delta_at_current_time()
    release_lease_and_recompute_current_state()
```

上述任何一步都不读取“本日剩余额度”。当前机会判定与真正执行之间必须再次验证来源和授权；伪代码不替代实际事务和竞争条件测试。
