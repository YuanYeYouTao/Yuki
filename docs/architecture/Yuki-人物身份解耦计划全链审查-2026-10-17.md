## 3 第一轮确认的合并设计约束

真实前向迁移至0128的SQLite与ORM核对：**33个直接Person外键、2个Binding外键，分布于29张表**，外键检查无异常。该结果证明当前schema盘点完整对应实际迁移，不证明尚未实现的合并已验收。

涉及：automation_versions、automations、autonomy_initiative_runs、canonical_conversations、chat_events、client_devices、client_link_codes、emoji_assets、emoji_usage_events、identity_bindings、memberships、memory_dream_clusters、memory_facts、memory_jobs、memory_rebuild_proposals、memory_self_reflection_runs、memory_self_reflection_states、memory_tool_receipts、person_active_routes、person_aliases、plugin_agent_messages、plugin_agent_sessions、plugin_background_target_grants、plugin_background_turn_jobs、plugin_config_values、plugin_notification_outbox、plugin_state、runtime_config_overrides、runtime_turn_observations。

FK之外还核对Work/sandbox source JSON、自动化authority snapshot、Memory/Dream输入proof、JEV观察source_revision、Client请求/outbox、Social/通知/命令回执中的原主体和hash。以下均为计划约束，不将Person合并尚不存在导致的兼容风险冒充既有merge故障。

| 约束 | 具体后果与计划修订 |
| --- | --- |
| 不能批量迁FK后删来源Person | 两个已存在App Binding物理改到同Person，真实SQLite报唯一冲突。来源ID和原Binding保留，通过一个明确同人归并事实表达当前身份 |
| 不可修改原source/已付proof | 错误地修改原事件/Conversation Person后，原WorkSourceGuard拒绝；原Dream input/partition也含人物身份。保原件与原hash，当前语义同人判断另行统一；fact_signature本身不直接含Person |
| subject、visibility和证据作者不同 | 同人归并须贯通SQL授权及新自述/旧Conversation证据对齐；只改actor或只改subject会使正确证据不可读或错误放开private SELF |
| 自省是多条原来源流 | 每Person state和Person×slot run唯一，不能取max游标或删除冲突run；原批次/事件范围继续，新当前人物读取汇集 |
| 有效配置与历史冲突值分开 | 目标现值优先、来源独有key并入有效配置，来源冲突值保留可查；不能raw union后任意dict覆盖或把重复历史行算成数量门槛 |
| KV不是Person键空间 | SDK KV实际plugin-global，保namespace/key/value/version；Host不递归替换插件不透明JSON |
| App当前人物与原请求来源不同 | 当前root可以变化，合并不改变实际App入口或默认上下文；原device/Binding/Conversation/UUID/body/hash保留，不能用新`/me`重算旧message或upload证明 |
| 本地outbox有持久owner | 同服务器A→B直接bind会报owner mismatch；需真实同人证明和原scope，不换UUID、不删旧队列。旧draft入口必须在Client和HTTP两侧明确 |
| 路由trigger也比较owner | root选择来源Binding时，实际SQLite trigger及runtime须采用同一当前人物含义；新增Person指针不足以完成新发送 |
| 新授权不能替代原回执匹配 | 访问权按当前人物，原target/参数/child-parent/audit-receipt仍精确匹配；不把所有raw Person相等都替换成宽泛同人比较 |

## 5 第二轮交叉复审修订

三名审查者交换第一轮模块，分别重审Client/平台、Memory/SQLite和Runtime/JEV，再核对应源码与开发约束。输入计划hash为第一轮输出；不把第一轮缺陷重复记作新增故障。

| 发现 | 修订 |
| --- | --- |
| Person合并顺带自动创建App、切默认会话属于多余机制 | 删除该初稿方案；既有设备和新请求维持真实入口，显式切入口才切Conversation，合并不依赖App可用性 |
| 原request namespace不止GET查询 | `/me`分别表达当前人物和实际入口/原namespace，Client/HTTP/幂等/上传保持原scope＋UUID。同scope跨设备与跨操作继续原冲突语义；每outbox文件一个namespace，否定新建多入口混装队列的必要性 |
| root配置unset和再次merge可能复活来源历史值 | 当前读写只作用于root有效配置，后续merge只继承来源当前有效行；历史冲突保留但不做fallback |
| 同value/version不证明旧rollback对应当前同一修订 | 补原scope、原行/修订沿用事实及合并审计；旧回执精确读取，新rollback不误覆盖目标另一行 |
| JEV独立库仍直接比较actor字符串 | 明确Yuki-Semantic-Participation比较接口、实际pin/lock和跨库回归。实际固定`89d14c763b12289d9d83ae9dca3cbe1049221314`的真实Controller探针确认旧A unit不能匹配B，原State不变；这是计划依赖，非已实现merge故障 |
| 来源Person显式disabled与启用目标组合未定义 | merge不复活来源已撤权凭据/执行，也不一刀切停目标正常入口；补disable→merge和merge→disable验收 |
| 自省源流与当前人物集合仍可能混用 | 明确来源扫描互不交叠，当前facts/candidates/授权才按root集合处理；不改原游标、run或paid输入 |
