## 实现

模型创建安排时只必须填写完整 `goal` 和 `trigger`，名称可选。默认目录标签只显示任务编号，不从私有目标生成摘要。需要有限次重复时填写 `max_runs`；更新省略则保留，`null` 解除，正整数修改累计上限，不清零已发生次数或取消在途执行。

删除 `delivery`、独立 `constraints`、固定 `version` 和任务级重复时区。收件人、平台和是否静默放在完整要求里，发消息仍调用共同的 `send`。到期通过已有 `runtime_context` 提供原创建人、来源、创建时间、本次发生和到期时间；完整目标作为本次正文交给 Main。没有增加发送完成门槛、裁判模型、纠正轮或重试调度，也没有禁止合法后续安排。

Work 续跑取当前 Work 目标和原执行资料，删除 `work_current_material` 中重复的完整目标。已有已付协议、工具配对、未知结果、预算和执行 ID 保持原事实。Person、SELF 和派生子 Work 使用共同的发生资料回调。

查询保留 `list/get/history`。目录是安全摘要；本人或当前超管可以读取完整定义，以及历史发生接纳的原定义。分页在数据库执行。历史按原身份读取 Social 回执，分开显示确认、失败、未确认、未发送计划和 Work 预留；原生命周期与原计数不重写。

| 内容 | 处理与事实源 |
| --- | --- |
| goal、trigger、可选 name | 唯一版本定义；goal 不截断，默认标签不泄露目标 |
| max_runs | owner 保存当前累计上限；creation_max_runs 只保存不可变原创建参数，供重放核对 |
| delivery、constraints、version | 新合同删除；旧补充原文与正向交付要求并入未来版本 goal，旧 none 不制造禁发指令 |
| 重复 timezone | 删除；daily/weekly 一个有效时区，once 带 offset |
| owner 定义/hash/schedule/authority 副本 | 删除，automation_versions 为唯一定义源 |
| 旧 owner target、空能力、连续失败计数 | 删除；历史版本的真实旧目标保留供隐私清退与回执查询 |
| 原 Conversation、内部来源事件 | 保存可信原来源；不从平台消息号反造旧内部事件 |
| 原 run/version/step/cursor/Work/budget/effect | 保留原件；缺原授权保持未知，不借当前版本修复过去 |
| 空 delegated_authority、TurnOrigin 再导出、无人消费目录辅助方法 | 删除，直接使用现行来源与运行时类型 |

`0151` 一次性前向迁移为未来安排发布简化定义，不重写已接纳发生、历史版本、原 Work 和回执。改名、改要求或迁移不移动原 `next_run_at`。原 A 在群里安排给 B 的私聊，仍可沿历史版本按 B 清退。

Plugin API 升为 **8.0**，Host、SDK、Fake、示例和内置订阅插件同步。外部已安装插件须验证该 SDK 和对应 manifest 后部署。旧同调用恢复只核原参数与回执，不提供旧格式的新任务执行入口。

仅本次自动化差异相对同步后的 main，`src/` 增加 1,045 行、删除 1,221 行，净减 176 行；另有 252 行冻结迁移。owner 删除 10 个旧列，新增原 Conversation、内部来源事件及原创建次数三个事实列。删除无人消费的等价任务查询分支及其旧成本测试文件；不按文件数量拆出新层。

## 隔离实模

本机 DeepSeek `deepseek-v4-flash`，Chat Completions，经过真实 Main、TaskModelExecutor、SQLite 和 Social，投递终止于本地内存接收器。本地 profile 的 tools 标记只在测试内存中补齐；生产配置未改。原始请求/响应和 usage 留在本机私有目录。

| 场景 | 实际工具选择 | 结果 |
| --- | --- | --- |
| “一个小时后提醒我背单词”到期 | send | 发送提醒，没有再建一小时后的任务 |
| 明确静默的内部任务 | 无工具 | 内部结束，零发送，零后续安排 |
| 明确要求另建一天后的提醒 | automation_manage(create) | 新建合法后续安排，本次零发送 |
| 飞书安排给另一名 QQ 用户 | find_contacts、automation_query、send、automation_manage(cancel) | 飞书来源保留，实际为指定 QQ 私聊，随后取消原一次性安排，没有新建任务 |

最终 schema 的四例行为均由原请求、发送回执及任务数量核实，10 次模型请求。验证脚本原先按工具名误把 `cancel` 当成重建；改为检查 `action=create` 和实际新增任务后，四项原结果核验通过，没有为此再付费重跑。最终输入 141,274 tokens、输出 2,448 tokens、已缓存输入 128,256 tokens，输入缓存命中率约 90.79%。此前 schema 去重前四例也已通过；两轮合计 20 请求、输入 287,597、输出 6,418、已缓存输入 260,096 tokens。

这是连续隔离样本，不能推为所有日常任务的命中率。接口未返回金额，不将 token 数写成实际扣费。线上收发另认部署后的自然流量。去除合成目标和正文后的[usage 摘要](evidence/automation-refactor-20261024/real-model-summary.json)保留两轮数据。

实模样本来自 `0ee23310` 自动化候选。随后同步 #510，自动化代码、迁移和 SDK 没有变化，外部 Agent 工具描述与 schema 有更新；保留样本当时的行为和 usage，不声称新工具前缀逐字相同或缓存可以跨合同延续。合并候选另做来源、Provider 和恢复的增量回归及当前 head CI。

## 性能

同一 Windows 主机、真实 SQLite/领域装配，40 次等长完整目标创建、30 次 41 项目录读取、一次到期 Main 激活；Fake 模型，不含网络等待。

| 项目 | 原基线 | 新实现 |
| --- | ---: | ---: |
| 创建中位数 / p95 | 20.18 / 23.58 ms | 18.51 / 20.12 ms |
| 41 项目录中位数 / p95 | 3.23 / 4.05 ms | 3.50 / 4.23 ms |
| 到期至 Fake Main 结束，单次 | 343.89 ms | 282.68 ms |

目录中位数多约 0.27 ms；创建和单次激活较低。单次激活不足以证明日常响应提升。第二组诊断在相同条件下另记录 SQL 和 writer，各组仍为 40 次创建、30 次目录与单次激活：

| 诊断项目 | 原基线 | 新实现 |
| --- | ---: | ---: |
| 创建总 SQL，写 / 读 | 80 / 480 | 80 / 480 |
| 目录总读取 SQL | 30 | 30 |
| 到期总 SQL，写 / 读 | 10 / 88 | 10 / 88 |
| 40 次创建 writer 事务累计 | 533 ms | 469 ms |
| 单次到期 writer 事务累计 | 47 ms | 46 ms |
| claim 至首次 Provider 调用 | 364.28 ms | 321.88 ms |

无新全局串行或逐任务全库扫描。此顺序样本的 writer 入队等待低于 Windows `monotonic` 计时分辨率，不能称为绝对零等待，也不代表争用负载。[原探针](evidence/automation-refactor-20261024/perf-baseline.json)和[新探针](evidence/automation-refactor-20261024/perf-new.json)保留细项。

三个自动化工具按紧凑 UTF-8 序列化 name/description/parameters，合计从 6,121 B 减到 4,886 B，减少约 20.2%；只计 parameters 从 4,791 B 减到 3,760 B。字节数不等于模型 token 数，[测量口径与结果](evidence/automation-refactor-20261024/tool-schema-bytes.json)单列。
