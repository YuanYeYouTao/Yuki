## 2. 设计

不加协议字段。`write_paths` 含根目录（`/`）、`network` 为 true、`commands` 含 `"*"` 的范围就是**完全范围**（`Scope.full`）；其余范围照旧。

- **Claude**：完全范围的会话以 `permission_mode="auto"` 打开，不带副作用工具的 `ask` 覆盖，只保留 `ask: ["SendMessage"]`（F9 的决定不因“完全”而放弃：跨会话消息不是文件、命令或联网）。`add_dirs` 仍为 `write_paths`（即 `/`）。`can_use_tool` 照接：auto 模式仍上交的请求进入 `_permission`，完全范围批准除 `AskUserQuestion`（提问）和 SendMessage 以外的一切工具。进程姿态只在打开时决定：以 auto 打开的进程只接受完全范围的输入，非完全或无范围的输入返回 `scope_conflict`（释放后再委派）；以 ask 覆盖打开的进程可以接受完全范围的输入（仍经连接器、全部自动批准）。
- **Codex**：完全范围把线程设置改为 `approvalPolicy: "never"`、`sandboxPolicy: {"type": "dangerFullAccess"}`（不改 `approvalsReviewer`），记录原设置、回合结束与释放时恢复、回执带 `thread_settings_before`，与收窄完全相同。
- **ACP**：没有标准的完全访问模式（F8），完全范围不调 `session/set_mode`，会话保留 Agent／用户自己的模式；Agent 仍发来的 `request_permission`（任何 kind）由完全范围选 Agent 给出的一次性 allow；文件与终端回调照常执行。没有会询问模式的 Agent 也能接受完全范围。
- **Bot**：`start_subtask` 委派（delegate、takeover）省略 `scope` 时填入完全范围并随记录保存，之后的 queue、resume 都带它；observe 不填。这样默认不取决于模型是否照提示传参。实例未声明 `scope` 时委派在执行处返回 `connector_outdated`，不在无范围的情况下执行（同 F10）。

## 4. 决定

- 不加协议字段、不加模式表：完全与否从范围本身判断；ACP 不猜 Agent 的模式 ID。
- Claude 保留 `ask: ["SendMessage"]`（F9）。这偏离“纯 auto 模式”一处；跨会话消息仍上报。
- 进程姿态冲突用现有 `scope_conflict`，不另建切换机制（SDK 的 `set_permission_mode` 是会话级的，排队输入的落点由 Claude 决定，按输入切换会让另一条输入在错误模式下运行）。
- 同一 Codex 线程上不同范围的并发操作沿用“最后一次设置生效”；Bot 一个原生会话只允许一个委派拥有者，不另加限制。
- Windows 上 `/` 解析为当前盘根；完全范围的判断按“写路径含某个文件系统根”，其他盘的写入由原生完全访问模式决定，连接器自动批准时按 `Scope.writes` 核对。
