# 自主参与的连续概率模型

## 在线调参

自主机会模型的可调系数、采样基率和时间尺度集中在
[`config/autonomous-model.example.json`](../../config/autonomous-model.example.json)。
将其复制为宿主机挂载的 `config/autonomous-model.json` 后，可原子替换该文件；
路径可通过 `SEMANTIC_PARTICIPATION_MODEL_CONFIG_FILE` 配置，默认仍为上述文件。
SemanticParticipationService 每次约两秒的采样轮读取内容散列，校验成功才把完整配置
应用到所有当前 scope。无需重新构建或重启 Bot。无文件时使用镜像内默认值；删除文件
会恢复默认值。无效 JSON、未知字段或越界数值会记录错误类别并在健康状态中显示
`model_config_error`，已生效的上一版参数继续使用；健康状态的 `model_profile`
是生效内容散列前缀。

参数直接编辑上述热更新 JSON，使用独立库的 `AutonomyParameters` schema 校验。
管理健康只投影当前状态，不 tick、不刷新参数、不建立新控制器。

热更新只改变之后的机会率，不重放旧消息、不重新计算已接纳 Work 或回执，也不累积
停机时的抽样。已裁剪的历史迹线不会因为调大衰减时标而恢复。配置涵盖非请求自主机会
的全部可调数学参数；权限、显式邀请、来源有效性和持久执行合同仍由各自模块负责。
退役的 `independent_source_factor`、`recall_source_decay_seconds`、`contact_source_decay_seconds`
与 `continuation_review_span` 仅在旧参数读取处清退，其余未知字段仍拒绝加载。
部署时原子去除挂载中的这些废键，保留其他真实覆盖，
包括 `source_interval_seconds`；不能用整份示例覆盖线上调参。更早的 `quiet_group_floor` 仍不受支持。
当前示例使用 600 秒基率分母、0.2 基础倾向、600 秒冷场上升时标和 80 活动半饱和值。

开放群聊来源机会使用独立的 `source_interval_seconds`，不是上述无来源机会的
`intrinsic_interval_seconds`，也不是语义置信度阈值。源码与示例默认 30 秒，
已有挂载若显式设为 45 仍覆盖默认值；这不是固定等待或 JEV 周期。明确邀请/续答仍走及时路径。
示例、磁盘保存、控制器实际加载与群聊效果分别核验，不能由默认值宣称线上已应用或效果已改善。

Yuki Host 固定独立库修订并持有接纳、权限、Work、主 Agent 和发送。
本文件说明模型与宿主边界；具体参数与回放见独立库的
`docs/autonomous-evolution.md`。部署版本须以实际镜像、依赖锁和快照核验。

## 决策边界

Jev 确认的明确邀请或直接续答走普通真人消息入口，不计新 SELF Work 密度。已有有效参与
单元且归属明确的续聊进入普通 Main 的原去抖 worker，不等待 Jev，原 Work 输入及时接回。
快路保留后台稀疏语义复核，不按续聊次数要求 Main 等待评分；Main 自身 stay 或发送回执不推翻真实纠正。
直呼 Yuki 只提高语义观察优先级，不等同 `@`；无法归属旧话题也不能挡住真实邀请。
非请求式群聊和无来源机会使用连续机会率，形成新 SELF proposal；
一次 proposal 仅表示可启动 SELF 工作，不是发送命令。

来源有效期、撤回、停止、群授权、唯一 owner、generation、Presence 和活动 Work
仍由 Host 按事实核验。控制器不产生真人消息、Jev 观测、执行权限或聊天正文。
Host 不在停机时补采样，不重放历史机会；原已接纳 Work 按原执行 ID 和回执恢复。

## 新机会的产品开关

`auto_reply_enabled` 控制 conversation 候选；`proactive_wakeup_enabled` 控制无来源 intrinsic。
后台记忆种子、recall/contact 新候选已删除，不替换为另一种后台 Memory 轮询。
Host 将实际允许的 CandidateKind 集合传给独立库的 allowed_kinds，
在原 _eligible_groups/opportunity_scores/advance 中于分组、rate 和取样前筛选。None 表示
原全部种类，空集仅排除来源候选；intrinsic 仍由独立的 intrinsic_allowed 控制。
两个开关不切换 proposer，不改变 epoch、公式、原候选与反馈。禁用期间原采样时间继续前进，
重开不会补抽之前的时间。新 SELF 仍需原 master/scene 授权；明确真人入口及已接纳 Work 独立。

## 状态与反馈

真人活动 `q`、来源候选的慢群情境 `ℓ`、无来源机会的真人活动量 `H`、实际计算 `f`、无来源真实 `NO_REPLY` 的 `n`
和 SELF 结构化 `engage` 的 `d` 保留各自职责。无消费者的自由文本 `mood` 已删除，
旧报告读取只清退该字段，保留原 engage、来源和顺序，不因旧 mood 丢弃整份有效自报。

普通 `engage` 仍限定原讨论/对象，quiet 直接收起局部快路；不向 source_rate/pressure 再加一份局部意愿权重，
也不把局部 quiet 广播成全群开关。SELF 整体意愿沿原自主公式，W/E/R、计算和真实 NO_REPLY 反馈保持原事实。
Jev 的已有真人焦点请求附带两种 scope 的当前合法意愿，帮助解释新邀请、续聊、换题与他人交流；
它们是 Yuki 自身状态，不是真人邀请、停止或授权。状态变化本身不新增观察，已发请求的快照不变。

## 普通续聊与稀疏复核

已确认互动继续走快路，不逐条等待 Jev，也不设置未核验续聊跨度。
同一讨论/对象的可归属待办合并为最新焦点，独立邀请与归属不明来源分别保留；在途 Snapshot 不变。
调度统一使用既有 3 秒去抖、12 秒调用间隔、20 秒最长去抖等待，持续新输入不重置最早待评时间。
这些参数只控制后台观察，不是 Main、发送或任务补充的等待门槛，20 秒也不是端到端刹车时限。

他人交流、转题、真实停止与自身 quiet 各自能收起对应快路，不能互相覆盖放行。
quiet 清理其已覆盖的旧续聊待办，不补评、不取消在途请求或删除后到的新邀请。
unknown 和失败保持原有依据，迟到纠正不覆盖更新的真实邀请；同 Main 已选择的补充保留选择时资格。
语义开启时开放群同样核当前隐式资格；关闭时沿原 require_mention 策略，明确入口和原 Work 不受影响。
相关参与事实在下一次本来需要的正常 Main 请求尾部提供，不改原请求或新增确认轮。

减少采样会增加部分转折的识别等待，本体 quiet 是独立补位。调用量、主请求、实际发送与刹车延迟分别回放，
不能用队列项减少冒充实际付费请求减少，也不由合成结果宣称自然群聊效果已改善。

## 自主率与真实反馈

每个确实启动主 Agent 的自主 Work 只计一个快慢时间尺度脉冲 `W_f/W_s`。
一次 Work 内发送任意条消息、分条或调用多个工具都不增加这个脉冲。
Work 有确认的公开发送时，才产生一份“尚未被接住”的暴露 `E`；未确认发送、
仅有 proposal 或模型 `NO_REPLY` 都不是公开表达。Host 使用真实
`chat_events.id` 与原 run 关联出站锚点，Jev 后续的概率观测形成接收反馈 `R`。
无回复时 `E` 平滑上升并最终自行衰退；没有真人输入不被伪造成明确拒绝。
同一 Work 的多条消息只增加可核对的锚点，不按消息数加重下一轮频率成本。

```text
z = 0.2 + 0.8d - 0.5q - 0.3f - 0.8n - 1.8W_f - 0.25W_s - 0.55E + 0.5R
H(t) = Σ_human exp(-(t-t_i)/172800)
A(t) = H(t)/(H(t)+80)
s = t - t_last_human
G(s) = (1-exp(-s/600)) · exp(-s/64800)
λ_intrinsic = A(t) · G(s) · sigmoid(z) / intrinsic_interval_seconds
P(本轮无请求式机会 | Δt) = 1-exp(-λ_total Δt)
```

示例基准时间为 `600` 秒，线上实际值以挂载文件为准；它是率的倒数，
不是调度 tick 或固定等待时间。

没有真人活动证据时，无来源机会率为零。活跃群冷场时 `G` 平滑上升，沉默继续延长时
`H` 和 `G` 一起衰减；不会出现“沉默累计越过门槛”或固定时间
禁言。近期已有自主 Work／无人回应会连续降低新 Work 的频率，不对**当前 Work**
设置消息条数或工具调用次数阀门。主 Agent 仍自行决定在该 Work 内发送、行动或
`NO_REPLY`。明确请求与确定日程的自动化不受自主长尾率控制。

旧 `g` 恢复项、`p` 短时发言惩罚、`N_Y/N_H` 比例和净值正数门槛退出决策。
旧快照字段迁移读取后丢弃，不依据旧正文或平台消息 ID 重建不存在的发送／回应。
现有快照没有 `H` 时，Host 在短时事件窗口之外，对当前代次最近五个活动衰减时标的已入账真人事件
时间做按小时聚合的只读初始化；之后迹线随快照持续演化。不重写历史聊天、不补采样或补发。

先前生产观察后曾放松慢 Work 密度、未获确认回应的暴露，并移除长期沉寂底率。短时 Work
惩罚仍抑制连续启动。Host 在启动及运行期间发现当前获准群的会话代次，即使新代次
尚无绑定或真人消息，也建立新的控制器并按现行配置选择 owner。旧代次的 proposal、
消息与采样时间不带入新代次，停机期间不补机会。

Jev 的真实语义观测继续形成接收反馈 `R`、修正暴露 `E` 和来源候选；
健康故障只推迟新观察，不改变 proposer 所有权或关闭无来源率。故障期间既有
有效反馈按自身时标演化，未知保持未知，不制造“有人回应”或停止观测。
启用语义参与时即使用 semantic proposer，显式关闭后才选 legacy。

## 验证边界

独立库单元测试覆盖按 Work 计数、多消息等价、真实锚点回应、活跃群冷场与沉寂衰减和恢复。
Host 回归覆盖 Social 回执从真实内部事件 ID 绑定到语义 run，并阻止 legacy
运行误绑定，以及 Jev 故障期间的真实无来源 proposal 接纳。两条 30 天合成轨迹分别模拟
`NO_REPLY` 和已公开发送却无人回应，先前参数的无来源机会为 25 次和 7 次；当前参数
为 304 次和 84 次，总机会为 1857 次和 1627 次（先前 1576 次和 1551 次）。
无人回应仍抑制后续无来源机会；没有按消息条数加重成本。独立库
`docs/evidence/autonomous-observer-recovery-*.json` 保存完整参数和配对证据。
回放仅能检验模型机会分布，不能证明真实发言或 Jev／QQ 的社交效果。迟到回应、
交错聊天和长空白由定向测试覆盖；实际 Host 固定修订仍须联测。
线上社交效果与合成回放分开报告。
