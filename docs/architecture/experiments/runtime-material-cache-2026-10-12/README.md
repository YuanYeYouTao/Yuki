# 本轮资料差量冻结：缓存与用量实验（2026-10-12）

本报告整理原方法 A、删除冗余后的整份方法 B、删除加首份/变化差量方法 C 的受控真实 API 测量。固定输入的已报告 input 在 C 中较少；缓存率与总费用并非所有协议都随之改善。第一阶段 DeepSeek Responses 的 C、第二阶段 DeepSeek Chat 的 C，输入加输出的名义 API 费用均高于对应 A。实验结果、旧版自然窗口与上线验收分别记录。

**版本分层。** 第一阶段“首次方案＋注入频率收窄前”保留385条原记录：A是`24da979`旧方法，B/C是原`3684dfee`候选。第二阶段新增198条“频率收窄候选”，使用同HEAD下另行冻结的改动源；具体指纹和三协议结果见后文，不能用HEAD相同推断请求体相同。第三阶段先审真实生产context，再新增72条生产来源混合请求对照，保持稳定有效资料差量＋原必要Host当前层，无用default包退出。D=C复用，没有额外D付费；第二阶段仍不能改称最终hybrid，第三阶段也不是候选上线请求。

当前实验总账为 **656 次网络尝试：655 条保存记录＋1 条原记录丢失**。保存记录中654次HTTP200、1次原HTTP400；另一次状态与用量未知。Gemini220次尝试（219保存），DeepSeek436保存（Chat221、Responses215）。第一阶段386次尝试、第二阶段198次、第三阶段72次分列，生产采样与部署前自然窗口另列。本报告没有候选上线后自然流量、真实QQ、生产容器重启或实际账单验收；同磁盘的本地双进程重启已完成，见后文的范围。

CSV 空值表示未知或不适用，不是零。`known_subtotal` 只累计实际已知行；只有所有行都已知时，才能作为该组完整总量。`input_known_subtotal` 与 `cache_eligible_input_subtotal` 可以不同：缓存率的分母必须使用后者。原373条请求CSV、313个分组和8个人口及summary JSON已在私有诊断目录只拷贝留存；新增12条后形成的385请求、343分组、8自然人口及summary JSON又单独冻结。新增198条候选记录后，原385请求仍为新CSV的逐字节前缀，全部旧343分组逐格与自然窗口字节均未改。新增第三阶段后，原583请求仍为655行CSV逐字节前缀，旧499分组逐格不变；583版另有不可变快照，自然窗口仍为原8人口。

对同一合法覆盖集合 S（input/cache同时明确可用且0≤cache≤input）：

```text
缓存率 = ΣS cached / ΣS input
uncached = ΣS input - ΣS cached
名义输入费用 = (ΣS uncached × miss单价 + ΣS cached × cache单价) / 1,000,000
```

不平均逐请求百分比，不将缺 cache 的请求补成0，不把两个不同覆盖集合的费用相减。`normalized_output_tokens` 沿当次适配器归一值；已含 reasoning/thinking 的成分不再相加。原始思考字段缺失继续保持未知，不能用配置或归一化默认值证明实际为0。Gemini数字定义见[UsageMetadata](https://ai.google.dev/api/generate-content#UsageMetadata)。

延迟有两套物理计时，均从 request hook 开始：

- **响应头耗时**：HTTP response hook 进入时记录；旧 `latency_seconds` 在 `await aread()` 前产生，只能归入此列。
- **完整响应耗时**：实际读完响应体后记录；只使用原专门字段，不按旧UTC差值补造，不等于用户收到QQ回复的时间。
- median沿实际有计时的请求；P95统一为排序后第 `ceil(0.95×n)` 个值（nearest-rank），max保留所有孤立慢请求。n=16时P95等于max，小样本结果不是SLA。自然窗口只有聚合median/min/max，P95未知。

## 三组对照与边界

| arm | 实际方法 | 比较范围 |
|---|---|---|
| A | 原 `24da979` 的默认 producer、整包冻结和自动 Observation 回读 | 旧方法基线 |
| B | 与C相同的冗余删除及存量清退；剩余有效资料仍整份提供 | 删除的贡献 |
| C | 与B相同的删除；本组稳定公共资料首次冻结，之后只追加真实变化 | 删除与差量的贡献；不代表每一种运行状态都永久冻结 |

三组从同一合成seed各建隔离数据库；B/C执行相同0108清退。固定静态合同、工具声明/顺序、模型route和generation；工具合同删减带来的部署变化不混入此纯资料对照。B只存在于隔离实验，不是产品开关或兼容模式。冻结源码与各批次manifest保留在私有诊断，不把一次捕获的结果外推到未来所有版本。

固定序列有10步：empty、first、unchanged、cold_after_unchanged、change、return_A、clear、before_expiry、expired、different_actor。`cold_after_unchanged` 指可丢投影行回收，既不是服务端cache清空，也不是完整进程重启。每协议按ABC、CBA两个block运行，每arm/block预热1次、measured10次，因此固定组每arm共22次。实际只读闭环每arm/block有first/unchanged/change/clear四步、每步2次实际模型请求，无额外预热，共16次/arm。

固定输入重放发送从真实 Main/serializer 捕获的同源请求，后一轮公共文本与工具读结果按fixture固定；它与“本组真实模型答案进入下一步”的工具闭环分开。真实输出、思考和费用可能不同。闭环三arm后续包含各自答案，因此不是完全相同后续输入的独立因果对照。所有实验只在隔离数据中运行，没有真实QQ网关调用、生产自动化或Work业务改造。
