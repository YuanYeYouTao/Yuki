# 桌面端易用性任务书

日期：2026-11-13

状态：已定稿，可执行。基线为 Yuki `main`（de00cb0c）与 Yuki-Desktop `main`（8133ac5），执行前以 origin/main 为准。涉及 Yuki 与 Yuki-Desktop 两个仓库，一次完成，每个仓库一个 PR。

目标用户：会照着说明买一台云服务器、拿到 IP 和 root 密码，但不懂 Docker、Tailscale、反向代理和证书的人。

## 1. 调研结论

| 事实 | 证据 |
| --- | --- |
| 本机部署已经很短 | 桌面端「在本機部署 Yuki」一键部署并自动连上（Yuki-Desktop `src/main/local-bot.ts`） |
| 服务器部署后从另一台电脑连接要 10 步以上 | 两端安装并登录 Tailscale、服务器执行 `tailscale serve`、核对端口与 ACL、点同意页、抄地址（`docs/operations/tailscale-connection.zh-CN.md`） |
| 安装器给出的地址在别的电脑上用不了 | `install.sh` 打印 `http://127.0.0.1:8080`；`docker-compose.yml` 只绑定 `127.0.0.1` |
| 配对码容易在配好网络前过期 | 32 字符 `token_urlsafe(24)`，10 分钟有效（`src/yuki/client_api/identity.py`）；重取要回安装目录跑 `sh deploy/pair.sh` |
| 桌面端已能解析完整配对链接，后端安装器没有输出 | 桌面端注册了 `yuki://`，`src/shared/pairing.ts` 能从粘贴文本识别 `yuki://pair?server=&code=`；带地址的链接只有聊天命令在配置了 `CLIENT_PUBLIC_URL` 后才生成 |

| 桌面端本机部署关掉了全部平台 | `deployment_setup/desktop.py` 清空 `COMPOSE_PROFILES`、`ONEBOT_ACCESS_TOKEN`、`TELEGRAM_BOT_TOKEN`、`FEISHU_*` |
| 交互安装只问 QQ，不问 Telegram、飞书 | `deployment_setup/command.py` 的 `_page_gateway` |

| 标准部署下桌面端存不了模型配置（已确认） | `docker-compose.yml` 与桌面本机部署叠加的 `docker-compose.local.yml` 都以 `:ro` 挂载 `webui-config`（`docker compose config` 渲染结果 `read_only: true`）。以 `yuki:local-3a837588` 镜像实跑 `ConfigFileService._replace`：`:ro` 下 `operation_unavailable`（`OSError 30 Read-only file system`），`:rw` 下写入成功。桌面端没有该错误码的文案，显示兜底「操作未完成（operation_unavailable）」。开发者本机用自定义 `compose.local.json`（可写），因此平时遇不到 |
| 去掉 `:ro` 后服务器安装仍可能无写权限 | `scripts/start.sh` 以 `YUKI_RUNTIME_UID`（默认 10001）运行 Bot，只 chown `data`、`character`、`workspace`、`social-transfer`，不 chown `webui-config`；`install.sh` 以安装用户身份运行 `yuki setup` 生成该目录。桌面本机部署把 UID 设为宿主用户，不受影响 |
| 安装器从 GitHub 下载发布包 | `install.sh` 从 `github.com/<repo>/releases/download/v<version>` 下载部署包；已有 `--bundle FILE` 可改用本地包 |
| Diana 可作实现参考 | SuInk/Diana 为 Limited Redistribution License；项目作者已获 Diana 作者许可参考其实现 |
| owner 配对码与普通配对码同一时效 | `install.sh` 经 `yuki setup desktop-pair` 调 admin `persons/{id}/client-pair` 签发，与设备自助 `/link-codes` 同为 10 分钟（`client_api/identity.py`） |
| 桌面端更换地址已保留同一 Connection | `connections.ts` 的 `verifyAddress` 先核新地址的 character id 与原 Person、Binding、Conversation 一致，沿用原设备凭据；连接器地址另经 `connector server --url` 更新（`agent-connector.ts`） |

| Bot 容器不能执行 `docker compose` | Bot 没有 docker socket；能执行的是宿主机上的桌面端主进程，或经 SSH 在服务器上执行 |
| 连接器只认 URL，与连接方式无关 | `yuki-agent-connector` 的 `connector_url` 接受 `https://` 或本机 `http://127.0.0.1`；作为 launchd/systemd/schtasks 服务独立运行 |
| 桌面端没有多语言机制 | 约 2,500 段繁体中文硬编码，85% 在 `renderer/views`；`<html lang="zh-Hant">`；字体栈只有 TC 字形 |
| 大陆服务器拉不下镜像 | 用户在大陆服务器实测失败；Bot 与环境镜像在 `ghcr.io`（amd64 压缩后约 284 MB + 233/634 MB） |
| SnowLuma 镜像已不可公开拉取，上游停止维护 | 2026-11-13 查询 Docker Hub `motricseven7/snowluma` 返回 404，官方 Docker 文档 404；`docker-compose.yml`、`.env.example`、`docs/deployment/snowluma.md` 仍指向该镜像 |
| SnowLuma 耦合度低 | 专属部分只有 `gateway/providers/snowluma.py`（能力集与平台键）、反向 WS 路径 `/onebot/v11/snowluma/ws`、`adapters/onebot/activity.py` 的输入状态、`client_api/snowluma_display.py`、`cli.py` 的 `render-snowluma-config` 与 `deployment_setup`；消息、媒体、社交操作均为通用 OneBot 实现 |
| 「QQ 登入」只因部署方式受限 | `snowluma_display.configured()` 判断 `COMPOSE_PROFILES` 是否含 `snowluma`；连接本身读取 `SNOWLUMA_VNC_HOST/PORT/PASSWORD`，可连任意地址 |
| QQ 官方 Bot 能力受限 | 2025-04-21 起不再支持主动推送；被动回复窗口单聊 60 分钟、群聊 5 分钟，且有次数限制；单聊对话后 30 天内分四个周期各可发一条互动召回消息（`is_wakeup`）。实现时以 QQ 开放平台现行文档为准 |
| 官方 Bot 可以在群里自然插话 | 参考实现 SuInk/Diana（HEAD 0ba8eda）：默认只收 @ 消息；群主把「机器人可获取的群聊消息范围」改为全部消息后，网关推送 `GROUP_MESSAGE_CREATE`，回复挂在这条非 @ 消息的 msg_id 上即可；用 `mentions[].is_you` 判断是否点名 |
| 被动窗口与次数不必预判 | Diana 不记录窗口与次数，只按平台错误码处理：40034128（时间或次数超限）、40034105/40034102（群无 msg_id 主动发）为永久失败；40054005（去重）换 `msg_seq` 重发一次 |
| 群主动消息不可用 | Diana 注释「群里的主动消息能力已被平台关闭」，不带 msg_id 的群发送以 40034105/40034102 被拒并记为永久失败；`bot_state.allow_proactive_msg` 等字段可读但不作为可发送依据。与社区「已部分恢复」的说法冲突时以 Diana 为准 |
| openid 在同一 Bot 内一致 | Diana 注释：openid 对同一台机器人的私聊和各群相同 |

## 2. 设计原则

- **连接方式与身份正交。** 设备凭据属于服务器上的 Person 与设备，不属于某条网络路径。直连 URL、Tailscale、SSH 隧道都只决定「桌面端怎么到达服务器」，不改配对、授权、Conversation 或回执。
- **连接器继续只认 URL。** SSH 方式由桌面端在本机提供固定的 `http://127.0.0.1:<端口>`，连接器代码不改，也不引入 SSH 依赖。
- **SSH 有两种用途：** 到达服务器的通道（隧道），以及管理服务器的手（安装、配对、启用 SnowLuma、升级、看日志）。后者对小白的价值更大。
- **复用现有机制。** 平台凭据沿用模型配置的文档、secrets、revision、回执与热切模式，不另建配置系统。
- **平台能力按事实声明。** QQ 官方 Bot 的限制如实反映在投递回执与设置页，不另设兼容层或改投其他平台。
- 不在本任务书范围内：公网暴露时强制 https 等安全收紧、移动端、开发者运营的中继、Yuki 本体多语言、恢复 NapCat（因风控已弃用）。

## 3. 方案

### 3.1 安装与配对

1. `install.sh` 与 `deploy/pair.sh` 输出完整 `yuki://pair?server=…&code=…`。地址按「已配置的 `CLIENT_PUBLIC_URL`」优先；没有可用公共地址时只输出配对码并说明用「部署到我的服务器 / 通过 SSH 连接」。
2. operator 经 admin `persons/{id}/client-pair` 签发的配对码（安装器与 `pair.sh` 都走这里）放宽有效期（例如 24 小时），保持一次性。设备自助的 `/link-codes` 不变。
3. 删除 `docker-compose.yml` 与 `docker-compose.local.yml` 中 `webui-config` 的 `:ro`：该目录本就是管理 API 的写入目录。`scripts/start.sh` 像 `data`、`character` 一样 chown `/app/webui-config`。`docs/operations/model-profile-path-migration.md` 中「自己写 override 才可写」的说明一并删除。平台文档与 secrets 放在同一目录。（桌面端为 `operation_unavailable` 补文案，归 Yuki-Desktop PR。）
4. 交互安装 `yuki setup` 的 gateway 页：QQ 默认不选；选 SnowLuma 时要求填写用户自己的镜像；补问 Telegram、飞书与 QQ 官方 Bot，或说明可在桌面端「平台」页设置。
5. `.env.example` 的 `COMPOSE_PROFILES` 默认为空，`SNOWLUMA_IMAGE` 去掉已失效的默认值。`docker-compose.yml` 的 `snowluma` 服务保留。Yuki 不发布、不转存 SnowLuma 镜像，也不以第三方转存作为默认来源。
6. 文档：补 Telegram 接入说明（BotFather 创建、关闭 Privacy Mode 才能在群里看到普通消息、已设置 webhook 时需先删除）；新增 QQ 官方 Bot 接入说明；`docs/deployment/snowluma.md` 改为「自备镜像」并说明上游已停止维护。

### 3.2 平台接入

后端（Yuki）：

1. 平台状态：`GET /admin/v1/platforms` 返回每个平台的 configured、已保存 secret 标记、revision、`apply_mode`（`hot` / `restart`），以及 health（enabled、running、healthy、`last_error_category`、`last_success_at`、当前账号）。
2. 凭据存储：Telegram、飞书、QQ 官方 Bot 以 `webui-config` 下的平台文档与 secrets 为唯一来源，沿用模型配置的 revision、原子写和回执。删除 `TELEGRAM_BOT_TOKEN`、`FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_DOMAIN` 等 env 配置项（含 `config.py`、`.env.example`、文档与测试）；已有部署升级时由 `yuki setup` 把 `.env` 中的现值一次性写入平台文档。SnowLuma 因 Compose 需要仍留在 `.env`。`container.py` 构造期的飞书成对校验改为保存时校验。
3. 应用：`POST /admin/v1/platforms/apply {request_id, expected_revision, platform, enabled, settings, secrets}`，返回 `applied` 或 `saved_pending_restart`。
4. 热启停（Telegram、飞书、QQ 官方 Bot）：常驻一个平台持有者；apply 时先用新凭据预检，成功后关闭旧实例（断开 Registry）再启动新实例，原地替换 health 源；停用即关闭。
5. SnowLuma 的配置留在部署目录的 `.env`：镜像名、`COMPOSE_PROFILES`、`ONEBOT_ACCESS_TOKEN` 由 Compose 与 SnowLuma 容器读取，Bot 容器写不了。后端不经 admin API 保存这些值，只在 `GET /admin/v1/platforms` 报告 OneBot 连接状态与「QQ 登入」是否可用；写 `.env` 并重建容器由桌面端在宿主机或经 SSH 完成（见下方桌面端第 2 条）。
6. 「QQ 登入」是否可用改为看 `SNOWLUMA_VNC_HOST` 是否显式配置，不再看 `COMPOSE_PROFILES`。

QQ 官方 Bot Provider（后端）：

参考实现：SuInk/Diana 的 `model/assistant/qq_official*.go`。已获 Diana 作者许可参考其实现。Diana 为 Go，Yuki 按自身 Gateway Provider 合同用 Python 重写，不逐行翻译；平台事实以 Diana 现有实现为准。

- 连接：与 Telegram、飞书同级的 Gateway Provider。`POST bots.qq.com/app/getAppAccessToken` 以 AppID/AppSecret 换 token，按 `expires_in` 缓存，401 或网关关闭码 4004 时作废重取。只用 WebSocket 网关（无需公网回调）；intents 取群与单聊、群成员、INTERACTION，网关以 4013/4014 拒绝时去掉未获权限的 intent 后重连；有 session 时 RESUME。API 域名 `api.bot.qq.com`，沙箱只换 API base。
- 平台键独立于 OneBot 的 `qq`：`group_openid` 是 Space 的外部 ID；`member_openid` 与 `user_openid` 在同一 Bot 内相同，作为同一个平台账号。不暴露 QQ 号，不与 OneBot 账号互相推断或合并；人物关联沿现有 `/ai link` 显式完成。
- 群聊入站：默认只收 @ 消息；群主开启「获取群内全部消息」后收 `GROUP_MESSAGE_CREATE`，参与判断与其他平台相同。用 `mentions[].is_you` 判断点名；全量模式下自己发言的回推按已登记的出站平台消息 ID 识别；其他 Bot 的消息只作上下文。
- 出站被动回复：每次发送带触发事件的 `msg_id`（按钮回调用外层 `event_id`）。同一 msg_id 下的 `msg_seq` 由该 msg_id 已有的投递回执推出，重启后不从 1 重来。不预判窗口与次数，以平台错误码为事实：40034128、40034105、40034102 记为确定失败回执，不重试；40054005 换下一个 `msg_seq` 重发一次。
- 无可用被动窗口的投递（定时任务、SELF 主动消息、超窗完成的 Work 结果）：
  - 群：全量模式下挂在同群窗口内最新一条消息的 msg_id 上；没有可挂的消息时如实记为无可用投递路径。不发不带 msg_id 的群主动消息。
  - 单聊：先带 `is_wakeup`；平台回 40034122/40034123 时按普通主动消息再发一次，仍被拒则如实失败。
  - 不改投私聊或其他平台。
- 私聊长回复用 `stream_messages` 流式交付（同一流共用 `msg_seq`、`index` 递增）；群里没有流式。
- 媒体走分片上传换 `file_info` 后以 `msg_type 7` 发送；引用回复维护 `REFIDX_` 与平台消息 ID 的对应，随平台消息回执持久保存，入站引用内容取 `msg_elements`。
- 本次范围：文本、图片与文件、引用、@（Markdown 内的 `<qqbot-at-user>`）、私聊流式。Markdown 模板、按钮与 `INTERACTION_CREATE` 不在本次；若启用按钮，回调须先 `PUT /interactions/{id}` 应答。

桌面端（Yuki-Desktop）：

1. 设置新增「平台」页，每个平台一张卡片：状态与错误原因、凭据表单、获取凭据的分步说明（Telegram：BotFather 与隐私模式；飞书/Lark：自建应用、机器人能力、长连接事件订阅、权限、发布审批；QQ 官方 Bot：开放平台注册、AppID/AppSecret、沙箱与上线）。
2. QQ 卡片先选「官方 Bot」或「SnowLuma」：
   - 官方 Bot：填 AppID/AppSecret，保存前展示能力限制（默认只收 @，需群主开启「获取群内全部消息」才能自然插话；群里不能主动发消息；回复窗口）。
   - SnowLuma：填镜像名；本机部署由桌面端主进程改本机 `.env`（profile 加 `snowluma`、生成 token）后 `docker compose up -d bot snowluma`，SSH 管理的服务器在远端执行同样步骤，只有直连 URL 时显示需在服务器上执行的命令；启动后沿用现有「QQ 登入」接管扫码画面。用户自行部署在别处的 SnowLuma，填反向 WS 地址、token 与 VNC 地址即可。

### 3.3 SSH 连接与「部署到我的服务器」（桌面端）

连接：

- `Connection` 增加 `transport`：`{ kind: 'direct' }` 或 `{ kind: 'ssh', host, port, user, auth, remotePort, localPort }`。SSH 方式下 `baseUrl` 为 `http://127.0.0.1:<localPort>`，`localPort` 按连接固定并持久化，使设备凭据与连接器地址跨重启不变。
- 主进程用 ssh2 建立本地转发到服务器 `127.0.0.1:<YUKI_PORT>`（`YUKI_PORT` 经 SSH 从远端 `.env` 读取）；网络变化或断线自动重连，API 客户端沿现有离线处理。
- 认证支持密码、密钥文件与 ssh-agent；凭据存入系统钥匙串。首次连接展示主机指纹并记住（TOFU），指纹变化时拒绝连接并明确提示。
- 同一 Yuki 可以在不同设备上用不同方式连接；同一台桌面对同一 Yuki 只保留一个 Connection，在「連線」设置里切换方式：沿用现有 `verifyAddress`（核 character id 与原 Person、Binding、Conversation，沿用原设备凭据），已安装连接器时同时经现有 `connector server --url` 更新其地址。
- 打包 ssh2 时不构建其可选原生依赖（`cpu-features`、`nan`），三平台都用纯 JS 实现。

部署到我的服务器（与「在本機部署」对称）：

1. 填 IP、用户名（默认 root）、密码或密钥 → 确认主机指纹。支持 root 与免密 sudo 的用户；需要输入 sudo 密码时明确提示不支持。
2. 环境检查：系统、架构、内存、磁盘、Docker；缺 Docker 时代为安装，安装失败（如大陆服务器连不上 Docker 官方源）时显示原始错误并说明可改用国内软件源，由用户确认后重试。
3. 模型配置复用桌面端本机部署的表单，生成 `--answers`。
4. 桌面端经 SSH 上传与自身版本匹配的 `install.sh` 与部署包，远端执行 `install.sh --yes --answers --bundle`，不依赖服务器访问 GitHub；沙箱档位按内存推荐。镜像加速由用户自行配置：拉取失败时明确提示「请为服务器配置 Docker 镜像加速器」并给出配置位置，配置后可从此步重试。
5. 远端执行 owner 配对，桌面端直接拿到配对码完成绑定，用户不接触配对码。
6. 建立 SSH 方式的 Connection，进入聊天。之后升级、启用 SnowLuma、查看日志都走同一 SSH 管理通道。

已知限制（写进界面说明，不另加机制，也不强制登录时启动）：SSH 方式下，桌面端未运行时连接器离线，需要 Yuki 常驻控制本机时可自行开启登录时启动，或改用 Tailscale/HTTPS；移动端不适用。

### 3.4 桌面端三语

- i18next + react-i18next；主进程与渲染进程共用资源。资源放 `src/shared/locales/{zh-Hant,zh-Hans,en}/`，按模块分命名空间，错误以后端错误码为 key。以 zh-Hant 为源，用类型约束其余语言 key 齐全。
- `Preferences.language: 'system' | 'zh-Hant' | 'zh-Hans' | 'en'`，默认 `system`；系统语言映射 zh-TW/HK/MO→zh-Hant，zh-CN/SG→zh-Hans，其他中文→zh-Hant，其余→en。切换经 IPC 广播，渲染端改 `html lang`，主进程重建菜单与托盘，不需重启。
- 字体栈增加 `:lang(zh-Hans)`；`Intl` 统一传当前 locale，去掉写死的 `zh-Hant-TW`、`zh-TW`。
- zh-Hans 先用 OpenCC 转换再人工校对用词；英文需处理单复数与拼接句。
- 后端残留中文：步骤标签改由桌面端按 `category` 翻译；自动化描述、记忆更正摘要、「本人」暂按原文显示。
- 写入服务器回执的 note、剪贴板与截图默认文件名属于数据，不随界面语言变化。
- 本任务新增的平台页、SSH 与部署界面直接按 i18n 编写，不先写死再抽取。
- e2e 固定 zh-Hant 运行。

### 3.5 设置页顶栏间距（桌面端）

- 现象：设置页顶栏的「返回」「設定」紧贴左侧分类栏的竖线。
- 原因：顶栏 `.header` 绝对定位并横跨整页，macOS 下 `padding-left: 92px` 让出红绿灯，其后是「返回」按钮、12px 间距与「設定」标题；分类栏 `.layout` 第一列固定 `200px`，其 `border-right` 正好落在标题末尾附近（`src/renderer/views/Settings.module.css` 的 `.header`、`.layout`、`.categories`）。Windows、Linux 左侧只有 20px，不受影响。
- 处理：加宽分类栏使竖线右移，宽度以「macOS 红绿灯让位 + 返回按钮 + 间距 + 标题 + 留白」为准；英文「Back」「Settings」更长，宽度按三种语言中最长者确定，不按平台另设一套布局。

## 4. 失败情形（先写，再写代码）

安装与配对：

1. `install.sh` 输出的链接粘贴进桌面端无法识别，或在没有公共地址时仍输出一个从别的电脑不可达的 `127.0.0.1` 链接。
2. owner 配对码在放宽的有效期内第二次使用仍然成功。
3. 未选 QQ 的新安装仍尝试拉取 SnowLuma 镜像，或选了 SnowLuma 却没有要求填写镜像。

平台接入：

4. 填入错误的 Telegram token 后，旧的可用连接被关闭，或设置页看不到错误原因。
5. 更换 Telegram token 为同一账号时出现 `provider_conflict`，或新旧两个实例同时在线。
6. 飞书凭据被拒（PermissionError）后无法通过再次 apply 恢复。
7. 停用平台后仍有入站消息被接纳，或已有历史、Presence、回执被改写。
8. `expected_revision` 过期的保存覆盖了他人刚保存的配置。
9. 读接口、日志或错误信息中出现 secret 明文（Telegram token、飞书 Secret、AppSecret、VNC 密码）。
10. SnowLuma apply 返回 `applied` 而实际未生效；已填 VNC 地址时「QQ 登入」仍不可用，或未填时入口仍出现。
11. 全新安装（`install.sh` 服务器安装或桌面本机部署）后，在桌面端保存模型或平台配置报 `operation_unavailable`；或已有部署升级后原 `webui-config` 内的文件属主错乱、读不出已保存的 secrets；或升级后 `.env` 中原有的 Telegram、飞书凭据没有写入平台文档，平台掉线。
12. 群聊被动窗口过期后的官方 Bot 回复被记为送达，或被重试、改投其他平台。
13. 官方 Bot 的 openid 与 OneBot 的 QQ 号被合并成同一 Account，或据此推断 Person。
14. 定时任务或 SELF 主动消息发往官方 Bot 群且没有可挂的窗口内消息时，发出了不带 msg_id 的群消息、没有如实记为无可用投递路径，或被改投私聊、其他平台。
15. 重启后同一 msg_id 的 `msg_seq` 从 1 重来并触发 40054005；或 40054005 后重发超过一次。
16. 全量消息模式下，机器人自己发言的回推被当作新入站消息触发参与。
17. 单聊 `is_wakeup` 被拒（40034122/40034123）后没有按普通主动消息再试一次，或再试失败后仍记为送达。

SSH 与部署：

18. 桌面端重启后 SSH 方式的本地端口变化，导致设备凭据失效或连接器连不上。
19. 主机指纹变化时仍静默连接。
20. 网络切换后隧道不恢复，界面停在离线。
21. 从 SSH 切到直连（或反向）后产生第二个 Connection、重新配对或丢失原会话。
22. 「部署到我的服务器」中途失败后重试，产生两个部署或两个 owner Person。
23. 镜像拉取失败时只显示通用错误，没有提示配置镜像加速器。
24. SSH 密码出现在日志、错误信息或非钥匙串的文件里。
25. 服务器无法访问 GitHub 时「部署到我的服务器」失败，或上传的部署包与桌面端期望的后端版本不一致。

三语：

26. 切换语言后菜单、托盘、通知仍是旧语言，或需要重启才生效。
27. 某语言缺 key 时没有在类型检查阶段失败。
28. 简体界面使用 TC 字形显示。
29. 切换语言改变了时区、回执 note 或文件名。

设置页顶栏：

30. macOS 下任一语言的「返回」与标题碰到或越过分类栏竖线；Windows、Linux 下分类栏变宽后顶栏按钮与窗口控制按钮重叠。
