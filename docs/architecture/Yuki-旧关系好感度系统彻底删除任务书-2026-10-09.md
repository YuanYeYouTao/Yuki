## 3. 已确认的调用链

1. 人物观察/资料捕获/开通私聊 → People/PrivateUser Repository → `observe_canonical_person` → 自动创建 `person_relationships`，默认 50/50。
2. 普通真人上下文、真人 Work 新输入、部分外部私聊和自动化 → `ContextAssembler` 读取或创建关系 → `PromptComposer` 注入 `context.relationship` → 当轮真实动态快照/Prompt 投影。
3. 普通聊天确认实际发送 → `MessageProcessor` 在 `created and sent_count > 0` 时入队 → `RelationshipWorker` 定时/数量唤醒 → `LLMRelationshipEvaluator` → `StructuredTaskRunner.run(task=ModelTask.RELATIONSHIP_EVALUATION)` → schema/置信度/规则二次校验 → 改分及写事件。旧pending及超时processing也会被重新领取；第三轮核实没有另一条独立生产模型评分入口，不能仅撤新聊天入队。
4. LEGACY 群参与 → `AdmissionFeatureBuilder` 读取关系权重 → 局部参与 scorer 加减分。当前 SEMANTIC controller 输入没有发现旧关系字段，不能把 JEV/SELF 一起删。
5. Agent、管理员、Control Plane、WebUI、插件分别查询或调整同一份分数；自动化声明可以让关系再次进入上下文。删除任何一端都不等于整链退役。
