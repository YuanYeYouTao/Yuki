## 一、目标与不可变边界

1. 主 Agent 继续使用统一生成入口，以及启动时冻结的完整工具合同。聊天、自动化、插件自主轮和任务续跑不能各自选择工具表。
2. 不引入工具召回、按内容路由、动态裁剪、按场景懒加载声明，权限继续在执行处核验。目录查询不得修改声明。
3. 本轮主要治理工具说明和重复实现。除用户明确要求移除的麦当劳 MCP 外，默认保留工具名称、参数结构、顺序和用途，不批量删除带后缀的入口。
4. 工具说明也属于请求前缀。说明更新及麦当劳移除必须作为一次明确的合同版本发布；版本内保持不变，不能承诺发布前后仍是相同前缀。
5. 不修改用户 `system_prompt.md`，不重排人格、历史投影或动态信息区。不改变事件身份、任务预算、委托边界、持久回执及发送幂等。
6. “清理旧实现”和“从模型声明中删除工具”是两件事。仍在使用的入口可保留为薄适配器，底层逐步共用实现；移除其他公开入口不作为本任务的默认动作。

## 三、确认的问题及处理决定

### 1. 双入口来自两套声明来源，不是随机生成工具

`services/main_agent_contract.py` 先收集核心目录，再追加 `AutomationCapabilityRegistry` 的能力声明。未配置 `model_tool_name` 的能力通过 `automation/registry.py::agent_tool_name` 生成模型名。

后缀取能力名称 SHA256 的前八位，是确定性名称，不会每次启动随机变化。当前合同只拒绝同名工具冲突，不拒绝不同名字的语义重叠。

现有 `model_tool_name` 映射要求名称、参数、描述及缓存属性严格匹配，不能直接把参数不同的两个名字指向一起就算完成迁移。

| 入口组 | 核查结果 | 本轮方案 |
|---|---|---|
| admin_execute_action / admin_execute_action_d110d370 | 前者使用 action + arguments；后者对应 admin.execute_action，参数平铺。后者 handler 经超级用户检查后固定抛 operation_unavailable | 确认属于失效执行路径。保持声明时必须修复为经过原权限和参数校验的明确适配；不得仅写“已废弃”后继续让模型踩坑。若无法保证等价则单列退役方案供审阅 |
| automation_create / automation_create_task_d57e3199 | 两个注册来源；后者使用 TaskSpec 类型输入，不能仅按名称认定参数等价 | 说明各自输入合同；追踪调用方，复用业务服务及创建幂等，不重加自然语言正则 |
| automation_cancel、automation_update / 对应带后缀入口 | 同属自动化管理，存在不同适配上下文 | 核对所有权、委托和回执；统一底层操作，不扩权、不重复创建或执行 |
| send_group_message、send_private_message / onebot_send_* 后缀入口 | 核心发送与自动化主动网关接口并存 | 明确目标表示和当前上下文要求；复用交付服务，保留委托和重复发送防护 |
| web_search / web_search_15f83c80 | 自动化说明硬写 Tavily，实际 handler 调用注入的 Web 服务 | 改成真实通用搜索合同，不在说明中规定 Provider 分流 |
| read_webpage / web_read_page_e5935864 | 两个读取适配，返回预算与上下文可能不同 | 核对 URL 授权及结果格式后共用服务，不能凭“都是读网页”抹平边界 |
| search_chat_history / history_search_63bedf8a | 自动化 handler 有创建者、群和 canonical conversation 范围逻辑 | 明确搜索范围和默认值；不得为了合并而扩大可读范围 |
| admin_get/set_config / config_get/set 后缀入口 | 读接口存在批量 keys / 单 key 差异；自动化 config_set 禁改 automation.* | 保留差异并说明，适配不得绕过该限制 |
| send_voice / speech_send_group_efc5e124 等 | 前者配置本轮最终回复语音；后者明确文本和目标主动发送；profile_id 实际可省略 | 不是简单重复。说明交付方式，不能合并为一次调用发送两遍 |
| memory_change / admin_execute_action 的 memory.* | 当前用户真实入站证据变更与超级用户管理是不同授权路径 | 保留两者；把“唯一长期记忆变更工具”改成准确的日常记忆入口说明 |

带后缀入口的逐项真实使用次数尚不能由现有聚合准确还原，不能写成“全部零调用”。实施时先补齐静态调用者与已有执行记录映射，再删除内部实现；不为调查修改线上日志或保存正文。

### 2. 明确错误的说明

- `admin_set_config` 指向未声明的 `admin_list_capabilities`。必须检查 `get_my_capabilities` 的真实参数和返回信息后修正引用，不能只做字符串替换、继续保留旧 focused 参数指引。
- `memory_change` 的“唯一”表述与管理员记忆维护入口冲突，应说明证据来源和授权用途。
- 自动化 `web.search` 将实现写死为 Tavily，与注入 Web 服务的抽象不符。
- 语音说明需要区分最终回复布局、显式主动发送、可选 profile，避免模型误判参数必填。
- `main_agent_backend.py` 仍有无 main_contract 时的旧“先 request_tools 加载工具”错误分支。先证明生产入口、插件入口及恢复路径都不依赖它，再删除分支；不能重新启用该模式。
- `admin_list_capabilities` 的旧执行分支仍存在，应核查插件及内部调用后决定是否删除，不能因未声明便断言无调用方。

### 3. 说明修订规范

每项说明仅覆盖：用途、适用输入、目标/范围默认值、重要参数差异、异步状态或真实交付结果。保留影响正确调用的约束，不为减少字数丢掉权限、版本检查、输出游标和幂等语义。

同一功能的多个现存入口需要明确差异；不引入按用户文本关键词选工具的强制策略。所有引用的工具名称、枚举、字段均需在当前合同中真实存在。

核心说明在原工具定义处维护，自动化在 registry 维护；MCP 如需本地说明覆盖，应按稳定 Server/远端工具身份做版本化配置，在冻结前生效。禁止每轮改写说明、把目录搜索结果拼回固定前部。

## 七、本次发现但不混入清理的运行错误

近期失败并不都来自说明混乱：get_recent_chat_history 的 9 次调用全部失败（6 次 result_too_large、3 次 CanonicalIdentityError）；workspace_import_attachment 9 次有 8 次附件定位失败；search_chat_history 有 10 次 result_too_large；read_webpage 有 11 次 url_not_authorized。还有 TurnSupersededError 等中断类别。
