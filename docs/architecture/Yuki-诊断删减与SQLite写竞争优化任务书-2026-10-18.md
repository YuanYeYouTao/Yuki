## 1. 线上事实与归因边界

部署后的有界只读样本有 440 条 trace、32 次模型调用；原始 JSON 6,532,038 字节，gzip 1,988,024 字节。`turn_start`、`model_start`、`provider_start` 三种请求视图占原始体积 84.27%。一轮 3 次模型、2 批工具、3 条发送留下 39 条 trace，原始 614,584 字节；三层请求视图占 97.49%，另有模型和工具统计事务。该百分比说明重复来源集中，不代表删除后能省去全部这些字节：实际 HTTP 请求、返回仍须可查。

采样中有 52 次失败 SQL 尝试：40 次入站回执 INSERT 集中在 16:59:36–38，12 次自省 run UPDATE 分布在四轮自省。错误码包括 BUSY 和 BUSY_SNAPSHOT。诊断、Memory 入队、Work scope、投影发布及会话状态写入均曾出现在持有者观测里。诊断事务 1111 的首次写入后可观测持有时间达到 470ms，不能从现有计时细分磁盘、驱动和调度成本，不能指认为持锁压缩或模型等待。失败尝试数不等于消息失败数；附近轮次有真实成功回执，四轮自省已完成。

同一 Conversation 的前后各 7 轮，装配中位数 95.10→48.11ms，拼装 45.43→24.54ms，但模型前准备总计 374.28→546.61ms。后样本的 F/E 更大，仍不足以建立严格因果实验。缓存已知样本的 token 加权命中率约 79.70%→79.46%，缺字段保留未知。不能把健康、低压缩字节或局部计时宣称为端到端性能和缓存验收。

## 2. 删除与重构清单

| 编号 | 范围 | 实施目标与必须保留的事实 |
| --- | --- | --- |
| D01 | 请求/响应采集 | 实际物理 HTTP attempt 保留一份经过原脱敏规则处理的请求和返回；逻辑模型合成一条路由/状态/真实 usage/耗时记录。删除 Compiler、Composer、恢复阶段及 Wire Observer 的整链诊断哈希、LRU 和 DTO；准备调用预算改由现有业务整数直接传递。实际 Provider 输入和缓存前缀不变。 |
| D02 | 空事件及工具批次 | 删除无信息成功结束记录、重复工具批次参数/结果；真实单项调用、原 call ID、结果及取消/错误仍可查，业务 journal 与回执不变。 |
| D03 | 语义参与 | Snapshot 保存一次，结果不再携带同一 Snapshot；收敛额外结果/空结束事件。真实概率、usage、elapsed 和 Host 接纳仍可查，不增加 observer 或改变参与策略。 |
| D04 | 诊断来源 | 删除每条独立 preflight reader；必要的 ID 类型、来源、归属、隐私代次及已确认投递条件在最终条件 INSERT 中原子核验。诊断缺样不改变业务结果。 |
| D05 | 诊断提交 | 复用原有界队列和资源 owner，锁外准备后单项条件 INSERT；合批因实测扩大旁路业务 writer 等待而否决，不保留候选代码。通过删除生产者减少提交频率，不等新记录、不持 writer 编码或读历史。提交失败/未知只报告缺样，不重试效果或未知提交；诊断 SQL 不把正文钉在编译缓存里。 |
| D06 | 旧统计链、索引与读取 | 无现行读者的 tool_invocations 与 runtime_turn_observations 连生产者、依赖注入、清理、ORM 和表一并退役；保留真正的 MemoryToolReceipt、模型用量、执行 ID、内存阶段计时和投递回执。删除 roots、operation_id 两条无消费者索引，保留六条实际索引；元数据查询不加载 gzip。0134 清退两张旧统计表，其余原事实及 trace 正文不变。 |
| D07 | Work scope | 原租约获取收敛为带 generation、owner、SQL 执行时期限条件的写入；删 writer 内多次往返，忙 scope 仍沿原只读快路返回。不得把准备时钟当取得 writer 时钟。 |
| D08 | 自省检查点与周期 | 后续输出进度更新直接沿原 checkpoint CAS，不先重读整行；按 source_key 命中已有周期时只读返回，不重新聚合快照或零行 INSERT。manual 原事件与 Conversation 验证、新周期并发唯一键、首次来源验证、隐私擦除与原已付结果仍保留。 |
| D09 | Memory 重复入队 | 已有原 event_id job 时只读返回原事实，避免重新准备和零行 INSERT；不由当前账号反推原 Person，也不产生新 Memory 授权。 |
| D10 | 消费者与交付 | 同步查询、合同、配置说明及测试；保执行过程旧记录读取，不伪造历史新字段。退役两张无消费者统计表的数据不重建，0134 只能向前修补。验证源码、PR/CI、合并、镜像、上线与自然流量各阶段。 |

## 3. 审查与验收

1. 第一轮按生产者和现行消费者划定删除范围，核对保存正文的唯一层；第二轮按来源/隐私/取消/回执和持锁边界复核重构。实现后再作独立交叉审查及合流终审。
2. 真实 SQLite 覆盖：就绪队列、来源变化与删除竞态、取消和关闭、失败/未知提交、资源释放、并发租约、checkpoint CAS、重复入队和迁移。禁止为取绿降低身份、来源或已发生效果断言。
3. 相同输入与假 HTTP/平台的完整链测量正文处理量、SELECT/DML/commit 数及局部时间。新旧实际请求和结果、工具声明、续跑配对、内部事件与回执要等价；不能用单次本机墙钟声称生产加速倍数。
4. 迁移核对两张明确退役统计表被删除，其余所有表事实、执行过程行及正文逐字节保留；核对仍用到的查询计划和外键。不清空现行诊断或业务数据来冒充优化。
5. 验证仅做受影响范围及要求的静态检查；远端 CI 和线上自然样本另记。当前任务不以真实 QQ/TG 消息或付费模型作测试，不修改生产资源配置。

具体实现、验证状态和处理量见[实施记录](../operations/diagnostic-optimization-20261018.md)。D01–D09及D10本地部分已完成；远端CI、合并和上线不计入本地验收。
