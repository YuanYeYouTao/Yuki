## 1. 目标与基线

1. 彻底删除后台记忆种子功能：从 Memory 扫描、包装 seed、排队、JEV 评分、recall/contact 候选与机会，到专用去重、状态、参数、前端、提示、文档和测试一起退出新运行链。
2. 保留有实际作用的 `<yuki-state>.engage`：普通意愿由后端直接用于局部续聊，主 SELF 意愿继续影响原 scope 的自主机会。同时在已有 JEV 请求中附带相关参与意愿，帮助其理解交流关系与新邀请；不把局部 quiet 广播成全群停止，不因状态更新新增评分，本轮不扩展普通意愿的概率公式。
3. 删除无实际消费者的 `mood` 字段。全局三槽 `short_state` 是临时记录，保留其现有用途，不把自由文本转换为参与状态。
4. 修正 quiet/closed 单元仍被 Host 当作活跃参与的消费者错误。按用户后续意见保留同作者快速续聊，但把未经语义核验的连续外推变为有限额度，并接通后台 JEV 复核及负反馈；不能靠旧表达或自身 stay 无限续开。

## 2. 已确认的问题

### F01 记忆种子持续制造后台 JEV 请求

`SemanticParticipationService._seeds` 每群至少间隔 60 秒，调用 `read_self_seed_page` 读取最多 4 个获准事实。事实被包装为 `kind=seed`、`author=SELF` 的事件，逐条 `request_observation`；有唯一近期证据作者时为 CONTACT，否则为 RECALL。没有新真人消息也会运行。

首次游标从 1970 年开始，按事实变更时间向前扫描，不要求记忆发生于近期。相同代次有持久游标与内容摘要去重，不应笼统称为每分钟重复同一批；新代次扫描旧事实、必需评分维度无效后的重排，则会继续产生调用。

只读的一小时窗口中有 269 次 observation start，其中 222 次以记忆种子为焦点，47 次以真人消息为焦点。265 个可见结果记录 input/output tokens 为 3,494,798 / 78,073；没有 cached token 字段，不能据此宣称缓存率、未缓存成本或完整账单。

这些是持久 trace 可见的观察启动/结果记录；诊断可丢且请求可能跨采样窗口，不是完整物理 HTTP 调用账本，更不是 QQ 发言次数或 SELF Work 数量。

### F02 种子还进入后续上下文

真实 `memory:2331` / sequence 168，start trace `239784`、result `239791`：9 月 28 日创建的记忆在 10 月 15 日 18:51:29（UTC+8）接受评分。上下文 33 条中，31 条为其他 seed，2 条为真人输入；该次 input tokens 为 11,663。

真实真人事件 `104333` / sequence 207：上下文 53 条中有 36 条 seed，input tokens 为 14,825。删除不能只停止 `_seeds`，还必须确保旧快照、队列恢复与 observation context 不再把 seed 正文带给 JEV。

同一 `memory:2587` / revision 1 的 sequence 237、238 相隔 31.804 秒。第一次 `interaction_mark` 无效，随后重新排队；input tokens 分别为 16,665、15,526。没有原始 provider 响应，不能把“无效”进一步写成已证实的缺字段或具体格式错误。真人观察仍需要的通用失败处理不随种子一起误删。

### F03 yuki-state 有用，但两种意愿的消费范围不同

| 状态 | 真实写入与消费者 | 判断 |
| --- | --- | --- |
| 普通主轮 `engage` | `MainAgentBackend.observe_response` → `participation_ordinary.observe_main_response` → `Controller.observe_unit_hint` → 原 admission 的 `UnitState.hint` | 会影响对应讨论/对象的快捷续聊，quiet 能退出；没有进入自主机会率的意愿项，这是当前职责差异，不能单凭它认定反馈失效 |
| 主 SELF `engage` | 原 journal `progress.self_reports` → `participation_feedback` 回放 → `observe_self_report` → `engagement_report` → `_willingness` | 现有代码已将其接到来源机会和 intrinsic 的连续倾向中；不是整个状态无用 |
| `mood` | `SelfDelta` 接受最多 40 字自由文本；SELF report 可保存，普通 mood-only 不形成 unit hint | 未找到读取、概率或提示消费者；删除运行字段，不建设情绪量化系统 |
| `update_short_state` | 全局 3 槽临时文本 → 本轮 `runtime.short_state` 资料；24 小时过期 | 有跨会话临时记事用途；不是 engage，不直接进入 controller，保留 |

SELF `_willingness` 当前为 join 正向、stay 零、quiet 负向，并按既有 `willingness_decay_seconds` 衰减。是否发消息、Work 是否完成、工具是否成功仍分别依据真实执行，不能由 engage 代替。

反证后收窄原方案：普通 continuation 不经过 `opportunity_scores/source_rate`，所以给局部 hint 再接概率并不能修复同作者误续聊。这项是独立的产品行为扩展，不作为本轮修复的完成条件，也不以修改自主率公式替代快路自身的复核与退出。

后续用户明确要求将 engage 反馈给 JEV，作为帮助判断的已知自身状态。本轮据此增加 §4.2 的请求上下文投影；这与把普通 hint 接进概率公式是两项不同改动，后者仍不纳入主线。

`MainAgentBackend` 对 `lease.work_id` 非空的早退用于独立子工作者租约。主 SELF 的 `WorkRepository.acquire` 构造 scope lease，`work_id` 仍为空；不能把这段保护误诊为所有持久主 SELF 都丢失自报，也不能为接通反馈允许子 Agent 冒充主 Yuki。

已有生产快照中存在 stay/quiet 的普通 unit hint，说明普通反馈实际发生过；采样中的 `self_reports` 列表为空，不能单凭这个被裁剪集合证明 SELF 历史从未提交自报，也不能据代码路径宣称线上全部反馈已追平。

### F04 quiet/closed 没有使观察调度退出活跃档

Host `_advance_scene` 当前使用 `active=bool(controller.participating_units(now))`。库返回保留单元，quiet、closed 是单元字段，不会使返回集合自动为空。

既有隔离复现中，quiet/closed 后普通续聊已不匹配，Host 的 active 仍为 true；有待评项时，第 8 秒仍按活跃档取出。应消费现成的单元参与事实，不新增休眠状态或冷却计时器。有 pending、ready 和 in-flight 等队列条件，并不代表每 8 秒固定调用。

### F05 旧参与关系可能被当成同一作者所有新输入的续聊

固定库 `participation_view` 在同作者有唯一 expressed 或 join/stay 单元时，可匹配一个新 thread、`unit_ambiguous=true` 的未观测输入，并返回 `needs_observation=false`。原正文裁剪后，隔离恢复到 1 小时、24 小时、7 天仍可匹配；这是代码行为复现，不是已观测七天生产事故。

用户后续明确希望保留快速续聊、用计数及负反馈避免常开。因此不再整删这条快路：同作者与旧关系可以支持一次乐观接纳，但不是当前输入已解析的语义事实；连续借用旧关系必须受 §4.4 的复核跨度约束，未确认输入继续进入后台观察。

这会改变现行“匹配快路后通常不再观察”的行为，可能增加真人 JEV 调用；原合并、间隔与新鲜度队列继续使用，不机械改成每条消息立即评分。必须单独记录调用量与快路延迟，不能用种子删除的降量掩盖这项成本。显式请求、原 Work/wait 和 #439 的输入接纳不受复核额度限制。

### F06 其他入口不能声称已经统一反馈

`send_message.text` 的状态尾段在 Social/renderer 净化时被剥离，delta 不被消费；真正反馈只读取模型 `response.content`。不能把“成功发送正文里写了状态”当成自报成功。普通后台插件及没有 initiative run 的 SELF 定时工作也不会自动进入这条 report 链。

静态追踪还发现，受托插件 Main 可继承原 initiative run 并将报告写入插件自己的 progress，但反馈扫描选择的是 `initiative:<run_id>` 对应根 Work 的 checkpoint，不读取 `invocation:<boundary>` 插件 Work。这个委托路径存在“写入后无消费者”的缺口，本轮没有相应自然样本。应删除误导性自报写入或明确原父执行的回传来源后再修；不能让插件/子任务任意覆盖主 Yuki 意愿。

另有独立的资料装配缺口：子工作者可执行 `update_short_state`，但其初始请求只有固定材料与 brief，没有调用普通 Main 的 `ShortState.snapshot` 当前资料装配；与持久工作者文档中“同 Main 准备当前资料”的描述不符。这不证明 short_state 无用，也不应把修复转成公共历史重排。

上述两项登记为后续独立修复，不冒充 D11 已覆盖所有入口。执行本任务书时先复核是否已有其他变更修复；未处理的项目保持明确未完成状态。

### F07 JEV 当前没有收到已经存在的 engage

精确 pin 的 `JevObserver._semantic_state` 只投影 focus、context、相对时间与歧义时的 unit_options；Snapshot 本身也没有参与意愿字段。后端已保存的局部 hint 与主 SELF engagement_report 没有进入评分请求。当前 quiet 后的原消息补评也没有把 quiet 告知 JEV。

用户要求补齐这条信息反馈：让 JEV 在判断真人消息时知道 Yuki 此前想加入、维持还是退出，以及这个意愿的适用讨论和时间。该缺项是请求上下文事实，不据此推定现有所有误判都由它造成，也不把状态投影等同于模型已经实测更准确。

### F08 当前并行语义纠正不能可靠收起快路

后台 tick 的 `evaluate_due` 不持普通接纳的 service lock，具备与 Main 网络请求并行的基础；但 `_hydrate` 以 matched/needs_observation、已接纳与直接入口跳过观察，普通 join/stay 也不补评，所以快路新消息往往没有进入 JEV。已有队列和 HTTP 并行不等于已形成持续纠偏。

本地精确 pin、合成 DTO 的两个反例已复现：

1. B 已快接后，JEV 模拟结果将 B 解析为同一单元，但给出 `other_exchange=1`、`floor.other=1`；apply 成功，B 及下一条 C 仍能沿旧单元快接。当前匹配不消费这份负向交际反馈。
2. B、C 先后快接，使最新 input_ref 变为 C；随后 JEV 将旧 B 解析为新讨论，apply 成功。B 自身不再匹配旧讨论，但下一条 D 仍可沿旧关系快接，因为旧单元只检查最新 C。

这证明不能只增加评分请求：还需把原焦点的纠正归回它当时借用的关系，并让确认/否定真正影响后续快捷资格。这些是本地代码行为，不是生产发生次数，也不是 JEV 模型准确率测试。

另一路同 pin 离线对照还确认，当前纠正并非完全无效：

| 合成语义结果与时序 | 当前后续快路 |
| --- | --- |
| 同单元 other_exchange，回应楼层给别人 | 仍可能开启 |
| C 被解析到新单元，C 仍是当前 input_ref | 原单元可退出 |
| C 被解析到新单元，但期间 D 已快接到旧单元 | 原单元仍可能开启 |
| 对原单元的真实 ask_yuki_stop，停止范围可判定 | closed 生效，后续匹配退出 |

因此要修的是“哪些纠正没有被快路消费者采用，以及晚到纠正如何归属”，不能笼统写成 JEV 没有纠正能力，也不能把所有负向交际结果都塞进 stop 分支。

另有排队消费者遗漏：`_defer_ordinary` 的闭包会保留旧 continuation binding，后续 promotion 主要在来源 revision 变化时重查；仅语义结果改变、原正文版本未变时，尚未接纳的旧机会也可能继续使用旧快路资格。需在原接纳边界重核当前 continuation，身份和原输入仍沿原绑定保留，不用允许 direct 新建单元的兜底读取代替 continuation 核验。

## 3. 删除边界与既有事实

### 3.1 删除全部新种子能力

- Host 的分页 Memory 扫描、60 秒检查、seed 包装、offer 摘要、游标和观察提交。
- 参与库的 seed 事件能力、RECALL/CONTACT 新候选与 proposal、`seed_fit` 评分问题和对应必需维度。
- `seed_claims`、`seed_attempts`、`content_keys/_content_key`、`Proposal.source_fingerprints`、等待种子回复、种子重试恢复与专用保留/裁剪分支；已逐个核对，内容摘要的有效消费者随种子 claim 链一并退出。
- 仅种子使用的 `recall_source_decay_seconds`、`contact_source_decay_seconds`、`independent_source_factor`，以及 schema、示例、挂载配置、前端标签与相关说明。
- 仅证明旧功能继续存在的测试、样例、提示和当前合同表述。历史报告保留当时事实并标明退役，不全文改写旧证据。

不以默认 false、改成低频、关闭 proactive 或新建“按需种子”替代删除。没有新的 Memory watcher、JEV 预评分或同义候选入口。

### 3.2 保留共享能力

Memory 正常读写、检索、证据与权限、Self Reflection、Main 按需查记忆保留；`self_origin.py` 还有真实 SELF 来源用途，不能整个模块删除。真实 human/self 事件、真人 JEV 观察、真实发送锚点与回应、普通持续接话、自主 conversation/intrinsic、已有 Work/自动化与公共 Compact 保留。

`source_interval_seconds`、`source_opening_seconds/floor` 等仍用于真人 conversation 来源机会，不随名称中含 source 一并删除。`proactive_wakeup_enabled` 保留对 intrinsic 的现有产品语义，`auto_reply_enabled` 保留 conversation 与普通入口语义；不合并开关或顺便改默认值。

`familiarities/_familiarity/_consider` 与 `source_familiarity_weight` 仍服务真实 conversation，不随种子去重删除。自主活动页的 run/feedback/trace 查询保留，只去掉新候选统计里的 recall/contact 和失效参数；旧 run 按原类型显示。

### 3.3 历史 reader 不等于新种子入口

目前 `read_self_seed_candidates` 除 `_seeds` 外，还用于 `_dispatch` 核验已接纳旧 run 的 Memory 来源；`_sources_current` 也会核验已保存普通 admission/unit 的来源。`invitation_basis` 曾把 JEV context 引用纳入 binding，因此旧普通绑定也可能含 memory ref。

删除扫描器后，改用现有 Memory 按内部 fact ID 的获准精确读取，保留这些已有身份和来源的必要核验；取消无 fact ID 的种子优先列表入口和 seed 命名。不能通过移除旧 basis、把来源直接判有效、批量关掉普通关系或清空聊天逃避处理。

精确读取不是直接换成 `get_active_authorized` 就结束：该现有接口的 review、valid_from 和可读证据条件与旧种子 reader 不完全相同。旧已提交来源仍需核验 verified、有效起止和至少一条当前可读证据，复用原授权与 SQL 证据谓词，不恢复候选扫描。`memory_revision` 不含证据撤销信息，因此内容摘要相同也不能代替证据可读性核验。

已接纳旧 recall/contact run 按原 run、Work、权限、journal 和回执继续恢复，不产生新 proposal，不改成 intrinsic，不重置预算、不重发效果。尚未接纳的旧候选、排队观察和 proposal 退出；退出前先查原 proposal 是否已由 Host 接纳，不能丢失崩溃窗口内已提交的 run。

历史记录中的 recall/contact、memory source 和 seed_fit 仍可能需要被读取。仅在原持久化升级/历史读取边界识别，不保留可调度的新类型分支。真实历史效果与其 W/E/R、计算消耗不能因为来源退役而抹掉。

## 4. engage 与 JEV 的分工

### 4.1 后端直接消费意愿，保持现有作用范围

普通主轮继续按原 admission、activation、请求序号、response ID 和局部单元接纳 `engage`。来源核验、旧响应排序、去重和保存沿现有逻辑，不把普通 activation 伪装为 initiative run，也不把它塞进按 SELF run 裁剪的 `self_reports`。

普通局部 quiet 继续退出该单元的快捷续聊。D13 保留乐观快接，并按 §4.4 接入有限复核与语义负反馈；D12 让观察调度正确消费 quiet/closed。不新增局部 d，不改 `source_rate`、`pressure` 的自主率意愿输入或权重。

主 SELF 的 scope 意愿和真实 Work 密度、计算、暴露、回应及 NO_REPLY 反馈沿现有公式消费。局部 quiet 不写成 scope 的最新 SELF report；真实邀请、直接请求和原 Work 输入沿原及时路径处理。不因本次删种子调整采样系数，已有公式中的不同作用项也不冒称新修的重复计权问题。

JEV 判断真实输入的交际动作、信息变化、回应机会与停止范围，使用 §4.2 附带的自身意愿作为关系上下文，不重新认证这份意愿。不为确认状态本身新建评分请求。后端负责是否参与，Host 继续负责原来源、唯一接纳和真实执行。

不新增持久意愿副本、汇总布尔值或 mood 分类器，不为状态汇报增加补问或额外模型链。SELF 和普通自报均为可选，无尾段维持原状态，不把空正文或 NO_REPLY 自动改写为 quiet，不要求逐轮汇报状态才能完成任务。

### 4.2 在已有 JEV 请求中附带参与意愿

**这是本轮明确纳入的改动。** 每次实际选出真人评分焦点时，从当前合法控制器状态生成一份小型参与上下文，冻结进原 `Snapshot`，由现有 observer 一并发送。JEV 不需要单独的反馈 API 或持久记忆会话；每次请求带当时已知值。

#### 事实来源和范围

- 普通局部意愿来自原 `UnitState.hint`，沿已有 binding、当前 input 解释和 hint_basis 有效性读取。只选 focus 精确 `(thread,target)` 以及它已有 unit_options 对应的单元；不按同作者猜回一个旧单元，也不发送全群全部关系。
- focus 有歧义时保留已有选项与各自状态的对应关系，让 JEV 选择；不能先按 quiet 或活跃程度挑一个选项。已收起的 quiet 仍是有用信息，不因 active 过滤而丢掉。
- 主 SELF 的 `engagement_report` 可作为同 scope 的整体意愿单独附带，明确标为整体，不冒充某个局部报告，不覆盖所有局部 quiet。没有实际报告就不提供，不从 Work 状态或普通 hint 伪造整体意愿。
- 保留 `join/stay/quiet` 原枚举。没有合法 hint 表示未知，不能默认 stay；stay 不因其数学映射为 0 而被省略。`mood` 和全局短记录不进入此投影。
- 原 run/activation、response ID、请求序号、来源引用和原时间留在本地快照的出处信息中，用于追踪本次究竟采用哪份报告；无需为 JEV 外发 Provider response ID 或新建来源表。状态仍只保存在原 controller/journal。

#### 请求与时间

在 `state` 增加一个结构化 `yuki_participation` 区域，区分可选的 `scope_intent` 和相关 `units`。下例仅说明字段含义，是合成缩写，不是真实调用或已定稿 wire schema：

```json
{
  "yuki_participation": {
    "scope_intent": {"engage": "stay", "source_seconds_from_focus": -120},
    "units": [
      {"thread": "t2", "target": "已有目标标识", "engage": "quiet", "source_seconds_from_focus": -30}
    ]
  }
}
```

thread 复用原请求的 `tN`，目标复用同一次 focus/options 的目标标识；不让 JEV 生成新业务身份，不额外泄露内部 run/response 编号。映射必须覆盖状态引用的已有讨论选项，即使对应旧消息正文已裁剪也保持一致。

时间沿原报告 `at` 表达为相对 focus 的位置，结合已有 `focus_age_seconds` 解释。普通报告的 at 是原入站事件时刻，不是模型输出完成时刻，不改成当前时间来伪造新鲜度。补评原焦点时，已知意愿可能来自对该焦点的处理；JEV 不能把它倒推成真人此前要求停止的证据。

字段沿原 Snapshot/Observation 传递，`TracedSemanticObserver` 因而能记录本次实际采用的状态。observer 编码时只读取冻结的 Snapshot，不再实时读取 controller；在途的新报告不会篡改旧请求。仅有更新的 engage 不撤销已付观察、不新增报告版本 veto；真实来源撤回仍沿现有核验处理。

queue checkpoint 继续按 ref/kind 保存待观察身份。冷恢复或合法重试在下一次实际取出时，生成新的请求序号并冻结当时合法状态，不把旧在途请求假装成原样重放。旧 Snapshot 缺该新字段时读为“未提供”，不补造历史意愿、不重写 trace 或原已付协议。

#### JEV 提示和输出

在现有固定 rubric 简短说明：这些是 Yuki 已报告的自身意愿，带作用范围和时间；用来理解交流关系，不是聊天成员发言、用户停止要求或授权。quiet 后仍可能出现真实新邀请；join/stay 本身也不证明任何真人正在邀请。范围和语义不明仍可选择 unknown。

保留现有评分维度和输出合同，不新增“是否允许发言”或“意愿是否正确”的评分项，不设置 quiet 自动否决。没有状态时继续依据真实材料判断。同步更新投影/rubric 修订标识；旧有效观测与回执按原基线保留，不为切版本清空历史。

新增的是已有请求的一份上下文，不增加状态上报请求、tick、重试策略或参数开关，也不改普通意愿的后端概率公式。仅保证状态正确送达和作用说明清楚；真实判断改善与刷屏下降需要后续自然样本验证，不能由 fake observer 测试宣布。

投影修订必须在实际 trace/观测证据中可辨认，不能只修改一个未被记录的常量。历史请求重构仍按当时 pin、rubric 和字段投影，不用新字段倒写旧请求。

### 4.3 保留有真实用途的原消息补评

调查基线中 quiet 回调的补评不发送 quiet，而是评估尚缺有效解释的原真人消息。实施 §4.2 后，这种已有补评也携带当时合法参与意愿，评分焦点仍是原真人消息。`apply_semantic_observation` 先记录回应、建立真实 stop/closing boundary，再检查 consumed 是否禁止新候选；原消息已经接纳不表示停止含义也已经解释。

因此本轮保留这条有条件补评及重复响应去重，不把它归为无用种子重排，也不扩大为每次状态变化都调用。直接入口、已接纳输入与真实引用续聊目前可能跳过初始观察；若另行删除 quiet 补评，须同时让真人输入的独立观察路径承担这些停止/回应语义，并单独评估增加的 JEV 调用量，不能只删回调后声称覆盖不变。

### 4.4 保留快路，补齐并行复核和有限外推

#### 快响应与慢判断分开

有真实已建立关系、当前来源有效且未 quiet/closed 时，保留原普通及时入口，不先等待 JEV 完成。与此同时，真实新输入可以在原观察队列登记复核；是否已接纳或匹配快路不再一刀切地排除其观察。原队列去抖、间隔、公平性、来源版本和重试仍生效，不另起观察服务。

主回复与 JEV 可并行。结果回到原 controller，先更新关系、回应和停止事实，再由原 admission/consumed 防止同一输入启动第二次 Main。后台复核不能重发、撤回已确认发送，不能把“纠正当前关系”变为重跑已完成回答。

#### 两种反馈都能独立收起快路

这是明确的目标行为，不是只把状态发给 JEV 或记录一个概率：

| 对应单元的当前事实 | 后续可否借旧关系快接 |
| --- | --- |
| 语义依据仍支持交流、没有有效 quiet，且未核验额度可用 | 可以，沿原快速入口 |
| JEV 已纠正为他人交流、转题或真实停止，旧快捷依据不再成立 | 收起；自身 stay/旧发送不覆盖这份纠正 |
| Yuki 已对该单元有效报告 quiet | 直接收起，无需等 JEV 评分或同意 |
| 两种退出同时发生 | 继续收起，分别保留自身意愿与真人语义事实 |

这是原参与事实和复核跨度的派生判断，不新增另一个全局开关或持久 fast_enabled 副本。两种依据不能用 OR 放行：JEV 仍判断在聊天，不会自动覆盖 Yuki 更新的 quiet；Yuki 仍写 stay，也不会自动覆盖该关系已经被语义纠正的事实。待评分/unknown 不是新的确认，仍按有限外推处理。

语义否定或有效局部 quiet 一旦成立就收起，不需要先用完 K；K 只处理持续未获确认的乐观外推。quiet 必须来自该单元原有效 binding/hint_basis，不从主 SELF 整体意愿或同作者关系猜回。

有效 quiet 保存后即影响该单元后续快速判定，下一次 JEV 只随真实待评输入接收这份状态。正在排队但尚未接纳的旧机会也要在原接纳边界重核；不能以“不等待 JEV”为由继续使用缓存的旧快路资格。已经接纳的 Main 和已确认发送仍保留事实，不为收快路另建取消或撤回链。

仅对原讨论、对象和代次生效。主 SELF 的整体 quiet 仍按原自主率语义处理，不因本项广播关闭所有普通聊天单元。quiet 之后的真实新邀请仍可从原普通入口处理，依据新来源建立有效的新参与关系与新意愿；旧 JEV 正结果、旧报告、旧发送或计数清零本身不能把已收起的关系复活。这里不禁止新邀请后的有效新报告，也不允许为绕过 quiet 凭空制造新 thread/unit；JEV 的正向解释本身不改写 Yuki 原有的自身意愿。

#### 计什么，怎样退出

记录每个讨论/对象连续借用旧关系、尚未得到新语义确认的快接量。建议最小状态为单元的快接进度及最近语义确认位置（如 fast_seq / semantic_confirmed_fast_seq），沿现有 snapshot/原 admission 身份保存或重建；若现有来源还不足以防重复递增，明确增加最小原事件/版本记账，不假称零新状态。不新增业务表、全群计数服务或每条发送的第二本账。

一个真实输入的原接纳只记一次；相同 admission 回放、同一输入被 steer 与排队同时看到、重复发送回执，不重复增加。计的是未经核验的快捷外推，不把一个 Work 的分条发送当多次快接。Yuki 自己的发送和 stay 不能将“用户确实仍在和她交流”自证为真、给额度续期。

不能在 `observe_unit_input` 每次调用时直接加一：Host `_hydrate` 会回放近期已接纳输入，当前实现只对恰好等于最新 input_ref 的一项短路，A/B/C 轮转仍可能反复进入写分支。计数须关联真实新增的快捷接纳及原 event/revision/activation；恢复和回放只还原已有进度，不制造新的次数。

采用明确的可调复核跨度 K：连续未核验快接达到这个跨度后，暂不再沿旧关系快判，新输入继续走原语义入口；不是禁止用户发言、关闭整个群或第 K 条后不能回复。明确请求、真实直接入口和原 Work 输入保留原处理。不得把 K 包装成没有边界的 confidence 公式；若只提高 JEV 优先级而不给快路任何退出条件，JEV 长期失败时仍会无限快接，不满足用户要求。

K 的实施默认值选为 4。独立库 `scripts/replay_fastpath_review.py` 与
`docs/evidence/fastpath-review-replay-2026-10-15.json` 记录 192 条合成轨迹，沿已有约 6 秒
请求延迟、2 秒 tick 和活跃/非活跃队列比较 2/3/4/6 的取舍。输入持续 90 秒，另排空 22 秒，
调用量属于完整 112 秒窗口。活跃档、5 秒一条时 K=4 的 18 个输入均可快接，K=2/3 为
12/15 个；固定非活跃档的对照为 16/18。高密或换题时不再无限外推，unknown 与真实 session
timeout/冷恢复均不补确认进度。这只是已知延迟下的离线选择，不是线上最优值、Main 延迟或
模型准确率验收。沿现有参数 schema/热配置入口提供这一个复核参数，不新增配置文件或一组冷却开关。
它是未经复核外推的跨度，不是每日发言配额或通用任务完成门槛。

#### 什么能恢复，什么构成负反馈

- JEV 对真实新焦点确认仍在该讨论向 Yuki 交流，或真实新明确邀请，才能更新相应关系的语义依据。以已评焦点建立新的确认位置，焦点之后已发生但未核验的快接仍保留；不能因它们出现在 context 中就整批算已确认。
- `other_exchange`、明确转到别的讨论、真实停止等结果，要作用到原焦点当时借用的单元，终止从这份旧依据继续快捷外推；后续没有独立确认的新输入回到语义路径。不能只更新概率日志后继续按 expressed/stay 无条件匹配；这也不等于永久删除人物关系或制造用户 stop。
- unknown、缺维度或 JEV 暂时不可用不伪造成用户拒绝，也不补充确认额度；跨过复核跨度后交回语义入口，不能靠原 stay 无限续开。
- quiet 是自身退出，用户 stop 是真实语义边界，继续分别保存。减少快捷资格不改写自身 engage 为 quiet，不把别人交流制造成全群 stop。

按原 admission/binding 和原事件版本关联纠正，不能只看“当前最新 input_ref”。本地评分 Snapshot 记录本次焦点对应单元的快接进度，用于迟到确认只推进当时覆盖的位置，不把新到 C/D 的债务一起清零；这是本地回写依据，不必外发给 JEV。旧 B 的纠正即使晚于未核验的 C，也能否定从同一旧依据外推的关系；但不能越过更新、已确认的新邀请撤销另一段有效关系。新 Main 的晚到 stay 或晚到真实发送不重建已经被语义否定的旧快路。优先复用原单元、报告顺序、观测来源与回执身份，不另建全局协调器。

对尚未接纳的排队机会，在原 promotion/selected 接纳边界重取当前 continuation 资格；语义纠正并不要求正文 revision 必须改变。不得继续执行闭包里的过时快路 binding，也不得通过 direct 的新单元兜底把已否定的快路重新打开。已接纳 Main、真实效果与预算不因纠正倒退。

旧 snapshot 不含新计数时，应按原已确认来源与 admission 恢复事实，不能默认赋予无限或全新满额；不能为推算计数在写事务中扫描历史。此计数是派生参与资格，不是执行授权，实际 @、Work、预算与真实效果仍沿原合同。

### 4.5 输出与缓存

可见发送与内部最终正文继续剥离控制尾段；格式错误不购买修复请求。只接受共同主执行真实回调，子 Agent、用户文本、网页与工具结果不能写主 Yuki 意愿。

提示词只需说明现有 engage 的意愿及作用范围，不添加逐轮输出要求。当前资料不增加 controller 全量状态副本，不回填公共冻结历史、Compact 或 Provider 原已付请求。沿现有 journal 保存真实内部输出和回执，不重排工具合同或历史前缀。

删除 `mood` 时，旧报告的读取在既有升级边界丢弃该无消费字段，保留同份报告的 engage、身份和排序信息；不因旧 mood 使整个快照或原已付链无法恢复。

真实载体分别为 State 的 `self_reports`、`engagement_report`、`host_checkpoint.participation_v1.units[*].hint`，以及 journal 的 `metadata.progress.self_reports`。在各自既有 `SelfReport` 严格验证前只移除退役 mood；不能只迁顶层 State 就宣称所有报告已兼容，也不新增通用递归清洗器。

### 4.6 已确认的发言节奏提示

不设固定字数或后端发送次数上限。在共同固定提示中加入以下文字，保留明确工具发送、实际写入回执通报和任务进展反馈：

> 【发言节奏】
> 日常聊天简短自然，通常用一两句、一条消息表达清楚。确需分条时控制在两三条；没有新的真人接话时，不要连续发送四条或更多消息。多次调用和换行分条都算连续发言。说清楚后留出空间，让别人接话。
> 执行任务时，有进展就及时报告已完成的内容和下一步；遇到阻塞及时说明，需要用户决定时讲清楚问题，完成后交付结果。

同步收拢原“可以按需多次发送”的无约束表述与五六条连续发言示例，不加入“不为单独操作发消息”的负向要求。生产挂载人格资料保留用户现有内容，只备份后定点更新相关节奏文字与示例，不以仓库示例覆盖整个自定义文件。

### 5.1 升级时必须单独核查

独立库 `Record` 使用 `extra=forbid`。直接删 enum、seed 字段或 `source_fingerprints`，会使旧 `participation.sqlite3` 快照在 load 时验证失败。沿现有 State before migration 和观察队列 restore 处理退役派生数据；不 catch 后静默返回新空状态。

旧快照的 seed 可能同时存在于 events、candidates、observations 的 context refs、proposals、pending、source versions 和 observer queue。StoredObservation 的 context 保存 SourceRef，queue checkpoint 保存 ref/kind；完整事件 Snapshot 位于运行请求与 trace。按实际结构处理当前状态，不为此建设递归迁移框架，也不重写历史 trace 或原已付请求。应保留仍在服务真实旧 run、ordinary binding、停止边界或回执的最小来源证明，退出其可评分/可采样部分；新保存状态不再携带可执行种子。

旧 pending 必须先保留原 proposal 身份供 Host 查询实际接纳，再清未接纳派生状态。已接纳旧 proposal 若直接从 State 丢掉，现有 feedback 会走 `proposal_missing → observe_committed_effect`，可能只恢复 effects 而丢失 Work 脉冲、暴露和接收关联；须以原 proposal/run 历史数据或现有最小恢复信息保住反馈，不能把“没有重发”当成完整恢复。

配置 schema 严格拒绝未知字段。同步处理实际挂载的三个退役键，不能只改仓库 example，不能覆盖用户的其他热参数。优先在既有参数读取/保存或部署升级步骤移除明确退役键，不放宽成接受任意未知键；WebUI 磁盘值与实际生效值继续分开报告。

不改写已发布迁移。确需数据库结构变更时新增迁移；若仅快照投影足够，不为删除功能新建表或迁移框架。

测试按消费者拆分：`test_self_seed_rotation` 的分页轮询用例可删除，其正常 Memory 可读证据与 exact-ID 授权用例迁入对应测试；`test_self_automation_delivery` 只替换种子可用性断言，保留 SELF 自动化写入、原执行版本、回执恢复和正常读取的真实验证。
