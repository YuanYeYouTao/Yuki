# 当前聊天媒体与发送合同

这页描述源码中的当前实现。上线状态以实际镜像、数据库迁移和切换记录为准。

## 普通文件与交付快照

普通文件的读写、搜索、目录、移动、删除和局部编辑统一走持久终端，使用正常 Linux
文件语义；不再提供 `workspace_list/read/write/search/patch/mkdir/move/delete`，也不保留
旧 artifact 的公开目录、分页文本读取和删除兼容接口。终端操作不要求工作区版本或 CAS。

工作区只保留 `workspace_inspect` 和 `workspace_publish` 两条桥。前者将选定的真实像素交给
原模型，后者把终端文件制作成不可变 artifact，返回内部 ID 后再由 `send_message` 发送。
终端后来改写或删除原文件，不改变已经发布的快照与投递回执。发布与普通 artifact 读回
没有固定 200 MiB 单文件、512 MiB 总量或 1000 对象配额；真实磁盘和平台传输错误照实返回。
模型看图的字节与帧数预算属于实际输入准备，不等于发布文件的容量。

不可变存储仍保存原来源、内容哈希与引用，供 Social 发送、插件媒体投递、Client 下载和
短状态使用。旧导入迁移仍可列举内部快照；引用回收不依赖已删除的对象配额。普通文件
工具退出不删除历史快照、私有工具结果或原已确认执行回执，旧外置页按原 `result_ref`
读取，不重新读取今天的文件。

## 媒体引用与读取

入站消息在原位置留下 `[图片附件0]`、`[视频附件0]` 或 `[文件附件0：名称]` 等稳定文字标记。编号对应 `chat_events.id + attachment_index`：接入在同一短事务写入真实 segment 位置、canonical Conversation、generation 和媒体元数据。标记只说明附件存在，不表示 Yuki 已看过内容。文本上下文不放 URL、网关文件 ID、Base64 或缓存路径。

原生编辑在同一个原事件更新正文、提及与附件索引。仅 caption 或位置变化时复用同一媒体的原缓存期限；替换媒体后当前索引改指新原件，旧下载不得覆盖新来源。历史附件解析前后核当前来源、路径及内容版本，文档正文不能搭配另一版本的哈希。已经冻结的请求与工具结果保留原件；旧版本缓存沿原文件寿命回收，来源被遗忘或删除时不继续保留。

当前消息入账后，Host 为每个实际图片、视频或文件准备同一份本次原件引用，供媒体预取、Main 附件输入和原生表情收藏共享下载。图片直接共享不可变字节；文件和视频沿本次临时原件按各消费者预算读取。引用只属于这次已接纳消息，不按 URL 跨事件缓存，不进入公共历史或原模型请求。各消费者继续独立处理原授权、预算、类型及失败；Main 不等待缓存发表、永久收藏或索引描述，缓存容量不足也不成为 Main 新门槛。后台发表仍核对原 segments 版本，编辑不能把旧字节接到新附件上；最后一个等待者取消会停止未完成下载，owner 关闭会清理仍存活的临时原件。收藏任务先收拢复制，再释放共享媒体和 Manager。

本次收敛的是同一附件被多个消费者重复下载。不同附件的前台准备与语音转写仍沿原顺序，
按原顺序应用文本、帧数和部分失败结果；没有容量与竞争的等价证据前不扩大并发。
无图片、视频或文件的输入直接沿用原消息，不编码媒体来源或创建共享原件。

Bot 在消息入账后异步预取原件，不调用视觉模型。缓存目录为 `data/conversation-media-cache/v1/<conversation-id>/<event-id>/<index>-<sha256>.<verified-ext>`，容器内目录由 Compose 持久挂载。成功缓存后固定保留 24 小时，访问不续期；启动、每分钟及读取时核验到期。忘记用户导致来源事件删除时，索引随事件删除，清理器移除失去来源的缓存文件。单文件上限 200 MiB，单会话接纳预算 512 MiB，全局 4 GiB；空间不足会拒绝新缓存，不提前清除尚未到期的文件。失效的网关 URL 或不支持的类型会返回明确类别，不从网关容器本地路径读文件。

清理每轮最多只读发现 128 条过期元数据，短 writer 重新核验状态、期限、generation 和已发布
文件名后标为 expired。文件 GC 在线程中按固定目录层级流式推进，每页最多 128 项、路径容量
64 KiB，并在文件系统调用之间检查 100 ms 时间预算；不读取媒体正文或一次加载全部缓存路径。
已经开始的单个系统调用仍受操作系统 I/O 时延限制。扫描位置只保存在进程内，重启重新扫描；
积压通过后续轮次清理，不因此重新开放已过期或忘记来源的附件。
每页只查询候选内部事件及文件名的引用。GC 与最终发布共用锁，并在删除前复核 lstat 的文件
身份、类型、大小和修改时间；未过期引用、刚替换的文件和其他来源仍保留。取消等待中的 GC
先结束当前线程页，再释放锁，不能让后台 unlink 与新发布竞争。清理不改变接纳容量和授权规则。

主 Agent 的 `query_chat_history` 按 recent/search/around 返回真实内部事件 ID，并受当前 generation floor 约束。插件在当前会话的历史搜索也遵守同一 floor。模型可按语义、发送者和消息顺序选择候选，再调用 `inspect_conversation_attachment`。执行处从本轮运行时取得当前 canonical Conversation；入站消息使用已接纳的会话 ID，不依赖主动轮专用字段。随后核验事件为该会话的入站 keeper、generation 未变化且文件未过期；模型不能提供路径、平台消息 ID 或别的会话 ID 代替来源。图片和视频帧进入原主 Agent 的原生图片输入；文档仍由本地有界 reader 解析。历史工具不调用独立 Qwen，也不扣辅助模型请求；结果标明真实来源、hash 和处理模式。

附件工具命中缓存时直接读取原件；未缓存的原生文件按原事件的 `ingress_presence_id` 取得原接收连接，由 Provider 的 `media(handle)` 下载。当前工具所在账号不能替代原接收账号；公共 URL、内联资料和已有缓存不要求原连接在线。

## 已观察媒体与历史

合并转发在外层原事件保留标记、原 segments 和内部事件 ID。默认模型不再请求远端
转发节点；公共历史只读已入账事件，明确 observed 覆盖。原已付请求与历史工具结果
不追溯改写，退役能力不据此重新派发。

入场不展开 forward，不预处理内层媒体、人物、记忆或引用；纯 forward 在媒体 queue/
limiter 前返回空 NativeInput。混合消息与明确引用只处理实际外层 IMAGE/VIDEO/FILE，
保持 current→reply 顺序。原 native file locator 只由其平台适配器使用。

共同媒体链消费 PlatformMediaGateway 返回的真实字节/类型。QQ get_image/get_record
和 SILK、Telegram getFile 下载及凭据都留在适配器；共用缓存、ASR、文档/视频和
主模型输入，不伪造 OneBot 调用，也不把平台 file_id 跨端当文件。

## Agent 选取媒体与主链输入

当前、明确引用、历史附件与工作区看图复用 `NativeMediaPreparer`、已有图片解码器和视频采帧器。
裸图片字节由同一解码器计算原件哈希，包装层不再预先重复扫描；下载器提供的期望哈希仍核验，
不改变像素、来源、帧次序或预算。
GIF 按真实字节识别，包含 Telegram animation 的缺 MIME 或误扩展名情况，保留有界代表帧；视频保留实际采帧秒数；视频不声称分析音轨。历史视频使用本轮运行时
时长、间隔与帧数预算。图片原件读取最多 20 MiB，prepared 图片仍受配置的字节预算；缓存
可以接纳 200 MiB 原件不代表一次看图可以读取同样多的内存。解码、文件读取和采帧不进入
SQLite writer。没有 `image_input` 时如实报告未读，不暗中调用 Qwen 或换模型。

`workspace_inspect` 接受 `path` 或 `artifact_id` 二选一和 `question`；path 可带已选定文件的
`expected_version`，不要求先调用已退役的文件读取工具。Manager 通过现有工作区目录 FD 核验路径、软链接/硬链接和真实内容版本，
返回冻结字节；这次读取不发布 artifact，也不修改文件。已发布 artifact 必须不可变。
工作区视频因控制通道的读取预算同样限制为 20 MiB；超限明确拒绝。Agent 可自行先用终端
生成较小文件/代表帧，再选择它查看，Host 不为其自动扫描全部工作文件或图片。

私有 `PreparedMediaData` / `ToolExecutionResult.images` 将像素与小型 JSON 回执分开。Runner
先按原工具调用顺序配对本批全部文字回执，再追加含原 call_id 的 Host 媒体观察，交给原固定
主模型继续。承载图片的 `user` 是协议角色，不新增真人消息、账本事件或用户授权。工具
缓存、同批别名和恢复携带原不可变媒体；公开文字回执、普通历史和展示不包含 Base64。

派发前在模型名额取得后再次核验历史来源的 keeper/inbound、Conversation、generation、floor、
TTL 与 hash；工作区路径重新核验版本，artifact 核验仍存在、未过期且不可变。不同来源的相同
hash 不共享授权。Work journal 保存选中图片、原 call_id 与顺序，工具回执已落地而 paired
检查点未落地时按原回执恢复图片，不重新下载、搜索或执行已确认效果。普通下一轮不自动
带入旧图，私有检查点只用于原执行恢复。

获准工具图片 使用同一纯准备器进入原生输入，工具图片归入原
读取授权的私有 artifact。`read_tool_artifact(operation="image")` 返回像素；text/get/search
仅返回图片 manifest。来源权限、owner、generation、有效期和字节完整性在读取前后及派发前
复核，不把任意 URL 当成可读取文件。插件自己拥有的媒体 handle 不因此开放跨插件读取；
SDK `vision.analyze_current_media` 是另一个明确授予 `VISION_ANALYZE` 的辅助合同。插件工具
本次显式返回 `PluginResult/ToolResult.media_artifacts` 才接入主模型；普通插件媒体句柄不自动附图。Host 保留实际插件、manifest revision、原工具与 TTL/hash，
派发前重验当前批准、精确委托及原文件；归档副本不延长授权。该桥接已完成本地定向测试，
真实 API 与生产验收另记。

Bot 与 sandbox Manager 的媒体读取实现须配套更新。来源、文件版本、GIF、采帧与
原生请求配对可离线核验；实际 Provider 图片能力、端到端速度和 QQ 自然流量分别验收。

`save_conversation_attachment_to_workspace` 先执行相同的临时读取授权，再显式复制到全局持久工作区。临时副本仍按原时间过期；已提升的工作文件可由其他会话的共享终端处理。提升按原 request 和快照回执处理，不受已删除的工作区单文件配额阻挡；真实磁盘或导入失败不能声称文件已共享。独立插件计算会话没有主聊天临时媒体的读取权。

## 入站语音

ASR 沿配置的下载大小、单段时长、队列并发及整个入站准备截止时间处理音频。
按真实附件顺序转写当前和引用语音，不固定只取三段，也不把已识别的长文字报告为无语音。
Provider 响应继续受实际读取字节预算和完整性检查约束；保存及读取原转写保留全部文字和来源。
部分失败保留已完成转写并报告真实错误，空转写仍为 no_speech。

## 共享表情目录与后台配图

平台明确标记的表情从本次共享原件直接收藏到持久环境的 `/workspace/stickers/<platform>/files/`，不再次下载；QQ 只有编号的内置 face 保留文字语义。原生贴纸标记和实际 MIME/动画格式分开保存，Telegram WEBP/TGS/WEBM 原件不以静态图片解码成功作为收藏条件。普通图片可通过现有保存桥显式放入对应平台目录，原目的路径不被静默改写。平台目录是编目用途，原事件/人物来源独立保留，不按账号或群再拆库。旧 collector、worker、候选池、采用/作用域、容量替换、冷却、拼图和专属插件 facade 已退役。

原图与 `stickers/<platform>/index/<asset-id>.json` 是唯一图库资料源，短 tags 与长 description/OCR 分开。Main 与 Qwen 自由编辑相同文件；Yuki 主业务库不保存资产、标签、来源或倒排资料。每平台 `search.sqlite3` 是可删除重建的派生缓存。独立 helper 在原持久环境运行，Main 可直接 update/rebuild/search；Manager 调同一实现，Host 不直接连接用户可编辑路径的 SQLite。任意终端编辑后新标签在 update/rebuild 完成后可搜；命中项重读当前 JSON 和原件，不全库扫描、不从缓存回写旧资料。冷构建不冒充无候选，也不阻塞正文。

首次完整 JSON 原子创建的赢家可沿现有明确 Vision 配置后台补一次描述；没有配置、解码失败、请求失败或关闭不阻止收藏，不隐式重试 HTTP。合法大尺寸原件保存和最小编目不依赖像素解码成功。普通文件保存没有图库后置 hook，Main 自行用终端编目。共享复制前只读核原事件/附件/segments，接纳后普通完成或遗忘不回滚共享原件；不另建来源表或接纳状态。私人附件授权继续认原事件，相同 hash 不开放原私人资料。

`send_message.emoji` 表示可选配图意图。图文先完成原正文发送，再持久接纳配图输入并返回；选图、publish 和图片发送由后台完成，Main 不等待。纯配图返回接纳事实，不能冒充已投递。图片沿原 Social 服务使用独立稳定派生键与不可变 artifact，发送结果只认原 Social 回执，不追加进已开始的正文分段计划。普通 Main/Work 完成不撤销已接纳配图，真实取消、换代和撤权在原 claim 边界处理；已 claim 中断保留未知，不自动重发。公共图片记录仅有表情标记和短 tags，长描述不进入公共历史或自动摘要。恢复与 Work 效果查询复用原 Social 实际分步回执，父 PREPARED 不否认已成功子项；已派发或未知不因图库或 Manager 失效而重发。纯图提及/引用交给原图片计划，有正文时仅正文提醒一次。

明确指定的 artifact 图片和普通文件保持原同步发送语义。QQ 小表情沿 OneBot 原生 `image.data.sub_type=1`，普通图片不附此字段。Telegram 原生贴纸使用 `sendSticker`，GIF 配图使用动画发送，明确的 GIF 文件仍使用 `sendDocument`；无原生跨端转换的格式按实际传输结果报告，不伪造静态替代图。

收到普通文件或图片只做本地媒体准备，不隐式调用独立视觉模型。WebM 与 MP4 沿共用视频采帧器产生真实帧。TGS 原件继续保存和原生发送；Main 只读取平台实际提供并随原附件保存的缩略图，明确标注静态预览，不把动画 JSON 冒充图片。缺少预览时保留原生 emoji 与格式资料，不能宣称已看过像素；后续读取仍沿原内部事件、附件索引、来源版本和期限。

旧 Telegram 事件即使保存为 IMAGE、文件名为 sticker 且没有 MIME，当前、引用、缓存、历史与 Workspace 仍按原件字节识别 TGS/WebM。读取修正不改写原事件 segments、冻结正文或已付请求；TGS 无真实预览时只提供元信息，WebM 使用共用实际采帧器。

## 定时发送

普通图片仅在传输派发时构造 OneBot 媒体段；公开聊天账本与日志不保存 Base64 或本地路径。
私有恢复媒体按原 Work 的配额、引用和备份合同保存，不据此取得再次发送资格。
Genie 出站 record 构造已退出；历史 record、真实转写和已接受回执继续按原来源读取。

PR #139 已将新建静态提醒编译为 `social.send_message`，SELF 和用户使用 canonical Social 路由与持久回执。`delivery=none` 不发消息。自动化 DSL 不再注册旧 OneBot 私聊/群聊、语音、表情直接发送和通用 OneBot 调用；模型需要表情时使用主 Agent 的 `send_message` 结构化参数；语音合成与出站录音已退役，入站 ASR 和历史 record 继续读取。历史终态脚本和回执只读保留；迁移 `0072` 在存在启用或暂停的旧发送脚本时拒绝升级，需先人工核验，不猜测或重发外部效果。自动化主 Agent 的 OneBot 辅助网关禁止直接 `send_*` 和 `upload_*`。插件通知仍走插件自身的持久 outbox 和授权传输，属于独立的通知合同。
