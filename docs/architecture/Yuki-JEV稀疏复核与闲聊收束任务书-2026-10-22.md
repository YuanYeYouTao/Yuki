# JEV 稀疏复核与闲聊收束任务书

日期：2026-10-22。

状态：**实施与本地定向验证完成，按授权交付 PR。** 实施、验证、提交、PR、合并和上线分别记录；本轮不合并、不部署，线上配置未改。

## 1. 用户目标与设计边界

**保留自动续聊快路，减少 JEV 实际调用；JEV 负责唤起和旁路语义刹车，本体 `engage=quiet` 是另一条独立刹车。** 日常聊天少接、少补、说到点上就停，执行任务的能力与进度反馈保留。

此前讨论中“删除同人自动续聊，让新的普通输入重新等待 JEV”的建议撤回，不作为实施方向。“把 JEV 放后台”也不足以完成本任务：必须减少实际付费判断，不能只消除主模型的等待。

约束：

- 阅读并遵守[共同开发约束](development-contract.md)、[语义参与宿主](semantic-participation.md)、[自主参与模型](autonomous-participation-model.md)、[主 Agent](main-agent-runtime.md)、[工具合同](tool-kernel.md)与[会话 Compact](conversation-compact.md)。删除重复待办和门槛优先，不另建分类器、发言分数、审批或状态机。
- 明确 @、回复、命令、私聊等现行直接入口，以及原 Work/wait 的获准补充，继续按原入口及时处理。普通群聊和任务补充不能混成一条限速链。
- `send` 继续走统一出口，不增加待发送审核、pending veto、发送次数上限、撤回或冷却。JEV 不是每条消息或每次发送的批准人。
- 不取消已付模型请求，不重购“确认闭嘴”的请求，不撤销已接纳输入、已执行工具或已确认发送。闲聊收束不取消任务、终端或子 Agent。
- 不设硬字数、固定消息条数或“没有明确拒绝就一直说”的规则。保留换行分条和任务所需的完整说明。
- 人物、事件、讨论、权限与回执沿现行内部身份；不按昵称、外部账号或最大事件号重建归属。
- 本轮不修改公开信息搜索要求，不改 SELF 自主率公式，不把普通闲聊重新登记成 SELF Work。

## 3. 目标流程

### 3.1 唤起、续聊、收起

1. 输入照常入账，先给现行明确入口和原 Work/wait 处理；JEV 不阻塞它们。
2. 当前确实在与此人、此讨论交流，关系未被纠偏收起，本体也未 quiet：普通消息走原自动续聊和防抖，不逐条取得新的 JEV 许可。
3. 后台只保留仍有价值的待复核现场；适合合并的续聊输入合并后，JEV 判断当前交流关系和回应机会。结果返回即更新相关关系，不再多等一次防抖才应用。
4. JEV 发现话头转给别人、讨论结束或实际停止要求，收起对应自动续聊；本体主动 quiet 也能独立收起。
5. 收起之后回到观察。真实的新问题或邀请仍可重新唤起；不要求本体先自行解除 quiet，才允许真人叫它。

JEV 的纠偏是语义事实，本体 quiet 是自身意愿，二者各认来源。JEV 不代写 Main 的 `engage=quiet`，Main 的 stay 和实际发送也不能抹掉更新的语义纠偏。quiet 只作用于相关讨论/对象，不广播成全群、全平台或任务总开关。

### 3.2 普通防抖复用现状

沿现有 Conversation worker 的可热配静默窗口合并连续输入。窗口内 A、B、C 先后到来，最后 C 触发一次机会，Main 结合 A、B、C 的真实历史整体理解，按当前值得回应的内容答复，不按每条输入机械逐条回应。

不新增“批量请求”协议、另一条 steer、批次数据库、待发送缓存或最大事件号消费逻辑。现有防抖可通过已有热配置调整；不为放大窗口另设消息数量门槛。窗口变大只合并尚未开始的普通机会，不延后任务补充或明确 @。

本轮不重写无 Work Main 的观察/接纳机制：已经实际选入请求的新普通输入，继续沿原 admission 防止排队再次激活；只有看到历史不等于取得输入所有权。不能仅删掉 admission，却仍把同一消息交给原 Main 和后续队列。

### 3.3 开放群入口单独核对

实施必须同时覆盖 `group_open` 与 `continuation`。开放群资格不等于真人直接点名，不能把旧关系被收起后同一讨论的输入换个 reason，再无条件启动一次 Main。

语义开启时，所有非显式群消息复用现有隐式资格解析：已有有效续聊走快路，真实新语义邀请走唤起，暂无机会的输入留在原稀疏观察队列。开放群不再以 `group_open` 绕过这份资格直接开 Main；`require_mention=false` 表示允许未 @ 的交流进入观察，不把每条消息等同直接点名。这是本轮明确的开放群语义调整，实施时同步修改对应说明。

没有相关单元不能伪造 quiet 或把某个人的退出扩大到全群。关闭语义参与时保持现行产品开关与 `group_open` 行为，不暗中开启 JEV 或自动切换 owner。不另加一个 quiet 永久拒绝分支，真实新邀请仍可重新唤起。

验证必须分别报告开放群与需提及群的调用量和新激活数。不能为了实现收束，把所有开放群消息改成每条先评分，或用语义模块关闭后的路径绕过已生效的语义模式。

## 4. 删除逐条补评，保留稀疏复核

### 4.1 合并对象与最小数据

只对**已存在、唯一匹配的真实参与单元中的普通续聊复核**合并未派发待办。可合并依据是原 `continuation` admission 与 UnitBinding；尚未正式接纳时，只采用现行隐式资格解析已经明确返回的 continuation 及其唯一绑定。唯一性认 `ParticipationView.matched_unit` 或实际续聊 UnitBinding，不认原 ScopedEvent 的 `unit_ambiguous=false` 或 unit_options 的数量：原候选较多时，既有参与关系仍可能唯一匹配。复用原 Conversation/generation、讨论、内部人物及 UnitBinding，不另做一次语义分类，也不新增永久人物桶。

- 同一单元尚未发出的多个普通续聊焦点，只保留最新的待复核焦点。最早待评时刻沿该合并待办保留，防止连续发言不断推迟已有最长等待。
- 同一单元已有 JEV 请求在途时，原 Snapshot 不变；后到输入合并成下一份待办。请求返回后不逐条补跑所有中间消息。
- 已知独立唤起来源、现行解析仍无法唯一匹配的讨论/对象与 Host 优先观察焦点，不以“作者一样”直接合并。不能在尚未评分时预知所有潜在新邀请；这里保留的是原结构已经能区分的来源。尤其不能按昵称、当前账号或全群最后一条消息覆盖另一个人的独立来源。
- 被替换的只是尚未付费的评分待办。旧事件仍在账本与当前合法上下文中，不标记成 observed、已消费、已确认或已接纳。
- 无新真人材料时不周期评分；本体发送、stay、quiet、工具结果、读诊断或保存快照都不单独制造 JEV 焦点。
- 本体已有较新 quiet，且按原 admission、实际观察范围与 source 次序足以证明其覆盖该段已处理续聊时，清掉仅为该段快路复核保留的未派发旧待办。不能只删 quiet 的额外申请入口，却留下稍后仍会付费的旧复核；也不能按 quiet 清空整个单元、取消在途请求或删除其后的新唤起来源。
- 失败退避保原事实与当前有价值的待办，不复活已经被更新材料替换的逐条补评队列。旧请求失败后不能覆盖新焦点。

不把每个人的消息统统合成全群最后一条。当前纠偏关联原讨论与人物，单个焦点也不自动审过全群所有参与关系。

### 4.2 取消活跃加密，统一复核节奏

合并待办主要消除停聊后的逐条补评；若持续高流量时仍每 8 秒调用，新旧调用数可能一样。因此本轮同时删除“活跃时使用更密的 2/8/15 秒档”，首轮统一复用现有较稀疏的 **3 秒去抖、12 秒最短调用间隔、20 秒最长去抖等待**。这是一套已有调度参数，不是发送冷却或接纳门槛；Main 自动续聊与任务补充不等待它。

这三个数分别管合并突发、限制实际请求频率、防止持续输入使待办永远等不齐；最长去抖等待不覆盖 JEV 在途耗时、失败退避或其他单元排队，不能称为端到端刹车时限。新待办替换不重置最早待评时刻，保同 Conversation 单请求在途和原调度所有权。

新队列尚无调用记录时，保持现行 `last_call=-inf` 语义，首次观察不额外预等一整个调用间隔。从 quiet 后再次出现邀请仍沿原 scope 的 last_call，不重置间隔或每次免间隔；没有新材料就没有周期请求。之后按相同时间线核对实际成本与纠偏延迟，再决定是否调整现有参数。不新增“几条消息一次”与时间、风险急评、独立冷却并行的多套触发器，不把 12 秒冻结成不可变业务条件。

### 4.3 复核跨度清退

删除 `continuation_review_span` 作为新普通激活的同步等待条件，删除仅为该门槛存在的 `check_budget` 分叉、配置说明、管理项和旧断言。不要把 4 改成 2、另加配额或改名保留同一限制。

逐项核对 `unconfirmed_inputs`、fast sequence、review coverage 的实际消费者：只服务额度计算的状态整链删除；迟到语义纠偏仍需的原输入、单元和顺序事实继续复用。不能为了删计数而抹掉较新邀请与较旧纠偏的真实先后。

主模型未填 engage、JEV 返回 unknown 或观察失败，都不等于真人结束、确认继续或授权变化。保留当前 `_record_unit_reviews` 跳过未知 verdict 的语义：未知不抹掉原有正向或负向依据；没有已有关系时，也不能凭 unknown 新建续聊资格。真实否定、来源失效和自身 quiet 各自保有收起效果，不因此无限购买补确认。

删除持久计数字段时必须同步提供一次性 checkpoint 升级：当前严格 Record 校验会拒绝多余字段，不能删模型字段后让旧参与 checkpoint 整份校验失败、退成空对象。仅转换已经删除的辅助字段与队列结构，保留原 UnitBinding、自身 hint、实际 review、来源和顺序；旧本地 Snapshot 中废弃的配额元字段可由升级 reader 清退，不改变原已付 HTTP 正文、来源、签名、实际观察和执行回执，不宣称本地旧快照序列化字节完全相同。旧参数资料清退废键，不因一个已废键拒绝整份有效配置；不长期维护双套运行合同，也不清空整个 Controller 冒充升级。

### 4.4 真实取舍

减少判断会降低语义采样密度，不能同时保证每次瞬时转折都被立即识别。本体在已合法看到的新输入中自行 quiet，和 JEV 稀疏复核共同改善收束；这不是零延迟禁言器。

较早普通消息可能包含“别说了”，后面又有一句确认。若它未单独评分，最新焦点必须结合可用上下文解释**当前**关系；不能把上下文中的停止要求伪记成最新作者刚刚提出的要求。必须回放“停止→确认”“他人插话”“停止→重新邀请”，如实报告漏判和延迟。

不为追求零漏判增加关键词停止名单、第二个分类器、逐条追评或发送审核。也不声称每类群、每种邀请的调用量都按相同比例下降。

## 5. 两条刹车如何反馈给运行 Main

当前文档限定 `<runtime_context>` 只承载 Work 状态，并说明参与内部状态不默认注入。实施时须同步修订[主 Agent 合同](main-agent-runtime.md)，不能暗中把整个 Controller 塞进去。

- 由原参与服务提供当前请求相关讨论的最小视图：自身参与意愿、已有语义判断及其真实作用范围、来源与顺序。相关范围从当前激活的原 ordinary admission 或原 Work 场景绑定定位，不取全群最后一份 JEV，不向其他来源广播同 activation 的状态。读取既有 UnitSemanticReview 与 SelfReport，不另存第三份“刹车状态”，不复制全部概率、队列、人物列表或历史正文。
- 复用当前激活/Work 已有的有序运行资料尾部，在**原本就要发起**的下一次正常 Main 请求前读取最新值。既覆盖 Work，也覆盖无 Work 的 Main；不只接到其中一个 begin 分支。
- 资料作为程序运行事实提供，不装成人类发言或新的任务输入，不送入会强迫 `settle_final` 继续的业务 mailbox。没有下一次正常请求时，不单独唤醒 Main 确认 quiet。
- 新反馈不改写初始运行块、公共 FrozenFragments、旧历史、已付 Snapshot、签名或工具配对，也不插回已经增长的私有轨迹前面。
- 原生 pause、opaque 或其他精确已付续接在协议禁止插入输入时，沿原恢复路径处理，不为反馈强改该请求；待下一个合法业务请求边界再接入。
- 只对有相关事实的请求提供，不逐 tick 注入时间戳心跳，不为去重另存永久“最后展示值”。实际新输入和事实更新沿现有合法请求边界接续。
- 后端即时收起**尚未选择**的普通机会和新激活；已选择/接纳输入保原合同。模型根据新资料决定不继续闲聊，但发送与工作能力不增加 veto。

这里的反馈是让本体知道交流已经转向或自己已经说够；它不保证中断当前在途响应，也不代替模型自己按上下文判断。

删改“对方已经 ok/嗯嗯 之后继续叮嘱、追问好吗”“为什么不回我”等默认示例倾向。不是全删语气示例，也不教成每条输入必须一对一答复。替换片段：

```text
{{name}}：找到原因了，请求参数和接口不匹配，我继续修
```

例子只示范语气，不伪造真实执行证据；不附“保持沉默”等可能被念出的舞台说明，不复制真实群聊。真实对话研究只作小样本参考，Person 类型不自动代表真人，其他 Bot 的长回复不能当成人类说话习惯。

### 6.2 系统约束的发言与参与状态

删除“通常一两条”“不连续四条以上”等数字要求及重复的多发鼓励，保留自然换行。发言段拟用：

> 日常聊天用自然短句，围绕当下值得回应的内容说清这一层就停，留出空间让别人接话。话题已经说清、对方只是确认，或话头转给别人时，可以听着；有新的问题或值得回应的内容再接。需要分条时按内容用换行自然拆分，普通回复不额外加自己的姓名前缀。正式任务按内容需要展开，把所需事实、步骤和结果交代清楚。

参与状态段拟用：

> 可在内部最终正文末尾附 `<yuki-state>{"engage":"quiet"}</yuki-state>`。join 表示想加入，stay 表示愿意继续，quiet 表示当前话题先听着。有意愿变化时填写即可，不必逐轮重复。quiet 只收起闲聊续接，不停止已有工作，也不拒绝之后的新问题；状态不发到聊天里。

必须保留：

> 用户委托的交互式任务有实质进展、阻塞或需要决定时，必须简短报告并继续处理，完成后交付结果。

`reporting=quiet` 仍是工作汇报约定，`engage=quiet` 是讨论参与意愿，不能合并。公开信息搜索段保持原内容。

### 6.3 Work 与 send 说明删冗

- “保持原任务，按内容补充或回答”改为“结合原目标吸收补充并继续处理，按实际需要答复或更新进展”。
- “有新的输入到达，请先处理再继续。”改为“收到新的输入，请结合原目标处理后继续。”真实输入仍需处理，不删除原 mailbox 接纳。
- 后续讨论中用户尚未决定是否调整 send，故本轮保留 send 的描述、schema 和执行模式，不实施原拟议的说明删改。多次发送、只发表情和发送后继续工作均保持。

### 6.4 JEV 缩短、纠正语义并统一名称

保留现行 interaction / information / floor / boundary，以及有真实候选时的 unit_selection。不新增“刷屏分数”或另一个审核模型。

共用说明拟压缩为：

> 你是交流观察者。结合原位提及、引用和上下文，判断焦点与 {{name}} 的关系。target 是宿主提供的讨论对象，不一定是被叫到的人；engage 是 {{name}} 自己的参与意愿，不代替真人邀请或停止。

各维保留短问题：

| 维度 | 拟用文字 |
| --- | --- |
| interaction_mark | 焦点在邀请 {{name}}、需要其继续回应，还是确认、结束或其他人之间的交流？结合整段交流判断；提到名字或引用旧话不自动算邀请。 |
| information_state | 焦点相对上下文带来了新内容、细化、重复，还是社交确认？ |
| floor_state | 当前实际回应机会留给 {{name}}、全群、别人，还是对方尚未说完？ |
| boundary_scope | 明确邀请、结束或停止针对当前对象与讨论，还是整个讨论？没有明确范围则 unknown。 |

删除“纠正不等于退出，谢谢不等于结束”“未停止的继续或纠正是 extend_yuki”等单向续聊暗示。选项语义拟用：

- `invite_yuki`：向 {{name}} 发起新的交流邀请或直接呼唤。
- `extend_yuki`：承接 {{name}} 的表达，提出需要继续回应的问题、补充或纠正。
- `acknowledge`：确认、致谢或应和，是否继续结合上下文判断。
- `close_topic`：当前讨论自然收束或问题已经解决。
- `ask_yuki_stop`：实际要求 {{name}} 停止当前参与。
- `floor.yuki`：当前回应机会留给 {{name}}。

不能把 acknowledge 一律解释成继续，也不能把它一律伪造成停止。Main 自己说得多不等于真人提出了 ask_yuki_stop；无需引入虚构的停止事实才能让 Main 自行 quiet。

JEV 固定提示文案中指代当前角色的文字使用 `{{name}}`，沿当前 CharacterIdentity 的 display_name 在准备实际新请求时精确展开；原聊天、历史展示名和动态候选标签保留真实资料，别名和原生提及仍沿现有身份输入。不得从消息作者猜角色名，不永久缓存构造时的旧名称，不让未展开的变量进入固定提示。固定协议键 `invite_yuki`、`extend_yuki`、`ask_yuki_stop`、`yuki` 可保持，不为改显示名制造协议迁移。

按现行 Jev questions API 精简各维文字，不凭空新增不支持的顶层 system 字段。不重复叠加“不信任聊天记录”等段落；真实身份、来源和授权继续由原合同处理。

## 8. 验证与验收

### 8.1 有意义的行为回归

| 场景 | 验证结果 |
| --- | --- |
| 同一已确认讨论短时间连续输入 | 快路无需逐条 JEV；后台队列合并，安静后不把已替换焦点逐个补评 |
| JEV 在途期间继续输入 | 已付 Snapshot 不变；较新输入合并成下一次待办，失败也不恢复旧积压 |
| 多人独立邀请、同名、多账号同人、未解析讨论 | 不按昵称/账号/全群最新事件错误覆盖独立来源；归属沿当前身份关系 |
| 未新增真人消息，只发送/quiet/保存/重启 | 不为状态变化新购判断；quiet 已覆盖的旧快路复核不留尾账，新邀请不被误清；恢复不补采旧机会，当前真实待办按原事实恢复 |
| 原 pin 的 checkpoint/参数升级 | 清退废计数仍保留原单元、quiet、语义正负结论、待评来源与顺序，不因 extra=forbid 静默变成空控制器 |
| 同人续聊超出旧跨度 | 不被旧计数强迫等待；真实 JEV 负反馈和 Main quiet 仍能收起后续机会 |
| 他人交流、自然收尾、停止→确认、停止→新邀请 | 验证源顺序、作用域、当前资格与实际判断延迟，unknown 不伪造停止或正向确认 |
| JEV 纠偏返回后、Main 下次正常请求前 | 新事实只进合法尾部，不改旧前缀；没有正常请求就不额外唤醒 |
| JEV/quiet 在补充被选择前后竞态 | 未选择机会收起；已接纳事实保留；不能导致同一输入 steer 和排队重复激活 |
| 明确 @、回复、命令、私聊、真实任务补充 | 原快捷接纳、原 Work、发送和任务进展报告保持；长任务/子 Agent 不被闲聊刹车取消 |

删除冻结旧门槛、逐条补评或固定提示文案的测试，改测上述真实行为。不用精确字数、固定全局调用次数、文件拆分或私有函数布局当正确性标准。定向测试过后不重复无关全量检查；CI 仅更新实际受影响范围。

### 8.2 成本、时延与复杂度

先用同一份匿名事件/时间轨迹，在原 pin 与新版本回放。JEV 的调度调用数、重试数、主模型请求数、普通激活数和实际发送条数分别计量；不能拿队列项减少冒充真实调用减少，也不能拿短句比例代替少接话。

至少给出突发聊天后停下、持续高流量续聊、零星消息、多人独立邀请、开放群、非活跃唤起和 JEV 故障的分组结果。突发后的补评及持续续聊的**实际观察调用数应下降**；已知独立来源不能因合并被静默丢弃，潜在邀请的语义漏判另行报告。开放群如有成本迁移单独说明，不用其他场景的下降掩盖增长。相同输入和模拟时钟可有确定调用数断言，但不把经验调用频次固化成产品门槛。

分别回放原版、只合并队列、合并队列并统一较稀疏档，区分删积压和降低采样频率各自省了多少调用。不得以降低采样频率却不报告刹车延迟，宣称“更快且更省”。后台纠偏就绪到状态应用不人为新增等待；真实端到端刹车仍包括采样等待、JEV 请求和下一正常 Main 边界。

队列 offer/替换应按既有单元索引做平均 O(1) 工作；若 take 仍扫描当前有界待办，记为 O(P)，不宣称整条请求 O(1)。上下文准备沿已有当前窗口，按当前所需事件数计量，不扫描永久聊天账本、不新增每消息全表查询。人物解析复用现行批读；准备/模型/文件 I/O 不进入 SQLite writer。

检查新增反馈读取的 SQL 数、锁内工作和前台等待；不得靠增加一个同步 Controller 保存或 JEV 等待才能发送。缓存核对实际请求前缀与上游 usage；缺缓存字段保持未知，不预报命中率提升。

### 8.3 审查顺序与交付

实施前审任务书三条主线：实际调用能否减少、双路刹车是否有真实消费者、任务/发送是否保持自由。实施后分别复审队列恢复与时序、所有接纳入口、提示词与名称、SQL/缓存/测试旧断言；发现缺口后修复再审，不把审查次数当验收结果。

实现 PR 应列清删除内容、受影响合同、前后实测与剩余限制；PR、CI、合并、部署及自然群聊效果分别报告。后续实施授权只到提 PR，不包含合并、部署或真实群发测试。
