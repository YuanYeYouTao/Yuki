## 1. 目标与范围

1. 降低无来源 SELF 自主机会在短时间内反复启动 Work／调用主 Agent 的频率；已公开发言而没有被接住时进一步降低后续自主唤醒频率。活跃群冷场后仍可能偶发自主苏醒，长期沉寂的群则随真人活动证据消退。
2. 区分“提出自主机会”“实际启动 Work／调用主 Agent”“Work 内是否公开发言”和“实际发出了几条消息”。频率模型控制的是未来的自主 Work／调用次数，**不限制单次 Work 的消息条数、工具调用次数或表达长度**。一次 proposal 不是调用事实，模型 `NO_REPLY` 不是群友冷落。
3. 复用现有 Jev 概率分布、SELF `engage`、真人活动、群情境、计算和实际发送回执。新增状态必须有独立语义，避免把同一次 Work 的多条消息重复算作多次自主行动。
4. 修复 SELF 静态自动化创建时旧 OneBot 投递 capability 的权限冲突；单独定位自动化 ID 94 的 `KeyError`、`delivery=none` 矛盾及 blocked 后恢复反馈。
5. 不改变明确邀请／直接续答的语义观察路径，不把直呼名字等同 `@`，不让自主社交降频阻断真人的明确请求。定时自动化按其确定日程执行，不进入自主随机机会模型。

本稿覆盖 Yuki Host 和 `Yuki-Semantic-Participation` 两个仓库。实施在本次新工作树中进行；开发阶段不调整线上开关、任务或群消息。

实施时已创建两个仓库的新工作树。SELF 自动化的静态投递与 ID 94 代码修复另见已合并的 [Host PR #139](https://github.com/YuanYeYouTao/Yuki/pull/139)；本次数学模型工作不重复修改该 PR 的自动化代码。线上 ID 94 状态与部署事实仍须单独核验。

## 2. 已核实的基线与缺口

2026-09-24 线上只读样本，在 13:24 前后各约 3 小时 44 分钟：两群无来源机会 `20 → 45`，实际发言的机会 `3 → 42`，对应 Work 的 `sent_messages` 总量 `12 → 114`；真人入站 `106 → 192`。活动量也变了，不能把全部差异归因于提示词。上线后自主机会最短约 6 分钟再次发言，单次 Work 常记录 2–4 条发送。**需要降低的是自主 Work／调用密度，不是每个 Work 的消息条数。**样本须在开发时用内部 run、Work 和事件 ID 重取并冻结为**聚合统计**，不把真实群正文塞入公开 fixture。

变更前控制器的 `p` 和 `N_Y/N_H` 主要按约 150/120 秒衰减；`n` 只由 SELF 自己的 `NO_REPLY` 增加。没有“已发出但无人回应”的持续状态。无来源公式中的群情境 `ℓ` 终会趋零，而净值趋负，因此长期沉寂最终不再产生无来源公开机会。SELF 的 `engage` 映射为 `join/stay/quiet → +0.7/0/-0.7`，约 1800 秒回中性；自由文本 `mood` 被保存，却不进入公式。此基线对应独立库 `a55b8e5` 的 `dynamics.py`、`controller.py`、`self_report.py`；新算法见[当前模型](autonomous-participation-model.md)。

Jev 现有的 `interaction_mark`、`information_state`、`floor_state`、`boundary_scope` 和 `seed_fit` 是带概率的**真人焦点观测**。现行控制器已在回忆／联系尝试中使用真实 Yuki 发言锚点识别后续回应；无来源自主发言尚未得到同等的接收反馈。无来源 proposal 不得伪造一条 Jev 输入。

自动化方面，Agent 步骤已要求显式 `send_message`，但新建静态任务仍由 `automation/compiler.py` 编译成 `onebot.send_group_message`／`onebot.send_private_message`；SELF 的 DSL 委托目前只准 `yuki.agent`。2026-09-24 16:22 的三次 SELF 创建均记录 `PermissionError`。ID 94 则是另一故障：15:00 的 `yuki.agent` Work 在第一次模型请求前因 `KeyError` 暂停，自动化成为 `blocked`、`next_run_at=NULL`；失败回执未记录缺失键。其目标写明定时在群发提醒，保存的结构化投递却是 `none`。之后一次 `resume` 审计 `success=true`、`changed=false`，现行仓库恢复条件并不接受 `blocked`。

## 3. 从 Alice 借什么，不借什么

参考 Alice 的[时间信号](https://github.com/LlmKira/Alice/blob/main/runtime/src/pressure/signal-decay.ts)、[社交成本](https://github.com/LlmKira/Alice/blob/main/runtime/src/pressure/social-cost.ts)、[群组接收度](https://github.com/LlmKira/Alice/blob/main/runtime/src/mods/observer/group-reception.ts)、[候选评分](https://github.com/LlmKira/Alice/blob/main/runtime/src/engine/iaus-scorer.ts)、[长期好奇心](https://github.com/LlmKira/Alice/blob/main/runtime/src/pressure/p6-curiosity.ts)。借鉴的是多时间尺度的行动密度、习惯化、社交接收反馈和可审计的信号寿命，不复制它的完整人格／压力体系。

Alice 的群组 `consecutive_outgoing` 按 24 小时半衰，但普通群消息也能清零；冷落需后续至少 5 条群消息，无人说话 10 分钟只产生 `unknown_timeout`；候选评分还有连续 4 条的硬上限。其关系冷却和好奇心有些项随沉默增加，并非“所有兴趣随群沉寂衰减”。这些行为都与本任务的社交意图或无硬触发要求不一致，不照搬。

## 4. 决策与状态模型（待按真实回放校准）

### 4.1 输入、归属与可观察量

| 量 | 来源 | 在新模型中的职责 |
| --- | --- | --- |
| `b,x,S,floor` 及 Jev 概率 | 已核验的真人／记忆焦点与有效观测 | 有来源候选的内容支持、交流楼层、停止边界和回应方向；不是无来源虚构输入 |
| `q` | 真实真人事件 | 短时群聊忙碌程度，不直接等于对 Yuki 的回复 |
| `ℓ` | 已提交本群真人事件 | 缓慢变化的群聊背景；极久沉寂时渐近零 |
| `f` | 真实模型／工具计算效果 | 反复空转成本 |
| `n` | 无来源 Work 的真实 `NO_REPLY` | 抑制重复空醒；不代表别人冷落 |
| `d` | 主 SELF 的结构化 `engage` | 自己的短时参与倾向，不能覆盖停止或明确负面反馈 |
| `mood` | 主 SELF 自由文本 | 当前只作表达语境与诊断；保留以后以结构化、可审计的量化参数参与模型的扩展点 |
| `W_f,W_s` | 实际启动的自主 Work／主 Agent 调用 | 短时及较慢尺度的调用密度；同一 Work 无论发送多少条，都只贡献一次。替换现行过短的 `p`／120 秒比例惩罚 |
| `E,R` | 已确认自主 Work 的公开表达及后续真人观测 | 该 Work 尚未得到回应的暴露程度、被接住或被拒绝的接收反馈；不按消息条数计价 |

`W` 按已接纳且实际启动主 Agent 的自主 Work 增加，使用内部 Work／run ID 幂等计一次；仅提出 proposal、接纳前失败或插件事件不计入。`E` 在该自主 Work 有确认的公开发送后按 Work 建立一次，不因 Agent 在同一 Work 内多次发送、分条或使用多个 `send_message` 而增加。真实消息 ID 只用于关联回应及核对回执。`uncertain` 出站不能按成功计入 `E`，也不能为了重新采样而重发。

### 4.2 连续衰减与回应

候选形式如下。时间参数是衰减尺度，不是到点开关：

```text
W_f(t) = Σ_started_autonomous_works exp(-(t-t_i)/τ_f)
W_s(t) = Σ_started_autonomous_works exp(-(t-t_i)/τ_s),  τ_s > τ_f

E(t) = Σ_public_works u_i(t)
       · (1-exp(-(t-t_i)/τ_wait)) · exp(-(t-t_i)/τ_forget)
```

自主 Work 启动会立即抬高 `W_f`；如果它公开发言后一直没有可信回应，`E` 平滑上升，随后即使无人来“解锁”也会自行衰退。`u_i(t)∈[0,1]` 是该 Work 尚未被接住的概率／程度，由真实 Jev 观测更新，不是按发送条数设置的权重，也不靠一个回复的硬开关归零。单次 Work 多条消息只扩大可核对的回应锚点集合，不放大 `W` 或 `E`。每个真人焦点由 Jev 概率和 Host 已存在的内部出站锚点共同评价：`extend_yuki`、有锚点的 `acknowledge`／内容接续提供正向接收；`ask_yuki_stop` 与经证据确认的反感提供负向接收；同群别人的无关讨论只能提供弱的“被绕开”证据。没有真人消息时接收结果保持不确定，用暴露随时间增长表达轻微抑制，不凭空造出一次“明确拒绝”。迟到观测、重复观测和同一 Work 的多条消息按内部事件 ID 幂等归并。

接收反馈 `R` 由有来源观测更新，并以较慢的时间尺度回到中性；它不等同消息条数。明确停止仍保留原边界及权限语义，不稀释成一个可以被积极心情抵消的浮点成本。第一版可以仅使用现行 Jev rubric；若无法可靠区分“致谢 Yuki”和“群里对别人致谢”，先保持未知，不新增无证据的正反馈。

初次回放只把 `τ_f≈15–45 分钟`、`τ_s≈4–12 小时`、`τ_wait≈10–30 分钟`、`τ_forget≈6–24 小时`当作搜索范围。系数和长尾率从真实聚合、保密离线回放和合成轨迹定标，不直接抄 Alice 的常量。

### 4.3 自主机会而非积累门槛

针对无来源与非请求式候选，用非负、随状态变化的机会率代替旧的 `U>0` 加 `g(t)` 恢复。示意为：

```text
H(t) = Σ_human exp(-(t-t_i)/τ_H)
A(t) = H(t)/(H(t)+K)
s = t - t_last_human
G(s) = (1-exp(-s/τ_rise))exp(-s/τ_fade)
z(t) = β₀ + β_d d - β_q q - β_f f - β_n n
       - β_wf W_f - β_ws W_s - β_e E + β_r R
λ_intrinsic(t) = λ₀ · A(t) · G(s) · sigmoid(z(t))
P(本轮提出机会 | Δt) = 1-exp(-λ_intrinsic(t)Δt)
```

每次调度用**当前状态**采样，重启后使用原 scope 与时间推进的确定性随机流／持久抽样记录；不保存一个等待越过阈值的累计数，改变 tick 频率不改变单位时间概率。真人活动证据消退后，无来源机会率随之趋近零；有根据的自主 Work 仍由 SELF 自行决定公开发言、内部行动或 `NO_REPLY`。有真实来源的非请求候选用原 `S_i`、楼层与信念构成独立的 `λ_i`，共享自主调用密度与接收反馈；无效、撤回或过期来源仍不可采样。多个候选按各自率竞争，一轮最多接纳一个原有 Work。明确邀请／直接续答继续由 Jev 语义证据走现行及时路径，不使用无来源率。

旧 intrinsic `g`、`p`、`N_Y/N_H` 比例项应在新调用密度与接收反馈被验证后退出决策公式；`q,ℓ,f,n,d` 保留各自明确职责。快照迁移从现有真实效果和时间戳构建可证明的初始值，无法证明的旧状态取中性并标明版本，不凭历史文本或平台 ID 补造调用、发送、回应。

### 4.4 唤醒与公开发送的边界

控制器只提出 SELF 思考机会，不能从 proposal 推断“必发一条”。主 Agent 仍走同一固定入口和 `send_message`；提示词呈现可解释的近期自主调用／接收状态，`NO_REPLY`、安静工具行动仍是正常结果。**单次已接纳 Work 内不加消息数量、工具调用次数或表达长度的社交频率限制**；所有发送仍遵守原有权限、目标和回执合同。模型只影响后续非请求式自主机会，不得给普通聊天、真人明确请求或按日程到点的自动化悄悄加自主频率阀门。

## 5. SELF 自动化独立工作包

1. 静态字面量提醒继续免模型执行，但**新生成的 DSL 投递**应走与 `send_message` 相同的 SocialService 发送、净化、目标核验和持久回执边界；可注册内部 `social.send_message` capability。它不是另一个面向主 Agent 的工具声明。SELF 仅可委托创建时获准的当前群，不提供 `self_private`；Person 的既有私聊与群投递合同保持原权限。
2. 已存旧 `onebot.send_*` 脚本保留 script/hash、原 run/step、历史回执与不确定状态，在兼容处理器执行；不就地改写执行中的脚本、重发历史消息。新建／更新转新 capability，退出旧路径须以存量脚本清单和可迁移状态为依据。
3. Agent 计划中要求公开提醒时，结构化 `delivery.target` 应是 `current_group`；`none` 表示可以安静完成。改进工具说明、创建结果预览和定向对话回归，避免 ID 94 那种“目标要求发、结构化投递为 none”的矛盾。后端只校验结构化合同，不用关键词／正则重新解释自然语言目标。
4. 对 ID 94 的原 Work、run 和失败回执做只读定位与离线复现；记录安全的异常类型、阶段与缺失字段名称，查明 `KeyError` 后再修。修复后的更新／恢复路径须保留原失败 run 和效果回执；当前 blocked 状态不能因一次 `resume` 返回 `changed=false` 却被审计显示成已恢复，也不能自动补发错过的 15:00 提醒。

这组修复不依赖自主频率模型，可以在同一新工作树分独立提交／PR 审查；不把两个错误归并为一个根因。

## 6. 实施顺序与验收

**A. 证据和回放。** 从生产只读抽取内部 ID 关联的聚合轨迹：真人活动间隔、Jev 维度分布、自主 proposal／实际启动的 Work／主 Agent 调用、Work 是否公开发送、真实发送条数／分条、后续锚点回应、未回应持续时间和实际 `NO_REPLY`。消息条数仅供诊断及回应关联，不作为频率目标。存储可公开合成 fixture，不上传真人正文、外部 QQ ID 或私密群时间线。旧 30 天回放只模拟 `NO_REPLY`，必须补入有发送、无回应、迟到回应、交错群聊、长空白和突发多条的结果轨迹。

**B. 独立库。** 增加版本化表达／接收状态、带内部锚点的 Jev 反馈投影、时间推进、可复现概率采样、快照迁移和定向测试。取消被替换的旧 intrinsic 公式与重复惩罚；保留直接邀请、来源失效、停止边界和唯一 proposal 合同。

**C. Host。** 从 Work 启动回执按内部 run ID 输送自主调用，从真实 Social 回执识别该 Work 是否公开表达及其回应锚点；从 Jev 观察输送可证明的回应。固定主 Agent 工具声明与执行身份；自主调用频率由控制器调节，已经开启的 Work 保留主 Agent 的自主表达，不用提示词给消息条数施加隐性限制。更新 Host 的依赖 pin 与 lockfile，联测**实际固定修订**。

**D. 自动化。** 单独完成第 5 节，定向验证 SELF 静态 current_group、安静任务、Person 静态任务、权限拒绝、旧脚本兼容、未知回执、重启和 ID 94 型 blocked 诊断。

**E. 验收和上线决策。** 固定随机种子与参数版本进行 Monte Carlo 回放；比较现网旧模型、新模型在“短时自主 Work／主 Agent 调用密度”“公开发言后无人回应时的后续自主调用密度”“6 小时以上偶发苏醒”“7 天以上沉寂群的低尾率”“明确邀请响应”上的分布。验证单次 Work 可以自由完成多条发送，模型不按发送条数增加惩罚。再做隔离 Jev／主 Agent 回放和小范围真实观察；合成绿色不等于线上社交效果验收。上线只替换 Bot，保留独立库修订、快照迁移和回滚证据；不重放或补发历史自主机会。

## 7. 不可破坏的边界

- 永久 SELF、Person、Space、Conversation、Presence、Binding 和 run 分开；平台 ID 只在传输入口与网关关联。回应识别以真实内部出站事件及其 run／thread 为锚。
- Jev 只观察真实焦点，不能凭无来源机会制造真人消息、记忆来源或响应。`unknown` 不能转成肯定的邀请或肯定的接纳。
- Host 仍独占接纳、权限、唯一 owner、generation、Work 恢复及发送；概率率不授权、不绕过全群停止、目标可见性或已发生副作用围栏。
- 参数、随机样本、版本和选择原因应可重放；进程重启不制造机会风暴。读模型、网络、历史均在 SQLite 写事务之外。
- 模型频率控制只针对非请求式 SELF 机会／自主公开表达；日程投递、真人请求、插件外部事件各自按原合同。

## 8. 需要先讨论并定稿的选择
