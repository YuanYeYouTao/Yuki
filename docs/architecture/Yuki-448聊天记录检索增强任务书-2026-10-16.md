## 1. 重构结论与明确取舍

目标是可靠、快速地找回**谁在什么入口、什么时间说过什么**。前版只收 Main/Plugin 还不够：Social、个人入口、Client API 的账本读取、翻页和事件投影也一起收拢。

- 模型只留 **query_chat_history(view=recent/search/around)**。把 read_conversation_history、read_personal_entry 的真实目标选择纳入这一入口，删除两个旧声明和新执行分支；原 accepted call/receipt 继续按原调用读取。
- 新执行只留一份固定 manifest、revision 与 Code API。删除仅因旧个人历史工具而存在的 App/platform 双声明，以及为选择声明查入口平台的 SQL；真实入口、actor、设备身份与授权继续用于执行。
- Main、Social 目标解析、个人入口、Client/ACP、Plugin 共用 EventLedgerRepository 的页/邻文/检索与 EventRecord。入口仍核自己的真实授权，不建立新授权器、ScopePolicy 或万能查询服务。
- **所有聊天查询按内部账本 ID 排序和续查。** occurred_at 保存原生发生时间，只作日期筛选和展示；observed_at 保接收时间。迟到事件按入账顺序出现，不按发生时间插回旧页。删除未实施的复合时间游标和双排序方案。
- **一张带 Conversation 前缀词元的 1/2/3-gram FTS** 提供候选，原字段精确核验。索引只加速、不给答案改作者；不按会话建表，不把每个结构化过滤维度都复制成词元。
- 日常热路只读完整派生结构，不每次全范围 NOT EXISTS 查漏行。停写期间直接建立最终命名的 FTS 并完整装载，再完成原迁移版本；删除强制影子表交换、常态缺行补搜、队列、frontier、epoch、自检和 ready 状态机施工要求。
- 单条原事件是匹配单位，聊天原话默认 message，外部事件保原类型；邻文是上下文。保留多词、繁简/全半形、作者/日期/媒体筛选、实时续查和同次邻文；碎句用锚点/any＋邻文理解，不自动跨人拼原话。字符高亮、语义改写与相关度排名不在本轮。
- 删除经验上限和重复预检，保真实类型、身份、授权、来源和回执。Artifact 仍处理单次结果的载荷读取，不能把它误删成重复的账本翻页。

这是读侧优先的选择，不承诺所有成本同时最低。[新实验](experiments/chat-search-448-2026-10-21/README.md)中，前缀方案比“独立 scope token AND 全局 gram”查得更快，完整 gram 小样索引约 3.5 倍、构建约两倍。真实正文/ASR、磁盘、内存及同步 writer 成本仍须实施验收。普通列索引缺失不新增启动拒绝；不以固定耗时/计价门槛截掉真实查询。

## 4. 一个模型入口、一套领域读取

### 4.1 目标与授权

保留 view=recent/search/around；新增可省略的 target，互斥单字段对象：

| target | 行为 |
| --- | --- |
| 省略 | 当前 Conversation，复用当前真实来源和原上下文边界。 |
| {conversation_id} | 明确内部 Conversation；沿现有 Social/个人入口授权，不凭知道 UUID 取得权限。 |
| {person_id} / {space_id} | 查人物/空间的已观察入口；多个真实入口返回 Conversation 候选，不自动拼接。 |
| {binding_id} | 复用现 App/ACP 本人其他私聊入口的授权；不会因工具合并向平台群入口开放。 |
| {operation_id} | 按原发送回执核来源，保原 event_id 与真实出站 Conversation；不能只换到该入口最近消息就声称看到了原发送。 |

删除 display_name/subject_ref/presence 等查询目标的同义写法；名称发现仍沿现有联系人目录。target.person_id 是选聊天入口，顶层 person_id 是筛原作者，二者职责分明。

本人来源有资格读取的当前私聊也可显式选取，不保旧“必须是其他入口”的条件；这不改变他人、群、委托范围或 App/ACP 来源资格。互斥 target 和字段类型在统一参数边界核验，入口适配不再复制相同字段预检；正整数 ID、非负邻文条数和真实引擎错误仍按事实处理。

Main 当前历史仍遵守原 floor/keeper；Social 目标仍遵守其原 floor/read_target 许可。本人全历史保原 App/ACP 本人主会话来源资格，Client 保设备 principal，不被 Main floor 覆盖；其他来源即使目标属于本人，也不能因 conversation_id/person_id 选择绕过原来源资格升级为全历史。具备同一真实个人资格时，binding_id/conversation_id 才得到同一授权范围。Client 的 ACP 出站还认原 succeeded 回执条件。事件类型另由明确的数据过滤控制，不按 target/view 隐式改变；page/search/around 与同次邻文共用所选集合，N+1 也按该集合计事件。

operation 的原事件身份与回执不能被 floor 否定；越 floor 的定点读取只适用于该 receipt 自己持久关联的原 event_id，不给同会话其他旧事件授额外读取资格。around 未给 event_id 时可用该原事件为中心，其他显式锚点仍核普通范围/keeper；周围邻文也只沿普通合法范围。原事件已删除/脱敏或不可读时，保原 event_id 与真实缺失/脱敏事实，不补旧正文、不用 recent 替代，也不把原回执改判失败。recent/search 回显实际原回执锚点与该状态。

### 4.2 查询参数

| 字段 | 含义 |
| --- | --- |
| keyword、match | 普通字面查询；all/any/phrase，默认 all。空白允许只按其他条件筛选，无条件就是分页浏览。 |
| exclude | 字面短语数组；归一后非空项任一精确成立则排除。允许只有 exclude。 |
| person_id、author_kind | 当前读快照中解析同人族，筛真实原作者/类型；不把私聊对方或账号今日持有人当原作者。 |
| event_kind | message / external_event / all，默认 message；明确筛事件类型。all 保原 Social 时间线能力，外部事件保原类型/来源，不冒充人物原话。Client/个人原 API 默认仍 all，不因工具合并隐藏非消息事件。 |
| start_at / end_at | 发生时间的 [start,end)，不是新的排序键；时区见 §5。 |
| has | image/audio/video/file 任一；沿已观察领域分类，record 计 audio，仅自身附件。旧贴纸缺真实格式证据不强读验证，URL 不冒充附件。 |
| order | recent/oldest，指 ID 从大到小/从小到大，即最新/最早入账。 |
| limit、cursor | 正整数事件数与整数内部事件续页位置，按所选 event_kind 计数；未给 limit 才用默认值，不新增经验最大值。 |
| before / after | 仅 around 的前后条数；不是事件游标。默认沿配置，不把默认值当上限。 |
| context_before / context_after | search 的同次邻文条数，默认 0。 |

不保本地冗余 space_id 筛选和旧平台 user_id/group_id 查询参数。邻文只沿真实范围、keeper、已选事件类型和锚点 ID，不带文字/作者/时间/has/cursor 的命中条件；不能把两张远处图片当图片命中的相邻消息。

### 4.3 仓库、SDK 与工具退出

入口先完成真实授权/目标解析，再把同一 session、Conversation、具体合法边界及必要附加谓词交给 EventLedgerRepository。它共用 ID page、around/search 邻文与 EventRecord；不新增策略器、第二套范围或独立搜索平台。

- 合并 recent/canonical_recent 的重复查询；当前无消费者的 list_canonical_recent 删除。around 与搜索邻文复用同一仓库条件和事实提取；同一 session 可逐锚点有界读取，不强制单 SQL、窗口函数或固定调用次数。
- 删除 Social/个人入口/Client 自写的页 SQL及 services 对 client_api.views 的反向依赖。共用原作者、名字、回复、ASR、mention 和稳定媒体资料提取；各接口只装自己的信封，不强求万能 DTO。
- 共享实际需要的事实提取，不要求各接口复制 Main 的全部字段，不新增 Client 读取接口或通用序列化框架；journal、checkpoint、私有协议不进入公开聊天投影。自动上下文的增量装配、FrozenFragments 与缺正文读取保原职责，不强制改成模型工具的 N+1 分页。
- Plugin get_recent/search_history 同样读共同内核；保按消息数选取、账本正序展示，query 显式 match=all。删除这两个历史入口的经验 100 条 clamp、search 的 400 字符/非空预检，不连带改其他 facade。
- direct/Code/SELF/自动化/子 Agent 复用同一工具与自身原授权。删除两个旧模型工具的声明、执行和能力目录/Code 投影/提示/测试；新声明只在合法新链采用。
- 原已接纳调用、result_ref、参数、预算、已付 Provider 请求和 receipt 只读保留，不注册退役工具新执行别名。新查询仍 result_cacheable=False，不新建跨 call 结果缓存。
- MainAgentContract 去掉 entry 分类、_app_tools/app_revision/app_script_api、entry_for 与 health.entry_revisions；前台、恢复、子 Agent 直接用同一声明和投影，删仅为选声明而存在的参数和查询。沿现 WorkSession.contract_changed 接续，保旧 hash、chain link、已接受 effect 与 Code snapshot_unavailable 事实，不改历史 hash、不保现役双声明装兼容。

## 5. 文本、作者与时间

### 5.1 一个匹配定义

先实现一个可独立测试的纯匹配函数，原文答案和所有候选核验共用它。基础 fold 对**整个独立字段**依次 NFKC、casefold、NFKC，再按 Unicode 空白折叠为一个空格并去首尾空白。查询先做基础 fold，再按 match 切词；exclude 每项同样处理，归一后空项忽略。保留词间空格，不把“ab”和“a b”变成相同文本。

只处理真实正文和解析后的 current ASR 片段。不将若干片段拼成一个可匹配短语，不索引 JSON 键、source 标签、附件说明模板或提及元数据。

繁简是对基础字面匹配的放宽：每个查询词/短语与每个合法字段，**基础 fold 子串成立，或二者完整 OpenCC t2s 转换后子串成立**，即为该词命中。phrase 不跨字段或表示串接。不能只保转换后的字段：OpenCC 会按词组保留“乾坤”的“乾”，单独“乾”可能转为“干”，若覆盖掉基础表示反而找不到原有同字。两种表示属于同一个纯匹配定义，不做失败后再查或两套产品开关。

使用完整 t2s 配置与词典，不自建小字表、不调用模型；实施时锁定实际依赖和词典来源，转换器在 writer 外复用。候选须覆盖基础表示与繁简放宽的命中，原文照常返回；词典转换不冒充所有中文同义词匹配。旧探针的 12 字样表不能作为完整覆盖证据。语义改写和拼写纠错另行讨论，不添加隐式外部补查。

不做逐字符 NFKC 再拼接。先返回原文和 matched_fields/片段编号，不承诺字符级高亮偏移；删除旧“Unicode 安全切分＋全码位证明＋反向高亮映射”施工线。若以后确需偏移，应独立验证它指向返回的那个原字段，不能给 ASR JSON 的坐标去标注另一份渲染正文。

### 5.2 不重新造作者

person_id 通过 person_family_condition/person_family_ids 查同人族；输出逐事件原 Person/Account/Presence、原 author_kind、当时名字和原生 mention 快照。查询时不更新这些字段，不查当前平台归属来补“真正是谁”。

Person 合并只扩展当前同人查询集合，账号转移不改变旧作者；解绑、停用或没有账号不抹去获准历史。按 Yuki 筛选使用原 author_kind，不把私聊双方都当成对方。

member_ 后缀如果出现在现有主体引用中，必须是本轮可信内部 Person UUID，不是 user_id。本工具直接使用内部 person_id，不新增昵称/平台号解析捷径。

引用语音 source=reply 只能作为带真实来源的上下文；source=current 才是此事件作者的 ASR 证据。自动转录须标明来源及可能有误，不变成模型确认过的真人原话。

### 5.3 时间和顺序

- 带偏移输入转换为 UTC；不带偏移按系统统一默认 UTC+8；不引入个人时区偏好。
- 按数据库实际 DateTime 类型/编码绑定，不能把带时区 datetime 原样塞进 raw text SQL 并假定 SQLite 自动换算。
- 命中区间为含起点、不含终点；返回解释后的区间和统一展示时间。无结果不自行扩大到前一天。
- 全部账本页与 search 使用内部 ID 顺序。原生时间相同不会造成游标歧义；迟到事件拥有新 ID，按新入账位置出现。日期过滤仍检查真实 occurred_at，不能用 ID 推导发生时间。
- around 与搜索邻文沿原账本内部事件顺序，不把时间排序键误当消息主键。邻文只沿实际 Conversation、keeper、已选 event_kind 集合、合法下界及每个锚点的 ID 邻接范围；不带 keyword、exclude、person_id、author_kind、时间、has 或搜索 cursor 条件。它可展示其他作者和时间，明确标为 context。

## 6. 共享页边界，保留结果载荷分页

仓库统一得到“事件＋查询方向＋是否还有更多＋ID 边界”，不为各入口重新判断。实际范围和原授权由入口提供，分页算法不另做权限。

- 精确核验到 limit+1 个真实事件或穷尽；返回前 limit 个。has_more 由额外命中证明，next_cursor 是当前方向最后已返回事件的整数 ID，不跳过未返回的额外项。
- recent 用 id<cursor，oldest 用 id>cursor。把同方向下界合成 max(floor,after/anchor)，上界合成实际最小值，避免多个同向谓词让 SQLite 从较远边界起扫。新链不使用深 OFFSET 或时间复合 cursor。
- Client/个人信封沿共同行的最小/最大 ID 给 next_before/next_after，补个人反向边界；这些边界在展示反转前算好。Main search 按查询方向返回，recent 窗口/Plugin/Client 可按其展示合同正序排列，不据展示顺序重算游标。
- 页内候选、核验、必要邻文使用同一只读快照；跨调用实时读取，每次沿现有资格和当前人物族。页尾行删除后仍可按其 ID 继续。页间编辑/删除/合并可改变后页，不承诺跨页静态导出，也不新增签名、epoch、无关 revision 门禁或从头重跑循环。
- Client SDK 的 revision 变化重读维护的是本地时间线副本；不能把它当 Plugin 搜索重启循环删掉。真实 generation、来源或租约失效仍沿既有执行/提交合同，原回执保留。
- matches/context 按内部 ID 去重，命中优先；邻文明确是其他原话，不生成证据组结论。按锚点分别有界读取，不扫两个遥远锚点之间的完整历史，不逐条再调用 around 工具。

**账本续查与 Artifact 载荷分页分别复用现有职责：** next_cursor/has_more 查询下一批聊天事实；read_tool_artifact.get 的 offset/next_offset 读取一次调用已经保存的数组/字符串。读完第一页 Artifact 不会自动去数据库查下一页，恢复原 call 也不会重跑账本。

大结果沿现 ToolResultBudgeter/Artifact，完整页的游标可用通用 get 取回。外层 truncated/ToolReceiptView.complete 表示展示完整度，不是账本已经穷尽。不新增聊天结果专用回填器、摘要白名单或第二种载荷分页。

输出复用原事件事实，Main 的 id 与其他接口的 event_id 同为内部主键。Plugin message_id 保平台传输语义，presence_id 保接入语义，原作者另给 author_presence_id；未入账不造事件 ID。补原 Person/Account、当时名字、回复、ASR 片段和稳定 attachment_index，分别返回 occurred_at/observed_at，不把 received/created 的旧外壳误当发生时间，保 event_kind。搜索按已有 current ASR 命中时，不能只返回空正文。

文件过 24 小时不抹去消息与元数据，不为搜索重新下载、识图或转录；媒体索引不把引用附件算当前作者上传。结果给模型前仍沿原来源/隐私提交规则，不改已付协议前缀。

## 7. 选定查询架构、复杂度与升级边界

### 7.1 一张 FTS，单次 MATCH 的候选

离线构建和正常维护覆盖有真实 canonical Conversation、keeper/legacy NULL 的 message 与 external_event；按查询 event_kind 筛，不只给默认 message 建索引。选择 SQLite FTS5 的 contentless-delete、ASCII 编码词元、detail=none；需要 SQLite 3.43 及以上的真实能力，实施须核部署镜像并统一依赖，不能凭 Python 版本推断，不保新旧运行路线。

1. 对可读 canonical 原事件的真实正文和独立 current ASR 各取基础/t2s 表示，在 writer 外生成所有 1/2/3 字符 gram。
2. 每个词元为无歧义的“可信 Conversation UUID＋gram 长度＋字节编码”，应用生成并引用，不把模型的 NOT/OR/引号当 FTS 语法。每事件取词元集合，FTS rowid 等于原账本 ID。实施实验后补充最多两个稳定原作者词元（Person 与 author_kind），与正向文字合成一次 MATCH；只在查询时组合当前人物族，不复制 gram、不存当前 root 或权限。
3. 一字用 unigram、二字用 bigram、长词用所有 trigram 的 AND。每词的基础/t2s 分支取 OR，all 对词组 AND、any 对词组 OR；**一次 MATCH 自然按事件并/交及去重**，不做多来源游标合并。
4. 正文/片段/表示混合只会增加假阳性，原独立字段精确核验剔除。真实子串的全部所需 gram 必然在该事件词元集合里，不能漏掉真命中。exclude 不在这个超集上先取 NOT，统一精确后置。
5. FTS 候选回原事件核实际 Conversation、keeper、已选事件集合/合法下界、原作者、日期和媒体；前缀不承担授权。按 rowid 方向批取，精确到 N+1 停止，不物化全命中时间排序。

外部事件只索引其真实 content/current ASR，不索引 external_payload JSON；返回保 event_kind 和原作者。不按人物 root、当前权限、generation 或日期预造多套 gram，不建每 Conversation 动态 FTS 表，不恢复相关度和位置排名。没有正向关键词的查询走同一内核的结构化范围；仅 exclude 仍需核验，不误走无需文本检查的纯元数据页。

### 7.2 普通索引与查询计划

- 复用既有 ix_chat_events_canonical_conversation_id：SQLite 已隐含 rowid，不另加同义 (Conversation,id) 索引。
- 作者先在本页快照解析人物族一次，用原 author_person_id IN。采用 (Conversation,author_person_id) 的必要可用索引；若 partial，谓词覆盖 keeper/legacy NULL，不能只为 message 建索引却声称 all 查询也可用。先用普通 SQL，不手造每作者 top-N 合并器。
- 日期范围采用 (Conversation,occurred_at) 的可用索引，复用隐含 rowid，不再显式附加同义 id；含起点不含终点。ID 排序不意味着从最新 ID 一路扫到过去的日期。日期窗口可做局部 top-N，不能声称任意时间窗都无排序。
- 媒体复用 conversation_media_items 的 (conversation_id,source_event_id)，source_snapshot_json IS NULL 排除观察到的引用附件；按事件去重，并回原事件核 keeper、本次合法范围及必要附加谓词，不复制 has 表或 JSON 历史扫描。
- 不强制所有组合以 FTS 或所有组合以 metadata 起步。真实有词/作者/窄日期/媒体组合须验证所选 SQL 访问路径；不把 CROSS JOIN 钉死为所有情况模板，不凭 EQP 出现 TEMP B-TREE 就新增协调器。
- 现平台 sender 索引仍服务真实提及等消费者，不能因搜索改 Person 顺手删除。是否新增 visible-message 索引看真实非消息/duplicate 密度，不预设它为必做。

### 7.3 可以保证什么

设 G 为全库事件数、N 为目标范围事件数、V 为词元词典规模、Q 为查询 gram 数、P 为实际倒排访问工作、C 为回表候选数、K 为返回数、T_text 为实际文字处理成本（含全字段归一化、按词重复核验及输出），F 为人物族规模。

| 查询 | 实际目标/下界 |
| --- | --- |
| ID 页、定点锚点 | 仅 ID 候选页用覆盖索引可 seek＋遍历，目标 O(log G＋K)；完整事件另计 K 次主键回表与正文处理。附加过滤跳过的行也计入，不把 LIMIT 当访问量证明。 |
| 正向全文 | 成本分解为词典访问＋P＋C 次主键回表＋T_text，按 ID 早停；不是严格物理上界，FTS 分段/磁盘成本另测。all 的必需词在基础/t2s 两分支都无候选，或 any 的全部分支都为空时才可证空；不能拿 any 的一个缺词否掉其他分支。无关会话不应变成账本回表候选。 |
| 作者/日期/媒体 | 对应索引缩小候选，再做必要 top-N/核验；人物族读取规模 F、日期窗口大小及媒体密度均计入。 |
| 仅排除、全部 gram 存在但无真实短语、常见词叠加稀疏条件 | 最坏可核完整 N 并重复处理文本；不承诺普遍 O(log N)。 |
| 输出与索引维护 | 输出至少读写实际结果，词元准备至少随原字段长度增长；同步提交与 FTS 段合并仍有真实写成本。 |

不加人为扫描预算、空中间页或固定次数封口来伪造快。批次控制内存与调度，不改变查询完成语义。长正文 CPU 退出 Host 事件循环；取消须验证底层 SQLite 工作终止及读事务释放，不能只观察 Python CancelledError。单页快照仍可能变长、阻碍 WAL checkpoint，须测真实范围与并发 writer。

### 7.4 停写完成一次离线升级，正常写同步维护

**主动选择一次离线数据升级，放弃不停写的半成品索引服务。** 删除“每查 NOT EXISTS 找缺行再补搜”的常态路径；它会把已完整的索引也拖回范围扫描。不存 ready、frontier、epoch、失败计数或永久回填队列。

现 migrations/env.py 外层 BEGIN IMMEDIATE 必须被尊重：正文读取、OpenCC 与 gram 生成不能放进这个持锁范围。复用现 init-db/Alembic 的离线升级入口与版本事实，形成结构准备→锁外转换/分批装载→最终完成三个事务边界；只处理这次真实数据升级，不建通用阶段引擎或运行时索引版本服务。

- 旧版本迁移先按原边界完成并释放 writer，保 0048/0049 冻结桥的原子性；新增结构阶段直接建立最终命名的唯一 FTS。Bot 和其他业务 writer 在整个数据升级期间停止，旧程序也不同时使用这份库。
- 按内部 ID 分批读取、锁外转换，再用短 writer 装载同一 FTS；读批次不跨写提交保留长读事务。全部完成后，最终短事务安装正式维护对象并记录最终 Alembic 版本。init-db 及受支持的 Alembic 升级调用都不能绕过数据步骤先记最终 head。
- 中断保未完成的原迁移事实；重跑只清理重建这次尚未完成的派生结构。原账本/人物/执行/回执不回滚、不重放，不另存构建进度、发布标记或恢复队列。现有最终 head 校验已阻止新程序使用未完成升级，不新增索引 ready 检查。
- 删除强制 build/live 双对象、rename/swap、双维护触发器及原子切表施工要求；已经停写，无需维护在线读者的切换协议。离线切表探针只保机制证据，不再决定实施形状。
- 空库 create_schema 直接形成相同最终结构；有历史的普通启动不 IF NOT EXISTS 一个空 FTS 冒充完成，不每次启动扫描/回填。正常缺少普通 B-tree 加速索引不拒启动；所选 FTS 表及维护对象按同一真实结构维护，不为任意损坏另造隐式搜索切换或自动修复。
- 接管后正文/ASR/源范围/抑制状态/隐私变更的实际 writer 同步维护唯一 FTS；删除旧 raw content/audio_json FTS 与写消费者，不保旧 schema 查询兼容路线。不改变 Memory 自己的事实索引。
- 维护只需一个纯正文/gram 准备入口与原 writer 内的替换/删除；保一条固定 AFTER DELETE 按 OLD.id 清派生行，覆盖批量隐私删除，不在触发器中读历史或转换正文。视觉摘要、名字、reply 指针、附件资料和权限变化不重新分词；不加原文编码大列、ORM flush hooks、全局事务协调器或第二套 mutation framework。
- 正文/ASR 解析、OpenCC、非命名 gram 与旧/新来源准备在首次写入前。命名空间使用原来源流程实际裁定的 Conversation ID；首次会话若在 writer 才创建 ID，仅在此完成必要的确定性命名/参数封装，不用猜测 UUID、不在锁内重做正文转换。封装及 FTS 段合并并非 O(1)，A43 必须测其真实锁成本；原事件与派生变化同事务接纳。回写不能只查 EXISTS(id)，原地脱敏后 ID 仍在。
- Person 合并、账号换绑、普通 floor/generation 或权限改变不重建派生索引；原作者/原 Conversation 不变，当前范围条件在查询时核。
- 不把一张可选、可能被单独 DROP 的 FTS 用“WHEN EXISTS 就安全”的触发器假设接入所有事件写入；实际探针显示缺表仍会使 DELETE 失败。正式对象、删除维护及升级按同一生命周期验证，不加运行时自愈状态机。

实际维护落点是 identity/canonical_uow.append_inbound；scoped_event_uow._append_canonical、update_platform_message 和 _set_derived_text 的 audio 分支；people_repository.prepare_person_forget/apply_person_forget 的脱敏与批量删除。record_account_fact 没有 canonical Conversation，不为它伪造 scope。ASR 对公共 prompt 的失效触发器保原职责，不与旧聊天 FTS 触发器一起删。

### 7.5 搜索结果的真实隐私

索引清退和已复制的搜索正文分开核。原工具结果、journal、artifact、context_note、协议私有输入要能追踪原事件及实际隐私来源；缺引用则补最小来源与删除消费者，不因“没建结果表”忽略副本。

搜索证据的来源引用不等于 Main 激活来源。不得把跨会话命中塞进 WorkSession.event_ids，借 WorkSourceGuard 将它们当作 accepted client_input/work_input；沿原工具结果与 artifact 的来源记录补缺，不新增另一 SourceGuard。

原事件变更与对应 FTS 增删在同一 writer 中接纳；查询页只读，不为搜索取得 writer。journal、artifact、协议输入等实际持久消费者分别复用原提交 writer 的来源/隐私核验，只补确实缺失的来源引用与清退，不把它们绑成一笔跨消费者事务，也不新增搜索提交框架。

外置文件复用原暂存/登记/清退；模型输入沿现有请求最终接纳边界核真实来源，不承诺数据库提交与网络发送分布式原子化，不持锁等网络或增加第二派发锁。遗忘完成后的迟到登记不能复活正文；已付请求和原回执保原协议事实。普通消息/ASR不新增失效门禁，真实授权、原 generation/租约失效仍按既有执行合同处理。

contentless-delete 的可读结果清退不等于取证级物理擦除；不因此新增每次查询 VACUUM、全库巡检或自动清库重建。
