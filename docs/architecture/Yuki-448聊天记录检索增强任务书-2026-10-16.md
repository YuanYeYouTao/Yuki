## 1. 本次收敛

目标是可靠找回**谁在什么时间说过什么**，能定位原事件并按需读上下文。先修事实归属和查询语义，不把它做成另一套搜索平台。

- 只增强现有 **query_chat_history(view=recent/search/around)**，不恢复三个退役名称，不增加一套 Main 搜索工具。
- Person 查询认同人族，返回仍认原作者；Conversation 是聊天上下文边界，账号归属和人物合并不拼接入口。
- 消息正文和当前作者的真实 ASR 文本才是原话。JSON 元数据、引用者语音、视觉摘要不冒充当前作者说的话。
- 单条消息是命中单位；邻文与引用是上下文。删掉默认“跨消息最小覆盖证据组”、20 条/30 分钟跨度及局部排名范围重算。
- 用普通 keyset 续查与实时读取语义，不承诺跨调用维持一个历史数据库快照；删除 HMAC、进程密钥、W/S/E 计价、索引 epoch 绑定和无关更新强制重查。
- 匹配定义先统一。索引是可替换加速，不是答案源；不预先强制 1/2/3-gram、contentless-delete、队列、frontier、自检 worker 一整套方案。
- 缺索引不能变成“查不到”或“禁止工作”。性能瓶颈以当前 schema 的测量定位，不能拿旧合成表的返回行数证明延迟、WAL 或写锁上界。
- 旧实验保留为日期背景，不能作为本版完成项、当前性能或身份/隐私验收。

保留多词、繁简/全半形、作者/日期/媒体筛选、续查和同次邻文这些找聊天记录的基础体验。碎句用锚点/any 与邻文显式还原，不自动把不同人的句子合成一条原话；字符级高亮、语义改写和相关度排名暂不在本轮施工范围。删除的是旧实现机制，不以旧样表不完整为理由取消繁简需求。

## 4. 查询合同：保留一个入口

### 4.1 Main

保持 query_chat_history 这个工具名称和三个 view：

| view | 行为 |
| --- | --- |
| recent | 当前授权 Conversation 的近期原事件，保留按账本 id 取最新 N 条再正序展示的现行为；提供 limit 时使用请求值，未提供才用现有默认值。 |
| search | 关键词、作者、时间、媒体元数据筛选、续查及可选邻文。空关键词允许只按其他条件查找；没有额外条件时就是该范围的分页浏览。 |
| around | 按内部 event_id 定位，before/after 是消息条数。默认值沿现配置；不再把默认半径和总数当硬上限或静默 clamp。 |

search 建议字段如下，实施时统一更新固定合同、Code Mode、工具说明和消费测试；不增加另一套别名。

| 字段 | 语义 |
| --- | --- |
| keyword | 普通字符串，不开放 SQL/FTS 运算语法。空或空白视为没有正向文字条件。 |
| match | all / any / phrase，默认 all。all/any 对查询按 Unicode 空白切词；phrase 将整段视为一个字面短语。引号、NOT、OR、星号、%、_ 不产生隐藏运算。 |
| exclude | 字面短语数组；在同一事件可搜索字段中出现任一项就排除该事件；空项不产生条件。允许只带 exclude。 |
| person_id | 内部 Person ID；在本页读快照中解析同人族，只筛真实原作者，删除 private peer 代替作者的 OR 条件。 |
| author_kind | 可按原作者类型筛选，例如 yuki；没有人物的原 account 作者仍可正常出现在未限定人物的搜索里，不能归给该账号今日持有人。 |
| start_at / end_at | 对命中应用 [start,end)；解释见 §5。 |
| has | image / audio / video / file 数组，任一类型即可；认已入账/已观察的领域媒体分类，record 统一计为 audio。旧贴纸标为 image 但缺编码证据时不声称已验证真实文件格式；forward/card/unknown 不冒充四种媒体，正文 URL 不另造 link 类型。只检查本事件自身附件元数据，引用附件不算作者自己的上传；不读取附件、不调用模型，不为 QQ/TG 各建过滤器。 |
| order | recent / oldest，默认 recent；按 (occurred_at,id) 的同方向全序。 |
| limit | 本页匹配消息数，正整数；默认沿现行为，不新增经验最大值。 |
| cursor | 上次已返回命中的 (occurred_at,id) 位置；是位置，不是授权票据。 |
| context_before / context_after | 非负条数，默认 0；需要邻文可在同一次调用给出，不必逐条再调 around。 |

删掉本地工具冗余的 space_id 筛选：Conversation 已确定范围。显式跨 Conversation 继续使用现有 Social/个人入口的目标发现和授权，不把 person_id 当作“搜索此人在所有入口的历史”。

单条消息是匹配单位。all 的每个词可命中该消息不同的合法字段，但 phrase 不跨字段、不跨独立 ASR 片段；exclude 不搜索引用者语音或 JSON 元数据。不同人的碎句不会被包装成共同事实。找拆开发送的句子时，搜索其中锚点并请求邻文，或显式用 any；不设时间跨度/消息跨度来否定真实原话。

无身份、范围或数据库事实时返回真实问题；不改用平台号、最新消息、主动路由、另一个人或另一个 Conversation。普通无命中与基础设施错误分别表达，不把异常包装为空集。

### 4.2 Plugin、SELF、子 Agent 与恢复

- direct、Code Mode、SELF、自动化、子 Agent 使用同一查询内核和自身原授权，不获得第二套范围或隐藏工具。
- Plugin search_history(query,limit) 保消息数及现有时间正序返回语义，沿批准的 MESSAGE_HISTORY_READ 和原 Conversation；query 明确使用共同 match=all，SDK 说明和测试记录多词语义变化，不依赖实现函数的偶然默认值。在该历史入口删除固定 100 的静默上限及 query 的 400 字符/非空预检，直接沿共同匹配定义处理。其他 facade 不因此改变。
- Plugin 一次调用在自己的读快照内批读到 N 条或实际穷尽。不循环调用“页预算→stale→清空结果→从头来”，没有读完也不能假装已读完。
- 不为恢复注册退役工具的新执行别名。旧已接受 call、result_ref、原参数、已付请求、预算及原回执按当前恢复合同只读保留；工具声明仅在合法的新链生效。
- 新历史读取继续 result_cacheable=False。同参的新调用重新读取当前事实；原 call 的真实持久结果仍是原回执，不建跨 call 缓存或失效总线。

## 5. 文本、作者与时间

### 5.1 一个匹配定义

先实现一个可独立测试的纯匹配函数，原文答案和所有候选核验共用它。基础 fold 对**整个独立字段**依次 NFKC、casefold、NFKC，再按 Unicode 空白折叠为一个空格并去首尾空白。查询先做基础 fold，再按 match 切词；exclude 每项同样处理，归一后空项忽略。保留词间空格，不把“ab”和“a b”变成相同文本。

只处理真实正文和解析后的 current ASR 片段。不将若干片段拼成一个可匹配短语，不索引 JSON 键、source 标签、附件说明模板或提及元数据。

繁简是对基础字面匹配的放宽：每个查询词/短语与每个合法字段，**基础 fold 子串成立，或二者完整 OpenCC t2s 转换后子串成立**，即为该词命中。phrase 不跨字段或表示串接。不能只保转换后的字段：OpenCC 会按词组保留“乾坤”的“乾”，单独“乾”可能转为“干”，若覆盖掉基础表示反而找不到原有同字。两种表示属于同一个纯匹配定义，不做失败后再查或两套产品开关。

使用完整 t2s 配置与词典，不自建小字表、不调用模型；实施时锁定实际依赖和词典来源，转换器在 writer 外复用。候选须覆盖基础表示与繁简放宽的命中，原文照常返回；词典转换不冒充所有中文同义词匹配。旧探针的 12 字样表不能作为完整覆盖证据。语义改写和拼写纠错另行讨论，不添加隐式外部补查。

不做逐字符 NFKC 再拼接。先返回原文和 matched_fields/片段编号，不承诺字符级高亮偏移；删除旧“Unicode 安全切分＋全码位证明＋反向高亮映射”施工线。若以后确需偏移，应独立验证它指向返回的那个原字段，不能给 ASR JSON 的坐标去标注另一份渲染正文。

### 5.2 不重新造作者

person_id 通过 person_family_condition/person_family_ids 查同人族；输出逐事件原 Person/Account/Presence、原 author_kind、当时名字和原生 mention 快照。查询时不更新这些字段，不查当前平台归属来补“真正是谁”。

Person 合并只扩展当前同人查询集合，账号转移不改变旧作者；解绑、停用或没有账号不抹去获准历史。按 Yuki 筛选使用原 author_kind，不把私聊双方都当成对方。

member_ 后缀如果出现在现有主体引用中，必须是本轮可信内部 Person UUID，不是 user_id。本工具直接使用内部 person_id，不新增昵称/平台号解析捷径。

引用语音 source=reply 只能作为带真实来源的上下文；source=current 才是此事件作者的 ASR 证据。自动转录须标明来源及可能有误，不变成模型确认过的真人原话。

### 5.3 时间和顺序

- 带偏移输入转换为 UTC；不带偏移按系统统一默认 UTC+8；不引入个人时区偏好。
- 按数据库实际 DateTime 类型/编码绑定，不能把带时区 datetime 原样塞进 raw text SQL 并假定 SQLite 自动换算。
- 命中区间为含起点、不含终点；返回解释后的区间和统一展示时间。无结果不自行扩大到前一天。
- search 的 order=recent/oldest 使用 (occurred_at,id) 作为全序，时间相同按内部主键打破平手。迟到事件可拥有更大 id、更早 occurred_at，不能用 id 推导时间距离；不要与 view=recent 的账本顺序混淆。
- around 与搜索邻文沿原账本内部事件顺序，不把时间排序键误当消息主键。邻文只沿 Conversation、keeper、message、floor 及每个锚点的 id 邻接范围；不带 keyword、exclude、person_id、author_kind、时间、has 或搜索 cursor 条件。它可展示其他作者和时间，明确标为 context。

## 6. 返回与实时续查

~~~json
{
  "source": "canonical_ledger",
  "coverage": "observed",
  "conversation_id": "<内部 Conversation UUID>",
  "read_semantics": "live",
  "matches": [
    {
      "id": 381,
      "person_id": "<原作者 Person UUID>",
      "author_kind": "person",
      "content": "电吉他预算三千",
      "matched_fields": ["content"]
    }
  ],
  "context": [],
  "returned_count": 1,
  "has_more": true,
  "next_cursor": {
    "occurred_at": "2026-10-20T12:00:00Z",
    "id": 381
  }
}
~~~

示例省略的原事件字段不意味着另造简化消息合同。Main 的 id、around 的 event_id 与待补齐的 Plugin 历史 event_id 都指向同一个内部账本主键；不输出旧平台 sender_user_id 作为业务身份。Plugin 的 message_id 保原平台传输语义，不能就地改解释成内部 ID；presence_id 保接入语义，原作者另用明确的 author_presence_id。未入账输入没有内部事件 ID 时不造值。历史输出补原作者、回复主键和结构化 current ASR 证据，ASR-only 命中必须能看到实际匹配的片段，不能仍只返回空正文。

- 批读直到找到 limit+1 个真实命中或实际穷尽；只返回前 limit 个。Main matches 严格按所选 order 的查询方向返回；has_more 由额外命中证明，不能恒写 false；next_cursor 指向**该方向最后已返回的命中**，不跳过尚未返回的额外命中。Plugin 仅在完成选取后按其合同正序展示，不能拿反转后的列表末项重算游标。
- recent 用小于该键的后续范围，oldest 用大于；不使用越来越深的 OFFSET。cursor 作为排序边界不要求原行仍存在，因此删除页尾事件后仍可继续。
- 每次调用重新核当前真实授权并解析本页人物族；同一次调用各批次持有同一个只读快照完成候选、核验和本页上下文。批次之间不等待外部工作，真实取消结束事务，跨调用不持有事务。扫描可使读事务变长，不把“分批”写成短快照保证。
- **实时分页不是静态导出。** 页间新增、迟到插入、ASR、合并、删除、floor/keeper 改变，可能改变后页；页前新近匹配可从首页另查，不承诺整个会话的一次性无漏快照。静态数据才验证所有页可覆盖、不重不漏。
- 同人族在页间变化也沿当前含义读取：B root 未变而 A 合并到 B 时，下一页按新的族读取，但不宣称与上一页属于同一个结果快照。不为此引入身份版本服务或强制从头重跑。
- 改筛选或 limit 后，cursor 仍只是当前筛选的位置；它不能带入旧授权、旧人物集合、旧 floor 或另一个会话。无需 HMAC、进程密钥、生命周期票据、预算签名和 cursor_stale 自动循环。
- 搜索自身不以人为扫描预算停在“一个命中都没返回”的中间位置；真实取消/超时沿现有调用链传播，释放读事务，不伪造穷尽。
- context 与 matches 按内部事件 ID 去重，命中优先。上下文只增加原文，不产生新的“证据组结论”，也不受关键词或人物筛选伪装成同一作者。
- 完整原文、ASR 的真实 source/segment_index、reply_to_event_id、原 mention 快照和稳定 attachment_index 共用领域来源与 renderer；Main 和 Plugin 补齐各自缺失的输出字段。不能从当前账号重渲染，也不能筛媒体后重新 enumerate。
- 文件是否仍在 24 小时缓存中不改变消息命中；返回现有附件元数据/索引，不强读、续期下载、识图、ASR 或自动解说。
- 超长结果沿既有工具结果/artifact 路径，保留分页信息及真实来源。完整 artifact 的 has_more/next_cursor 可由通用 get 读取；外层 truncated/ToolReceiptView.complete 是展示完整度，不是查询是否穷尽。显示预算不暗改匹配或剩余数量，不另加结果字数硬门槛、摘要白名单或特殊搜索取回工具，不改已提交协议前缀。

## 7. 查询算法与性能工作

### 7.1 正确性基线

复用 EventLedgerRepository 和既有 ConversationScope、keeper、同人族与时间绑定。不创建“搜索授权器”、独立搜索服务或第二套人物映射。

1. 本页只读事务中解析可信 Conversation 和原读取授权、floor、实际人物族。
2. SQL 先应用范围、keeper、message、真实作者和时间等可下推条件；按全序 keyset 成批取候选。没有 keyword 且没有 exclude 的纯元数据筛选直接在 SQL 取 N+1，不为它逐行正规化全文。仅 exclude 仍要核验正文/ASR，不能误走这条快速路径。
3. 纯匹配函数核验 content 和独立 current ASR；记录命中字段，不把原 ASR JSON 作为全文。
4. 得到 N+1 或穷尽即停止；需要的上下文从同一读快照批量读取。各锚点用自己的索引邻接范围和请求条数，可组合子查询批读；不要求固定 SQL 数量。不要对每条结果逐次等待独立 around 工具调用，也不要为两个相距很远的命中扫完整中间历史。
5. 结束事务后格式化/交给既有结果管道。沿既有来源、隐私清退和提交规则处理真实失效，不以无关入站或 ASR 变化废弃已经读出的正常页面。

基线最坏须检查当前授权范围的 N 个事件及其文本，不能声称常见短词或无命中查询天然 O(log N)。批量只控制内存/调用粒度，不是结果截断、权限或完成条件。真实运行仍要测读事务、取消、WAL 增长和 writer 等待；“只返回一行”不证明只访问一行或耗时有上界。

### 7.2 索引是测量后的单一选择

先修正确性，可与离线测量并行，不用完整评测套件阻止 G02/G04/G05 等独立修复。实施者对当前 schema、不同 Conversation 大小和长短正文给出比较：

| 候选 | 价值及必须承认的代价 |
| --- | --- |
| 当前 trigram | 只在已证明与匹配定义相容的路径上加速；不能用原文 trigram 的结果截断经过 NFKC/casefold 后的新匹配。短词和排除词仍需真实核验。 |
| 一个规范化派生文档＋trigram | 词长至少三字的候选可加速；一两字仍可能扫描。规范化、ASR 来源与原文必须一致维护。 |
| 规范化 1/2/3-gram 索引 | 可索引短词；需量化索引大小、常见字候选、ASR 更新写放大、回填及维护成本。不是唯一正确方案。 |

**产品只采用实测选中的一条读写路径，删除被替换路径与消费者，不为三套方案配置开关或隐式失败链。** 实测后确认原文路径合适，也可作为最终选择；是否新增索引不充当完成门槛。尚未完成测量和取舍时如实报告性能工作未完成，不能声称“已经最快”，也不在任务书中编造延迟或读量阈值。

候选数量和正文字节量均需测；SQL 的 Conversation 条件不自动证明 FTS 内部只遍历该会话。多会话交错 ID、常见字和稀疏命中必须验证真实计划及访问量。

加速候选必须覆盖真实命中。排除条件在独立合法字段的精确核验阶段生效，不能拿近似词元、拼接字段或超集候选的 NOT 提前删事件；除非证明它与精确定义等价，否则后置核验无法找回被删候选。只有 exclude 而无可用正向条件时，沿授权范围核验。

all 可以用完整覆盖某个必需词的候选作锚点，再核其余词；any 必须覆盖每个分支的并集，不能只拿可索引长词作锚点而漏短词。各字段、基础/繁简表示、索引与缺行来源按原 event_id 合并去重、沿同一搜索方向取数后，才核验、计数和判断 N+1；同一事件多次命中不等于有下一条消息。不能证明候选覆盖时沿范围核验，不另建分页协调器。

普通范围/作者/时间索引候选为 (canonical_conversation_id,occurred_at,id) 与按需的 (canonical_conversation_id,author_person_id,occurred_at,id)。是否建立以及 partial 谓词由当前查询计划决定；需要覆盖 keeper 与 legacy NULL，平台 sender_user_id 索引不是同人作者索引。

### 7.3 来源变更、回填和真实隐私

若选中新索引：

- 派生内容只认原事件 ID 与实际被索引字段；不把 Person root、账号当前 owner、名字或会话汇总抄成第二份业务身份。
- 每个存在的派生行必须对应当前匹配定义和当前实际来源。匹配定义变化时，以迁移替换旧派生结构并重新回填，不保留旧行冒充新定义；缺行原文路径不能挽救“有行但定义已旧”的漏查。不为此另建运行时版本服务。
- 优先在现有正文/ASR 写路径前准备转换，在原事件短事务内提交其派生变化。复杂准备在首次 DML/BEGIN IMMEDIATE 前完成。
- 回填按内部主键分批，读取/转换在 writer 外；在提交派生变化的同一个短 writer 内，以条件写或等价原子接纳核原内容/ASR及实际隐私来源仍一致，并处理真实受影响行数。不能把核对放在 writer 前另一次预读；也不能只查 EXISTS(id)，因为原地脱敏后事件仍存在。事务里不重做转换或扫描历史，不新增全局协调器。
- 删除或脱敏原事件时清退旧派生资料。旧准备者不得把旧词元写回来；来源改变即丢弃该份准备，以真实新来源重新准备，不借此重做外部识别或发送。
- 缺派生行的原事件不能成为搜索盲区；应沿明确的原文核验路径读取。读候选与缺行时使用同一快照，防止索引交接漏查。该路径不提供另一种匹配定义。
- 不预设 queue/frontier/epoch 或驻留 worker；只有选型证明确需后台维护时才说明唯一事实源、调用者和退出方式。不得为查询反复扫空库、每次启动随机自检、定时全库巡检或自动清库重建。
- 迁移只做必要结构工作，冻结自己的 SQL，不引用可变 ORM。不得在单一 writer 中正规化、遍历并排入全部历史；回填不能变成启动或模型回复前置条件。
- Alembic 与 create_schema 验证实际行为一致，不能只比较 SQL 字符串；空库、首条消息、缺行、ASR 更新、脱敏、删除均纳入。

无论是否新增索引，搜索结果的真实隐私清退都要核对：

- 正式隐私遗忘另核工具 call/result、Work journal、artifact、必要 context_note 和协议资料中的实际来源引用与清退路径。它们不因“没建结果表”自动消失。
- 按真实隐私授权清退，不把普通同人合并、换绑、generation 变化或缓存过期误当隐私删除；不重写普通已发生效果或原回执。
- 若现结果管道不能沿原事件追踪这些副本，作为本任务真实缺口补齐最小来源引用与删除消费者；禁止仅写“沿既有链”就宣称已覆盖。
- 结果进入现有持久化管道时，在其最终接纳点把实际来源/隐私核对与登记原子关联，不能“预读核对后，另开事务无条件登记”。外置文件沿原 artifact 暂存/登记/清退合同，不要求文件和 SQLite 做分布式事务；遗忘提交与迟到登记交错的行为须实证。查询内核仍只读，不为此新增搜索专用写锁、全局协调器或万能 prompt_source_revision 门禁。
- 删除完成前读出的旧结果不能在删除完成后重新引入已清退正文；普通无关消息或 ASR 更新不新增搜索失效门禁。当前调用的真实来源/授权、原 generation 或租约失效仍沿既有执行与提交合同处理，保留原回执；不能因此给旧执行补发资格或自动重跑。

数据库损坏返回真实失败，由显式维护修复；不把抽样通过当完整性证明，也不让错误触发普通查询中的自动删库、切方案或外部补查。
