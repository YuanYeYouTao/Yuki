# Yuki 3.8.4 发布说明

<!-- release-baseline: version=3.8.4 schema=0072 -->

本页以正式标签 [`v3.8.3`](https://github.com/YuanYeYouTao/Yuki/releases/tag/v3.8.3) 为起点，记录其后已合入主线的 PR。发行资产、镜像和现有服务器的部署状态分别核验；发布本身不会自动升级服务器。

## 主要变化

### 发言成为 Yuki 自己的显式行动

主 Agent 通过统一的 `send_message` 发送可见消息，可以按对话需要分条发送；最终正文不再由调度器自动转发。模型也可以选择 `NO_REPLY`。普通聊天、自动化、插件唤醒与自主工作沿用同一主 Agent 工具合同，执行时核验真实来源、权限与发送回执。这样 Yuki 能决定**说什么、何时发送，以及是否沉默**，但不意味着可以绕过群聊权限或保证每次机会都发言。

### 群聊语义观察与自主行为

可选的语义参与在群聊中观察邀请、续聊、记忆线索和无当前消息来源的自主机会，经过控制器接纳后由正式 SELF Work 唤醒主 Agent。直接叫“Yuki”会被优先观察，**不等同于 `@` 的直接触发**；讨论归属不是邀请的硬门槛。接纳后的 Yuki 可以自然开口、继续有意义的讨论、查证或推进自己的工作，也可以合理选择不发。

连续机会模型为长时间无人说话的群保留偶发机会，同时结合已有互动、互惠反馈、未获回复的发送和沉寂时间决定是否提出机会；它不是固定静默超时后强制发言。已确认的 Social 发送按内部事件关联参与运行，供后续反馈使用。重置会话后无需等待新消息即可恢复自主采样；自主模型参数可从挂载配置热加载，错误配置保留上一个有效版本。群聊自主总开关和语义参与开关仍由部署配置与群空间共同约束，**语义参与默认关闭**。独立参与库的模型版本已固定；合成轨迹和控制器回放只验证机制，真实 QQ 群聊的长期社交效果仍需观察。

### SELF 自动化与持久工作

Yuki 自己创建的自动化使用稳定 SELF 主体、原群场景和与用户自动化一致的主 Agent 执行与投递链。定时发送统一经 `social.send_message`，任务可持久等待原 Work 信号并沿原执行 ID 恢复。SELF 不能借用最近发言者或管理员权限；当前自主社交范围限定于授权群聊，不因此获得私聊权限。

### 恢复、身份与插件

回复、历史、图片、记忆和发送回执沿内部事件 ID 关联，平台消息 ID 只用于平台交互。历史投影在每组首条消息旁显示内部事件的本地时间；同一发送者相邻消息最多按五分钟窗口分组。原 Work 在断连、来源变化或执行冲突时按已知效果和持久回执决定恢复，不盲目重发；已接纳但在写账本前遭遇网关断连的群消息继续保留。模型未发送的最终正文与 Provider 故障分开归因，字面量 `NO_REPLY` 不会作为消息送出。Self Reflection 的部分失败、后台数据库占用、模型输出恢复及关系任务也得到修复。

新增订阅监控插件，经主 Agent 处理 RSS/Atom/JSON Feed 通知；GitHub Monitor 接受的积压事件加快出队，**外部 API 轮询间隔没有改变**。插件开发合同现为 Plugin API 3.0，旧插件需迁移。

### 聊天媒体与任务可见性

聊天记录中的图片、视频和文件通过内部事件与附件序号索引；来源字节缓存 24 小时，可在原会话内按引用查看，并可显式提升到共享工作区。旧自动化发送实现已删除，定时发送沿统一 Social 路由。升级到媒体索引迁移 `0072` 时，已有会话需按升级指南在停写状态执行一次离线 generation 重置；不会批量重写旧聊天历史。

普通聊天不再常驻注入当前群的自动化任务快照。需要查询、创建或管理任务时，主 Agent 按需使用 `automation_list` 核实；读工具不扩大修改权限。
