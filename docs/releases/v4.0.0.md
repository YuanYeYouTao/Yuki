# Yuki 4.0.0 开发基线

<!-- release-baseline: version=4.0.0 schema=0143 -->

[English](v4.0.0.en.md) · [升级指南](../upgrade-4.0.0.md) · [全部 PR 与贡献者](v4.0.0-prs.md)

4.0.0 把 Yuki 从以 QQ 为中心的 Bot，推进为同一个长期存在的 Yuki、多个平台入口和个人客户端共用的 Agent。QQ、Telegram、App 和 ACP 使用共同 Main、Work、Memory 与发送服务；人物、账号、会话和已经发生的执行各自保存真实归属。工具收拢到持久终端，媒体按需读取，表情改为文件库，管理从旧 WebUI 转向独立控制面。

这是 **4.0.0 的源码开发基线**。产品范围是正式 [`v3.9.0`](https://github.com/YuanYeYouTao/Yuki/releases/tag/v3.9.0) 的提交 `12de953e` 之后，到 main [`d7d14bc7`](https://github.com/YuanYeYouTao/Yuki/commit/d7d14bc7a0f7223dd8ddfc756de1df0d9921cae4)（#487）的 **37 个已合并 PR、185 个提交**；整理本文的 PR 不递归计入。当前数据库 head 为 `0143`，Plugin API 为 `7.0`，Main 固定工具合同为 `25`。正式下载仍见 3.9.0 Release。

## 多个平台，同一个人物

人物不再由 QQ 账号代替。一个 Person 可以有多个平台账号，也可以暂时没有账号；人物主名、账号昵称和群名片分别保存。账号转给另一个人会建立新的归属阶段，原人物的历史、Memory、Work 和执行回执继续归原人；同一人的显式合并则统一当前资料，保留各入口的独立会话。QQ 私聊、Telegram topic、App 与 ACP 不会因为关联账号而拼成一段历史。

底层用 Account 和唯一 AccountAssignment 统一原 Binding、Presence 的归属记录。入站作者、发送 ACK、旧设备和恢复中的任务都沿原内部身份处理，停用、解绑、换人或改名不会重写过去。通用工具及插件使用内部 Person、Space、Conversation ID，平台裸号留在传输边界。主要 PR：[#458](https://github.com/YuanYeYouTao/Yuki/pull/458)、[#482](https://github.com/YuanYeYouTao/Yuki/pull/482)、[#484](https://github.com/YuanYeYouTao/Yuki/pull/484)。

原生提及现在保留原句位置、当时名字和逐账号快照，Main、语义参与、历史与插件看到相同对象。发送自然 `@名字` 时按实际目标会话解析；真重名默认选择该会话最近发言的账号，也可用 `@{account:UUID}` 精确指定。无法解析时保留原文，普通文字不会被猜成平台提及；原位匹配和索引点查也修复了同一账号被误报为重名、`@` 被吞掉的问题。主要 PR：[#474](https://github.com/YuanYeYouTao/Yuki/pull/474)、[#484](https://github.com/YuanYeYouTao/Yuki/pull/484)、[#486](https://github.com/YuanYeYouTao/Yuki/pull/486)。

## 管理 API、个人入口与 ACP

旧浏览器 WebUI 的管理职责由管理 API、`yuki admin` CLI 和共同应用操作承接。超级管理员资格直接保存于 Person：换平台或解绑不丢资格，账号转给别人也不把资格带走。聊天管理统一为 `/ai admin <领域> <操作>`，人物、账号阶段、群恢复、模型、插件、Work 和原操作回执可按内部编号查询与管理。插件停用或首次启用前也能修配置；设备资料的普通读取不再写入“活跃度”。主要 PR：[#458](https://github.com/YuanYeYouTao/Yuki/pull/458)、[#476](https://github.com/YuanYeYouTao/Yuki/pull/476)、[#482](https://github.com/YuanYeYouTao/Yuki/pull/482)。

个人 API 提供一次性配对码、设备凭据、消息、附件、历史、Work 和 SSE 接续。设备凭据与 operator 管理凭据分开；没有 QQ 账号的人也能由 operator 创建 Person 并配对。原请求 UUID 保存投递和查询事实，响应丢失后查原请求，不因重新连接重复提交。

`yuki acp` 让外部 ACP 客户端通过本地 stdio 使用 Yuki，每个 session 对应独立 Conversation，复用同一 Main 和持久 Work。另一个方向的固定 `external_agent` 工具可以在原持久 Linux 环境中，委托 operator 配置的 ACP Agent，读取原 prompt、处理权限问题、取消或关闭原 peer。重连继续查原 session/request/run，不重新购买未知请求；普通任务完成也不自动关闭可复用 peer。主要 PR：[#469](https://github.com/YuanYeYouTao/Yuki/pull/469)、[#470](https://github.com/YuanYeYouTao/Yuki/pull/470)。

[Yuki Desktop](https://github.com/Institute-of-Agent-Life/Yuki-Desktop) 是单独维护的跨平台桌面客户端项目；其公开仓库目前提供项目简介与授权。当前个人 API、ACP 支持范围及互操作限制见[客户端合同](../architecture/client-api.md)。

## 更直接的工具与持久终端

普通文件、Python、系统包和交互 shell 统一使用持久 Linux 环境的 `terminal_exec`、`terminal_read`、`terminal_control`。环境内是管理员身份，HOME 仍为 `/home/yuki`，既有安装、后台服务和 `/workspace` 持续保留。执行默认没有时间上限，工具尽快返回原 run ID；之后读取增量输出、输入或取消原执行。取消一次观察不会停止程序。

八项普通 `workspace_*` 文件操作、专用包管理以及旧终端写入/取消入口退出新调用；需要模型查看媒体或交付文件时，仍使用 `workspace_inspect`、`workspace_publish` 和不可变 artifact。自动化收拢为 `automation_query/manage`，聊天历史为 `query_chat_history`，记忆详情为 `read_memory`，子任务消息并入 `subagent_control`。direct 与可选 Code Mode 共用领域实现和执行授权。主要 PR：[#463](https://github.com/YuanYeYouTao/Yuki/pull/463)、[#464](https://github.com/YuanYeYouTao/Yuki/pull/464)、[#470](https://github.com/YuanYeYouTao/Yuki/pull/470)。

搜索和网页读取分开。`web_search` 不再偷偷抓取来源页，明确调用 `read_webpage` 才读取正文；搜索连接可以独立选择 Gemini、Anthropic Messages 或 Responses，主模型保持自己的协议。删除隐式 Tavily 依赖，明确的 Tavily 配置仍有效。网页和 Telegram HTTP 复用标准代理与 CA 配置，固定公网 IP 的 HTTPS 请求保留原网站 Host 和证书校验。主要 PR：[#441](https://github.com/YuanYeYouTao/Yuki/pull/441)、[#457](https://github.com/YuanYeYouTao/Yuki/pull/457)、[#459](https://github.com/YuanYeYouTao/Yuki/pull/459)、[#463](https://github.com/YuanYeYouTao/Yuki/pull/463)、[#466](https://github.com/YuanYeYouTao/Yuki/pull/466)。

## 附件按需读，文字先发，表情后台追加

图片、视频、贴纸与文件的原件统一保存在 24 小时共享只读缓存，首次 Main 输入只给附件索引和文件资料，由 Agent 按需查看或收藏到工作区；不再把所有图片和文档自动展开进首个请求。语音转写保留独立配置，并新增显式 `ASR_PROTOCOL=audio_transcriptions`，可调用兼容服务的标准 multipart `/audio/transcriptions`；默认 `chat_completions` 仍保留原 Qwen 音频协议。主要 PR：[#480](https://github.com/YuanYeYouTao/Yuki/pull/480)、[#482](https://github.com/YuanYeYouTao/Yuki/pull/482)、[#483](https://github.com/YuanYeYouTao/Yuki/pull/483)。

表情原图和逐项 JSON 改为 `/workspace/stickers/<platform>/` 下的唯一资料源，标签可直接编辑，检索索引可重建。删除旧表情池、偷图 worker、分类采用和容量替换策略。`send_message.emoji` 支持图文和纯表情：文字沿原 Social 先发，后台再独立选图、发布快照并发送，Main 不等待配图。Telegram 保留 WEBP/TGS/WebM 原件与预览，QQ 保留原生小表情行为。主要 PR：[#480](https://github.com/YuanYeYouTao/Yuki/pull/480)、[#481](https://github.com/YuanYeYouTao/Yuki/pull/481)、[#482](https://github.com/YuanYeYouTao/Yuki/pull/482)。

这一轮还修复了原接收账号附件下载、普通聊天配图被空 Work ID 拒绝、中文英文混合标签分词，以及分段文字中断后配图意图丢失。恢复沿原文字与图片的分步回执，已发文字不重发，已确认图片不重选。引用消息导致的 `UnboundLocalError`、旧标记规则误删普通正文、编辑后原生提及丢失等问题也已修正。主要 PR：[#461](https://github.com/YuanYeYouTao/Yuki/pull/461)、[#466](https://github.com/YuanYeYouTao/Yuki/pull/466)、[#481](https://github.com/YuanYeYouTao/Yuki/pull/481)、[#482](https://github.com/YuanYeYouTao/Yuki/pull/482)、[#487](https://github.com/YuanYeYouTao/Yuki/pull/487)。

## 接话、静默工作与记忆

普通 Main 已选入的新消息归入同一 activation，排队入口不会再次为它回复。后到的参与反馈不再否决已经选入并付费处理的输入；自动语义邀请复用既有防抖，显式 @ 与已有 Work 的补充仍走原优先关系。后台记忆种子链退出，普通消息入口不再反复计算整份参与状态。主要 PR：[#444](https://github.com/YuanYeYouTao/Yuki/pull/444)、[#445](https://github.com/YuanYeYouTao/Yuki/pull/445)、[#446](https://github.com/YuanYeYouTao/Yuki/pull/446)、[#450](https://github.com/YuanYeYouTao/Yuki/pull/450)、[#451](https://github.com/YuanYeYouTao/Yuki/pull/451)。

SELF 醒来优先安静推进待办、资料和已有工作；没有可推进事项时保持静默，需要持续跟进则保存线索或等待条件，按用户约定和重要变化决定通知。运行资料被明确为程序提供的当前背景，不构成新发言或额外授权。真实空输入、Telegram 服务更新不再触发“请输入内容”式固定回复；支持的平台使用独立后台的原生输入状态，Main 不等待状态网络请求。QQ 私聊和 Telegram 支持该能力，当前 SnowLuma QQ 群没有相应接口。主要 PR：[#443](https://github.com/YuanYeYouTao/Yuki/pull/443)、[#467](https://github.com/YuanYeYouTao/Yuki/pull/467)、[#479](https://github.com/YuanYeYouTao/Yuki/pull/479)。

自省只处理本批新证据、工具结果与必要衔接，生成新记忆/Episode；旧正式记忆整理由 Dream 负责，不再每批回灌全部旧事实与候选。遗忘后的旧正文副本、迟到模型返回，以及 Embedding 部分成功后重复购买的问题一并修复。主要 PR：[#465](https://github.com/YuanYeYouTao/Yuki/pull/465)、[#487](https://github.com/YuanYeYouTao/Yuki/pull/487)。

## 上下文、恢复与数据库开销

自动 Compact 的默认 `96000` token 是提前整理水位，模型硬容量单独取当前 Profile 的明确声明。请求仍放得下时，不因没有可整理前缀或整理后高于水位而拒绝继续。公共投影改为不可变追加块，复用已有字节，只读取和写入真实增量；精确私有协议恢复也能接入同会话实际选中的新公共输入，保原签名、工具配对和累计预算。主要 PR：[#462](https://github.com/YuanYeYouTao/Yuki/pull/462)、[#471](https://github.com/YuanYeYouTao/Yuki/pull/471)、[#487](https://github.com/YuanYeYouTao/Yuki/pull/487)。

首答前同步补查远端昵称、群名和群名片的链路退出，改从原生事件更新已有资料。重复诊断、工具统计和回合观测写入减少，SQLite 租约、附件授权、任务祖先、归档、参与反馈、Memory/Reflection 与插件队列改为按实际候选或索引查询。性能索引缺失不再成为启动拒绝条件；调度器按真实空闲名额选择工作，不把候选检查次数当作容量。主要 PR：[#468](https://github.com/YuanYeYouTao/Yuki/pull/468)、[#471](https://github.com/YuanYeYouTao/Yuki/pull/471)、[#472](https://github.com/YuanYeYouTao/Yuki/pull/472)、[#477](https://github.com/YuanYeYouTao/Yuki/pull/477)、[#486](https://github.com/YuanYeYouTao/Yuki/pull/486)、[#487](https://github.com/YuanYeYouTao/Yuki/pull/487)。

这些变更有 SQL、迁移、协议与真实原生执行回归支持。局部扫描量和写入字节的减少，仍与具体部署的端到端延迟、模型费用及缓存命中率分别观察。

## 插件与相关项目

Plugin API 从 3.9.0 的 `3.5` 演进到 **`7.0`，Host 精确匹配**。插件须适配内部身份、原位提及 `CurrentMessage.mentions`、旧表情 facade 退役及 `plugin.agent_session.v2`。独立模型会话删除未生效的工具能力和工具预算参数，保留真实模型请求预算；已接纳结果不因自然到期或辅助审计失败而被推翻，一个后台 runner 失败也不再停止整个插件。见 [API 7.0 迁移](../plugin-development/api-7.0-migration.md)和[升级指南](../upgrade-4.0.0.md)。

GitHub Monitor 已从主仓外置，[Yuki GitHub Monitor](https://github.com/Institute-of-Agent-Life/Yuki-GitHub-Monitor)、[Yuki Kun Game](https://github.com/Institute-of-Agent-Life/Yuki-Kun-Game) 与 [Yuki Semantic Participation](https://github.com/Institute-of-Agent-Life/Yuki-Semantic-Participation) 在组织仓库分别维护；参与库继续由锁文件固定版本，外置不改原插件 ID、数据或批准。主要 PR：[#458](https://github.com/YuanYeYouTao/Yuki/pull/458)、[#480](https://github.com/YuanYeYouTao/Yuki/pull/480)、[#484](https://github.com/YuanYeYouTao/Yuki/pull/484)、[#485](https://github.com/YuanYeYouTao/Yuki/pull/485)、[#487](https://github.com/YuanYeYouTao/Yuki/pull/487)。

## 升级与贡献

Python 模块和发行包统一为 `yuki`，命令为 `yuki` / `yuki-bot`；旧 `qq_ai_bot` 和旧可执行别名退出。已有部署保留原数据库路径、Compose 项目、挂载与网关，按实际 revision 从 `0119` 前向迁移到 `0143`。人物资格、Plugin API、系统提示实际挂载文件、Manager、原环境 rootFS 和共享媒体挂载需配套处理，详见[4.0.0 升级指南](../upgrade-4.0.0.md)。

37 个 PR 中，35 个由 [YuanYeYouTao](https://github.com/YuanYeYouTao) 提交，2 个由 [Hilbert-beinghappy](https://github.com/Hilbert-beinghappy) 提交。Hilbert-beinghappy 的原始 #299 控制面工作由 #458 接续实现，本范围内另贡献多入口任务书 #436 和插件示例修正 #420；参与库原 `allowed_kinds` 的贡献也沿上游记录保留。维护者确定人物、平台、工具与删除导向边界，Codex 协助实现、验证和交叉复审。每项 PR 的作者、内容、合并提交和归属见[完整目录](v4.0.0-prs.md)。
