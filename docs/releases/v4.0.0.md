# Yuki 4.0.0 发布说明

<!-- release-baseline: version=4.0.0 schema=0156 -->

[English](https://github.com/YuanYeYouTao/Yuki/blob/v4.0.0/docs/releases/v4.0.0.en.md) · [升级指南](https://github.com/YuanYeYouTao/Yuki/blob/v4.0.0/docs/upgrade-4.0.0.md) · [全部 PR 目录](https://github.com/YuanYeYouTao/Yuki/blob/v4.0.0/docs/releases/v4.0.0-prs.md)

4.0 把 Yuki 从一个以 QQ 为中心的机器人，变成一个跨平台、长期存在的 Agent。QQ、Telegram、飞书、Lark、个人客户端和 ACP 共用同一套人物、记忆、工具和任务。Yuki 有了自己能看、能点的电脑，也能在你授权后操作你的电脑、和你的电脑互传文件。安装从“部署 Bot 再单独装沙箱”变成一条命令。

本版覆盖 3.9.0 之后到 #610 的 **146 个已合并 PR**，逐项列在 [PR 目录](https://github.com/YuanYeYouTao/Yuki/blob/v4.0.0/docs/releases/v4.0.0-prs.md)。

## 一条命令安装，沙箱进 Compose

宿主机只需要 Docker 和 Compose 插件。`install.sh`（Windows 为 `install.ps1`）下载并校验发布包，运行配置向导，选择沙箱档位，创建数据卷，启动全部服务，并等到 Yuki 的环境真正可用才结束。在同一目录再运行一次就是升级，`.env`、数据和 `docker-compose.override.yml` 保留；加 `--yes --profile <档位> --answers model.json` 可无人值守安装。

首次安装会问你的名字，装好后自动创建你的人物和管理员资格，并打印 Yuki Desktop 的地址和绑定码；绑定码 10 分钟有效，`sh deploy/pair.sh` 可再取一个。Bot 只发布到本机 `127.0.0.1:8080`，其他设备经 Tailscale 或 HTTPS 访问。Manager 随宿主重启自动恢复。

沙箱的 Manager 改为 Compose 里的一个服务，与 Bot 使用同一镜像和版本；HOME、运行记录、Manager 状态和媒体缓存是 Docker 命名卷，`docker compose down -v` 不会删除它们。宿主机上的 systemd 单元、venv、loop 挂载的 ext4 盘、同步脚本和内网 Squid 代理全部退出。

| 档位 | 内容 | 内存约 |
| --- | --- | --- |
| `lite` | 终端和文件 | 512 MiB |
| `headless` | 加无头 Chromium | 1 GiB |
| `desktop` | 加可观看、可接管的桌面和有头 Chromium | 3 GiB |

安装器按 Docker 内存推荐档位。Docker 注册了带 `--overlay2=none` 的 gVisor（`runsc`）时使用 gVisor，否则用 `runc`，选定后不再隐式改变。换档只需改 `.env` 的 `YUKI_SANDBOX_PROFILE` 再 `docker compose up -d`：换大在原环境上补装软件，换小只改模式和资源，内存、CPU 等限额即时生效。环境可以访问公网，不能访问宿主机和私有网络。发布同时提供 `yuki-environment` 的两个镜像（`lite` 用基础镜像，另两档用 `-desktop` 镜像），Bot 与环境镜像均为 amd64/arm64；ARM64 上也能运行可选的 Code Mode。

旧部署的宿主 Manager 用 `deploy/sandbox/migrate-host-manager.sh` 一次性迁入，原环境里装过的软件和文件都带过来，见[升级指南](https://github.com/YuanYeYouTao/Yuki/blob/v4.0.0/docs/upgrade-4.0.0.md)。相关 PR：[#610](https://github.com/YuanYeYouTao/Yuki/pull/610)、[#609](https://github.com/YuanYeYouTao/Yuki/pull/609)、[#607](https://github.com/YuanYeYouTao/Yuki/pull/607)、[#606](https://github.com/YuanYeYouTao/Yuki/pull/606)、[#567](https://github.com/YuanYeYouTao/Yuki/pull/567)、[#570](https://github.com/YuanYeYouTao/Yuki/pull/570)、[#571](https://github.com/YuanYeYouTao/Yuki/pull/571)、[#572](https://github.com/YuanYeYouTao/Yuki/pull/572)、[#519](https://github.com/YuanYeYouTao/Yuki/pull/519)、[#521](https://github.com/YuanYeYouTao/Yuki/pull/521)、[#464](https://github.com/YuanYeYouTao/Yuki/pull/464)。

## Yuki 自己的电脑：屏幕和浏览器

新增 `computer` 与 `browser` 两个工具。`computer` 截屏、点击、双击、右键、拖拽、输入、按键和滚动，坐标就是截图上的像素；`browser` 按页面快照节点操作 Yuki 专用的 Chromium，支持对话框、下载、文件选择和跨站 iframe。`desktop` 档有可观看的桌面，你可以在 Yuki Desktop 的电脑窗口里看着她操作，随时接管、再交还；`headless` 档只有无头浏览器，`lite` 档没有浏览器，相应工具会明确返回不可用。

输入动作逐个执行并留有回执，同一次调用重试拿到原结果，中途中断的报告为未知而不会重做；你接管期间她的输入会被拒绝，截图照常可读。相关 PR：[#595](https://github.com/YuanYeYouTao/Yuki/pull/595)、[#596](https://github.com/YuanYeYouTao/Yuki/pull/596)、[#597](https://github.com/YuanYeYouTao/Yuki/pull/597)、[#591](https://github.com/YuanYeYouTao/Yuki/pull/591)、[#553](https://github.com/YuanYeYouTao/Yuki/pull/553)。

## 你的电脑

你的电脑通过[本机连接器](https://github.com/YuanYeYouTao/Yuki/blob/v4.0.0/docs/operations/local-agent-connector.zh-CN.md)主动连到 Yuki，不用开放入站端口。在 Yuki Desktop 的「設定 → 這台電腦」里连接即可，Desktop 自带连接器运行时，随 Desktop 启动、退出时停止，最小化到托盘时仍保持连接。连接器版本为 **0.6.2**。

- **完整访问。** 默认关闭，只能由你在本机打开。打开后 Yuki 以你当前系统账号的权限运行命令（PowerShell 或 POSIX Shell）、读写文件、运行已安装的程序；关闭后新的命令、文件和浏览器操作立即被拒绝。
- **屏幕。** macOS 14 及以上和 Windows 支持 `computer`：截屏、点击、输入，支持多显示器和高分屏。你正在用电脑时她不会抢着输入，而是等你停手、按新的截图重试；Desktop 里按「停止」可以随时叫停。macOS 需要给 Yuki.app 屏幕录制和辅助功能权限。
- **后台操作单个窗口。** 指定窗口时只截这个窗口（被遮挡也能截到），输入只投给它，不动你的光标、不切换前台 App。macOS 支持点击、输入、按键、滚动等动作；Windows 通过 UI Automation 支持点击、滚动和向输入框输入。窗口不在你当前的 macOS 桌面空间时只能截图。
- **专用浏览器。** `browser` 使用你已安装的 Google Chrome，但用独立的配置目录，不碰你日常 Chrome 的登录状态。
- **编码 Agent。** 可以调用你电脑上的 Codex、Claude Code 或其他 ACP Agent，沿用它们自己的登录和会话；进度和提问回到 Yuki 原来的任务里。编辑或删除一个 Agent 不会重启无关连接。

连接器断线后自动重连，服务端出错也不会再让它停在“已撤销”状态；更换服务器地址（例如改用 Tailscale）保留原设备身份，不用重新配对。服务器端旧的本机执行器（LocalExecutor）和服务器上的 ACP 外部 Agent 链路退出。相关 PR：[#497](https://github.com/YuanYeYouTao/Yuki/pull/497)、[#510](https://github.com/YuanYeYouTao/Yuki/pull/510)、[#517](https://github.com/YuanYeYouTao/Yuki/pull/517)、[#518](https://github.com/YuanYeYouTao/Yuki/pull/518)、[#520](https://github.com/YuanYeYouTao/Yuki/pull/520)、[#530](https://github.com/YuanYeYouTao/Yuki/pull/530)、[#533](https://github.com/YuanYeYouTao/Yuki/pull/533)、[#535](https://github.com/YuanYeYouTao/Yuki/pull/535)、[#536](https://github.com/YuanYeYouTao/Yuki/pull/536)、[#540](https://github.com/YuanYeYouTao/Yuki/pull/540)、[#542](https://github.com/YuanYeYouTao/Yuki/pull/542)、[#556](https://github.com/YuanYeYouTao/Yuki/pull/556)、[#557](https://github.com/YuanYeYouTao/Yuki/pull/557)、[#561](https://github.com/YuanYeYouTao/Yuki/pull/561)、[#590](https://github.com/YuanYeYouTao/Yuki/pull/590)、[#593](https://github.com/YuanYeYouTao/Yuki/pull/593)、[#598](https://github.com/YuanYeYouTao/Yuki/pull/598)、[#599](https://github.com/YuanYeYouTao/Yuki/pull/599)、[#602](https://github.com/YuanYeYouTao/Yuki/pull/602)、[#603](https://github.com/YuanYeYouTao/Yuki/pull/603)、[#604](https://github.com/YuanYeYouTao/Yuki/pull/604)。

## 服务器和你的电脑之间传文件

`copy_file` 把文件原样复制到 Yuki 的环境或你的电脑。来源可以是聊天附件、Yuki 环境 `/workspace` 里的文件、已发送过的文件，或你电脑上的文件；也可以在两台已连接的电脑之间复制。目标已存在时原子替换，同一次调用重试不会重复写，结果未知时不会盲目重传。`view_file` 和 `send` 也可以直接读取或发送你电脑上的文件。

此前写到你电脑上的文件超过 64 KiB 时传输不会完成，本版已修复。相关 PR：[#576](https://github.com/YuanYeYouTao/Yuki/pull/576)、[#600](https://github.com/YuanYeYouTao/Yuki/pull/600)、[#574](https://github.com/YuanYeYouTao/Yuki/pull/574)。

## 多个平台，同一个人

QQ、Telegram、飞书和 Lark 共用身份、消息、媒体和发送服务。飞书/Lark 使用企业自建应用的长连接，不需要公网回调，支持私聊、群聊、话题、提及、引用和图片/文件，接入见[配置说明](https://github.com/YuanYeYouTao/Yuki/blob/v4.0.0/docs/operations/feishu.zh-CN.md)。

一个人可以关联多个平台账号，也可以没有账号。同人合并、账号转交、暂停和解绑分别处理；改昵称或换账号不会把旧消息、记忆和任务改归别人。各个聊天入口保留自己的对话历史。提及保留原句位置和当时的名字；某个平台入站出问题不再让整个 Bot 退出。相关 PR：[#458](https://github.com/YuanYeYouTao/Yuki/pull/458)、[#466](https://github.com/YuanYeYouTao/Yuki/pull/466)、[#468](https://github.com/YuanYeYouTao/Yuki/pull/468)、[#474](https://github.com/YuanYeYouTao/Yuki/pull/474)、[#484](https://github.com/YuanYeYouTao/Yuki/pull/484)、[#486](https://github.com/YuanYeYouTao/Yuki/pull/486)、[#491](https://github.com/YuanYeYouTao/Yuki/pull/491)、[#525](https://github.com/YuanYeYouTao/Yuki/pull/525)、[#531](https://github.com/YuanYeYouTao/Yuki/pull/531)。

## Yuki Desktop 与个人客户端

[Yuki Desktop](https://github.com/Institute-of-Agent-Life/Yuki-Desktop) 是单独发版的 Windows、macOS、Linux 客户端（目前为 beta），支持配对、聊天、附件、任务、文件、记忆、自动化、电脑、模型配置和用量，可以连接已有的 Yuki，也可以在本机部署一个。个人客户端 API 提供设备配对、消息、附件、事件流、任务查询与接续；ACP 客户端也能接入。

QQ 的登录画面改由 Desktop 经认证连接查看和接管，扫码不再需要单独发布的 noVNC 页面（6081 端口）。旧的管理 WebUI 退出，管理改用 Desktop、CLI 和 `/ai admin`。相关 PR：[#469](https://github.com/YuanYeYouTao/Yuki/pull/469)、[#510](https://github.com/YuanYeYouTao/Yuki/pull/510)、[#515](https://github.com/YuanYeYouTao/Yuki/pull/515)、[#516](https://github.com/YuanYeYouTao/Yuki/pull/516)、[#568](https://github.com/YuanYeYouTao/Yuki/pull/568)、[#569](https://github.com/YuanYeYouTao/Yuki/pull/569)。

## 长任务和插话

聊天、SELF 自主行动、定时任务、插件和子任务共用同一条任务链，保存目标、父子关系、累计预算、模型请求和已经发生的效果。重启或断线后按原记录继续，不重置预算、不重发已发出的消息。

私聊里 Yuki 一开始调用工具，这件事就成为一个持久任务：你接着发的补充会并入原任务，失败可重试时会在后台重试。定时任务运行时你发来的消息会排队等它，而不是被丢弃。原来每段固定的模型请求和工具调用上限（`AGENT_MAX_MODEL_REQUESTS`、`AGENT_MAX_TOOL_CALLS`）和分段续跑机制删除，长任务不再在第 24 次请求处静默停下；插件显式给出的上限改为整项任务的总预算。定时任务的设置也简化了。长会话的整理（Compact）沿用当前模型，复用公共检查点。相关 PR：[#444](https://github.com/YuanYeYouTao/Yuki/pull/444)、[#450](https://github.com/YuanYeYouTao/Yuki/pull/450)、[#470](https://github.com/YuanYeYouTao/Yuki/pull/470)、[#500](https://github.com/YuanYeYouTao/Yuki/pull/500)、[#502](https://github.com/YuanYeYouTao/Yuki/pull/502)、[#504](https://github.com/YuanYeYouTao/Yuki/pull/504)、[#511](https://github.com/YuanYeYouTao/Yuki/pull/511)、[#544](https://github.com/YuanYeYouTao/Yuki/pull/544)、[#555](https://github.com/YuanYeYouTao/Yuki/pull/555)、[#577](https://github.com/YuanYeYouTao/Yuki/pull/577)。

## 工具更少、更直接

工具重新整理成一套更小的固定清单：终端（`run_command`、`read_command`、`control_command`）负责普通文件、项目、依赖和交互程序；`send` 统一发送文字、图片、文件和表情；`view_file`、`copy_file`、`read_result` 处理文件和长结果；任务控制收拢为 `get_tasks`、`manage_task`、`start_subtask`、`message_task`、`wait`。结果直接给业务数据，失败给出明确原因。旧工具名不再接受新调用，历史记录照常可读。

另外：`read_chat` 能读取 QQ 合并转发的第一层；`search_memory` 不带关键词时列出该范围的记忆；`/ai new` 只重开当前上下文，查询聊天历史时仍能读到之前的记录，并可按平台、群聊/私聊、作者、日期和媒体筛选；运行资料直接给出当前时间。相关 PR：[#463](https://github.com/YuanYeYouTao/Yuki/pull/463)、[#489](https://github.com/YuanYeYouTao/Yuki/pull/489)、[#492](https://github.com/YuanYeYouTao/Yuki/pull/492)、[#494](https://github.com/YuanYeYouTao/Yuki/pull/494)、[#495](https://github.com/YuanYeYouTao/Yuki/pull/495)、[#539](https://github.com/YuanYeYouTao/Yuki/pull/539)、[#579](https://github.com/YuanYeYouTao/Yuki/pull/579)、[#580](https://github.com/YuanYeYouTao/Yuki/pull/580)、[#583](https://github.com/YuanYeYouTao/Yuki/pull/583)、[#586](https://github.com/YuanYeYouTao/Yuki/pull/586)、[#587](https://github.com/YuanYeYouTao/Yuki/pull/587)、[#589](https://github.com/YuanYeYouTao/Yuki/pull/589)、[#592](https://github.com/YuanYeYouTao/Yuki/pull/592)。

## 模型配置与用量

部署向导和 Desktop 共用 Provider 预设。聊天、记忆、SELF 等用途分别选择模型；Embedding、视觉、语音转写和搜索都在同一份模型配置里，密钥单独保存、读取配置时不回传。可以发现模型 ID、测试已保存或草稿连接（会真实调用上游，可能计费）。明确关闭的连接和搜索不会被悄悄换成别的供应商。旧的模型配置用一次性离线命令 `yuki admin model migrate-legacy` 迁移。

用量按实际记录的供应商和模型、时间窗口和时区汇总；改名不会重标旧请求，缺失的计量不当作零。相关 PR：[#441](https://github.com/YuanYeYouTao/Yuki/pull/441)、[#457](https://github.com/YuanYeYouTao/Yuki/pull/457)、[#459](https://github.com/YuanYeYouTao/Yuki/pull/459)、[#462](https://github.com/YuanYeYouTao/Yuki/pull/462)、[#483](https://github.com/YuanYeYouTao/Yuki/pull/483)、[#548](https://github.com/YuanYeYouTao/Yuki/pull/548)、[#549](https://github.com/YuanYeYouTao/Yuki/pull/549)、[#550](https://github.com/YuanYeYouTao/Yuki/pull/550)、[#551](https://github.com/YuanYeYouTao/Yuki/pull/551)、[#552](https://github.com/YuanYeYouTao/Yuki/pull/552)、[#554](https://github.com/YuanYeYouTao/Yuki/pull/554)。

## 管理员与人格

超级管理员资格直接属于人物（Person）：改名、换平台、解绑都不丢资格，账号转交不带走资格，普通配对不授予管理权限。旧的 `SUPERUSERS` QQ 号名单和单独的角色 owner 层退出，共享的名称、头像、人格、模型和服务器电脑都按当前超级管理员核验。Person 超管可以用自己的 Desktop 凭据使用管理功能。

人格只来自一份可自由编辑的 `character/SOUL.md`，角色名称在角色资料里单独修改，可以热更新；空人格也能运行。工具、权限和任务规则由程序维护。旧的系统提示词和双人格文件退出。相关 PR：[#476](https://github.com/YuanYeYouTao/Yuki/pull/476)、[#490](https://github.com/YuanYeYouTao/Yuki/pull/490)、[#523](https://github.com/YuanYeYouTao/Yuki/pull/523)、[#545](https://github.com/YuanYeYouTao/Yuki/pull/545)、[#546](https://github.com/YuanYeYouTao/Yuki/pull/546)、[#547](https://github.com/YuanYeYouTao/Yuki/pull/547)。

## 更快、更稳

## 升级须知

- 升级前完整备份数据库（含 WAL/SHM）、`.env`、配置、插件、工作区和沙箱数据。数据库迁移只能向前，旧镜像不能运行升级后的数据库。
- 3.9.0 的数据库文件名是 `qq_ai_bot.db`，4.0 的 Compose 默认读取 `data/yuki.db`：升级时改名，或在 `docker-compose.override.yml` 里指定原文件，不要让它新建一个空库。
- 沙箱：3.9.0 和 4.0 开发版在宿主机上运行 Manager，需要先用 `sudo sh deploy/sandbox/migrate-host-manager.sh --deployment-root <部署目录>` 迁入 Compose，安装器在检测到旧环境时会停下并提示这一步。
- 管理员资格、人格文件、插件和旧模型配置各有一步，见[升级指南](https://github.com/YuanYeYouTao/Yuki/blob/v4.0.0/docs/upgrade-4.0.0.md)。
