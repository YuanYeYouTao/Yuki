# Yuki 4.0.0 development baseline

<!-- release-baseline: version=4.0.0 schema=0143 -->

[中文](v4.0.0.md) · [Upgrade guide](../upgrade-4.0.0.en.md) · [All PRs and contributors](v4.0.0-prs.md)

4.0.0 moves Yuki from a QQ-centered bot toward one persistent Yuki with multiple platform and personal-client entrances. QQ, Telegram, App and ACP share Main, Work, Memory and Social services, while people, accounts, conversations and completed actions retain their own identities. Everyday tools converge on the persistent terminal, media is read on demand, stickers become a file library, and a separate control plane replaces the old browser administration UI.

This is the **4.0.0 source development baseline**. It covers **37 merged PRs and 185 commits** after the official [`v3.9.0`](https://github.com/YuanYeYouTao/Yuki/releases/tag/v3.9.0) commit `12de953e`, through main [`d7d14bc7`](https://github.com/YuanYeYouTao/Yuki/commit/d7d14bc7a0f7223dd8ddfc756de1df0d9921cae4) (#487). The PR preparing these notes is excluded from that product range. The current database head is `0143`, Plugin API is `7.0`, and the fixed Main tool contract is `25`. Official downloads remain on the 3.9.0 Release.

## Full native-agent benchmarks and cache records

Yuki completed native-agent execution and official grading for all 300 SWE-bench Lite tasks and all 89 Terminal-Bench 2.0 tasks. The run used DeepSeek Flash 1017 through the `deepseek-flash` alias, preserving the real Main, Work, fixed tools, execution receipts and usage records.

| Benchmark | Official result | Input cache hit rate |
| --- | --- | --- |
| SWE-bench Lite test | **216 / 300, 72.00%** | **97.47%**, complete usage for all 300 tasks |
| Terminal-Bench 2.0 | **66 / 89, 74.16%** | **98.32%**, the known-field subset across 89 tasks; **98.26%** for the 84 tasks with complete usage |

Cache rates use the weighted `sum(cached input tokens) / sum(input tokens)` from the same known requests. Missing cache fields are not zero. Native source was fixed at `313b6b9bdf07d411751db13b0a35f8f634f0035b`, before the 4.0.0 cutoff: the coverage and measured cache reuse belong to that run, rather than a rerun of today's source. See the [full report](../benchmarks/2026-10-20-yuki-flash-1017/SUMMARY.en.md) for individual results, usage coverage, failures and limitations. This preparation includes the reports; execution code remains on its original branch.

## Multiple platforms, one person

A Person is no longer represented by a QQ account. One person may have several accounts or no account at all. Personal display names, account nicknames and group cards have distinct owners. Transferring an account creates a new ownership period; earlier history, Memory, Work and receipts remain with the original person. Explicitly merging the same human unifies current personal data while preserving separate conversations for QQ private chats, Telegram topics, App and ACP.

Account and one authoritative AccountAssignment replace the old dual Binding/Presence ownership records. Inbound authors, delivery acknowledgements, existing devices and recovering tasks use their original internal identities. Disabling, transferring or renaming an account does not rewrite the past. General tools and plugins use internal Person, Space and Conversation IDs; platform IDs stay at transport boundaries. Main PRs: [#458](https://github.com/YuanYeYouTao/Yuki/pull/458), [#482](https://github.com/YuanYeYouTao/Yuki/pull/482), [#484](https://github.com/YuanYeYouTao/Yuki/pull/484).

Native mentions retain their original positions, names and account snapshots. Main, semantic participation, history and plugins see the same targets. Outgoing natural `@name` mentions resolve within the actual destination conversation. Genuine name collisions prefer its most recent speaker, with `@{account:UUID}` available for an exact target. Unresolved text remains intact. Indexed lookup also fixes duplicate observations of one account being mistaken for different recipients. Main PRs: [#474](https://github.com/YuanYeYouTao/Yuki/pull/474), [#484](https://github.com/YuanYeYouTao/Yuki/pull/484), [#486](https://github.com/YuanYeYouTao/Yuki/pull/486).

## Administration, personal clients and ACP

Administration now uses the management API, `yuki admin` CLI and shared application operations. Superuser authority is stored directly on Person: changing platforms or unlinking an account preserves it, while transferring an account does not transfer authority. Chat management uses `/ai admin <domain> <operation>`. People, account periods, group recovery, models, plugins, Work and original operation receipts can be discovered and managed by internal IDs. Plugin configuration is editable before first enablement and while stopped; ordinary device reads no longer write activity timestamps. Main PRs: [#458](https://github.com/YuanYeYouTao/Yuki/pull/458), [#476](https://github.com/YuanYeYouTao/Yuki/pull/476), [#482](https://github.com/YuanYeYouTao/Yuki/pull/482).

The personal API provides pairing codes, device credentials, messages, attachments, history, Work and SSE reconnection. Device and operator credentials have separate roles. An operator can create and pair a person without a QQ account. Original request UUIDs retain submission and delivery facts across reconnects.

`yuki acp` exposes Yuki to an ACP client over local stdio. Each session has a separate Conversation and shares the existing Main and persistent Work runtime. In the other direction, the fixed `external_agent` tool delegates to operator-configured ACP agents inside the persistent Linux environment. It can inspect an original prompt, answer permission questions, cancel it or close its peer. Reconnection observes the original session/request/run; it does not purchase another unknown request. Completing a task does not automatically close a reusable peer. Main PRs: [#469](https://github.com/YuanYeYouTao/Yuki/pull/469), [#470](https://github.com/YuanYeYouTao/Yuki/pull/470).

[Yuki Desktop](https://github.com/Institute-of-Agent-Life/Yuki-Desktop) is a separately maintained cross-platform desktop-client project. Its public repository currently contains the project introduction and license. See the [client contract](../architecture/client-api.md) for the implemented personal API, ACP support and interoperability limits.

## A simpler tool surface and persistent terminal

File operations, Python, system packages and interactive shells use `terminal_exec`, `terminal_read` and `terminal_control` in the same persistent Linux environment. Commands run as its administrator, with `HOME=/home/yuki`; installed software, services and `/workspace` persist. Execution has no default deadline. Tools return the original run ID, which is then used to read output, send input or cancel. Cancelling an observation does not stop the command.

The eight ordinary `workspace_*` file tools, separate package-installation path and old terminal write/cancel entry points no longer accept new work. `workspace_inspect` and `workspace_publish` retain media inspection and immutable artifact delivery. Automation uses `automation_query/manage`, chat history uses `query_chat_history`, memory detail uses `read_memory`, and subtask messaging is part of `subagent_control`. Direct and optional Code Mode share the same domain operations and authorization. Main PRs: [#463](https://github.com/YuanYeYouTao/Yuki/pull/463), [#464](https://github.com/YuanYeYouTao/Yuki/pull/464), [#470](https://github.com/YuanYeYouTao/Yuki/pull/470).

Search and page reading are separate operations. `web_search` no longer fetches source pages implicitly; `read_webpage` explicitly retrieves their contents. Independent search connections can use Gemini, Anthropic Messages or Responses while Main keeps its own protocol. Implicit Tavily dependencies are removed; explicit Tavily settings remain valid. Web reading and Telegram HTTP use standard proxy and CA settings, including correct website Host and TLS verification when connecting to a validated public IP. Main PRs: [#441](https://github.com/YuanYeYouTao/Yuki/pull/441), [#457](https://github.com/YuanYeYouTao/Yuki/pull/457), [#459](https://github.com/YuanYeYouTao/Yuki/pull/459), [#463](https://github.com/YuanYeYouTao/Yuki/pull/463), [#466](https://github.com/YuanYeYouTao/Yuki/pull/466).

## Read attachments on demand; send text before stickers

Images, videos, stickers and files share a read-only original-media cache with a 24-hour lifetime. Main initially receives an attachment index and file information, then inspects or saves the files it needs. Images and documents are no longer automatically expanded into the first request. Incoming ASR remains independently configured. The explicit `ASR_PROTOCOL=audio_transcriptions` option supports compatible multipart `/audio/transcriptions` services; the default `chat_completions` mode retains the existing Qwen audio protocol. Main PRs: [#480](https://github.com/YuanYeYouTao/Yuki/pull/480), [#482](https://github.com/YuanYeYouTao/Yuki/pull/482), [#483](https://github.com/YuanYeYouTao/Yuki/pull/483).

Sticker images and per-item JSON under `/workspace/stickers/<platform>/` are the authoritative library. Tags are directly editable and the search index is rebuildable. The old pool, automatic collection worker, adoption flow and capacity-replacement policy are retired. `send_message.emoji` supports text with a sticker or a sticker alone. Text is sent through Social first; background work selects an image, publishes an immutable snapshot and sends it without holding up Main. Telegram retains native WEBP/TGS/WebM files and previews; QQ retains its native small-sticker behavior. Main PRs: [#480](https://github.com/YuanYeYouTao/Yuki/pull/480), [#481](https://github.com/YuanYeYouTao/Yuki/pull/481), [#482](https://github.com/YuanYeYouTao/Yuki/pull/482).

Fixes include attachment downloads using their original receiving account, ordinary chat sticker requests incorrectly rejected for an empty Work ID, mixed Chinese/English tag tokenization, and interrupted multipart text losing its sticker intent. Recovery uses the original text and image receipts rather than sending text again. Reply-message `UnboundLocalError`, ordinary text removed by legacy marker rules, and lost native mentions after edits are also fixed. Main PRs: [#461](https://github.com/YuanYeYouTao/Yuki/pull/461), [#466](https://github.com/YuanYeYouTao/Yuki/pull/466), [#481](https://github.com/YuanYeYouTao/Yuki/pull/481), [#482](https://github.com/YuanYeYouTao/Yuki/pull/482), [#487](https://github.com/YuanYeYouTao/Yuki/pull/487).

## Participation, quiet work and memory

New messages selected by an active Main belong to that activation, so the queue does not answer them a second time. Late participation feedback cannot reject an input already selected into a paid request. Automatic semantic invitations share the existing debounce path; explicit mentions and inputs to existing Work retain their established priority. Background memory seeds are retired, and message ingress no longer repeatedly computes the entire participation state. Main PRs: [#444](https://github.com/YuanYeYouTao/Yuki/pull/444), [#445](https://github.com/YuanYeYouTao/Yuki/pull/445), [#446](https://github.com/YuanYeYouTao/Yuki/pull/446), [#450](https://github.com/YuanYeYouTao/Yuki/pull/450), [#451](https://github.com/YuanYeYouTao/Yuki/pull/451).

SELF wake-ups first advance existing tasks and organize material quietly. Continued follow-up retains its notes or waiting conditions; notifications follow the user's agreement and meaningful changes. Runtime material is current background supplied by the program, not a new utterance or additional authorization. Empty input and Telegram service updates no longer trigger canned “please enter content” replies. Native typing status runs separately from Main on supported platforms: QQ private chat and Telegram currently support it; SnowLuma has no equivalent QQ-group operation. Main PRs: [#443](https://github.com/YuanYeYouTao/Yuki/pull/443), [#467](https://github.com/YuanYeYouTao/Yuki/pull/467), [#479](https://github.com/YuanYeYouTao/Yuki/pull/479).

Reflection processes new evidence, tool results and necessary continuity from its current batch to create new facts or Episodes. Dream maintains existing long-term memory; reflection no longer reinjects all older facts and candidates. Fixes also cover retained text after forgetting, late model responses, and repurchasing successful parts of an Embedding batch. Main PRs: [#465](https://github.com/YuanYeYouTao/Yuki/pull/465), [#487](https://github.com/YuanYeYouTao/Yuki/pull/487).

## Context, recovery and database work

The default `96000`-token Compact trigger schedules early compaction; the current Profile explicitly declares the model's hard capacity. A request that still fits can proceed even when no valid prefix is available or compaction remains above the trigger. Public projections use immutable append chunks and reuse existing bytes. Exact private-protocol recovery can also incorporate newly selected public input from the same conversation while retaining signatures, tool pairing and cumulative budgets. Main PRs: [#462](https://github.com/YuanYeYouTao/Yuki/pull/462), [#471](https://github.com/YuanYeYouTao/Yuki/pull/471), [#487](https://github.com/YuanYeYouTao/Yuki/pull/487).

The synchronous remote-profile lookup before a first reply is removed; native events update existing names and group information instead. Duplicate diagnostics and unused tool/turn statistics are retired. SQLite leases, attachment authorization, task ancestry, archiving, feedback, Memory/Reflection and plugin queues query their actual candidates or indexes. Missing performance indexes no longer refuse startup, and scheduling uses real free execution slots rather than a candidate-check allowance. Main PRs: [#468](https://github.com/YuanYeYouTao/Yuki/pull/468), [#471](https://github.com/YuanYeYouTao/Yuki/pull/471), [#472](https://github.com/YuanYeYouTao/Yuki/pull/472), [#477](https://github.com/YuanYeYouTao/Yuki/pull/477), [#486](https://github.com/YuanYeYouTao/Yuki/pull/486), [#487](https://github.com/YuanYeYouTao/Yuki/pull/487).

SQL, migration, protocol and native-runtime regressions support these changes. Reduced local scans or write volume remain separate from end-to-end deployment latency, provider cost and measured cache hits.

## Plugins and related projects

Plugin API advances from 3.9.0's `3.5` to **`7.0`, with exact Host matching**. Plugins must adopt internal identities, positional `CurrentMessage.mentions`, retirement of the old sticker facade and `plugin.agent_session.v2`. Independent model sessions remove ineffective tool-capability and tool-budget fields while retaining the real model-request budget. Natural expiry or auxiliary audit failure cannot overturn an accepted result, and one background runner failing no longer stops the entire plugin. See the [API 7.0 migration](../plugin-development/api-7.0-migration.md) and [upgrade guide](../upgrade-4.0.0.md).

GitHub Monitor has moved out of the main repository. [Yuki GitHub Monitor](https://github.com/Institute-of-Agent-Life/Yuki-GitHub-Monitor), [Yuki Kun Game](https://github.com/Institute-of-Agent-Life/Yuki-Kun-Game) and [Yuki Semantic Participation](https://github.com/Institute-of-Agent-Life/Yuki-Semantic-Participation) are maintained separately in the organization. Participation remains pinned by the lockfile, and moving repositories does not change plugin identity, data or approval. Main PRs: [#458](https://github.com/YuanYeYouTao/Yuki/pull/458), [#480](https://github.com/YuanYeYouTao/Yuki/pull/480), [#484](https://github.com/YuanYeYouTao/Yuki/pull/484), [#485](https://github.com/YuanYeYouTao/Yuki/pull/485), [#487](https://github.com/YuanYeYouTao/Yuki/pull/487).

## Upgrading and contributions

The Python module and package are now `yuki`, with `yuki` and `yuki-bot` executables. `qq_ai_bot` and the old executable aliases are removed. Existing deployments retain their database path, Compose project, mounts and gateways, and migrate forward from their actual revision to `0143`. Person authority, Plugin API, the mounted system-prompt file, Manager, original environment rootFS and shared-media mount require coordinated changes. See the [4.0.0 upgrade guide](../upgrade-4.0.0.md).

[YuanYeYouTao](https://github.com/YuanYeYouTao) authored 35 of the 37 PRs and [Hilbert-beinghappy](https://github.com/Hilbert-beinghappy) authored two. Hilbert-beinghappy's original #299 control-plane work is carried forward in #458; this range also includes the multi-entry taskbook #436 and plugin-example correction #420. The earlier upstream `allowed_kinds` contribution retains its original attribution. The maintainer defined the identity, platform and tool boundaries, with Codex assisting implementation, validation and independent review. The [complete ledger](v4.0.0-prs.md) preserves each PR's author, scope and merge commit.

This preparation also updates bundled Echo and Subscription Monitor API7.0 manifests, product4.0 compatibility ranges, the SDK default contract and internal-identity examples. These belong to the preparation PR itself and are not counted as additional historical product PRs.
