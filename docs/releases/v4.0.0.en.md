# Yuki 4.0.0 release notes

<!-- release-baseline: version=4.0.0 schema=0156 -->

[中文](https://github.com/YuanYeYouTao/Yuki/blob/v4.0.0/docs/releases/v4.0.0.md) · [Upgrade guide](https://github.com/YuanYeYouTao/Yuki/blob/v4.0.0/docs/upgrade-4.0.0.en.md) · [Every merged PR](https://github.com/YuanYeYouTao/Yuki/blob/v4.0.0/docs/releases/v4.0.0-prs.md)

Yuki 4.0 turns a QQ-centred bot into one long-lived agent across platforms. QQ, Telegram, Feishu, Lark, personal clients and ACP share the same people, memory, tools and tasks. Yuki now has a computer she can see and click on, and with your permission she can operate your computer and move files to and from it. Installing went from "deploy the bot, then set up the sandbox separately" to a single command.

This release covers the **146 merged PRs** after 3.9.0 through #610, listed one by one in the [PR ledger](https://github.com/YuanYeYouTao/Yuki/blob/v4.0.0/docs/releases/v4.0.0-prs.md).

## One-command install, with the sandbox in Compose

The host needs Docker and the Compose plugin. `install.sh` (`install.ps1` on Windows) downloads and verifies the release bundle, runs the setup wizard, asks for a sandbox profile, creates the data volumes, starts everything, and waits until Yuki's environment actually works. Running it again in the same directory upgrades; `.env`, data and `docker-compose.override.yml` are kept. `--yes --profile <profile> --answers model.json` installs without prompts.

A first install asks for your name, creates your Person with administrator status, and prints the address and binding code for Yuki Desktop; the code is valid for 10 minutes and `sh deploy/pair.sh` issues a new one. The Bot is published on `127.0.0.1:8080` only; other devices reach it through Tailscale or HTTPS. The Manager comes back by itself after a host reboot.

The sandbox Manager is now a Compose service running the same image and version as the Bot. HOME, run records, Manager state and the media cache are named Docker volumes that `docker compose down -v` does not remove. The host-side systemd units, venv, loop-mounted ext4 disks, sync scripts and the internal Squid proxy are gone.

| Profile | Contents | Memory, roughly |
| --- | --- | --- |
| `lite` | Terminal and files | 512 MiB |
| `headless` | Adds headless Chromium | 1 GiB |
| `desktop` | Adds a desktop you can watch and take over, with headed Chromium | 3 GiB |

The installer suggests a profile from Docker's memory. If Docker has gVisor (`runsc`) registered with `--overlay2=none`, the sandbox uses it; otherwise it uses `runc`, and that choice never changes silently. To switch profiles, edit `YUKI_SANDBOX_PROFILE` in `.env` and run `docker compose up -d`: a larger profile installs the extra software into the existing environment, a smaller one only changes the mode and resources, and memory and CPU limits apply immediately. The environment can reach the public internet but not the host or private networks. The release publishes two `yuki-environment` images (the base image for `lite`, `-desktop` for the other two); the Bot and environment images are both amd64/arm64. The optional Code Mode build now also works on ARM64.

An existing host Manager moves over once with `deploy/sandbox/migrate-host-manager.sh`, carrying the software and files already installed in the environment; see the [upgrade guide](https://github.com/YuanYeYouTao/Yuki/blob/v4.0.0/docs/upgrade-4.0.0.en.md). PRs: [#610](https://github.com/YuanYeYouTao/Yuki/pull/610), [#609](https://github.com/YuanYeYouTao/Yuki/pull/609), [#607](https://github.com/YuanYeYouTao/Yuki/pull/607), [#606](https://github.com/YuanYeYouTao/Yuki/pull/606), [#567](https://github.com/YuanYeYouTao/Yuki/pull/567), [#570](https://github.com/YuanYeYouTao/Yuki/pull/570), [#571](https://github.com/YuanYeYouTao/Yuki/pull/571), [#572](https://github.com/YuanYeYouTao/Yuki/pull/572), [#519](https://github.com/YuanYeYouTao/Yuki/pull/519), [#521](https://github.com/YuanYeYouTao/Yuki/pull/521), [#464](https://github.com/YuanYeYouTao/Yuki/pull/464).

## Yuki's own computer: screen and browser

Two new tools, `computer` and `browser`. `computer` takes screenshots, clicks, double-clicks, right-clicks, drags, types, presses keys and scrolls, using pixel coordinates from the screenshot. `browser` drives Yuki's own Chromium through page-snapshot nodes, including dialogs, downloads, file inputs and cross-site iframes. With the `desktop` profile you can watch her in Yuki Desktop's computer window, take over at any time and hand control back. The `headless` profile has only a headless browser and `lite` has none; the tools say so plainly.

Input actions run one at a time and leave a receipt. Retrying the same call returns the original result; an action interrupted midway is reported as unknown and never redone. While you hold control her input is refused, and screenshots still work. PRs: [#595](https://github.com/YuanYeYouTao/Yuki/pull/595), [#596](https://github.com/YuanYeYouTao/Yuki/pull/596), [#597](https://github.com/YuanYeYouTao/Yuki/pull/597), [#591](https://github.com/YuanYeYouTao/Yuki/pull/591), [#553](https://github.com/YuanYeYouTao/Yuki/pull/553).

## Your computer

Your computer connects out to Yuki through the [local connector](https://github.com/YuanYeYouTao/Yuki/blob/v4.0.0/docs/operations/local-agent-connector.zh-CN.md) (Chinese); no inbound port is opened. Connect it from Yuki Desktop under Settings → This Computer. Desktop ships the connector runtime, starts it with Desktop, stops it when Desktop quits, and keeps it connected while minimized to the tray. The connector version is **0.6.2**.

- **Full access.** Off by default, and only you can turn it on, on that computer. When it is on, Yuki runs commands (PowerShell or a POSIX shell), reads and writes files and runs installed programs with your current account's permissions. Turning it off refuses new commands, file and browser actions immediately.
- **Screen.** `computer` works on macOS 14+ and Windows: screenshots, clicks and typing, across multiple displays and high-DPI screens. If you are using the computer she does not type over you; she waits for you to stop and retries from a fresh screenshot. Press Stop in Desktop to halt her at any time. On macOS, Yuki.app needs Screen Recording and Accessibility permission.
- **One window in the background.** Given a window, she captures only that window (even when it is covered) and sends input only to it, without moving your cursor or changing the frontmost app. macOS supports clicks, typing, keys, scrolling and more; Windows supports clicking, scrolling and typing into input fields through UI Automation. A macOS window outside your current Space can only be captured.
- **Dedicated browser.** `browser` uses your installed Google Chrome with a separate profile, so it never touches your everyday Chrome logins.
- **Coding agents.** Yuki can drive Codex, Claude Code or another ACP agent on your computer with their own logins and sessions. Progress and questions return to the original Yuki task. Editing or removing one agent no longer restarts unrelated connections.

The connector reconnects after network drops, and a server-side error no longer leaves it parked as "revoked". Changing the server address (for example, to Tailscale) keeps the device identity without pairing again. The server-side LocalExecutor and the server-hosted ACP external-agent path are retired. PRs: [#497](https://github.com/YuanYeYouTao/Yuki/pull/497), [#510](https://github.com/YuanYeYouTao/Yuki/pull/510), [#517](https://github.com/YuanYeYouTao/Yuki/pull/517), [#518](https://github.com/YuanYeYouTao/Yuki/pull/518), [#520](https://github.com/YuanYeYouTao/Yuki/pull/520), [#530](https://github.com/YuanYeYouTao/Yuki/pull/530), [#533](https://github.com/YuanYeYouTao/Yuki/pull/533), [#535](https://github.com/YuanYeYouTao/Yuki/pull/535), [#536](https://github.com/YuanYeYouTao/Yuki/pull/536), [#540](https://github.com/YuanYeYouTao/Yuki/pull/540), [#542](https://github.com/YuanYeYouTao/Yuki/pull/542), [#556](https://github.com/YuanYeYouTao/Yuki/pull/556), [#557](https://github.com/YuanYeYouTao/Yuki/pull/557), [#561](https://github.com/YuanYeYouTao/Yuki/pull/561), [#590](https://github.com/YuanYeYouTao/Yuki/pull/590), [#593](https://github.com/YuanYeYouTao/Yuki/pull/593), [#598](https://github.com/YuanYeYouTao/Yuki/pull/598), [#599](https://github.com/YuanYeYouTao/Yuki/pull/599), [#602](https://github.com/YuanYeYouTao/Yuki/pull/602), [#603](https://github.com/YuanYeYouTao/Yuki/pull/603), [#604](https://github.com/YuanYeYouTao/Yuki/pull/604).

## Files between the server and your computer

`copy_file` copies a file byte for byte into Yuki's environment or onto your computer. The source can be a chat attachment, a file in Yuki's `/workspace`, a file she has already sent, or a file on your computer; it can also copy between two connected computers. An existing destination is replaced atomically, retrying the same call never writes twice, and an unknown outcome is never blindly resent. `view_file` and `send` can also read or send a file straight from your computer.

Writing a file larger than 64 KiB to your computer previously never completed; that is fixed. PRs: [#576](https://github.com/YuanYeYouTao/Yuki/pull/576), [#600](https://github.com/YuanYeYouTao/Yuki/pull/600), [#574](https://github.com/YuanYeYouTao/Yuki/pull/574).

## Many platforms, one person

QQ, Telegram, Feishu and Lark share identity, messages, media and delivery. Feishu/Lark use an enterprise custom app's long connection, with no public callback, and support private chats, groups, topics, mentions, replies and images/files; see the [setup guide](https://github.com/YuanYeYouTao/Yuki/blob/v4.0.0/docs/operations/feishu.zh-CN.md) (Chinese).

A person can have several platform accounts, or none. Merging people, transferring an account, suspending and unlinking are separate operations; renaming or switching accounts never reassigns old messages, memories or tasks to someone else. Each chat entry keeps its own history. Mentions keep their original position and the name used at the time, and a problem on one platform's ingress no longer stops the whole Bot. PRs: [#458](https://github.com/YuanYeYouTao/Yuki/pull/458), [#466](https://github.com/YuanYeYouTao/Yuki/pull/466), [#468](https://github.com/YuanYeYouTao/Yuki/pull/468), [#474](https://github.com/YuanYeYouTao/Yuki/pull/474), [#484](https://github.com/YuanYeYouTao/Yuki/pull/484), [#486](https://github.com/YuanYeYouTao/Yuki/pull/486), [#491](https://github.com/YuanYeYouTao/Yuki/pull/491), [#525](https://github.com/YuanYeYouTao/Yuki/pull/525), [#531](https://github.com/YuanYeYouTao/Yuki/pull/531).

## Yuki Desktop and personal clients

[Yuki Desktop](https://github.com/Institute-of-Agent-Life/Yuki-Desktop) is a separately released client for Windows, macOS and Linux (currently in beta). It covers pairing, chat, attachments, tasks, files, memory, automation, computers, model settings and usage, and can either connect to an existing Yuki or deploy one locally. The personal client API provides device pairing, messages, attachments, event streams, task queries and continuation; ACP clients can connect as well.

The QQ login screen is now viewed and taken over from Desktop through an authenticated connection; scanning the code no longer needs the separately published noVNC page on port 6081. The old management WebUI is gone; administration uses Desktop, the CLI and `/ai admin`. PRs: [#469](https://github.com/YuanYeYouTao/Yuki/pull/469), [#510](https://github.com/YuanYeYouTao/Yuki/pull/510), [#515](https://github.com/YuanYeYouTao/Yuki/pull/515), [#516](https://github.com/YuanYeYouTao/Yuki/pull/516), [#568](https://github.com/YuanYeYouTao/Yuki/pull/568), [#569](https://github.com/YuanYeYouTao/Yuki/pull/569).

## Long tasks and interruptions

Chat, SELF initiative, scheduled tasks, plugins and subtasks share one task path that records goals, parent-child links, cumulative budgets, model requests and effects that already happened. After a restart or disconnect, work continues from those records without resetting budgets or resending messages.

In a private chat, as soon as Yuki starts using tools the request becomes a durable task: what you add next is merged into it, and retryable failures are retried in the background. Messages you send while a scheduled task is running wait their turn instead of being dropped. The fixed per-segment request and tool-call limits (`AGENT_MAX_MODEL_REQUESTS`, `AGENT_MAX_TOOL_CALLS`) and the segment hand-off are gone, so long work no longer stops silently at the 24th request; explicit plugin limits become the whole task's budget. Scheduling is simpler. Long-conversation compaction uses the current model and reuses the public checkpoint. PRs: [#444](https://github.com/YuanYeYouTao/Yuki/pull/444), [#450](https://github.com/YuanYeYouTao/Yuki/pull/450), [#470](https://github.com/YuanYeYouTao/Yuki/pull/470), [#500](https://github.com/YuanYeYouTao/Yuki/pull/500), [#502](https://github.com/YuanYeYouTao/Yuki/pull/502), [#504](https://github.com/YuanYeYouTao/Yuki/pull/504), [#511](https://github.com/YuanYeYouTao/Yuki/pull/511), [#544](https://github.com/YuanYeYouTao/Yuki/pull/544), [#555](https://github.com/YuanYeYouTao/Yuki/pull/555), [#577](https://github.com/YuanYeYouTao/Yuki/pull/577).

## Fewer, more direct tools

The tools are a smaller fixed set. The terminal (`run_command`, `read_command`, `control_command`) handles ordinary files, projects, dependencies and interactive programs; `send` delivers text, images, files and stickers; `view_file`, `copy_file` and `read_result` handle files and long results; task control is `get_tasks`, `manage_task`, `start_subtask`, `message_task` and `wait`. Results are plain business data and failures state their reason. Old tool names no longer accept new calls; historical records still read normally.

Also: `read_chat` reads the first level of QQ forwarded-message bundles; `search_memory` without a query lists the memories in that scope; `/ai new` only resets the current context, and history queries still reach earlier messages, filtered by platform, group or private chat, author, date and media; the runtime context now carries the current time. PRs: [#463](https://github.com/YuanYeYouTao/Yuki/pull/463), [#489](https://github.com/YuanYeYouTao/Yuki/pull/489), [#492](https://github.com/YuanYeYouTao/Yuki/pull/492), [#494](https://github.com/YuanYeYouTao/Yuki/pull/494), [#495](https://github.com/YuanYeYouTao/Yuki/pull/495), [#539](https://github.com/YuanYeYouTao/Yuki/pull/539), [#579](https://github.com/YuanYeYouTao/Yuki/pull/579), [#580](https://github.com/YuanYeYouTao/Yuki/pull/580), [#583](https://github.com/YuanYeYouTao/Yuki/pull/583), [#586](https://github.com/YuanYeYouTao/Yuki/pull/586), [#587](https://github.com/YuanYeYouTao/Yuki/pull/587), [#589](https://github.com/YuanYeYouTao/Yuki/pull/589), [#592](https://github.com/YuanYeYouTao/Yuki/pull/592).

## Model settings and usage

The setup wizard and Desktop share provider presets. Chat, memory, SELF and other uses each pick a model; embeddings, vision, speech transcription and search live in the same model configuration. Keys are stored separately and never returned when the configuration is read. You can discover model IDs and test saved or draft connections (a real upstream call, which may cost money). A connection or search mode you turned off is never quietly replaced by another provider. Old model settings migrate with the one-time offline command `yuki admin model migrate-legacy`.

Usage is summarized by the provider and model actually recorded, over a time window and time zone. Renaming does not relabel old requests, and missing metering is not counted as zero. PRs: [#441](https://github.com/YuanYeYouTao/Yuki/pull/441), [#457](https://github.com/YuanYeYouTao/Yuki/pull/457), [#459](https://github.com/YuanYeYouTao/Yuki/pull/459), [#462](https://github.com/YuanYeYouTao/Yuki/pull/462), [#483](https://github.com/YuanYeYouTao/Yuki/pull/483), [#548](https://github.com/YuanYeYouTao/Yuki/pull/548), [#549](https://github.com/YuanYeYouTao/Yuki/pull/549), [#550](https://github.com/YuanYeYouTao/Yuki/pull/550), [#551](https://github.com/YuanYeYouTao/Yuki/pull/551), [#552](https://github.com/YuanYeYouTao/Yuki/pull/552), [#554](https://github.com/YuanYeYouTao/Yuki/pull/554).

## Administrators and persona

Superuser status belongs to the person. Renaming, switching platforms or unlinking an account keeps it; transferring an account does not carry it; ordinary pairing never grants it. The old `SUPERUSERS` list of QQ numbers and the separate character-owner role are gone, and the shared name, avatar, persona, models and server computer are all checked against current superusers. A superuser can administer Yuki with their own Desktop credentials.

The persona comes from a single freely editable `character/SOUL.md`. The character name is edited separately in the character profile and applies without a restart; an empty persona is valid. Tool, permission and task rules are maintained by the program. The old system prompt and dual persona files are gone. PRs: [#476](https://github.com/YuanYeYouTao/Yuki/pull/476), [#490](https://github.com/YuanYeYouTao/Yuki/pull/490), [#523](https://github.com/YuanYeYouTao/Yuki/pull/523), [#545](https://github.com/YuanYeYouTao/Yuki/pull/545), [#546](https://github.com/YuanYeYouTao/Yuki/pull/546), [#547](https://github.com/YuanYeYouTao/Yuki/pull/547).

## Memory, media and stickers

Images, video, stickers and files arrive as an index first, and originals are read when needed. Originals sit in a shared 24-hour cache; anything worth keeping can be copied into the workspace. Stickers are a file library in the workspace; text goes out first and a sticker follows in the background. Speech transcription needs an explicit protocol. SELF reflection only processes new evidence, and group participation keeps a fast path for continuing a conversation with fewer unnecessary checks. Vector search uses Vec1 tables in the same database; existing vectors move over as they are, without new embedding calls. PRs: [#443](https://github.com/YuanYeYouTao/Yuki/pull/443), [#445](https://github.com/YuanYeYouTao/Yuki/pull/445), [#446](https://github.com/YuanYeYouTao/Yuki/pull/446), [#461](https://github.com/YuanYeYouTao/Yuki/pull/461), [#465](https://github.com/YuanYeYouTao/Yuki/pull/465), [#467](https://github.com/YuanYeYouTao/Yuki/pull/467), [#479](https://github.com/YuanYeYouTao/Yuki/pull/479), [#480](https://github.com/YuanYeYouTao/Yuki/pull/480), [#481](https://github.com/YuanYeYouTao/Yuki/pull/481), [#482](https://github.com/YuanYeYouTao/Yuki/pull/482), [#496](https://github.com/YuanYeYouTao/Yuki/pull/496), [#503](https://github.com/YuanYeYouTao/Yuki/pull/503), [#526](https://github.com/YuanYeYouTao/Yuki/pull/526), [#527](https://github.com/YuanYeYouTao/Yuki/pull/527), [#528](https://github.com/YuanYeYouTao/Yuki/pull/528), [#529](https://github.com/YuanYeYouTao/Yuki/pull/529).

## Faster and steadier

SQLite writes go through one queue and never wait on the network, a model or files inside a write transaction. Context is prepared incrementally, group participation no longer repeats work or rescans history as state grows, and the public health check dropped its expensive historical statistics. A CPU spin caused by stale participation feedback, shutdown ordering and several receipt-recovery problems are fixed. A large code reduction removed duplicate diagnostics, branches kept only for tests, forwarding layers and repeated validation. ## Removed and incompatible

- The Python package and commands are renamed: `qq_ai_bot` → `yuki`, `qq-ai-bot-cli` / `qq-ai-bot` → `yuki` / `yuki-bot`. The image moves from `ghcr.io/yuanyeyoutao/yuki-qqbot` to `ghcr.io/yuanyeyoutao/yuki`. New installs use the database file `data/yuki.db`.
- The host install chain for the sandbox (systemd, venv, loop disks, sync scripts, Squid) is replaced by Compose services.
- The management WebUI, `SUPERUSERS`, the character-owner role, old persona files and variables, the old sticker pool, the server-side ACP external agent and LocalExecutor are removed.
- Old tool names and the per-segment request/tool-call limits are removed.
- Plugin API moves from 3.5 to 9.0 with an exact match; old plugins need porting and re-approval.
- The Kun game and GitHub monitor plugins live in their own repositories.
- SnowLuma no longer publishes the noVNC port 6081.

## Before you upgrade

- Back up the database (including WAL/SHM), `.env`, configuration, plugins, the workspace and the sandbox data first. Migrations only go forward; an old image cannot run the upgraded database.
- 3.9.0 named its database `qq_ai_bot.db`, while the 4.0 Compose file reads `data/yuki.db`. Rename it during the upgrade, or point to the original file in `docker-compose.override.yml`; do not let Yuki create a new empty database.
- Sandbox: 3.9.0 and 4.0 development deployments run the Manager on the host. Move it into Compose first with `sudo sh deploy/sandbox/migrate-host-manager.sh --deployment-root <deployment dir>`; the installer stops and points to this step when it finds the old environment.
- Administrator status, the persona file, plugins and old model settings each take one step; see the [upgrade guide](https://github.com/YuanYeYouTao/Yuki/blob/v4.0.0/docs/upgrade-4.0.0.en.md).
