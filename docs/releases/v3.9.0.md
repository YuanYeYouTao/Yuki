# Yuki 3.9.0 发布说明（草案）

<!-- release-baseline: version=3.9.0 schema=0083 -->

**3.9.0 只是当前开发基线，尚未发布。** 本页不表示已有 `v3.9.0` 标签、GitHub Release、发行包或 3.9.0 镜像，也不表示服务器已升级。当前正式版仍是 [3.8.4](https://github.com/YuanYeYouTao/Yuki/releases/tag/v3.8.4)。以下内容以该正式标签的提交 `9c20ede` 为起点，截止到编写本草案时主线提交 `a8de71c`；发布前应重新核对后续合并和实际发行资产。

## 本轮源码变化

- **可观察、可操作的管理界面。** 管理 WebUI 接入真实聊天事件、执行轮次、工具和模型轨迹、工作区、终端及媒体；模型连接、任务路由和用量统计改由共享控制面维护。执行诊断有保留期限，展示和管理写入各自受授权约束。
- **多 Provider 接入与热配置。** 补充 Gemini GenerateContent、Claude Messages 和其他已支持协议的适配，处理工具声明、原生搜索、媒体输入、思考设置和连接切换。Gemini 搜索桥独立于通用网页搜索；禁用的 MCP Server 不进入启动清单和工具声明。正在执行的 Work 保留原身份、预算及可核验的发送回执。
- **记忆、缓存和用量。** 主 Agent 可按需显式搜索记忆，检索的截断与不完整状态对调用者可见；Embedding 降级时保留预算原因。Claude 的跨轮前缀缓存与写入用量记录得到补充；Gemini 缓存与真实转发另有独立审计。模型请求失败时尽量保留已知用量，用量总数和缺失明细分开解释。缓存命中率取决于真实请求前缀，不保证恒定命中。
- **运行可靠性。** 修复网关快速重连、Jev 故障回退、子 Agent 和旧账本写锁范围、WebUI 执行查询、拆分发送计划与回执核对；将容器存活检查与详细健康诊断分开。Provider 切换、媒体、搜索及真实 QQ 接受情况应以各自验收记录和当前运行版本核对。

## 版本与升级边界

| 项目 | 本开发基线 |
| --- | --- |
| 应用源码版本 | 3.9.0；正式发行仍为 3.8.4 |
| 数据库迁移 | 当前单一 head `0083`；3.8.4 正式镜像随包为 `0072` |
| Plugin API | 3.0；可选 Genie-TTS Worker 组件版本仍为 1.9.0 |
| 部署 | 本次只准备源码和文档，不发布、不构建发行镜像、不替换 Bot |

`0073`—`0079` 增加控制请求回执、执行诊断及索引、模型物理请求用量记录；`0080` 记录新拆分发送的计划份数；`0081` 记录后续 Claude 缓存写入与期限分层用量；`0082` 补齐来源 revision 对事件元数据及 rollup 原会话的失效覆盖；`0083` 增加 Memory evidence 的 receipt 引用索引。新字段不推断旧调用、旧发送计划或旧账单。升级操作、备份与回退边界见 [3.9.0 升级草案](../upgrade-3.9.0.md)。

当前源码还移除了模型返回前的诊断 SQLite 写入等待、已有关系读取及空轮询的 writer 申请，统一 Provider 并发 admission，并将参与快照连接的完整生命周期移到专用线程。来源历史读取和指纹计算在只读快照中完成，短写事务复核原租约及 revision。过期发送尝试保留为结果未知，只有明确未发送的失败可重试；同尝试的迟到回执可确认原发送。具体边界与待办见 [SQLite 延迟修复说明](../operations/sqlite-latency-20260930.md)。这些源码说明不表示已经发布或完成生产验收。
