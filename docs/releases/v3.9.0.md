# Yuki 3.9.0 发布说明（草案）

<!-- release-baseline: version=3.9.0 schema=0104 -->

**3.9.0 是当前开发基线，尚未正式发布。** 正式下载仍为 [3.8.4](https://github.com/YuanYeYouTao/Yuki/releases/tag/v3.8.4)。本页覆盖 `v3.8.4`（`9c20ede`）之后、截至 main `0ddd7eee`（2026-10-09，Asia/Taipei）的 **109 个已合并 PR**。开发提交镜像与正式发行分别记录，源码版本号不代表已有 `:3.9.0` 发行镜像。

## 3.9.0 的主要变化

- **管理 WebUI。** 手帐界面关联真实聊天、执行轨迹、工具回执、模型用量、工作区和终端；模型连接、路由、配置与管理操作共用控制面。默认关闭，服务端核验管理身份与权限。主要 PR：[#153](https://github.com/YuanYeYouTao/Yuki/pull/153)—[#166](https://github.com/YuanYeYouTao/Yuki/pull/166)、[#175](https://github.com/YuanYeYouTao/Yuki/pull/175)、[#252](https://github.com/YuanYeYouTao/Yuki/pull/252)。
- **统一 Agent 循环，默认 direct 构建。** 聊天、SELF、插件、自动化、子任务与 Work 续跑复用 `YukiRuntime` 和类型化 Agent loop。默认镜像提供完整工具声明，不包含 Monty binding、worker 或 launcher；Code Mode 已合入主线，是显式选择 `codemode` 构建并启用的可选编排方式。终端保持直接调用，其余 API 复用原执行器和授权。主要 PR：[#214](https://github.com/YuanYeYouTao/Yuki/pull/214)、[#218](https://github.com/YuanYeYouTao/Yuki/pull/218)、[#265](https://github.com/YuanYeYouTao/Yuki/pull/265)。
- **长任务恢复与主动收尾。** Work 保存原目标、累计预算、协议对象及效果回执；新聊天和用户指示在原任务继续处理。模型可显式完成、等待、取消或交接；收尾沿一次接纳的控制结果和唯一 settlement writer。上下文整理按真实容量处理，允许部分成果与未决事项；删除相同工具结果自动判“无进展”的挂起链，不强制每次压缩覆盖全部输入或变得更短。已确认效果不因重启重做，未知结果先核原 ID。主要 PR：[#215](https://github.com/YuanYeYouTao/Yuki/pull/215)、[#228](https://github.com/YuanYeYouTao/Yuki/pull/228)、[#254](https://github.com/YuanYeYouTao/Yuki/pull/254)、[#255](https://github.com/YuanYeYouTao/Yuki/pull/255)、[#258](https://github.com/YuanYeYouTao/Yuki/pull/258)、[#271](https://github.com/YuanYeYouTao/Yuki/pull/271)、[#272](https://github.com/YuanYeYouTao/Yuki/pull/272)。
- **删除 Memory 派生策略。** 长期事实按 fact ID 管理，同 key 的不同事实可以共存；删除单 active/key 槽位、按标签强造争议、归因/强化/Activation/意图评分、自动注入、人工升格、容量腾位及经验过时策略。主动 `search_memory` 保留授权范围、用户时间条件和真实证据；提取、SELF 与 Dream 可分别绑定 Profile，Rebuild 复用提取。换模型不再冻结 Rebuild，批准子集可以提交，未处理部分继续保留。主要 PR：[#170](https://github.com/YuanYeYouTao/Yuki/pull/170)、[#176](https://github.com/YuanYeYouTao/Yuki/pull/176)、[#272](https://github.com/YuanYeYouTao/Yuki/pull/272)。
- **删除旧人物评分关系系统。** 好感、信任、阶段语气、后台模型打分、工具、管理员入口和插件Facade一并退出；Plugin API为3.4，删除迁移为0103。升级精确移除真实模型路由、配置与自动化专属字段，不提供旧评分兼容接口；实施及上线状态见 [任务书](../architecture/Yuki-旧关系好感度系统彻底删除任务书-2026-10-09.md)。
- **修复记忆人物信息丢失（issue #270）。** 正文与主体引用保留真实内部身份，复用聊天姓名/提及还原，不再分别编排无名“成员序号”。SELF 多条证据按原引用保存，不再只取第一条。请求登记移到真实 HTTP 派发前，准备失败不占物理请求额度；Dream 恢复先取得 writer 再读取执行元数据，避免 deferred 快照升级竞争。主要 PR：[#272](https://github.com/YuanYeYouTao/Yuki/pull/272)、[#273](https://github.com/YuanYeYouTao/Yuki/pull/273)。
- **群聊持续接话。** 真人邀请与既有互动进入普通消息路径，持续接话不每轮额外请求 Jev；自主加入仍沿 SELF 与既有开关。实际反馈保留来源，参与意愿不重写旧历史，也不保证每次机会发言。主要 PR：[#150](https://github.com/YuanYeYouTao/Yuki/pull/150)、[#151](https://github.com/YuanYeYouTao/Yuki/pull/151)、[#230](https://github.com/YuanYeYouTao/Yuki/pull/230)。
- **统一原生多模态。** 当前、引用、历史附件、工作区与获准工具图片由原主模型读取；没有图片能力时明确未读，不暗换 Qwen 摘要。后台表情分类、SDK 显式视觉任务与 ASR 保留独立连接。主要 PR：[#152](https://github.com/YuanYeYouTao/Yuki/pull/152)、[#247](https://github.com/YuanYeYouTao/Yuki/pull/247)、[#248](https://github.com/YuanYeYouTao/Yuki/pull/248)。
- **显式 Provider 配置。** 支持 Chat Completions、Responses、Claude Messages、Gemini GenerateContent 及供应商参数方言。结构化任务沿 Profile 模式，Gemini JSON Schema 仅使用 `responseJsonSchema`；不再由辅助任务强行改模式。思考按显式配置，不强制开启、设置 low 下限或自动抬档。Claude 适配器内的额外付费续跑和正文 DSML 转工具兼容退役，只有真实协议调用参与执行。新安装默认开启模型搜索，显式禁用仍有效；Gemini 使用独立搜索桥，其他连接按实际能力配置。主要 PR：[#152](https://github.com/YuanYeYouTao/Yuki/pull/152)、[#170](https://github.com/YuanYeYouTao/Yuki/pull/170)、[#172](https://github.com/YuanYeYouTao/Yuki/pull/172)、[#253](https://github.com/YuanYeYouTao/Yuki/pull/253)、[#272](https://github.com/YuanYeYouTao/Yuki/pull/272)。
- **减少数据库争用。** 历史与来源在一致读快照中准备，writer 只复核与提交；可丢诊断不阻塞成功响应，维护按索引分页。模型耗时、等待与发送确认分别观测，优化不等于已经消除真实流量长尾。主要 PR：[#229](https://github.com/YuanYeYouTao/Yuki/pull/229)、[#236](https://github.com/YuanYeYouTao/Yuki/pull/236)、[#238](https://github.com/YuanYeYouTao/Yuki/pull/238)—[#245](https://github.com/YuanYeYouTao/Yuki/pull/245)、[#273](https://github.com/YuanYeYouTao/Yuki/pull/273)。
- **退出 MCP 与 Genie 语音输出。** 删除专属工具、SDK/管理入口、配置、合成服务、转换器及发布依赖。共享正文、媒体、原 Work/发送回执和 ASR 保留；语音真实事实及被引用文件须在迁移前冷备。Plugin API 为 **3.4**，旧插件需适配并重新批准。主要 PR：[#259](https://github.com/YuanYeYouTao/Yuki/pull/259)、[#260](https://github.com/YuanYeYouTao/Yuki/pull/260)、[#265](https://github.com/YuanYeYouTao/Yuki/pull/265)。
- **裁剪测试与 CI。** 删除冻结旧策略、重复快照、质量基线与专属评测维护链。Quality 保留源码检查、前端测试/构建及真实回归；Release 使用单个 direct 镜像与部署包 smoke，删除平行发布、重复测试数量门与 bootstrap/finalize 链。主要 PR：[#272](https://github.com/YuanYeYouTao/Yuki/pull/272)。

现行模块边界见[架构索引](../architecture/README.md)。

## 缓存与用量

固定工具合同、当轮历史快照和原协议续跑状态减少不必要的请求前缀变化。Claude 增加跨轮前缀缓存与 5 分钟/1 小时写入用量记录；失败请求保留已知 usage，逻辑模型调用与实际派发的 HTTP 请求分开计数。总量、明细缺失和零用量不混为一谈。

缓存数据按 Provider、日期、场景和计量覆盖分别报告；加权比例为 `Σ已知 cached input / Σ这些请求的 input`，缺少缓存字段的请求保持未知。下表为公开记录中的历史样本，不是本截止提交或 MCP 退役后的最新线上命中率。

| 样本与日期（Asia/Taipei） | 模型 / 场景 | 缓存计量覆盖 | 已知命中输入 / 对应输入 token | 输入加权比例 |
| --- | --- | --- | ---: | ---: |
| [10-01 核查报告](../operations/provider-compaction-audit-2026-10-01.md)，自然群聊一个回复轮 | `gemini-3.8-flash`，同链三次请求 | 3/3 | 96,464 / 106,532 | **90.55%** |
| [10-03 多场景手工实验](../operations/semantic-continuation-2026-10-03.md#手工缓存样本) | `gemini-3.8-flash`，续聊、Work 切换、恢复、压缩 | 7/13，另 6 次未知 | 121,264 / 163,332 | **74.24%** |
| 同一多场景实验 | `deepseek-flash` / Responses，含冷轮和独立摘要 | 13/13，含 1 次明确零缓存 | 222,976 / 316,442 | **70.46%** |
| [10-03 累积聊天手工实验](../operations/work-context-cache-experiment-2026-10-03.md)，03:40—03:41 | `deepseek-flash` / Responses，一次预热加八次续接 | 9/9 | 178,560 / 187,745 | **95.11%** |

最后一组八次热续接单独为 **99.02%**（165,760 / 167,395 token），完整九次的 95.11% 保留首请求，不能只取热轮宣传整体命中率。实验使用合成公共前缀与真实 Provider 请求，不读取生产聊天或向 QQ 发消息；多场景实验的 DeepSeek 有一项未发布要求的 context note，HTTP 成功与缓存计量不等于任务能力全部通过。

Gemini 多场景的全部已报输入为 319,485 token，表中分母只包含缓存字段已知的七次请求，不能把另外六次当零或推算精确总体命中率。[脱敏计量文件](../operations/evidence/semantic-continuation-cache-20261003.json)保留完整覆盖口径。各组模型、时间、场景和合同不同，不是 Provider 优劣或修改前后提速的 A/B；缓存命中也不能证明回复时延正常。

## 验证与现存问题

PR #272/#273 的 CI、direct 镜像本地无源码部署及生产 Bot-only 上线证据见 [10-09 任务书交付记录](../architecture/Yuki-Memory-Provider分工与后台收尾审查任务书-2026-10-09.md#12-实施与交付记录)。这些是开发提交的验证，不是正式 3.9.0 发行。

10-09 SELF 临时恢复完成 236 批、33 次写入，当前有效积压清空，随后恢复原日额度；另发现旧 generation 的无来源重试会阻挡新输入，当时用原队列隔离清障。当前源码已按真实 live 来源过滤占用范围，见[Self Reflection 现行恢复合同](../architecture/self-reflection.md#部署与历史运行证据)；本地修复与上线状态分开记录。禁用空间的旧语义 owner 仍可能被调度 hydration 并遭身份拒绝，也未修复。详见[10-09 残留核查](../operations/documentation-residual-audit-20261009.md)。不能将历史隔离数归零或启动健康冒充所有运行时缺陷已解决；可选 Code Mode 的隔离验证也不等于生产容量或长期内存验收。
