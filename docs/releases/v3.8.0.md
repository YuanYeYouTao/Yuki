# Yuki 3.8.0 发布说明

Yuki 3.8.0 完成永久 Yuki 与 canonical runtime 收口。账号、Provider 和 WebSocket 连接不再拥有
人格、记忆、关系或会话；NapCat 与 SnowLuma 成为同层正式 QQ/OneBot v11 Provider。

## 亮点

### Canonical-only 永久主体

- 一个数据库对应一个永久 Yuki。
- Person、IdentityBinding、Space、SpaceBinding、Presence 和 canonical Conversation 成为唯一
  身份与会话模型。
- 私聊按 Person 聚合，群聊按 Space 聚合；换 QQ Binding 或 Gateway Provider 不分裂关系、
  Memory、Plugin state、Automation 或 Conversation。
- Yuki Presence 不是 Person；第三方机器人使用 `external_bot`，不会获得人物关系或人物记忆。
- Person 主动、Space ingest 和 Space 主动三类路由相互独立；RouteGeneration、
  ConnectionGeneration 与 ConversationGeneration 不再混用。

### NapCat 与 SnowLuma 正式 Provider

- NapCat、SnowLuma 位于同一 Provider Catalog 与 provider-aware OneBot Adapter。
- 不同 QQ 可以分别通过两个 Provider 同时在线。
- 同一 QQ 的第二条活动连接在 Adapter 与 Registry 两层失败关闭；新连接不会挤掉旧连接。
- 正式切换按“停止旧 Provider、确认连接注销、启动新 Provider”执行。
- Provider 切换只改变 GatewayConnection 和 ConnectionGeneration，不创建 Presence，也不改变
  Conversation、Memory 或 RouteGeneration。
- Compose profiles、SnowLuma 配置渲染、持久目录、noVNC/WebUI bind address 和可重试
  `gateway-action.json` 进入发布包。

Yuki 不承诺切换 Provider 能降低腾讯账号风控风险。

### Conversation 与 Rollup

- OneBot `original_message` 成为正文、附件和 mention 顺序的唯一来源。
- 单个、多重、重复、引用和 mention-only 消息使用同一 MentionProjection；任一 Yuki Presence
  投影为 Yuki，成员目标按首次出现稳定编号且保留每个位置。
- 历史 Prompt 从已存 segments 重新投影；损坏 segments 安全回退原正文，不泄露 ID 或正文日志。
- canonical Conversation、primary alias、receipt、Rollup checkpoint 与 emergency overlay 直接
  运行，不再经过 legacy scope 或 runtime epoch 分支。
- 原始事件账本仍是 Rollup 证据源；摘要不进入 Memory，也不成为可信指令。

### Memory 变更修复

- `memory_change.visibility` 明确只控制 SELF memory。
- PERSON、PERSON_GROUP 和 GROUP 目标会忽略合法但无意义的 `current_scope` / `global` hint，
  然后继续授权与 mutation，不再返回 `visibility_only_valid_for_self_memory`。
- 非法枚举仍在 DTO 校验阶段拒绝，SELF 的 visibility、episode 和受保护键规则保持不变。
- 关系、偏好、Memory ownership 与人物删除按永久 Person 执行；同一 Person 的多个 Binding
  共享关系历史。

### Control Plane 与未来 WebUI

- transport-neutral Control Plane 提供 Principal、Capability、opaque cursor、乐观并发、幂等
  command receipt、同步审计和 OperationRef。
- 未来 WebUI 必须只经 ControlPlaneBundle 调用业务服务，不能直接访问 ORM、Gateway 连接或
  secret。
- 3.8 不新增管理 HTTP API、登录系统或前端，也不开放新管理端口。
- `/healthz` 保持公开瘦载荷；secret 仍不可回读。

## 数据库与兼容性

- 产品版本：`3.8.0`
- Alembic head：`0049`
- Plugin API：`2.0`
- Genie-TTS Worker 内部版本：`1.9.0`

`0048` 现在是无父 revision 的冻结 canonical baseline；`0049` 是唯一 bridge/finalization：

- fresh database：`0048 -> 0049`。
- historical database：只接受已经完成 canonical v2 的旧 `0048`。
- pre-3.8、v1、dual-write、backfill/cutover 中间态不再受支持。

`0049` 会在单个 `BEGIN IMMEDIATE` 中验证 canonical ownership、processing lease、schema
manifest、FTS/trigger 和外键，然后删除旧 carrier 与迁移状态。它不提供 downgrade；数据回退
只能恢复升级前同一时点的 DB/WAL/SHM 快照。

升级前请完整阅读 [3.8 升级指南](../upgrade-3.8.0.md)。

## 安装

Linux：

```bash
curl -fLO https://github.com/YuanYeYouTao/Yuki-QQbot/releases/download/v3.8.0/install.sh
chmod +x install.sh
./install.sh
```

Windows PowerShell：

```powershell
Invoke-WebRequest -Uri https://github.com/YuanYeYouTao/Yuki-QQbot/releases/download/v3.8.0/install.ps1 -OutFile install.ps1
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

已有 3.8 canonical 部署可重新运行安装器；安装器在迁移前停止 Bot，并保存数据库、WAL、SHM、
配置和镜像信息。更早数据库不能直接升级。

## 验证清单

发布产物应通过：

- Ruff format/check 与 mypy。
- 完整 pytest 和测试预算门。
- fresh `0048 -> 0049` 与 populated historical `0048 -> 0049`。
- SQLite quick/FK、FTS、trigger 和 ORM schema 一致性。
- NapCat QQ A 与 SnowLuma QQ B 并存，以及同 QQ 双连接拒绝。
- 停旧启新后 Presence、Conversation、Memory 与路由 generation 不变。
- Docker Compose config、release smoke、匿名 GHCR 拉取和不可变 digest 校验。

当前架构见 [Yuki 3.8 canonical runtime](../architecture/canonical-runtime.md)，SnowLuma 首次登录和
切换见 [Provider 部署文档](../deployment/snowluma.md)。
