# Yuki 3.8.1 发布说明

Yuki 3.8.1 修复插件后台事件污染普通会话前缀的问题，并把 GitHub Monitor 的轮询、投递与安全
合批收口为可恢复的持久队列。Alembic head 仍为 `0049`，本版没有 schema migration。

## 外部事件不再伪装成会话 system 消息

- Plugin notification 使用 canonical `external_event` 类型落账，不进入普通 user/assistant/system
  history，也不占用普通历史消息槽位。
- 常规聊天只在 history fit 完成后看到一份有条数、字符上限的 recent-event digest；全部字段都在
  `content_trust=external_untrusted` 载体内。
- Host 的可信 external-event policy 是恒定文本，不包含插件名、事件类型或正文，因此插件风暴
  不再持续改写模型请求的稳定前缀。
- 当前通知触发的后台 Agent turn 只把该事件作为 current input 使用一次，不会再从 recent digest
  重复注入。

外部事件仍保留在不可变账本中，但不能成为 Person、Memory、Automation、普通回复目标或工具授权
来源。Memory rebuild、MessageFacade 和自动化读取也只接受 `event_kind=message`。

## Rollup 三套尺子与停写 recount

3.8.1 分离三套含义不同的计量：

1. 前台历史只计算模型真实可见的 message 投影；external event 为零。
2. 持久水位保持所有 keeper 的连续事件计数，但字符只累加逐条 message 投影。
3. 压缩来源按真实 `rollup_source_projection` 序列化成本切分，external event 在这里仍有成本。

protected tail 按最近可见 message 计算，覆盖水位仍连续越过外部事件。外部事件 append 不再凭 Prompt
字符唤醒已有 Rollup job；GitHub 风暴位于 eligible prefix 时仍可触发有界压缩。

3.8.0 的存量 `uncovered_character_count` 使用旧尺子。升级必须停止全部写入，并在 rehearsal 与 live
数据库各执行一次：

```bash
qq-ai-bot-cli conversation recount-uncovered
qq-ai-bot-cli conversation recount-uncovered --check
```

命令只输出汇总计数，不输出会话 ID、正文、插件名或数据库路径；任一 generation、coverage 或
schema 不变量不满足时整次回滚并失败关闭。

## 后台 freshness 与完整请求幂等

- 后台 turn、通知回复、工具、Memory、Automation 与外部发送前都重验 Conversation generation、
  authorization、目标、Principal 和 immutable notification snapshot。
- 过期 turn 在获取锁后、模型前和副作用前都被取消；旧 generation 不能提交回复或工具结果。
- Host 幂等身份覆盖 target、payload、summary、text、Agent intent 和按顺序排列的媒体
  handle/SHA/expiry。相同 key 的相同请求返回旧结果，不同请求返回 receipt conflict。
- 已存在通知路径为精确只读复用，不能给旧事件补 text、media 或 Agent job。

## GitHub Monitor 1.2.0

- GitHub 原始数字 event ID 进入 CAS-backed FIFO WAL，分别记录 accepted/committed cursor、源
  fingerprint、pending、inflight、目标策略快照和 gap。
- 消费 oldest-first；分页重叠会核对 payload，cursor 缺口、同 ID 不同 payload、非数字 ID、媒体
  过期或不确定状态失败关闭，禁止跳到最新事件。
- 多目标投递在首次 attempt 前可按当前配置 skipped；attempting 后完整请求冻结，只能字节等价
  重试。已完成目标不会因另一个目标失败而重发。
- 只合并 pending FIFO 中相邻且兼容的 Create/Delete、Watch/Fork。Push、Release、PR、Issue、
  comments、reviews、Discussion、启用通知和 `/github test` 保持单例。
- 批次 key 基于有序单例 key；payload 保留全部 source event ID，并在 seal 前按 Host 32 KiB
  canonical JSON 上限校验。第一版不生成聚合卡片。
- `coalesce=false` 让尚未 seal 的事件按单例排空；已 seal 批次身份不变，旧 C4 drainer 仍可完成。
- 新增停写 queue doctor / legacy import，只输出无正文计数，并对未完成 activation、
  pending/inflight、gap、CAS/receipt conflict、媒体过期、活动诊断和 Host 积压失败关闭。

## 版本与兼容性

- 产品版本：`3.8.1`
- Alembic head：`0049`（无新增迁移）
- Plugin API：`2.0`
- GitHub Monitor：`1.2.0`，需要 Yuki `>=3.8.1,<4.0`

3.8.1 仍只支持 canonical 3.8 数据库。pre-3.8、v1、dual-write、backfill/cutover 中间态不受支持。
完整停写、快照、recount、验证与回退步骤见
[3.8.1 升级指南](https://github.com/YuanYeYouTao/Yuki-QQbot/releases/download/v3.8.1/Yuki-3.8.1-Upgrade.md)。

升级时不能只换 Bot 镜像：内置插件由 Compose 从宿主 `plugins/` 只读挂载，必须使用
同一 Release 包中的 GitHub Monitor 1.2.0 受控替换并通过离线 queue doctor。两个安装器
对 existing 部署会先停 Bot、快照、更新内置插件、recount 与 doctor，任一门禁失败都
不启动新 Bot。existing 路径只拉取并强制替换 Bot；NapCat/SnowLuma 保持原容器，只有向导生成
明确 gateway action 时才停止被取消的 Provider、启动新增 Provider。

## 安装

Linux：

```bash
curl -fLO https://github.com/YuanYeYouTao/Yuki-QQbot/releases/download/v3.8.1/install.sh
chmod +x install.sh
./install.sh
```

Windows PowerShell：

```powershell
Invoke-WebRequest -Uri https://github.com/YuanYeYouTao/Yuki-QQbot/releases/download/v3.8.1/install.ps1 -OutFile install.ps1
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

## 发布验证

- Ruff format/check、mypy、完整 pytest 与测试预算。
- fresh/populated `0048 -> 0049`、SQLite quick/FK、FTS、trigger 与 ORM schema。
- offline recount/check 的成功、失败关闭和事务回滚，以及 queue doctor/import。
- External event Prompt 隔离、三套 Rollup 尺子、三次 freshness 围栏与 Host request identity。
- GitHub WAL 崩溃点、多目标恢复、32 KiB 批次边界和 C5→C4 回退 drain。
- 本机 `linux/amd64` 镜像构建、Compose config、release smoke 和部署后健康检查。

Provider cache hit 不是硬验收项；3.8.1 保证请求前缀不再被外部 system 消息主动切断，但上游缓存
策略与最终命中率仍由 Provider 决定。
