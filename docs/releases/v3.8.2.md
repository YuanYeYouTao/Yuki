# Yuki 3.8.2

本版让 Yuki 拥有可长期保存文件和运行任务的工作环境，补齐接收语音识别，并统一聊天、插件、自动化和任务续跑使用的主 Agent。QQ 成员提及、消息路由、历史读取和长时间运行的资源管理也得到修复。

## 主要更新

### 持久工作环境

Yuki 可以在共用的 Linux 工作目录里保存项目、下载文件、安装依赖和运行代码，普通工作文件不再按 24 小时过期。文件工具与终端共用同一份内容，支持交互输入、后台执行、进度查询、取消和内部服务管理。

任务可以先留在环境里运行，Yuki 继续处理消息，再通过任务回执查看结果。Bot 或 Manager 重启不会主动销毁环境进程；环境重启后，普通任务标记中断，登记服务按策略恢复。文件可以发布为不可变快照后交付，旧 artifact ID 仍可使用。

**这是可选的独立部署组件**，需要 gVisor、execd 和 Yuki Manager，普通部署包不会自动安装。默认家目录 2 GiB、容器内存上限 512 MiB；系统包增量为监控预算，并非文件系统硬配额。详见[持久环境说明](https://github.com/YuanYeYouTao/Yuki-QQbot/blob/v3.8.2/docs/operations/persistent-environment.zh-CN.md)。

### 接收语音识别

私聊语音、符合回复策略的群聊语音以及引用语音可以通过 Qwen ASR 转写。转写参与正常聊天，并进入历史、搜索和 Rollup，无需另开一个语音 Agent，也无需安装本地识别模型。

可以复用已有千问连接；识别与 Genie-TTS 语音发送独立。引用语音不会被当作当前说话者的记忆证据。见[配置与限制](https://github.com/YuanYeYouTao/Yuki-QQbot/blob/v3.8.2/docs/speech/recognition.md)。

### 更一致的聊天与任务续跑

聊天、插件唤醒、自动化和续跑使用同一个主入口与完整工具声明。历史请求投影有界保存，减少跨轮请求前缀被重新排列；权限仍在执行时校验，不因固定工具声明而扩大。

新增全局短期记录区 `short_state`，用于暂存跨会话信息，与长期记忆、持久文件分开。后台任务使用持久回执和重连核对，避免结果不确定时盲目重跑。

### QQ 社交修复

- 撤回消息使用原消息所属的 Yuki 账号，不依赖当前主动发送路由。
- 查询群成员按实际可访问的连接判断；多个 QQ 绑定存在歧义时拒绝猜选。
- 支持真正的结构化 @成员，修复只拼接昵称却没有触发提醒的问题。
- 修正切换 QQ 账号后的路由相关问题，以及群自动化戳人的目标授权。
- 增加有来源与权限约束的网关历史读取，让 Agent 能查询实际会话，而不只看到发送回执。

### 记忆与运行稳定性

改进记忆批次提取、历史共同群读取、检索排序和证据状态区分；明确的记住、纠正与删除继续即时处理。自省和 Dream 增加输入、失败恢复及证据绑定检查。

修复空闲事件载荷、会话资源和媒体处理相关的内存占用问题，补充任务恢复与输出日志的容量控制。

## 配置向导精简

`install.sh` 和 `install.ps1` 只负责下载、校验部署包和填写配置。已有部署保留 Compose、插件和数据；确认后备份并写入配置。

移除了自动停服、数据库升级、部署文件替换和网关切换。配置完成后，按[首次启动与升级指南](https://github.com/YuanYeYouTao/Yuki-QQbot/blob/v3.8.2/docs/upgrade-3.8.2.md)操作，也可以直接手工编辑配置。

## 下载与升级

| 项目 | 版本或附件 |
| --- | --- |
| Bot 镜像 | `ghcr.io/yuanyeyoutao/yuki-qqbot:3.8.2` |
| 可选 TTS Worker 镜像 | `ghcr.io/yuanyeyoutao/yuki-genie-tts-worker:3.8.2`（组件版本 1.9.0） |
| 部署包 | `yuki-3.8.2-deploy.zip` / `yuki-3.8.2-deploy.tar.gz` |
| 校验文件 | `SHA256SUMS` |
| 数据库 | Alembic `0055` |
| 插件接口 | Plugin API `2.0` |

正式镜像支持 **linux/amd64**。Release 下方提供部署包、配置向导、Compose、环境模板和升级指南。单独的环境模板附件名为 `default.env.example`，压缩包内仍为 `.env.example`。

从 0051 升级会执行 0052–0055 迁移；更旧数据库需要先核对迁移前提，不得用 `stamp` 跳过。升级前保存一致备份，保留已有 Compose 覆盖文件与挂载。持久环境还要迁移文件并更新 Manager；仅替换 Bot 镜像不能完成这部分部署。

旧插件 `llm.generate` / `agent.run` 统一为主入口，依赖旧独立生成行为的插件需要适配。回退前必须保全升级后的消息、文件和执行回执。

## 已知限制

- 工作环境不包含浏览器或桌面；Yuki 管理 WebUI 尚未提供。
- 当前 DeepSeek Responses 接入的联网搜索需使用 Tavily；不能把模型响应成功当作搜索已执行。
- 语音转写、记忆提取和自省可能产生错误，证据引用不等于语义已核实。完整历史质量评估仍未完成。
- 曾经过旧 0048 迁移的数据库需单独核查历史完整性，本版不会自动恢复已丢失的数据。背景见[历史验收记录](https://github.com/YuanYeYouTao/Yuki-QQbot/blob/v3.8.2/docs/architecture/memory-evidence-acceptance-progress.md)。
- 固定工具声明与历史投影减少请求结构变化，不保证线上缓存命中率。
